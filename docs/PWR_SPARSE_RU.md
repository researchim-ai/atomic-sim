# Разреженный путь Radau для связанной PWR-модели — v146

[English](PWR_SPARSE_EN.md) · [Стационарный LU-кэш](SPARSE_STEADY_RU.md)

`SparseLocalModeratorPWRSession` включает CSC-якобиан для неявного solver
существующей монолитной исследовательской PWR-модели. Это переход от
оптимизаций отдельного аппарата к связанной системе нейтроники, топлива,
оболочки, локального теплоносителя и контура.

```python
from coupling.pwr_sparse import SparseLocalModeratorPWRSession
from coupling.refinement import coupled_pwr_mesh

model = SparseLocalModeratorPWRSession(**coupled_pwr_mesh(2),
                                      max_step_s=0.05, rtol=2e-9)
position = model.controls['rod_target']
row = model.advance(0.1, {'rod_target': position + 0.01})
saved = model.checkpoint()
restored = SparseLocalModeratorPWRSession.restore(saved)
```

## Что изменено

Общий solver получил узкий метод `_solver_jacobian`. По умолчанию он
возвращает прежний плотный массив без копирования или изменения значений.
Новый адаптер переводит его в CSC. Удаляются только точно нулевые записи:
порог отсечения отсутствует, каждый вычисленный ненулевой коэффициент
сохраняется, включая проверенное тестом значение 1e-300.

Численные производные остаются прежними: фиксированные относительные
возмущения, допуск физической области и односторонняя разность при
неподдержанном втором направлении. Известные моды, закон движения стержня,
абсолютные допуски, контроль работы solver и проверки запасов не меняются.
Не вводятся приближённая схема разреженности или замороженный якобиан.

Разреженный якобиан передаётся в SciPy Radau, который использует SuperLU
и собственные правила обновления/переиспользования факторов. Пользовательский
кэш LU из v145 здесь не применяется. Сведения о числе ненулевых элементов,
размере матрицы и штатные nlu/njev/RHS-счётчики сохраняются в наблюдениях.
Это не сокращает стоимость вычисления самих конечных разностей и не
гарантирует ускорение на небольшой системе.

## Физическая и численная проверка

Сравниваются плотный и CSC-путь, настройки `max_step_s=0.05, rtol=2e-9` и
`max_step_s=0.025, rtol=2e-10`, три сценария:

- ввод стержня на 0.01 хода за секунду, наблюдение до 2 с;
- ввод и возврат стержня, наблюдение до 3 с;
- явный SCRAM с наблюдением до 4 с и достижением конечного положения стержня.

Оба backend используют одинаковую сетку 2 нейтронные / 2 жидкостные /
4 тепловые ячейки и одинаковые иллюстративные физические параметры.
Проверяются совпадение начального физического состояния, согласованный
стационар, энергия, масса, бор, локальные запасы, предшественники, неизменная
опора обратной связи, команды и физические события. Различия полного
состояния между backend ограничены 1e-5, между настройками времени — 1e-4.

Выполняются 12 траекторий и шесть JSON-restart после 0.5 с с точным
повторением суффикса каждой подробной траектории. Неверная команда должна
полностью откатывать интервал. Шесть отрицательных контролей меняют копии
состояния, порога отсечения, restart, rollback, событий и энергобаланса.

SCRAM здесь относится к четырёхсекундному участку движения стержня и отклика
модели. Это не приёмка полного останова, выбега насосов или длительного
остаточного теплоотвода станции.

## Checkpoint и регрессия

Новый адаптер имеет отдельный формат `pwr-sparse-local-moderator/v1` и
подпись численной политики. Плотный и разреженный checkpoint нельзя
незаметно обменять. При восстановлении заново проверяется исходный
стационар и воспроизводится история; сохранённая матрица или факторизация
не принимаются как достоверное состояние.

Изменение общего файла solver изменило цепочки хешей также у прежних
PWR-адаптеров. Старые source-bound checkpoint больше не принимаются текущим
кодом. Их подписи не переписываются: для исторического восстановления нужна
соответствующая версия исходников либо отдельно принятая миграция.

Отдельная проверка повторяет нативные команды архивного v143 fine dilution
на текущем плотном пути. Совпадение физической траектории не означает
совместимость старого checkpoint и не переносит прежний часовой протокол
на изменённую подпись. Старые машинные протоколы не переписываются.

Принятая поставка: **125 профильных/регрессионных тестов исходников**, затем **17 профильных и 17 из wheel** на уточнённых настройках, восемь фаз и полный научный JSON без расхождений. Все шесть отрицательных контролей сработали. Максимальное отличие полного состояния между backend — `2.7758986e-06`, между настройками времени — `1.1413578e-05`. Наблюдаемая доля ненулевых элементов якобиана — `0.0516581–0.0557537`. Пять архивных физических наблюдений плотного борного режима v143 совпали побитно по десяти полям; его старый checkpoint отклонён по подписи. [Машинный протокол](benchmarks/pwr_sparse_v146.json).

## Локальное воспроизведение

```sh
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:. \
  python -m scripts.verify_component_delivery --component pwr-sparse \
  --output artifacts/pwr-sparse-local --phase-timeout-s 1200
```

Нужен новый каталог. Профиль выполняет новые и регрессионные тесты,
научную матрицу, sdist → wheel, установку вне checkout, тесты и полный
replay. Время каждого расчёта записывается отдельно от научного JSON;
конструирование и restart в него не входят. Подготовка snapshot/checkpoint
внутри измеряемого участка входит: это не время только линейного solve. Один замер на комбинацию не
даёт статистически подтверждённого преимущества по скорости. CI и сеть
не используются.

## Остаток плана

Разреженная структурная сборка якобиана без всех плотных проб, сокращение
стоимости производных, длительные режимы, другие сетки/сценарии, связь со
StationEnv и применимые экспериментальные данные остаются открытыми.
Уравнения содержат прежние исследовательские приближения. NPP-11.03/04,
NPP-12.03 и весь NPP-15.02 этим пакетом не закрываются. **58/76, открыто 18**.
