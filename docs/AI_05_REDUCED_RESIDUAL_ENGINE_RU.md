# AI-05: реестр residual-систем и редуцированный Radau

Реестр `SYSTEM_TYPES` содержит один поддержанный тип:
`constant_rho_thermal_graph_v1`. Он создаёт полный ограниченный граф через
[типизированный адаптер](AI_05_TYPED_GRAPH_ADAPTER_RU.md). Это регистрация
семейства систем, а не произвольная сборка нелинейного оборудования и не
расширение линейного `CompiledNetwork`. По данным JSON не импортируется код.
Состав сети, границы и физические параметры задаются исходным графом.

## Расчёт

```python
model = ReducedResidualEngine(graph_request(model_input), max_macro_step_s=2.0)
result = model.advance(120.0)
```

Backend использует SciPy Radau над редуцированными дифференциальными
координатами. Для каждой оценки RHS алгебраические давления/расходы решаются
по residual и аналитическому алгебраическому якобиану: масштабированный Newton,
обратный поиск по шагу, размерные допуски и ограничения числа итераций.
Во время продолжения прежний гидравлический solver и прежний DP-интегратор
не вызываются. Начальная инициализация и проверка handoff используют ранее
квалифицированные средства; это явно отдельные операции.

Поддержаны постоянная диагональная массовая матрица, положительные
дифференциальные коэффициенты и совпадающий порядок алгебраических строк
и координат. В данном реестре это температуры/интеграл энергии и давления/
расходы графа. Произвольная массовая матрица, произвольные DAE-индексы,
события и переменная структура этим backend не поддерживаются.

Интегрируются приращения температур и масштабированный интеграл внешней
энергии в исходной системе отсчёта. Это сохраняет малые изменения, которые
могли бы потеряться при повторном вычитании абсолютных температур.
Для каждого макроинтервала переиспользуется консервативная проверка области
из прежнего нелинейного графа: границы температур, потоков, давлений,
транспортируемой температуры и скоростей. Недоказанный интервал сокращается;
это не поиск точного времени физического события и не directed-rounding proof.
Промежуточные стадии проверяются на принадлежность допущенному боксу.

## Транзакционность и бюджеты

`advance` работает на отделённых координатах. Отказ Newton, Radau, допуска
области, ресурса, энергетического баланса или финального отчёта оставляет
исходную модель целиком неизменной. Ограничиваются макрошаг, попытки,
суммарные RHS-оценки за вызов, Newton и backtracking. Отрицательная,
неконечная или непредставимо малая длительность отклоняется.

Шаги внутри макроинтервала выбирает Radau. Его внутренний collocation solver
создаётся заново на каждом макроинтервале. Поэтому checkpoint не заявляет
перенос внутренней истории Radau: политика `fresh_collocation_history_each_macro_segment`
входит в snapshot. Разбиение внешних вызовов может изменить численную
траекторию в пределах проверяемого допуска. Продолжение из checkpoint и
продолжение того же объекта при одинаковом следующем вызове проверяются
на точное совпадение значений. Это не межплатформенная гарантия.

Checkpoint связывает исходники, бюджеты, тип системы, полный исходный вход,
метод, максимальный макрошаг, приращения, алгебраический seed и отчёт.
Восстановление проверяет источник, физическое состояние, алгебраические
невязки, интеграл энергии и согласованность экспортированного наблюдения.
Хеши проверяют согласованность, но не удостоверяют автора истории.
Один экземпляр предполагает последовательного владельца, без конкурентных
вызовов на один объект.

## Перенос между backend

```python
model.import_legacy_checkpoint(dp_checkpoint)
model.advance(10.0)
handoff = model.export_legacy_checkpoint()
dp_model.restore(handoff["checkpoint"])
```

При переносе сохраняются температурные приращения в исходной системе
отсчёта, масштабированный интеграл энергии и время. Алгебраические значения
согласуются с теми же уравнениями; их побитовое совпадение между разными
solver не заявляется. Передача выполняется без физического прогрева и без
проекции дифференциальных запасов на стационарное состояние.

При экспорте предложение шага DP явно сбрасывается в его исходный максимум;
коллокационная история Radau не переносится. Внешний регулятор, RNG, события
и будущие команды не входят в этот handoff. Исходники/бюджеты, исходный граф
и политика backend должны совпадать. Возвращаемый handoff содержит
provenance backend; сам legacy checkpoint сохраняет его прежний контракт.
[Пример](../examples/reduced_graph_handoff.py):
`python -m examples.reduced_graph_handoff` выполняет DP → Radau → DP до 20 с.

## Проверки и оставшаяся область

Шесть сценариев по 120 с до восьми узлов: прямой и обратный поток,
охлаждаемый цикл, нагрев при нулевом расходе, смешанная восьмиузловая сеть
и мостовой реверс. Для каждого выполнены три рабочих траектории с
максимальными макрошагами 2/1/0.5 с. Фактические максимальные внутренние
шаги измеряются и должны различаться; они меньше этих ограничений.
Итого 18 основных траекторий и 12 независимых Radau/DOP853 IVP с отдельными
гидравлическими root и энергетическим RHS. Проверяются 12 handoff,
restart в 37.5 с, энергетический баланс и расхождение разбиений.
