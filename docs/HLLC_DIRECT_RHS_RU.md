# Прямой RHS HLLC без повторного транспорта

Срез: 10 ноября 2026. Следующий шаг после
[быстрого жидкостного EOS](HLLC_LIQUID_EOS_FAST_PATH_RU.md) — удалить
транспортный расчёт, результат которого не использовался.

## Что изменилось

Раньше ContactHEMNetwork сначала вызывал родительский RHS Русанова,
вычислял его потоки и их распределение по ячейкам, затем заменял транспорт
на HLLC. В ветках `hllc`/`hllc-local` теперь сразу строится нужный поток.
Ветка `rusanov` и техническая инициализация по-прежнему используют родителя.
Квалифицированное основание, EOS, HLLC-формулы и шаг CFL не изменены.

Специализация допустима только в прежней области ContactHEMNetwork:
жидкость, отсутствие трения, кипения, внешнего нагрева. Конструктор и проверка
команд продолжают отклонять неподдерживаемые законы и ненулевые источники.
Удалён расчёт нулевого drag и заведомо неиспользуемого транспорта, а не
физический эффект, разрешённый этим режимом.

Проверка нулевого импульса узлов перенесена в прямой путь явно. Температурная
область и допустимость фаз по-прежнему проверяются при восстановлении состояния.
Вычисляются прежние тепловые/энтропийные выражения и все вспомогательные
ledger-поля, включая знаки нулей. Сохраняются обе проверки звёздных областей,
глобальные/локальные ограничения волн и конечность RHS.
Точный физический поток записывается в face-ledger, опорные силы — в support-ledger.

Условие специализации нельзя автоматически переносить на нагреваемый или
фрикционный режим: для его добавления нужны отдельные уравнения и квалификация.

## Проверка всего RHS

Тесты сравнивают старую и новую реализацию до и после развития переходного
процесса: три схемы, температурный и связанный разрывы. Сравниваются **все биты**
массивов RHS и aux через представление uint64, а не только несколько итоговых
температур. Дополнительно проверяются сохранение родительской ветви Русанова,
отказ при импульсе неподвижного узла и отсутствие вызова лишнего транспорта
при обычном HLLC-вычислении.

Для конструктора и одного advance до 1 мс на четырёх ячейках профиль дал:

- вызовы graph transport RHS: **302 → 0**;
- qualified RHS: **304 → 2** — осталась техническая инициализация;
- исходный inverse EOS: **2358 → 2358**;
- быстрый inverse EOS: **5984 → 5984**.

То есть вычислений EOS не стало меньше за счёт обхода допуска. Снята только
повторная сборка транспорта и нулевых замыканий. Счётчики не используются
как измерение времени под профайлером.

## Измеренные затраты

Проведены прогрев и пять парных запусков со сменой порядка на том же окружении.
Учитываются конструктор, advance до 1 мс и checkpoint. Медианы CPU:

- Неподвижный контакт, `hllc-local`, четыре ячейки:
  **0,09829 → 0,08453 с**, **1,16×**.
- Прямой перепад, `hllc-local`, четыре ячейки:
  **0,86384 → 0,83832 с**, **1,03×**.
- Широкий перепад, `hllc-local`, две ячейки:
  **0,68652 → 0,67697 с**, **1,01×**.
- Прямой перепад, фиксированный `hllc`, четыре ячейки:
  **0,81653 → 0,79606 с**, **1,03×**.

На волнах выигрыш небольшой: стоимость EOS остаётся доминирующей. Эти числа
не являются универсальным ускорением, gate времени или доказательством
превосходства над другими моделерами. Все пары и CPU/wall опубликованы.

## Строгое равенство и знак нуля

Сравнение сохранённых наблюдений и числового checkpoint усилено:
канонический JSON с конечными числами различает `+0.0`/`-0.0` и типы чисел.
Из checkpoint исключается только поле source, которое обязано измениться
при новых исходниках; внешний digest при этом не сравнивается как физическое число.
Все пять новых пар каждого профиля прошли такую проверку.

Прежний Python `==` гарантировал равенство чисел без допуска, но не различал
знак нуля. Дополнительно проверены сохранённые **последние** пары четырёх
профилей двух прежних кампаний и текущей: всего 12 пакетов. Различий не найдено.
Это аудит доступных пакетов, не повтор всех старых запусков; старые sealed
отчёты не переписаны. Для текущего широкого пути до 40 мс также отдельно
проверены канонические наблюдения и числовой checkpoint относительно
сохранённой исходной траектории.

## Научная область и воспроизведение

Текущая source-подпись контактного пакета новая. Повторно приняты
15 физических face-случаев, пять неподвижных контактных сеток, широкий режим
до 40 мс с точным restart, внешний Modelica-стенд и guard-программы.
Два прежних независимых reference-пути используются только после проверки
неизменности основания и RH-кода. Вся старая длинная матрица автоматически
на новые исходники не переносится. Старые checkpoint отклоняются по source.

```bash
python -m scripts.benchmark_hllc_speed \
  --baseline docs/benchmarks/baselines/hem_contact_v15 \
  --baseline-protocol docs/benchmarks/baselines/hem_contact_v15_source.json \
  --output artifacts/my-direct-rhs-speed
python -m scripts.verify_hllc_speed \
  --previous-long artifacts/hllc-long-v4 --output artifacts/my-direct-rhs-check
python -m pytest -q tests/test_hllc_direct_rhs.py
```

Нужны новые выходные директории; данные старого длинного прогона нужны только
для второй команды. Снимок версии до изменения включён в репозиторий как
read-only fixture, не как альтернативный поддерживаемый runtime. Подпись
основания должна соответствовать численному окружению измерений.

Теплообмен, трение, двухфазность и валидация установки этим изменением
не добавлены. `validated=false`, `plant_referenced=false`.
