# AI-05: онлайн-управление нелинейным графом

`OnlineThermalGraph` — инженерный адаптер внешнего регулятора к ранее
проверенному нелинейному теплогидравлическому графу. Регулятор получает
наблюдение, формирует пакет команд и задаёт длительность удержания. Исполняется
один пакет на текущей отметке времени и положительный интервал с неизменными
командами. [Рабочий пример](../examples/online_thermal_control.py) запускается
через `python -m examples.online_thermal_control` из checkout.

## Контракт взаимодействия

```python
model = OnlineThermalGraph(model_input)
observation = model.observation()
result = model.step(
    {"thermal_nodes": {"a": {"heat_power_w": 1000.0}}},
    10.0,
    expected_revision=observation["revision"],
)
```

Наблюдение содержит `revision`, хеш истории и полное инженерное состояние
модели. Версия начинается с нуля и увеличивается только после успешного шага.
`expected_revision` обязателен; bool и нецелые типы отклоняются. Повторная
доставка уже принятой команды отклоняется, без повторного исполнения.
Версия доступна только для чтения.

Один экземпляр рассчитан на одного последовательно работающего владельца.
Проверка версии защищает от устаревших действий; она не заменяет блокировку
при многопоточном доступе и не является системой распределённой доставки.

Разрешённые группы и единицы команд следуют
[контракту расписаний](AI_05_SCHEDULED_GRAPH_RU.md): мощности в Вт,
температуры в К, давления и напор в Па, инжекция в кг/с. Роли границ,
топология, объёмы, свойства и законы сопротивления фиксированы.
Одновременная смена подачи и её температуры задаётся одним пакетом.

Команда применяется на текущих температурах, без импульса запасов и энергии;
гидравлическое равновесие пересчитывается. После команды сбрасывается
предложение адаптивного шага. Отчёт содержит левое/правое состояние
`command_switch`, интеграционные сегменты и конечное наблюдение.
Наблюдение между шагами соответствует окончанию последнего удержания;
новая команда ещё не применена. Это существенно для сравнения давлений
и расходов с правосторонним независимым эталоном расписания.

## Транзакция и восстановление

Проверка, пересборка, интегрирование и подготовка ответа выполняются на
отделённой копии. При любом отказе исходная модель, версия, история команд,
интеграл энергии и адаптивное состояние сохраняются. Отклонённую команду
можно исправить и повторить с той же версией. Длительность должна продвигать
представимое время. Бюджет ограничивает эпизод 10000 с и 128 командами;
действуют также суммарные ограничения попыток и сегментов базового решателя.

Checkpoint связывает исходный model_input, исходники, бюджеты, версию,
полную принятую историю и внутренний checkpoint. Восстановление не повторяет
физическое исполнение истории: проверяется её согласованность с метаданными
и активным состоянием. Будущие/неудержанные команды, пропущенная начальная
команда и продвижение времени без команд отклоняются. Контрольные суммы
не подтверждают автора checkpoint и не являются криптографической подписью.

Внешний регулятор не вызывается внутри транзакции. Его случайное состояние,
интегратор PID, память агента и внешние побочные эффекты не входят в checkpoint
модели; владелец должен сохранять их согласованно. Адаптер не добавляет
скрытый reward, обученный регулятор, задержки связи или модель датчиков.

## Численная проверка

Четыре сценария: ограниченная пропорциональная тепловая обратная связь,
реверс давления, смена знака подачи и тепловое управление восьмиузловым графом.
Каждый длится 120 с с шестью удержаниями, включая неравные интервалы и
37.5 с. На трёх измеренных сетках 0.5/0.25/0.125 с получаются 12 основных
траекторий. Для каждого реализованного набора команд отдельно запускаются
Radau и DOP853: всего 24 независимых IVP. Это проверка физического исполнения
реализованных действий, а не независимая сертификация алгоритма регулятора.
Адаптивный restart проверяется в середине эпизода с пересчётом будущих команд.
Аудитор проверяет полноту матрицы, источники/бюджеты и повторяет все расчёты.

```bash
python -m scripts.qualify_online_graph --output artifacts/online_qualification
python -m scripts.qualify_online_graph --audit artifacts/online_qualification --output artifacts/online_audit.json
```

## Оставшаяся область

Это companion в репозитории, не зарегистрированный динамический backend SDK
и не Gymnasium-среда. Ранее квалифицированный пакет SDK не изменён.
Постоянные rho/cp, пользовательский L(T) и квазистационарная гидравлика
сохраняются. Инерция, гидроудар, переменные свойства/EOS, фазовые переходы,
общая компонентная сеть и экспериментальная/объектная валидация остаются
отдельными задачами. Качество управления реальной установкой не заявляется.
