# Нейтральная полоса подпитки и слива

Введён **отключаемый** режим регулятора уровня питательного бака. Если
измеренная ошибка лежит внутри заданной полосы, регулятор запрашивает
`feed_inventory_fraction=0.5`: оба направления подпитки/слива закрыты.
Это команда реальной модели клапанов, а не назначение массы бака.

По умолчанию `inventory_deadband_m=0`: сохраняется прежний PI без полосы.
Положительное значение задаётся в метрах, независимо от нормирующего
`scale` PI. Поддерживается диапазон до 1 мм только для split-range выхода
`feed_inventory_fraction` с нейтральным `bias=0.5`, без feed-forward.

## Интегратор и исполнитель

Внутри полосы эффективная ошибка PI обнуляется и прежний интегральный
запрос заменяется нейтральной базой. Поэтому накопленная команда не
продолжает открывать клапан при малой ошибке. Штатный `commit` продолжает
учитывать фактически доставленный выход и tracking: ограничение скорости
исполнителя и внешние ограничения не обходятся.

За пределами полосы работает обычный PI с текущим состоянием интегратора.
Отдельной проверки требует восстановление полезной подпитки при достаточно
большом отклонении: режим не должен просто отключать регулирование.
На самой границе действует включающее сравнение по вычисленному числу.
Этот режим не вводит отдельный гистерезис входа/выхода.

Измеренный уровень, его качество и заданное значение не изменяются.
`last_error` PI внутри полосы — эффективная управляющая ошибка; фактическое
расхождение остаётся доступно в измерительном кадре. Проверка готовности
стационара использует прежние исходные измерения и физический вектор.
Защита и останов сохраняют приоритет над нейтральным запросом.

## Воспроизводимость и подготовка состояния

```python
from atomic_model_station_faults import FaultSession

station = FaultSession(tick_s=5., history_budget_steps=8192,
                       inventory_deadband_m=0.0002)
station.step(modes={key: "auto" for key in station.control.loops})
```

Параметр записывается в начальный манифест сессии и конфигурацию PI.
Штатный `FaultSession.restore` воспроизводит тот же режим и проверяет
полный checkpoint. Сохранение только физической массы без памяти
управления не является таким restart.

Полоса также выбирается при создании горячего состояния:

```python
from atomic_model_station_readiness import prepare_hot_state

result = prepare_hot_state(maximum_warmup_s=7200., required_followup_s=3600.,
                           inventory_deadband_m=0.0002)
```

При продолжении `initial_session=` политика сохраняется. Передача иного
значения полосы отклоняется; менять управление скрытно внутри restart
нельзя. Указание `None` сохраняет политику переданной сессии и выбирает
старый режим для новой. В CLI есть `--inventory-deadband-m`.
Параметры подготовки не означают, что успешный прогрев уже получен.

## Что показывал прежний час

В сохранённом окне 3000–3600 с старого алгоритма максимальная абсолютная
измеренная ошибка уровня составляла около 0,0983 мм. Все 120 отсчётов
лежали внутри кандидатной полосы 0,2 мм, но было 32 запроса подпитки,
88 запросов слива и два изменения направления. Ни один запрос не был
точно нейтральным.

Это исторический разбор измерений и команд. Он **не является** расчётом
новой связанной траектории: отключение мелкого воздействия может изменить
последующую температуру, давление и уровни. Исторические v55/v56 и их
отрицательная оценка стационара сохраняются. После изменения исходников
управления их fingerprints относятся к прежней версии; source-check
старых checkpoint не обходится.

## Новая короткая проверка

До запуска фиксируется четырёхсекундная программа с тактом 0,1 с,
шестью автоматическими контурами и двумя разрешениями интегратора.
Первые три секундных участка задают смещения уровня +0,1, −0,1, +0,1 мм;
последний — +0,6 мм, за пределами полосы.

Сравниваются прежний алгоритм и нейтральная полоса на одном расписании.
За первые три секунды требуется ненулевой расход резервов в старом режиме
и не более 1e-10 кг в новом, при измеренной ошибке не более 0,2 мм.
На последнем участке должна возобновиться реальная подпитка. Отдельно
проверяются локальные/общие балансы, уточнение полного физического вектора,
native restart на 2 с с полным хвостом и конечным checkpoint.

```bash
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
export PYTHONPATH="$PWD/src"
python -m pytest tests/test_station_inventory_deadband.py
python -m scripts.qualify_station_inventory_neutral \
  --output artifacts/neutral-study-new
python -m scripts.verify_local_library --output artifacts/neutral-library-new
python -m scripts.verify_station_inventory_delivery --study inventory_neutral \
  --output artifacts/neutral-installed-new \
  --source-evidence artifacts/neutral-study-new \
  --library-evidence artifacts/neutral-library-new
```

Установленная проверка заново исполняет физическую программу из wheel
вне исходной копии и сравнивает все научные JSON побайтно. Дополнительно
выполняется установленный CLI диагностики. CI и внешний runner не нужны.

Это проверка малых отклонений и восстановления действия, а не длительного
стационара. До NPP-11.01 нужны согласованное горячее начало, полное окно
готовности и последующий hold 3600 с с уточнением/restart/установленным
повтором. Допуски прежних испытаний не меняются.


## Результат v57

[Машинный отчёт](benchmarks/station_inventory_neutral_v57.json) сохраняет
исходный отклонённый кандидат, исправленную проверку и хеши свидетельств.
За первые три секунды старый регулятор переместил между резервами
0.0904128542 кг, новый — 0 кг в обоих
разрешениях. Максимальная измеренная ошибка нового пути составила
0.18575097 мм при полосе 0,2 мм.
На последней секунде реальная подпитка возобновилась. Максимальная
покоординатная разница уточнения — 4.93554308e-06;
весь restart и конечный checkpoint совпали точно.

В первоначальном расчёте локальная проверка обнаружила пропущенную
в диагностике ветвь байпаса коллектора. Добавлены оба конца этого потока
и проверка открытого байпаса; допуск 1e-9 кг/с не менялся. Физический
решатель и его баланс не исправлялись задним числом.

Все 24 научных JSON короткого опыта и стандартной программы
диагностики повторены побайтно из wheel вне проекта; установленный CLI
также выполнен. При отключении полосы coarse/fine физические трассы
стандартной программы совпали с прежними хешами v56.
Локальная поставка — 1832 теста и восемь фаз; 37 целевых тестов
финальной версии отдельно прошли после исправления диагностики.

Положительный результат относится к указанным коротким программам.
Длительный стационар, полный hold и NPP-11 не приняты; 46/76, R1 открыт.
