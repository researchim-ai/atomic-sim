# Разреженная стационарная инициализация — v145

[English](SPARSE_STEADY_EN.md) · [Кэш переходного оператора](EXCHANGER_CACHE_RU.md)

Добавлены `SparseFactorCache` и опциональный `SparseSteadyExchanger`.
Первый переиспользует LU-факторизацию одной и той же вещественной матрицы
для разных правых частей. Второй применяет его к стационарному началу
существующего теплообменника. Физические уравнения, последующее интегрирование
и реализация по умолчанию не меняются.

```python
from core.sparse_linear import SparseFactorCache
from physics.thermal.sparse_steady_exchanger import SparseSteadyExchanger

factors = SparseFactorCache(entries=8, max_bytes=8 * 1024 * 1024)
model = SparseSteadyExchanger(configuration, boundary_controls,
                             {'mode': 'steady'}, factor_cache=factors)
# Передайте тот же factors следующей модели с другими входными температурами.
row = model.advance(0.2)
info = factors.cache_info()
```

При неизменных расходах и свойствах новые входные температуры меняют
правую часть стационарной системы `A*T=-b`, но не её матрицу. Факторизация
может использоваться повторно. Изменение расхода или коэффициента требует
другого ключа. Инициализация `mode='given'` не использует LU.

## Корректность линейного решения

Матрицы приводятся к вещественному float64 CSC: дублирующиеся записи
суммируются, явные нули удаляются, индексы сортируются. Ключ хранит размер,
индексы и точные значения полученной матрицы; квантования по допуску нет.
Поддержаны NumPy и SciPy sparse, размер 1–256, не более 65536 хранимых
входных записей, одна конечная вещественная правая часть. Boolean, complex,
неправильные формы и неконечные значения отклоняются.

При промахе выполняется **плотная проверка численного ранга**, затем
разреженная факторизация SuperLU. Эта проверка оставлена намеренно:
разреженное решение не должно незаметно принять незафиксированное или
численно вырожденное стационарное состояние. Это ограниченная реализация
для небольших систем, а не полностью разреженная обработка больших моделей.

Каждое решение, включая попадание в кэш, проверяется по текущей исходной
канонической матрице:

```text
||A*x-b||inf / (||A||inf*||x||inf + ||b||inf) <= 1e-12
```

Нормы и их произведения вычисляются с расширенным диапазоном `longdouble`;
неконечный результат отклоняется. Проверка не должна принять ошибочное
решение из-за переполнения знаменателя. При отказе solve или проверки
соответствующий фактор удаляется из кэша. Тесты намеренно портят решение,
в том числе для коэффициентов порядка 1e308.

У теплообменника дополнительно проверяются положительные температуры и
**размерная невязка не выше 1e-6 Вт на клетку**. Нормированная невязка
линейного solver не подменяет физический допуск.

## Память, совместное использование и restart

LRU ограничен одновременно 1–32 записями и бюджетом 1024–67108864 байт.
Если один фактор больше бюджета, решение возможно без его сохранения.
Учёт включает массивы CSC/LU, перестановки и байты ключей, но не внутренние
накладные расходы SuperLU/Python или временные плотные массивы проверки
ранга. Это предел учитываемого содержимого кэша, не пик RAM процесса.

Входные матрицы копируются. Пользователь получает новое решение и копию
статистики. Кэш можно явно передавать нескольким последовательным моделям;
глобального кэша нет, конкурентное использование одного экземпляра не
квалифицировано. `clear_cache()` удаляет факторы и счётчики.

Факторы не сериализуются. JSON-restart создаёт новый кэш и заново решает
исходное стационарное начало, затем восстанавливает физические запасы и
проверяет балансы. Чтение собственного snapshot и точное продолжение
проверены. Плотный и разреженный начальные якоря могут отличаться округлением:
бесшовная миграция всех старых snapshot, особенно нулевого времени,
не заявляется. Отдельно проверен пример старого snapshot положительного времени.

## Приёмочная матрица

Противоток, реверс обоих потоков и остановленный аппарат с ненулевой связью
с окружающей средой проверяются на 1/4/16 клетках. Для каждого случая
рассчитываются три пары входных температур. Всего по 27 стационарных моделей
на каждый backend, затем девять пар переходных процессов и девять точных
JSON-restart. Остановка без тепловой опоры отклоняется как незафиксированная.

Сравниваются температуры, размерные стационарные невязки, энергетические
интегралы, портовые мощности, команды и временные отметки. Для девяти семейств
требуются девять факторизаций и 18 повторных использований. Шесть отрицательных
контролей портят копии результатов.

Benchmark отделён от научного JSON: три серии по 32 полных инициализации
на 8/32 клетках, включая конструирование и первое построение факторов.
Сравниваются плотный solver, переиспользование и очистка перед каждым
решением. На малых системах обработка sparse и проверки могут стоить
дороже плотного метода; универсальное ускорение не предполагается.

Принятая поставка: **73 теста исходников и 43 теста из wheel**, восемь фаз и полный научный JSON без расхождений. Максимальное отличие температуры — `5.7980287e-12 К`, размерная стационарная невязка — `2.6107455e-09 Вт`. Все девять restart точные. Медианные локальные отношения времени dense/reuse — **0.55 / 1.49** на 8/32 клетках; величина ниже единицы означает замедление. [Машинный протокол с обоими измерениями](benchmarks/sparse_steady_v145.json).

## Локальный запуск

```sh
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:. \
  python -m scripts.verify_component_delivery --component sparse-steady \
  --output artifacts/sparse-steady-local --phase-timeout-s 1200
```

Нужен новый каталог. Выполняются целевые тесты, научные случаи, sdist → wheel,
установка вне checkout, тесты и полный replay. Времена сохраняются отдельно
в `source/performance.json` и `installed/performance.json`. CI и сеть не нужны.

## Что остаётся открытым

Это ограниченная оптимизация существующих линейных стационарных семейств.
Разреженная сборка нелинейного PWR-якобиана, критерии его обновления,
переиспользование нелинейных факторизаций и квалификация длительной станции
не реализованы этим пакетом. Экспериментальная валидация и полный библиотечный
прогон не заявляются. NPP-15.02 целиком остаётся открытым: **58/76, осталось 18**.
