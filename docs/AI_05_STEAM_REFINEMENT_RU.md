# Временное уточнение и длительные режимы парового цикла

Дата: 2 ноября 2026. Область: численная проверка редуцированной сборки
парогенератор — турбина — конденсатор; экспериментальный допуск отсутствует.

## Что реализовано

`scripts/qualify_steam_cycle.py` задаёт 14 семейств и 44 расчёта: три
уровня Radau для каждого семейства и дополнительные BDF для номинала и
ступени нагрева. Отдельный `scripts/audit_steam_refinement.py` заново
вычисляет метрики по сохранённым состояниям и независимому reference.
Он отвергает подмену сценария, пропущенный уровень, повтор пакета,
неверный runtime/driver и преждевременный выход из длительного режима.

Для Radau фиксированы `rtol=1e-9`, `atol_scale=0.01`;
предел шага делится на четыре дважды. Обычный ряд — 0.1/0.025/0.00625 с;
для коротких выходов по скорости, фазе и давлению задан меньший исходный шаг.
Приёмка проверяет фактически возвращённые сетки, а не только настройки.
Требуется минимум двукратное уменьшение максимального наблюдаемого шага.
Старые физические бюджеты закреплены SHA256 и не ослаблены.

Длительные задачи: номинал 100 с, увеличение нагрева 60 с, циклическая
смена нагрева/теплоотвода/расходов/нагрузки 120 с, смещение питания 60 с.
Для каждой требуется завершение полного горизонта на всех трёх уровнях.
Допустимый физический останов отдельно объявлен только для трёх
предельных семейств. Сравниваются давления, температуры, качества и
скорость ротора; reference использует абсолютные M/U и отдельный
двумерный корень равновесия при общей библиотеке IF97.

Адаптивная сетка и различия около численного шума не доказывают
асимптотический порядок: `observed_order=null`. Сохраняются реальные
различия, пороги шума и ошибки относительно reference.

## Диагностика и устойчивость

SDK сохраняет `solver_trace.json`: возвращённые времена SciPy, метод,
допуски и счётчики `scipy_nfev/njev/nlu` для принятых интервалов.
Неудачный внешний интервал откатывает также диагностику. Физический
останов сохраняет принятую часть; удержание границы не изображается
как работа решателя. Аналитическая турбина не получает выдуманных
счётчиков. Ручные вычисления якобиана не входят в `scipy_nfev`;
возвращённая сетка у события не выдаётся за все скрытые внутренние шаги.

На длинном номинале обнаружена потеря малых тепловых приращений при
вычитании больших температур/потоков. Потоки переписаны как опорное
значение плюс малое приращение — алгебраически те же балансы, без
линеаризации EOS. Дополнительно уточнён корень инверсии запасов.
Одно уточнение корня производительность не исправило.

[Сохранённая регрессия](../validation/ai05_steam_cycle_numerical_stability_v1.json)
связывает исходники до исправления и три одинаковых 100-секундных входа.
При прежних допусках число возвращённых шагов уменьшилось с 21 266 до
1 201, `scipy_nfev` с 545 419 до 8 607. Это один локальный steady workload,
а не квалификация скорости обучения ИИ. Прерванная первая кампания
`artifacts/ai05_steam_cycle_refinement_v1` не принята.

Вторая кампания отвергнута конечным контролем: у короткого выхода по
давлению реальное отношение максимальных шагов составило 1.987 вместо
требуемых 2. В бюджете v2 уменьшены только шаги этого семейства до
0.04/0.01/0.0025 с; порог 2 и все бюджеты ошибок сохранены.
[Регрессия сеточного контроля](../validation/ai05_steam_refinement_mesh_regression_v1.json)
сохраняет неуспешную кампанию отдельно.

`--reuse-from` позволяет перенести неизменённые raw-пакеты той же версии
runtime: вход должен совпадать полностью, проверяются manifest и SHA256
каждого артефакта. Все reference/балансовые проверки вычисляются заново;
старые verdict не копируются. Новые входы рассчитываются заново.

## Воспроизведение

```bash
python -m scripts.qualify_steam_cycle --output artifacts/NEW_REFINEMENT
python -m scripts.audit_steam_refinement artifacts/NEW_REFINEMENT \
  --output artifacts/NEW_REFINEMENT_AUDIT.json
```

Обе команды включены в CI; локальное выполнение не доказывает успешный
запуск удалённой матрицы. Raw-пакеты, точные drivers и frozen-поставка
должны переноситься вместе: одних сводок JSON недостаточно.

Следующий физический блок — сопряжение с первичной тепловой петлёй.
Эмпирический паровой расход и заданное питание сохраняют ограничения
своего паспорта; карты оборудования и объектные данные требуют отдельной
работы. `validated=false`, `plant_referenced=false`.
