# Переходная энергия конечных объёмов в гидравлическом графе

`scripts/transient_thermal_graph.py` добавляет конечные тепловые запасы
к прежнему стационарному графу. В каждом узле явно заданы объём жидкости
и начальная температура; C_i=rho*V_i*cp > 0. Гидравлические давления,
расходы и внешние команды фиксированы, rho/cp постоянны. Обратной связи
температуры с гидравликой, сжимаемости и движения границ здесь нет.

Это частичный блок AI-05.03/08. Он позволяет рассчитывать запуск и
накопление энергии в системах, у которых нет стационарной температуры.
Нагреваемая замкнутая петля без теплоотвода получает рост энергии,
а не искусственно закреплённую среднюю температуру.

## Уравнения и интегрирование

В узлах интегрируется внутренняя тепловая энергия
E_i=C_i*(T_i-T_reference). Портовая энтальпия сохраняет член p/rho,
смешение использует фактического донора, диссипация сопротивления
передаётся выходящей жидкости. Теплоотдача, внешнее тепло, энтальпия
подач/отборов, мощность заданного напора и гравитационная работа имеют
тот же смысл, что в [стационарной постановке](AI_05_THERMAL_GRAPH_RU.md).

```text
C_i*dT_i/dt = sum(inward enthalpy powers) + heat_i - UA_i*(T_i-Tambient_i)
sum(E_i(t)-E_i(0)) = integral(external enthalpy + heat - ambient
                              + prescribed gain + gravity) dt
```

Для фиксированной гидравлики это аффинная система dT/dt=A*T+b.
Рабочий решатель использует расширенную матричную экспоненту, одновременно
интегрируя внешний энергетический счётчик. Внутреннее представление
хранит приращения относительно явно заданной начальной температуры:
малый нагрев не теряется при многократном сложении с абсолютными 300–400 K.
Энергетический счётчик масштабирован суммарной теплоёмкостью.

Отсутствие стационарной тепловой опоры не делает эту ODE вырожденной:
начальные температуры всех положительных запасов заданы явно.
Нулевые объёмы и смешанные DAE-узлы в этом интерфейсе не поддержаны.

## Проверка всего интервала и транзакционный шаг

Одного допустимого конечного состояния недостаточно. Для фиксированной
аффинной системы на полном прямоугольнике допустимых температур
строятся покомпонентные нижняя/верхняя оценки производных. Верхние
границы температуры донора дополнительно уменьшены на нагрев выходящей
струи от диссипации, без изменения самого состояния.

Если интегральные оценки T0+h*min(rate_low,0) и
T0+h*max(rate_high,0) строго внутри области, вся непрерывная траектория
на интервале h остаётся внутри неё: при первом предполагаемом выходе
оценка производной ещё действует и исключает пересечение.
При отсутствии сертификата h делится пополам. Ограничены минимальный
внутренний шаг и число внутренних шагов.

Это консервативный допуск: безопасный интервал также может быть отклонён
как `interval_domain`, если оценка слишком груба. Такая диагностика
не означает доказанный физический выход или найденное время события.
Точного останова на границе и последующего переключения режима здесь нет.

`advance(duration)` сначала рассчитывает кандидата. Температуры, время
и интегральная энергия принимаются только после проверки всего запроса,
источников и абсолютного энергетического бюджета. Ошибка домена, исчерпание
шагов, нарушение энергии или смена исходников откатывают весь advance,
включая уже посчитанные внутренние интервалы. Проекции температуры нет.
`rates` и `snapshot` не меняют физическое состояние.
Непредставимо малое приращение времени, которое не увеличивает timestamp,
отклоняется до расчёта. Неконечные значения входа/checkpoint дают явную
ошибку контракта, а не частично восстановленную модель.

## Checkpoint и перезапуск

Checkpoint содержит входной SHA256, точные хеши скриптов/бюджетов и runtime,
Python/numpy/scipy, время, температуры, их приращения и интеграл энергии.
Проверяются имена узлов, конечность, область, равенство температур
начальному состоянию плюс приращения и энергетическая согласованность.
Restore также транзакционный. Изменение экспортированного checkpoint
или снимка не меняет модель.

SHA256 проверяет целостность, но не удостоверяет отправителя и не доказывает
физическое происхождение произвольно пересозданного checkpoint.
Другие входы, объёмы, команды, версии или зависимости отклоняются;
миграция между моделями этим интерфейсом не предусмотрена.

## Вход и CLI

Формат `atomic-thermal-graph-transient`, schema 1:

- `steady_input`: явный формат прежнего теплогидравлического графа;
- `volumes_m3`: положительные объёмы всех узлов;
- `initial_temperatures_k`: начальные температуры всех узлов;
- `max_step_s`: верхний предел интервала, не более 10 с.

Пример: `examples/transient_thermal_graph.json`.

```bash
python -m scripts.transient_thermal_graph examples/transient_thermal_graph.json \
  --duration-s 60 --output artifacts/NEW_DYNAMIC_FIRST
python -m scripts.transient_thermal_graph examples/transient_thermal_graph.json \
  --duration-s 60 --resume artifacts/NEW_DYNAMIC_FIRST/checkpoint.json \
  --output artifacts/NEW_DYNAMIC_RESTART
python -m scripts.qualify_transient_graph --output artifacts/NEW_DYNAMIC_MATRIX
python -m scripts.qualify_transient_graph --audit artifacts/NEW_DYNAMIC_MATRIX \
  --output artifacts/NEW_DYNAMIC_AUDIT.json
```

CLI сохраняет запрос, отчёт, checkpoint при успехе и manifest с SHA256
всех файлов. Неудачный запрос возвращает exit code 2 без checkpoint;
существующая папка не перезаписывается. Это инженерные скрипты рядом
с source-matched SDK, а не новый установленный console entry point.

## Численные свидетельства и ограничения

Бюджет: `validation/ai05_transient_graph_budget_v1.json`.
Абсолютная ошибка энергии рабочего расчёта <=1e-4 Дж; ошибка температуры
при restart <=1e-9 K. Сравнение с независимой гидравликой/IVP требует
температурной ошибки <=1e-6 K и интегральной энергии <=0.1 Дж;
между двумя независимыми IVP — <=0.01 Дж по интегральной энергии.
Эти критерии различаются: независимый решатель гидравлики даёт немного
другие расходы в пределах собственного размерного допуска.

Матрица: 22 случая до 128 узлов, горизонт 120 с, наблюдения
0/30/60/120 с и restart в 37.5 с. Два независимых интегратора,
Radau и DOP853, решают непосредственно портовый энергетический residual,
без рабочей матричной экспоненты. Проверяются аналитическое охлаждение,
подход к равновесию, адиабатический рост энергии, реверсы, нулевые потоки
и реальный внутривременной перегрев с допустимым конечным состоянием.
Аудит заново выполняет все IVP, restart и проверки замороженных файлов.

Для матричной экспоненты не заявляется фиктивный измеренный порядок
временной сходимости: временная дискретизация этой аффинной ODE не вносится,
остаются округление, точность expm и консервативная проверка интервалов.
Внешняя гидравлика остаётся квазистационарной и неизменной во времени.
Общая компонентная DAE-сеть, timeline команд, переменные свойства,
фазовые переходы и естественная циркуляция остаются открытыми.
`validated=false`, `plant_referenced=false`.
