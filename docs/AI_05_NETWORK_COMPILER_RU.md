## Что исполняется

`core/network.py` компилирует JSON-топологию schema 1 и зарегистрированные
контракты в постоянную систему `F=M*ydot+K*y-b=0`. Каталог задаёт паспорт
и точную версию, локальные переменные, порты, единицы, уравнения,
размерные допуски и матрицы. Пользовательская топология не может подменить
порты или уравнения через JSON. Неподдержанное оборудование отклоняется.

Синтаксис wire-формата описан в `validation/network_topology_schema_v1.json`.
Проверки каталога, связности и уравнений выполняет сам компилятор;
JSON Schema не заменяет семантическую проверку модели.

Поддержаны контракты портов:

- Гидравлический: давление Pa, массовый поток kg/s, энергетический поток W;
  medium и energy convention обязательны. Энтальпийный и полный
  энтальпийный потоки не смешиваются автоматически.
- Тепловой: температура K и тепловая мощность W.
- Механический: скорость rad/s и момент N m.
- Управляющий: направленный output→input с точной единицей сигнала.

Физический поток положителен **внутрь владельца порта**. На соединении
усилия равны, потоки противоположны. `from/to` задаёт ориентир, а не
запрет обратного течения. Для гидравлики и механики проверены контракты
синтетических линейных блоков; моделей жидкости, насоса или вала эти тесты
не предоставляют. Преобразований единиц и сред по умолчанию нет.

Обязательные физические порты соединяются ровно один раз. Ветвление требует
явного компонента-узла. Управляющий output допускает fanout, input — одного
источника. Проверяются неизвестные порты, дубли, направление, единицы,
medium, энергетическая конвенция, паспорт и версия, обязательные порты,
изолированные острова, число уравнений и неизвестных. Self-link в v1
не поддержан. Для необязательного неподключённого порта компилятор не
изобретает граничное условие: система всё равно обязана быть замкнутой.

## Структура и согласованная инициализация

Сначала проверяется полное паросочетание двудольного графа ненулей M/K.
Совпадение числа уравнений и неизвестных само по себе недостаточно.
Затем проверяется численный ранг размерно масштабированной матрицы
инициализации. Для заданных дифференциальных состояний y_D решается:

```text
[K_A | M_D] [y_A; ydot_D] = b - K_D*y_D
```

Порог относительных сингулярных чисел — 1e-12 после объявленного
масштабирования строк и столбцов. Проверка не подменяется рангом M+K:
например, корректное ODE `xdot-x=0` нельзя отклонять из-за M+K=0.
Численно вырожденная либо плохо обусловленная инициализация отклоняется
до интегрирования. После решения проверяются исходные размерные невязки
каждой строки. Нет скрытого предварительного разгона.

Это реализация для постоянных линейных коэффициентов с однозначной
инициализацией. Здесь нет универсального нелинейного DAE backend или
обещания индексности произвольной модели. Пределы v1: 64 компонента,
128 соединений и 512 неизвестных; линейная алгебра пока плотная.

## Три тепловых компонента и шаг сети

Реализованы постоянная теплоёмкость C, проводимость UA и тройной узел
нулевого запаса. Паспорта имеют статус `implemented`:

```text
capacity:    C*Tdot = Q_in + P_external
conductor:   Q_left = UA*(T_left-T_right), Q_right = -Q_left
junction:    T_a=T_b=T_c, Q_a+Q_b+Q_c=0
```

C и UA положительны, внешняя мощность постоянна и неотрицательна,
абсолютные температуры положительны. Алгебраические переменные исключаются
из той же собранной невязки, полученное постоянное ODE продвигается
матричной экспонентой. Это не метод решения произвольных нелинейных сетей.

Чтение наблюдений и residual не меняют состояние. Шаг принимает новые
температуры и время только после проверки области, всех размерных невязок
и энергетического баланса. Ошибка наблюдения оставляет прежнее состояние.
SDK сохраняет последний согласованный префикс при отказе шага. Модель
проверяет `sum(C*T)-E0-sum(P)*t` с объявленным абсолютным допуском.
Работа насоса, границы жидкости и двухфазная энергия здесь не моделируются.

Checkpoint schema 1 связан с topology hash и assembly hash, включающим
матрицы, раскладку переменных, порты и допуски. Возвращаемые снимки и
матрицы отделены от внутренних данных. Подмена раскладки, модели, версии,
состояний или отрицательного времени отклоняется при восстановлении.
Это проверка согласованности, не криптографическая подпись состояния.

## Проверяемый запуск

```bash
python -m sdk.network_experiment scenarios/ai05_thermal_two_capacity.json \
  --output artifacts/NEW_NETWORK_RUN
# После установки wheel:
atomic-network-experiment scenarios/ai05_thermal_star.json \
  --output artifacts/NEW_STAR_RUN
```

Пакет включает input, assembly с единицами и размерными допусками,
JSON-траекторию всех портов и состояний, checkpoint, report, SHA256 manifest,
source fingerprint и версии NumPy/SciPy. Неверная схема отклоняется до
создания каталога; существующие результаты не перезаписываются.

## Численные свидетельства

До запуска зафиксирован `validation/ai05_linear_network_budget_v1.json`:
ошибка температуры <=1e-9 K, мощности <=1e-7 W, энергии <=1e-5 J.
Серия `artifacts/ai05_network_verification_v3` содержит пять расчётов 1000 с
и проверки restart до 1010 с. Для двух теплоёмкостей использовано независимое
аналитическое решение затухающей разности температур с постоянным нагревом;
для трёх ветвей — известная антисимметричная мода.

Все пять случаев приняты. Максимальная ошибка температуры <2,28e-13 K,
теплового потока <3,19e-12 W; ошибка restart <2,85e-13 K. Это проверка
фиксированных линейных задач, не экспериментальная валидация теплообмена.
Первая попытка v1 прервана сериализацией NumPy-bool в сводном отчёте;
она сохранена и не засчитана как завершённая серия. Бюджеты не менялись.
