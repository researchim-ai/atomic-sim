# Станционные кампании и длительные управляющие сессии

Новый пакет `atomic_model_station_campaign` исполняет независимые эпизоды
на локальном компьютере. Он связывает физическую станцию, шесть регуляторов,
измерения, неисправности, монитор и журнал решений. Один и тот же протокол
можно выполнить последовательно, параллельно и с проверкой restart.

## Почему потребовался новый слой

Прежний предел в 256 принятых шагов не позволял выполнить часовую
программу с частым управлением. Простое увеличение предела также заставляло
каждую пробную транзакцию копировать всё более длинную историю.

Теперь бюджет задаётся явно: `FaultSession(history_budget_steps=8192)`.
По умолчанию сохраняются 256 шагов; допустимый диапазон — 256…8192.
Согласованный предел проходит через сценарий, контроллер, физическую
сессию и проверку restart. Независимый физический горизонт по-прежнему
ограничен 7200 с. Увеличение журнала не расширяет область физических моделей.

Внутренний `Journal` хранит неизменяемый связный префикс. Копирование
пробной транзакции создаёт только новую головную запись. Добавление
команды не изменяет историю исходной сессии; выдаваемые строки также
являются отдельными копиями. Сериализация материализует обычный JSON-список,
без собственного бинарного формата и без pickle.

Это оптимизация копирования журнала, не всего шага: физическая модель,
очереди приборов и остальные изменяемые состояния продолжают копироваться.
Вывод всей истории и restart не становятся операциями постоянной стоимости.
Численные уравнения, частота проверки допустимости и балансовые допуски
не упрощались.

## Контракт эпизода

`Episode` фиксирует число тактов и их длительность, seed, ручное/автоматическое
начало, расписание команд, неисправности, точки checkpoint, период записи
и настройки решателя. Времена команд выражены целыми тактами. Дублирование
команд одной эпохи отклоняется: одновременные воздействия задаются одним
явным составным запросом и проходят существующий арбитраж.

Ограничены размер списка, число команд, длина эпизода, количество checkpoint
и частота записи. Редкие сохранённые кадры не означают редкого управления:
каждый такт исполняется, проверяется и входит в последовательный SHA-256
полного наблюдения/квитанции и физического вектора состояния.

Число реально принятых шагов и достигнутое физическое время сохраняются
отдельно от запрошенных. Выход из области или ошибочная команда дают
`rejected`, причину и проверку rollback; неисполненный хвост не объявляется
успехом. Ожидаемое отклонение ввода можно явно включить в тестовый эпизод;
оно всё равно не превращается в завершённый физический горизонт.

Сведения об отказе и физические checkpoint в файлах кампании привилегированы.
Для агента предназначен только результат `FaultSession.step()`, а не весь
протокол научного опыта.

## Независимые процессы и лимиты

Каждый эпизод исполняется в новом интерпретаторе Python с отдельной станцией,
памятью PI, RNG и кэшами. Каталог запуска находится вне рабочей копии.
Параллельный исполнитель запускает не более четырёх процессов; исходные
эпизоды канонизируются и копируются до отправки рабочим процессам.

`Limits` задаёт число процессов и пределы на каждый эпизод: wall time,
CPU time, виртуальную память и размер выходного файла. Жёсткие ограничения
CPU/адресного пространства/файла устанавливаются через POSIX `resource`
перед импортом научных библиотек. Wall timeout прекращает процесс и
помечает эпизод неуспешным. Такие эпизоды не исчезают из итогового отчёта.

Пределы памяти и CPU действуют на каждый процесс; суммарный бюджет зависит
от `workers`. В каждом процессе до импорта NumPy выставляются по одному
потоку OpenMP/OpenBLAS/MKL. CI, сеть и внешний runner не нужны. Нынешний
жёсткий исполнитель требует POSIX; платформенная реализация без этих
ограничений не подменяет его молча.

Научные результаты хранятся отдельно от PID, RSS, wall/CPU времени и путей
установки. Последовательный и параллельный запуск должны точно совпасть
по научным данным. Время работы измеряется, но ускорение не считается
гарантированным: оно зависит от числа доступных ядер и нагрузки машины.

```python
from atomic_model_station_campaign import Episode, Limits, run_campaign
from atomic_model_station_faults import Fault

report = run_campaign(
    "artifacts/my-station-campaign",  # новый каталог
    [
        Episode("reference", 4, checkpoint_ticks=(1,)),
        Episode("measurement", 4,
                faults=(Fault("hidden", "bias", "pressure", 2, value=150_000.0),),
                react_on_alarm=True, checkpoint_ticks=(1,)),
    ],
    limits=Limits(workers=2, wall_s=180, cpu_s=180, memory_mb=8192),
)
```

## Проверяемый restart

Anchor связывает определение эпизода, число принятых шагов, составной
checkpoint, цепочку траектории и накопленные максимумы балансовых невязок.
При продолжении проверяются источник, принадлежность протоколу и эпоха.
Затем воспроизводится префикс; в сохранённой точке должны точно совпасть
всё состояние, цепочка и аудиты. Только после этого исполняется хвост.

Это проверяемое продолжение с повтором префикса, как у прежних станционных
checkpoint. Быстрая загрузка произвольного скрытого состояния без replay
не реализована и не заявлена. Переназначения запасов, очистки PI, нового
нуля времени или обнуления накопленной энергии при restart нет.

## Полный каталог R1

`atomic_model_station_campaign.matrix.catalog()` содержит 12 семейств
из основного плана. Сохранены исходные горизонты: номинал 3600 с,
смена нагрузки 1800 с, сброс нагрузки 7200 с, останов 600 с, выбег главного
насоса 1800 с, три обеспечивающих отказа по 600 с, три нарушения измерений
по 1800 с и совпадающие события 120 с.

Для каждой семьи предусмотрены три настройки физического решателя и
повтор из checkpoint. Такт управления 5 с не изменяется при уточнении
физического интегратора. Для выбега главного насоса в исследовательском
сценарии явно запрошены SCRAM и останов турбины: это не утверждение,
что реализована заводская автоматическая защита по потере насоса.

```bash
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
export PYTHONPATH="$PWD/src"
# Одна полная семья со всеми тремя настройками и restart:
python -m atomic_model_station_campaign.matrix \
  --family nominal --output artifacts/r1-nominal-new --workers 2 --wall-s 7200
# Вся матрица; намеренно без сокращения её горизонтов:
python -m atomic_model_station_campaign.matrix \
  --output artifacts/r1-all-new --workers 2 --wall-s 7200
```

Эти команды запускают длительные физические расчёты. Наличие каталога,
работающий исполнитель и короткая квалификация не означают прохождения
этих режимов. Неудачи и частичные горизонты сохраняются. Полная матрица
требует всех семейств, совпадения restart, численной чувствительности,
согласованных событий и стационарности номинала. Даже численно принятая
матрица сама не присваивает R1 всей библиотеке: остаются физическая область
и остальные требования выпуска.

## Локальная квалификация исполнительного слоя

Программа `scripts.qualify_station_campaign` проверяет 257 настоящих шагов
по 10 мс, событие около прежней границы 256, restart через неё и штатный
restore конечной сессии. Этот опыт проверяет бюджет операций и сохранение
состояния, **а не часовую устойчивость**: его физическая длительность 2,57 с.

Два отдельных связанных эпизода по 4 с повторяются последовательно,
параллельно и с anchor. Сверяются полные научные результаты; отдельно
проверяется принудительный wall timeout без ложного завершения. Измерение
стоимости копирования журнала хранится отдельно от научной приёмки.

```bash
python -m scripts.qualify_station_campaign --output artifacts/campaign-source-new
python -m scripts.verify_local_library --output artifacts/campaign-library-new
python -m scripts.verify_station_primary_delivery --study campaign \
  --output artifacts/campaign-installed-new \
  --source-evidence artifacts/campaign-source-new \
  --library-evidence artifacts/campaign-library-new
```

Установленный повтор сравнивает все корневые научные JSON. Подкаталог
`execution/` содержит реальные измерения PID, времени и памяти; они не
должны побайтно совпадать между запусками. Исходники и драйверы связаны
подписями; старые checkpoint другой версии не принимаются.


## Историческая приёмка v52

[Машинный отчёт](benchmarks/station_campaign_v52.json) связывает исходную
программу, wheel, локальные проверки и установленный повтор вне проекта.
Все 11 научных JSON совпали побайтно. 1742 теста и восемь фаз пройдены.
Отдельно приложены измерения исполнения; их равенство не заявляется.

На этой машине последовательная пара заняла 43.388 с,
параллельная — 29.061 с. Это наблюдение одного запуска,
не гарантия ускорения. Приняты независимость процессов, одинаковая
численная траектория, продолжение, принудительное ограничение времени
и отказ вместо фиктивного завершения.

Базовые физические состояния без новых режимов точно совпали с wheel
v51 на 0, 1, 5 и 20 с. Это ограниченная регрессия, не повтор всей
прежней длительной приёмки.

Закрыт NPP-15.03 в объявленной исследовательской области. План — 44/76;
остаются 32 задачи. Все четыре пункта NPP-11, полная матрица и R1 открыты.
