Дата: 1 ноября 2026. Продолжение [газовых накопителей](AI_05_GAS_STORAGE_RU.md).
Модель `inertial-gas-storage-pair` 1.0.0 связывает две газовые подушки через
двунаправленную идеальную гидравлическую инерцию. AI-05 остаётся **partial,
3/8 задач приняты**. Это следующий блок AI-05.03/05/08, а не завершение

## Уравнения и энергетика

Состояние содержит перенос жидкости x, четыре приращения внутренних энергий,
внешнее тепло, две работы газовых границ и независимый расход m. Давления
вычисляются из газовых запасов. Алгебраический перенос прежней модели
обязательно отключён: иначе одна масса одновременно переносилась бы двумя
несовместимыми законами.

```text
M_left = M_left0-x; M_right = M_right0+x
xdot = m
I*mdot = p_left-p_right-R*m*abs(m)
K = I*m²/(2*rho)
D = R*abs(m)³/rho >= 0
Wdot_into_gas_i = s_i*p_i*m/rho
s_left=-1; s_right=+1
```

I>0 — коэффициент идеальной гидравлической инерции, 1/m;
R>=0 — конечное квадратичное сопротивление, Pa*s²/kg². Нулевое сопротивление
разрешено и даёт консервативные нелинейные колебания. Расход имеет оба знака
и может временно идти против перепада давления за счёт кинетического запаса.
Газовая работа и теплообмен между газом и жидкостью сохраняют прежние знаки.
Трение нагревает жидкость ниже по фактическому потоку, не по знаку перепада.

Здесь нельзя сокращать энергетические потоки на двух разных концах линии:
их разность заряжает кинетический запас. Для m>=0:

```text
F_left  = m*(cv*T_left + p_left/rho)
F_right = m*(cv*T_left + p_right/rho) + D
```

Для m<0:

```text
F_left  = m*(cv*T_right + p_left/rho) - D
F_right = m*(cv*T_right + p_right/rho)
```

В обоих направлениях:

```text
F_left-F_right = (p_left-p_right)*m/rho-D = dK/dt
Delta(sum(U_liquid+U_gas)+K) = Q_external
```

На каждом конце линии порт сосуда и порт линии имеют одно давление,
противоположные массовые и энергетические потоки. Внутри линии разность
энергетических потоков контролируется отдельно. Давление не превращается
в дополнительное тепло сверх трения, а работа границы не учитывается дважды.

## Область модели

Это идеальная сосредоточенная инерция с мгновенным донорным теплопереносом
и нулевой собственной теплоёмкостью линии. Геометрически разрешённая труба,
её постоянная масса/тепловой запас, время переноса, скорости на сечениях,
акустика и гидроудар не моделируются. I не выдаётся за полный паспорт трубы.
Плотность/cv жидкости и теплоёмкости газов постоянны; нет фазовых переходов,
кавитации, гравитации, растворения газа или динамики стенок.

Поддержаны только конечные R и двунаправленный поток. Идеальное запирание,
контакт обратного клапана и принудительное обнуление m запрещены этой
постановкой. Сборка с насосом и паровым компенсатором ещё не реализована.
Данные производителя, экспериментальная и объектная привязка не заявляются.

## Стационар, управление и восстановление

Начальные запасы и расход задаются явно, ускорение следует из уравнения
импульса. Давление и температуры восстанавливаются через начальный базис
и приращения. При равных p/T, m=0 и нулевом нагреве вся производная ровно
нулевая, а не просто малая. Проверен точный 100-секундный покой без событий.

Первая непринятая серия выявила ложный реверс порядка машинного округления:
пересчёт T=U/C давал микроскопический теплообмен в точном стационаре.
Восстановление через приращения устранило причину; фильтр событий не введён.
Сохранены исходник до исправления и регрессионный тест, падающий на нём.
Серия `ai05_inertial_storage_verification_v1` не считается принятой.

Команда R меняет ускорение и тепловыделение, сохраняя m, запасы и K.
История решателя перезапускается. Пересечения m=0 локализуются по dense
output. Ошибка команды/шага сохраняет последнюю согласованную сборку;
неудачный шаг откатывает весь внешний интервал и отбрасывает историю.
RHS и аналитический CSC-якобиан чистые. В точке m=0 при разных температурах
используется донорная односторонняя производная, не уникальная классическая.

Checkpoint schema 1 включает исходный расход/энергетический базис,
конфигурационный hash, активное R и историю команд/реверсов. Проверяются
версии, положительность запасов, общий баланс и хронология. Снимок проверяет
согласованность; это не подпись подлинности физической истории.

Максимумы принятой серии: перенос <1,74e-10 kg, расход <2,58e-10 kg/s,
давление <8,17e-6 Pa, температура <9,80e-9 K, работы <9,82e-8 J.
Баланс по абсолютным температурам <1,75e-7 J при бюджете 1e-5 J.
Это расхождения с объявленными численными эталонами, не экспериментальная точность.

## Проверки и запуск

Добавлены **29 тестов**: якобиан и нелинейное энергетическое тождество,
адиабатические инварианты газа, оба направления/противодавление, портовая
работа, стационар, переходы сопротивления, rollback и restart.

Бюджеты зафиксированы в `validation/ai05_inertial_storage_budget_v1.json`.
Серия v2 содержит 11 семейств и 24 основных пакета: base/tight Radau и два
BDF. Переходы — 20 с, покой — 100 с; каждый пакет дополнен restart на 1 с.
Restart сравнивается с независимым продолжением, включая расход, температуры,
давления и работы, а не только с энергетическим ledger.

Независимый DOP853 интегрирует температуры, а не production-приращения энергий.
Для двух нелинейных случаев без трения период дополнительно вычисляется
квадратурой из газового потенциала p*V^gamma и кинетического запаса; время
каждого реверса сравнивается с этой квадратурой. Отдельно проверен предел
малого сигнала с частотой sqrt(sum(gamma*p/V_gas)/(rho*I)). Эталоны не вызывают
production RHS/Jacobian. Аудит повторяет метрики и временное уточнение из
сохранённых пакетов. Численная точность относится к объявленным уравнениям,
а не к реальному реакторному оборудованию.

```bash
python -m sdk.storage_experiment scenarios/ai05_inertial_storage_damping.json \
  --output artifacts/NEW_INERTIAL_STORAGE_RUN
# После установки wheel:
atomic-inertial-storage-experiment scenarios/ai05_inertial_storage_damping.json \
  --output artifacts/NEW_INSTALLED_INERTIAL_STORAGE_RUN

python -m scripts.verify_inertial_storage --output artifacts/NEW_INERTIAL_STORAGE_VERIFICATION
python -m scripts.audit_inertial_storage artifacts/NEW_INERTIAL_STORAGE_VERIFICATION \
  --output validation/NEW_INERTIAL_STORAGE_AUDIT.json
```

Input, initialization, trajectory, checkpoint, report и manifest содержат
паспорт, source fingerprint, версии зависимостей и контрольные суммы.
При отказе сохраняется согласованный префикс. Deadline проверяется в RHS
и не является изоляцией ОС. Исторические допуски остаются привязаны к своим
frozen source; старый AI-04 gate не переназначается на новый runtime.
