# AI-05: команды по расписанию в нелинейном теплогидравлическом графе

Модуль `scripts.scheduled_thermal_graph` добавляет заранее заданную временную
последовательность команд поверх `NonlinearThermalGraph`. Пример запроса:
[смена направления потока](../examples/scheduled_thermal_graph.json).

## Контракт

Вход содержит `format: atomic-scheduled-thermal-graph`, `schema_version: 1`,
`model_input` и `timeline`. Исходная модель должна быть допустимой самостоятельно.
Метки времени конечны, неотрицательны и строго возрастают; одновременные
изменения задаются одним атомарным пакетом `changes`.

Разрешены `thermal_nodes`: тепловая мощность, температура окружения и входящего
потока; `hydraulic_nodes`: давление существующей границы давления либо расход
существующего узла инжекции; `hydraulic_edges`: напор источника давления.
Идентификаторы, роли границ, топология, материалы, объёмы и законы сопротивления
фиксированы. Неизвестные поля и недопустимые значения отклоняются.

Интегратор останавливается точно на каждой команде. Результат в момент команды
содержит состояние после её применения, включая команду на конечной отметке.
Команда в нуле применяется при создании модели. Соседние представимые отметки
не сливаются. Коррекция календарного округления допускается только в пределах
одной ULP и записывается в отчёт сегмента.

Пересборка использует фактические текущие температуры. Тепловые запасы и
интеграл энергии сохраняются без импульса; давления и расходы могут измениться
скачком вследствие квазистационарного приближения. Предложение адаптивного
шага сбрасывается после команды. Число событий, сегментов и суммарных попыток
интегратора ограничено бюджетом. Любой отказ откатывает весь вызов `advance`,
включая успешно рассчитанные перед отказом интервалы.

Checkpoint связывает исходники, бюджеты и весь вход, включая будущие команды;
восстановление проверяет курсор, квитанции и активную модель. Изменение будущего
расписания требует нового запуска. Квитанции проверяют согласованность метаданных;
они не являются подписанной историей исполнения.

## Запуск и проверка

```bash
python -m scripts.scheduled_thermal_graph examples/scheduled_thermal_graph.json --duration-s 60 --output artifacts/scheduled_first
python -m scripts.scheduled_thermal_graph examples/scheduled_thermal_graph.json --duration-s 60 --resume artifacts/scheduled_first/checkpoint.json --output artifacts/scheduled_resumed
python -m scripts.qualify_scheduled_graph --output artifacts/scheduled_qualification
python -m scripts.qualify_scheduled_graph --audit artifacts/scheduled_qualification --output artifacts/scheduled_audit.json
```

Каталоги результатов должны быть новыми. CLI сохраняет запрос, отчёт, checkpoint
и manifest; при отказе checkpoint не создаётся. Это инженерный companion в
репозитории, не новый entrypoint установленного SDK.

Матрица включает шесть сценариев до восьми узлов и 120 с: импульсы нагрева,
реверс потока, совместные команды подачи и температуры, одновременные границы,
команду на checkpoint/конце расчёта и пустое расписание. Проверяются три реально
измеренные сетки 0.5/0.25/0.125 с, независимые Radau/DOP853, энергетический баланс,
отсутствие пересечения разрывов и точное продолжение после restart в 37.5 с.
Три отрицательных сценария проверяют недопустимое давление, выход из области
после команды и отсутствие температуры новой подачи. Аудитор повторяет расчёты,
проверяя также исходники, бюджеты, полноту матрицы и содержимое пакетов.

## Границы применимости

Плотность и теплоёмкость постоянны; L(T) задан пользователем. Гидравлика
мгновенно равновесна: инерция, гидроудар и динамика приводов не моделируются.
Онлайн-добавление команд, общий DAE backend, EOS, фазовые переходы и проверка
по экспериментальным данным остаются отдельными задачами. Численные сравнения
не подтверждают пригодность для управления реальной установкой.
