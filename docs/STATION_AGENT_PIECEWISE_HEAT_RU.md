# Тепловой аудит с границей остановки стержня — v93

`atomic_model_station_piecewise_heat.step_piecewise_heat` расширяет проверку теплового интеграла первым поддержанным внутренним событием — достижением заданной позиции стержня. Обычный шаг станции по-прежнему формирует принимаемое состояние; повторные физические расчёты служат только для аудита.

## Граница события

Время остановки вычисляется из исходной позиции, допущенной команды и скорости существующего привода: расстояние до цели, делённое на скорость. Оно сверяется с записью `rod_arrived` обычного шага, её позицией и причиной. Пропущенные, повторные или несовпадающие события приводят к отказу без изменения среды.

В каждом из трёх повторных расчётов аналитическое время добавляется в сетку. Ни одна трапеция не пересекает эту границу. В данном законе привода положение и тепловые потоки непрерывны в момент остановки, меняется скорость движения. Поэтому один отсчёт на границе служит обоим соседним интервалам. Это свойство **не переносится** на клапаны, переключения питания или исчерпание резерва, где потоки могут иметь скачок.

Положение стержня на каждом отсчёте сверяется с аналитической траекторией с допуском 10⁻¹² долей хода. В повторном расчёте округление может привести к достижению целевой позиции без записи `rod_arrived`: локально пересчитанное время прихода оказывается немного позже, хотя положение уже округлилось к цели. Адаптер не дописывает журнал и не меняет положение. В отчёте отдельно сохраняются аналитическая граница, фактические положения и число записей журнала повторного расчёта. Журнал обычного шага остаётся обязательной независимой проверкой.

## Балансы и точность

Сохраняются критерии v92: тепловые и электрические балансы на каждом уровне, привязка к конечным запасам обычного шага, покомпонентное сравнение конечных состояний, сходимость интегралов на трёх удваивающихся сетках. Никакие допуски этих проверок не ослаблены.

При стандартном `rtol=10⁻⁷` проверенный короткий ход стержня отклоняется по согласованности конечного граничного энергетического счётчика. Сам по себе успешный общий баланс недостаточен для принятия. Проверочный протокол задаёт более строгую точность обычного решателя: `rtol=10⁻¹⁰`, `max_step_s=0,01`. Адаптер не меняет параметры среды скрыто. Отказ стандартной конфигурации сохраняется вместе с расчётными данными.

Для остановки почти на правой границе первоначальный протокол с 4/8/16 подшагами отказал по балансу самого грубого уровня. Окончательный протокол задаёт этому случаю 8/16/32; для остановок внутри шага остаётся 4/8/16. Первоначальный отказ сохранён.

Это совместное уточнение физического решения и квадратуры. Оно не является строгой оценкой полной ошибки или проверкой на измерениях установки.

## Проверки

Прошли **140 целевых тестов**, включая 11 новых. Проверены движение в обе стороны, остановка почти на правой границе, точное сохранение обычного перехода, повреждённые/пропущенные/повторные события, несогласованное конечное состояние и смена исходников. Установленный wheel вне репозитория повторил 11 новых тестов и шесть расчётных JSON. Полный набор тестов библиотеки в этом этапе не запускался.

Короткий протокол использует шаг 0,01 с: остановки около 0,0037 с при вводе и выводе стержня, а также около 0,01 с. Продолжение на следующий шаг после checkpoint совпало точно; повторного события остановки нет. Это не проверка длительного управления мощностью.

## Использование

```python
from atomic_model_station_piecewise_heat import step_piecewise_heat

transition, proof = step_piecewise_heat(
    env,
    {"operator": {"rod_target": target_position}},
    subdivisions=(4, 8, 16),
)
```

Конфигурация среды должна обеспечивать требуемую точность; недостаточная точность приводит к `HeatEventError` с диагностикой. Агент получает обычный результат перехода. Расширенные данные `proof` предназначены для оценщика.

Локальный протокол:

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:. .venv-layout/bin/python scripts/qualify_station_piecewise_heat.py --output artifacts/piecewise-heat-local
```

Выходная директория должна быть новой. CI не требуется.

## Границы результата

Поддержано только событие `rod_arrived`, совпадающее с аналитическим законом привода. Другие события после левой границы и запланированные неисправности отклоняются. Открыты скачки потоков при клапанных событиях, исчерпании резерва, длительные режимы и экспериментальная валидация. Станционная приёмка **48/76**; новые станционные пункты этим коротким протоколом не закрываются.

Предыдущий этап: [уточнение DHR v92](STATION_AGENT_REFINED_HEAT_RU.md). Компактные результаты: [v93](benchmarks/station_agent_piecewise_heat_v93.json).

Продолжение: [двусторонний аудит исчерпания резерва v94](STATION_AGENT_JUMP_HEAT_RU.md). Реализован отдельный диагностический интерфейс физической сессии; клапанные скачки и интеграция в шаг агента остаются открытыми.
