# Проверяемые условия train/dev/test станции — v116

Ранее станционный evaluator проверял уникальность сценариев и объявленных
семейств. Новая библиотека `atomic_model_station_holdouts` дополнительно
выводит проверяемые факторы непосредственно из `EnvConfig` и `Fault`.
Переименование сценария, семейства или отказа не создаёт новых физических
условий. Агент получает только прежние копии наблюдений и схемы действий.
Конфигурации, назначения split и результаты аудита остаются у evaluator.

## Что проверяется

`audit_splits(cases, assignment, axes=...)` принимает три непустые группы
train/dev/test и явный набор факторов. Для **каждого** выбранного фактора
значения разных групп должны быть непересекающимися. Перестановка входных
сценариев и факторов не меняет результат. Повторение значения внутри одной
группы разрешено. Проверяются все значения составного сценария, поэтому один
общий отказ нельзя спрятать среди нескольких новых.

Поддерживаются следующие факторы:

- `inventory_deadband_m`: фактическая настройка нейтральной полосы регулятора,
  только при включённом автоматическом управлении;
- `equilibrium_start`: выбранная процедура начального состояния;
- `film_model`: выбранная корреляция теплоотдачи;
- `fault_mechanism`: тройка domain/target/kind для каждого заданного отказа;
- `fault_magnitude`: domain/target/kind/value для моделей с используемой амплитудой;
- `fault_onset_s`: заданное начало отказа в моделируемых секундах.

Не любой набор факторов позволяет построить три группы. Например, у
`equilibrium_start` лишь два значения: трёхстороннее непересечение по этому
фактору будет отклонено. Это ограничение данных, а не повод подменять фактор
названиями семейств.

Seeds, точность решателя, длина эпизода и произвольные метки не принимаются
за физические параметры. Отказы после запрошенного горизонта, нулевой
bias/drift и единичный множитель cooling_loss не создают удержанных условий.
Числа 0 и −0, а также целое и вещественное представления амплитуд не
создают разных групп. Начало сравнивается в секундах, а не по номеру тика.

`evaluate_holdouts(...)` выполняет аудит **до** создания политик. Затем
запускает стандартный StationEnv evaluator и сохраняет каждую попытку,
причину ошибки, моделируемое время и wall time. Внешняя сводка различает
полный горизонт, ошибку выполнения и досрочное завершение. Завершившийся
раньше SCRAM не становится успешным полным эпизодом. Само прохождение
горизонта также не означает достижения управляющей цели.

## Воспроизведение

Из корня checkout с установленными зависимостями:

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:. \
  .venv-layout/bin/python -m pytest -q tests/test_station_holdouts.py
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:. \
  .venv-layout/bin/python -m scripts.qualify_station_holdouts \
  --output artifacts/my-station-holdouts
```

После установки wheel вне checkout второй запуск выполняется через
`python -I -m scripts.qualify_station_holdouts --output <новый каталог>`.
Выходной каталог должен быть новым. `episodes.json` сохраняет все результаты
и стоимость. `scientific.json` исключает только поля измеренного wall time;
сценарии, отказы, источники, все переходные метрики и причины завершения
сохраняются для полного сравнения. JSON запечатаны SHA-256 для проверки
целостности; это не электронная подпись независимого эксперта.

## Область результата

Матрица содержит три коротких конфигурации по пять тиков 0,01 с:
нейтральная полоса 0/0,0004/0,0008 м, bias давления
150/300/450 кПа и начало отказа 0,01/0,02/0,03 с. Проверяются удержание,
недопустимая команда и SCRAM — всего девять попыток. Три специально внесённых
утечки должны отклоняться. Это небольшой тест контракта оценки, а не
длительное исследование эффективности политик.

Непересечение точных значений не доказывает достаточную сложность OOD,
статистическую независимость или причинный вклад отдельного фактора.
Совместно меняющиеся факторы не изолируют эффекты амплитуды или времени.
`fault_onset_s` означает расписание внутри эпизода, а не независимые временные
отрезки истории эксплуатации. Аудит до запуска подтверждает конфигурации;
реальное выполнение подтверждают отдельно сохранённые эпизоды.

Другая геометрия/установка сейчас недоступна через этот API. Поэтому
объектный holdout отклоняется, а `unseen_objects_validated` и
`operating_history_holdout` остаются false. **NPP-14.04 остаётся открытым**;
длительные режимы, другие объекты и промышленная переносимость не заявляются.

исходников; его 3367 тестов не объявляются повторёнными для новой версии.
