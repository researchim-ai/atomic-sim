# Пять первых программ со станционной средой

[English](STATION_EXAMPLES_EN.md)

Пакет `atomic_model_station_examples` входит в wheel. Примеры запускаются из любой рабочей директории после установки библиотеки и её научных зависимостей. Файлы исходного репозитория для выполнения не нужны.

Каждый пример сохраняет команды и наблюдения, конечный checkpoint и отчёт с проверками. Директория результатов должна быть новой. Повторный запуск в ту же директорию отклоняется, чтобы не заменить результаты предыдущего опыта.

## Первый расчёт

```bash
python -m atomic_model_station_examples first --output results/first
```

Среда создаётся с фиксированным seed и выполняет один шаг 0,02 с. В `trajectory.json` находятся исходные показания приборов и результат шага: новые показания, награда, признаки завершения и служебные сведения. `report.json` подтверждает исполнение заявленного шага. Это первый расчёт из исходного состояния; достижение стационарного режима здесь не проверяется.

## Изменение нагрузки

```bash
python -m atomic_model_station_examples load --output results/load
```

Три шага задают нагрузку 100 → 99 → 100%. Проверяется выбор каждой команды штатным диспетчером управления. Режим ручной, кроме команд нагрузки остальные настройки удерживаются. Горизонт 0,06 с показывает порядок передачи команд и измерений; качество регулирования и установившийся отклик требуют более длинного сценария из [протокола изменения нагрузки](STATION_LOAD_QUALIFICATION_RU.md).

## Отказ оборудования

```bash
python -m atomic_model_station_examples fault --output results/fault
```

В t=0,02 с срабатывает заданная потеря привода питательного насоса. Оператор продолжает запрашивать включённый насос. Проверки подтверждают момент отказа, наличие активной неисправности и отличие запрошенного включения от эффективного выключения. Сохраняющаяся инерция потока рассчитывается физической моделью; команда не обнуляет состояние жидкости.

Истинное состояние отказа используется только проверяющей частью примера после исполнения. Оно хранится в привилегированном checkpoint и не добавляется в показания приборов.

## Простой агент

```bash
python -m atomic_model_station_examples agent --output results/agent
```

Агент получает показания приборов и публичную схему доступных действий. Цель мощности берётся из допустимого начального измерения. Исходная политика включает штатный контур регулирования мощности стержнями и передаёт ему эту цель; прочие контуры остаются в ручном режиме. Политика также возвращает диагностический флаг по качеству и согласованности двух измерений давления.

Политика не получает объект среды, checkpoint, внутренний физический вектор или расписание отказов. При отсутствии допустимого начального измерения пример отказывается от запуска. Этот короткий эпизод показывает интерфейс агента; успешность промышленной задачи управления им не оценивается.

## Воспроизведение

```bash
python -m atomic_model_station_examples replay --output results/replay
```

После первого шага сохраняется `midpoint.json`. Новая среда восстанавливается штатным `StationEnv.restore`, затем исполняет оставшиеся действия. Все переходы хвоста и конечный checkpoint должны совпасть с непрерывным расчётом точно. Восстановление воспроизводит историю команд и поэтому само требует расчётного времени.

## Результаты и дальнейшая работа

В каждом отчёте `example_completed` означает выполнение заявленного числа шагов. Поля `physical_scenario_qualified`, `industrial_qualification` и `task_success_evaluated` оставлены ложными: короткие программы предназначены для знакомства с API. Checkpoint содержит полное состояние исследовательской модели; при обучении агента используйте измерительные наблюдения среды.

В Python тот же запуск доступен через `run_example`:

```python
from atomic_model_station_examples import run_example

report = run_example("replay", "results/python-replay")
assert report["passed"]
```

Для собственных действий используйте [API станции](STATION_AGENT_API_RU.md), для контролируемого теплового аудита последовательности — [advance_hybrid_actions](STATION_HYBRID_ACTIONS_RU.md). Длительный номинал проверяется отдельной [командой повторной приёмки](STATION_NOMINAL_REQUALIFICATION_RU.md).
