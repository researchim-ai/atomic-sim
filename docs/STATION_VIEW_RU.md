# Просмотр станции: потоки, оборудование и измерения

[English](STATION_VIEW_EN.md). Страницы `/ru/station/` и `/en/station/` показывают кадры настоящего StationEnv. Ссылка доступна с главной страницы сайта. Просмотр работает локально и на статическом хостинге; Python рассчитывает траекторию заранее, браузер выбирает сохранённый кадр. Подключения к работающей станции, удалённого управления или физического решателя на JavaScript здесь нет.

## Начать

Из корня репозитория, после установки библиотеки:

```bash
python -m atomic_model_station_view --output artifacts/my-station-recording.json
cd web
npm run dev
```

Откройте `http://127.0.0.1:4173/ru/station/`. Встроенная запись содержит пять кадров: исходное состояние, отключение/возврат питательного насоса, запрос DHR и SCRAM. Между тактами 1 и 3 задана неисправность измерительного канала давления. Шаг — 0,05 с, всё окно — 0,20 с. Возникшая по измерению защита остаётся защёлкнутой после восстановления канала. Это короткий пример интерфейса, а не квалификация длительного аварийного режима.

Для своего расчёта:

```python
from atomic_model_station_env import EnvConfig, StationEnv
from atomic_model_station_view import capture, document, write

env = StationEnv(EnvConfig(max_steps=2, tick_s=0.05, automatic=False))
env.reset()
frames = [capture(env)]
env.step({"operator": {"feed_pump_on": False}})
frames.append(capture(env))
env.step({"operator": {"feed_pump_on": True}})
frames.append(capture(env))
write("station-recording.json", document(frames))
```

Нажмите «Открыть свой расчёт». Файл остаётся в браузере. Максимум — 8 МиБ и 1025 строго упорядоченных кадров. Повторная запись файла экспортером запрещена; выберите новое имя. Экспорт доступен также из wheel, без checkout. `capture` читает snapshot копии физического владельца, не меняет checkpoint и не продвигает измерительные приборы.

## Как читать экран

Схема объединяет реактор и парогенератор в один узел. Это агрегированная топология исследовательской конфигурации, а не заводская монтажная схема. Девять связей показывают пар, питание, конденсат, тепло конденсатора, внешний теплоотвод, генерацию, собственные нужды, обмен с сетью и тепло DHR. Массовые потоки хранятся в кг/с, мощности — в Вт; экран переводит мощности в МВт. Отрицательный обмен с сетью сохраняется как импорт, направление меняется. Толщина линий не кодирует мощность, а тепловые и массовые потоки не складываются между собой.

Панель оборудования различает запрос оператора, фактическое питание привода, скорость вращения и состояние обратного клапана. Отсутствие питания само по себе не означает мгновенного исчезновения вращения или расхода. Показывается результат backend; например, к концу первого такта встроенной записи питательный обратный клапан уже закрыт.

Измерения вынесены отдельно от физической истины: значения, единицы, quality-коды, возраст, время отсчёта и доставки. Недостоверный канал остаётся помеченным; график не подставляет вместо него точное физическое давление. Причины защит переведены с сохранением машинных кодов. Журнал сохраняет параметры событий. Состояние SCRAM физического backend и защёлка надзорной защиты показаны раздельно.

В балансах видны накопленные относительные невязки энергии, массы и бора, знаковая энергетическая невязка в Дж и мгновенный дефект в Вт. Их малость проверяет численный учёт, но не подтверждает экспериментально физические замыкания. Разница входящих и выходящих мощностей может изменять запас энергии; мгновенные мощности не выдаются за стационарный КПД.

## Формат и доверие

`station-view-file/v1` содержит точную UTF-8 строку документа `station-view/v1` и её SHA256. Оба загрузчика проверяют формат, единицы, часы, структуру оборудования и измерений; браузер проверяет SHA256 перед заменой записи. При ошибке предыдущая запись сохраняется. Контрольная сумма обнаруживает повреждение, но не удостоверяет автора: любой автор файла может вычислить новую сумму. SHA256 исходников станции и экспортера фиксирует происхождение заявленной записи; просмотр не присваивает старому файлу статус текущей физической валидации.

Экспорт явно помечен `privileged=true`. Он содержит физические значения, причины защит и события, поэтому не должен передаваться агенту вместо штатных измерительных наблюдений. Браузер отображает строки через текстовые DOM-операции; импортированный текст не исполняется как HTML. Загрузка не отправляет файл на сервер, storage и аналитика не используются. Для проверки Web Crypto нужен поддерживающий его браузер на localhost или HTTPS.

## Приёмка v112

Прошли 68 целевых Python-тестов и 12 тестов сайта. Из wheel вне checkout повторены все 17 новых Python-тестов; демонстрационный JSON совпал целиком. В браузере проверены оба языка, выбор последнего кадра, недопустимый импорт с сохранением записи и мобильная компоновка. Проверки экспорта дополнительно подтверждают неизменность последующего расчёта и остаточное вращение ГЦН после отключения питания.

[Квитанция v112](benchmarks/station_view_v112.json) принимает NPP-16.01 для просмотра локальных записей этой конфигурации. Длительные сценарии, физическая валидация, общий выпуск R1 и полноценная сетевая диспетчеризация этим пунктом не закрываются. Научный backend станции не менялся.
