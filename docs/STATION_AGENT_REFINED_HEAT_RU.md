# Уточнение теплового интеграла при командах DHR — v92

Пакет `atomic_model_station_refined_heat` добавляет `step_refined_heat`: атомарный шаг станции с независимыми повторными расчётами физического интервала на копиях. Его задача — проверять тепловой интеграл после переключения, когда двух отсчётов потоков недостаточно.

## Что делает адаптер

Сначала обычный `StationEnv.step` формирует кандидат и квитанцию реально допущенных команд. По ней восстанавливается состояние сразу после переключения, без скачка запасов и накопленных счётчиков. От этой общей точки выполняются три расчёта с удвоением числа подшагов. Регуляторы, измерительная система и агент внутри этих расчётов не вызываются; действуют уже выбранные команды.

В проверочных копиях обходится только ограничение фиксированного такта адаптера неисправностей. Это допустимо здесь исключительно для точного поддержанного типа физического backend и пустого списка неисправностей. Обычный шаг среды сохраняет свой такт и историю. Исходный код прежних пакетов v90/v91 не изменён.

Для каждого повторного расчёта проверяются тепловой и электрический балансы, запас энергии и конечное состояние. Дополнительно тепловой интеграл сверяется с **конечными счётчиками и запасами обычного шага**, а не только со счётчиками собственной повторной траектории. Различие конечных векторов состояния ограничено 10⁻⁶ при покомпонентном масштабе `max(abs(native_state), 1)` в исходных единицах. Это численный критерий согласованности, не допуск на физическую точность установки.

Между уровнями уточнения сравниваются интегралы всех четырёх потоков. Для результирующего потока, который может быть близок к нулю, масштабом служит также интеграл ядерного тепловыделения. Последняя разница должна быть не больше 2·10⁻⁶; она не должна увеличиваться относительно предыдущей сверх порога численного шума 10⁻⁸. Балансы каждого уровня должны проходить прежний допуск 10⁻⁶.

После всех проверок принимается **состояние обычного шага**, а не более подробной повторной траектории. Поэтому наблюдения, вознаграждение и checkpoint сохраняют поведение исходного симулятора. При любой ошибке исходная среда остаётся неизменной.

## Область результата

При первом включении DHR двухточечная квадратура давала относительную невязку около 1,28·10⁻⁵. На 4/8/16 подшагах невязка уменьшается примерно в четыре раза при каждом удвоении и достигает около 5,25·10⁻⁸. Переход от 8 к 16 подшагам меняет интеграл ядерного тепла примерно на 3,14·10⁻⁷ относительно его величины.

Первый общий протокол с 4/8/16 подшагами остановился при **выключении DHR**: уровень с четырьмя подшагами не прошёл баланс. Отказ сохранён; допуск не ослаблялся. Для последующих переключений используется явно заданный больший бюджет 8/16/32. Это не автоматический неограниченный подбор: API принимает ровно три удваивающихся числа от 2 до 64 и отказывает при недостаточной точности.

Расчёты с подшагами одновременно меняют квадратуру и частоту перезапуска физического решателя. Поэтому результат не является изолированной оценкой ошибки квадратуры, строгой верхней границей ошибки или экспериментальной валидацией DHR.

## Проверки

Прошли **129 целевых тестов**, включая 12 новых. Проверены атомарный отказ, ограничение вычислительного бюджета, неизвестные события внутри шага и на правой границе, изменение исходников и несовпадение конечных состояний. Установленный wheel вне репозитория повторил 12 новых тестов и шесть расчётных JSON. Полный набор тестов библиотеки на этом этапе не запускался.

Протокол длится 0,04 с при такте 0,01 с: включение DHR, выключение, совместное включение DHR и снижение коэффициента нагрузки до 0,95, затем шаг без новой команды. Продолжение после checkpoint совпало точно. Для первого включения выполнено дополнительное сравнение с уровнями 8/16/32. Это короткая численная проверка; она не подтверждает длительную работоспособность DHR.

## Использование

```python
from atomic_model_station_refined_heat import step_refined_heat

transition, proof = step_refined_heat(
    env,
    {"operator": {"dhr_requested": True}},
    subdivisions=(8, 16, 32),
)
```

`proof` содержит исходные отсчёты, все повторные траектории, их аудиты, сравнения интегралов и контрольные двухточечные оценки. Полные диагностические данные предназначены для оценщика, а не для наблюдений агента.

Локальный протокол:

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:. .venv-layout/bin/python scripts/qualify_station_refined_heat.py --output artifacts/refined-heat-local
```

Директория должна быть новой. CI не требуется.

## Что остаётся

Не поддержаны запланированные неисправности и физические события после левой границы интервала: для них требуется явное разделение по времени события и восстановление односторонних потоков. Открыты длительные режимы, стационарный КПД и сопоставление с измерениями. Этот этап не закрывает станционную промышленную приёмку: **48/76**, новых закрытых задач нет.

Предыдущий протокол: [v91](STATION_AGENT_EVENT_HEAT_RU.md). Результат поставки и расчётов: [v92](benchmarks/station_agent_refined_heat_v92.json).

Продолжение: [аналитическая граница остановки стержня v93](STATION_AGENT_PIECEWISE_HEAT_RU.md). Поддержано первое внутреннее событие с непрерывными потоками; произвольные скачки потоков остаются открытыми.
