# Два консервативных EOS-контура и стенка с теплоёмкостью

`CoupledEOSWall` — ограниченная совместная сборка двух периодических
Euler-контуров и одного или нескольких тепловых запасов стенки. Каждый контур
сохраняет собственные массу, импульс, внутреннюю, кинетическую и гравитационную
энергии. Через стенку передаётся только тепло. Гидравлического соединения
между контурами нет: это не модель ветвящегося узла.

```bash
python -m examples.coupled_eos_wall
python -m pytest -q tests/test_coupled_eos_wall.py tests/test_eos_wall_audit.py
python -m scripts.qualify_eos_wall run artifacts/ai05_eos_wall_campaign_v1.json
python -m scripts.qualify_eos_wall audit artifacts/ai05_eos_wall_campaign_v1.json
```

## Тепловые порты и балансы

Каждая стенка имеет постоянную теплоёмкость C, начальную температуру Tw0,
две ссылки на ячейки разных контуров, две постоянные положительные UA,
неотрицательную UA среды и положительную температуру среды Ta.

```text
Q_i = UA_i * (Tw - Tfluid_i)
dEwall/dt = UAambient*(Ta-Tw) - Q_1 - Q_2
Tw = Tw0 + deltaEwall/C
```

Тот же Q_i входит со знаком плюс в полную энергию жидкости. Разные стенки
могут подключаться к одной ячейке: их потоки и тепловые нагрузки суммируются.
Сетки контуров могут иметь разное число ячеек. Это ссылки на состояния
существующего ограниченного компонента, а не открытый реестр оборудования.

Локальный журнал каждого контура считает тепло от стенки внешним для этого
контура. Общий журнал вычитает этот внутренний перенос из внешнего нагрева
и добавляет только обмен стенки со средой. Поэтому внутреннее тепло не
учитывается повторно в первом законе сборки.

Энтропия стенки меняется на C*ln(Tw/Tw0). Производство на соединении равно
Q_i*(1/Tfluid_i-1/Tw); при положительном UA оно неотрицательно. Вклад обмена
со средой вычисляется аналогично. Общий энтропийный журнал исключает
внутренний перенос энтропии как внешний источник, но включает его производство.
Это не доказательство энтропийной устойчивости гидродинамической схемы:
прежний численный контроль допуска каждого Euler-контура сохраняется.

## Интегрирование и отказ

Все рабочие состояния интегрируются совместно SSPRK3, без раздельного
последовательного обновления жидкостей и стенки. Ограничение шага использует
акустический CFL обоих контуров и тепловую нагрузку каждой ячейки/стенки.
Тепловая нагрузка жидкости делится на текущую m*cv, стенки — на C;
для нескольких стенок учитывается сумма UA. Проверка повторяется на стадиях.
Это явный ограниченный метод, а не implicit/IMEX или all-speed solver.

Входы и бюджет фиксируются хешами; advance выполняется на копии, ошибка
стадии/баланса не устанавливает промежуточных состояний. Чистый residual,
JSON-checkpoint и точный restart проверяются в одной среде. SHA не
удостоверяет автора или подлинность истории. Изменение нагревателей онлайн,
состояния внешнего регулятора и гибридные события в сборку пока не включены.

## Численная проверка и границы

Для пространственно равномерной задачи три температуры сравниваются с
матричной экспонентой системы трёх тепловых запасов. Её постоянные ёмкости
жидкости равны m*cv; такая задача не требует изменения массы или движения.
Независимая пространственная модель использует абсолютные m/P/E и собственное
соединение тепловых портов поверх независимого Euler RHS. DOP853/Radau
сравниваются с SSPRK3 на семи программах, трёх ограничениях шага и пяти
наблюдениях до 0.2 s; restart после 0.1 s проверяется отдельно. Это короткая
численная кампания, а не длительная эксплуатационная валидация.

Синтетическая stiffened-caloric EOS не является калибровкой воды/IAPWS.
Нет фазовых переходов, давления/расхода в резервуарных границах, движущихся
граней, общей гидравлической сборки, осевой теплопроводности стенки, расчёта
геометрического UA, напряжений, загрязнения или автоматического закона
потерь давления теплообменника. Область стенки ограничена пересечением
заявленных температурных диапазонов жидкостей. Полный репозиторный прогон этого нового семейства пока не выполнен.
Результат переносимой проверки — в отдельном
`validation/ai05_eos_wall_portable_replay_v1.json`: офлайн-wheel, архивный
аудит, тесты и пример вне checkout с унаследованными numpy/scipy/pytest.
Это не герметичная среда и не повтор всей кампании.
AI-05.03/07/08 остаются открыты; validated=false, plant_referenced=false.

Ограничение устойчивости шага не гарантирует точность энтропийного баланса
при предельно быстром теплообмене. Такой расчёт может быть отклонён по
балансу; требуется явно уменьшить max_step_s. Автоматический подбор по
оценке временной ошибки в этом семействе не реализован.
