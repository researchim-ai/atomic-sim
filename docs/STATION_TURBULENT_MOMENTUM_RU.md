# Турбулентный импульс в гладкой трубе: сравнение с независимым DNS

Исследовательский модуль `atomic_model_station_turbulence` рассчитывает средний
профиль скорости и трение в полностью развитом вынужденном течении гладкой
круглой трубы. В него включены четыре исходных профиля независимого DNS.
Компонент не подключён к станционной плёнке: теплоотдача, плавучесть,
переход к ламинарному течению и фактическая геометрия оборудования требуют
отдельного обоснования.

## Источники и право на распространение

Формула вихревой вязкости Cess взята из приложения B, уравнение B2 статьи
[Marensi, He, Willis, JFM 919 A17 (2021)](https://doi.org/10.1017/jfm.2021.371).
Формула, нормировки и коэффициенты сверены с оригинальной страницей 27.
Использованы опубликованные `kappa=0.42`, `Aplus=27`; коэффициенты не
подгонялись к данным сравнения.

Независимые профили: [Schlatter, Turbulent pipe flow up to Re_tau = 1000,
Zenodo, v1 (2022)](https://doi.org/10.5281/zenodo.7352880), данные статьи
[El Khoury, Schlatter, Noorani, Fischer, Brethouwer, Johansson,
Flow, Turbulence and Combustion 91, 475–495 (2013)](https://doi.org/10.1007/s10494-013-9482-8).
Это DNS спектрально-элементного кода Nek5000 в трубе длиной 25R,
**численный эталон, а не измерения установки**.

Лицензия данных — [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).
Оригинальные `180_Re_1.dat`, `360_Re_1.dat`, `550_Re_1.dat`, `1000_Re_1.dat`
из архива `PIPE.tar.gz` включены побайтно, без изменения значений.
Опубликованная MD5 архива `7ac89735122270da030a135c228b2ed9` проверена;
для отдельных опубликованных файлов также проверены их MD5.
Файл 180_Re_1 находится внутри архива и не имеет отдельной записи в списке
файлов Zenodo. Его происхождение проверяется через контрольную сумму архива.
SHA-256 каждого исходного профиля, MD5, ссылки, нормировки и отдельная лицензия
данных записаны в `src/atomic_model_station_turbulence/data/sources.json`.
Эта лицензия относится к данным, а не меняет лицензию программного кода.

## Уравнения и единицы

`r` — радиус, делённый на R; в DNS первая колонка содержит **1-r**, а не r.
`Re_tau=u_tau R/nu`, `Re_b=2 Ub R/nu`. В качестве Re_tau используются точные
значения заголовков, а не округлённые числа в именах файлов.
`u_plus=u/u_tau`, `nu_t` — отношение вихревой вязкости к молекулярной.
Полная относительная вязкость равна `1+nu_t`.

```text
X = [(kappa Re_tau/3)(1-r²)(1+2r²)(1-exp(-(1-r)Re_tau/Aplus))]²
nu_t = X / [2(sqrt(1+X)+1)]
u_plus(r) = integral_r^1 [Re_tau s / (1+nu_t(s))] ds
Ub_plus = integral_0^1 [Re_tau r³ / (1+nu_t(r))] dr
Re_b = 2 Re_tau Ub_plus
f_Darcy = 8/Ub_plus² = 32 Re_tau²/Re_b²
```

Рационализированный квадратный корень и `expm1` сохраняют вязкий предел у
стенки без вычитания близких чисел. На стенке `nu_t=0`, `u_plus=0`;
производная скорости стремится к `-Re_tau`. Коэффициент Дарси не смешивается
с коэффициентом Фаннинга: они отличаются в четыре раза.

Основное сравнение фиксирует **Re_b из DNS**. Скалярный поиск определяет
Re_tau и трение модели; скорость после расчёта не нормируется на данные DNS.
При сравнении `u/Ub` применяется собственное Ub модели, согласованное с
заданным расходом. Дополнительное сравнение при заданном Re_tau показывает
профиль в стеночных единицах, но не заменяет проверку ошибки трения.

## Независимые численные проверки

Адаптивная квадратура интегрирует аналитический баланс полного напряжения.
Отдельный конечно-объёмный расчёт решает
`-div[(1+nu_t) grad(u_plus)] = 2 Re_tau` на кольцевых ячейках.
Поток на оси равен нулю, условие прилипания задаётся в линейной системе.
Расход после решения не исправляется скрытым масштабированием.

Сетки 256/512/1024 сравниваются с квадратурой по максимальной ошибке профиля
и среднему расходу. Контролируются линейная невязка, напряжение на стенке
и равенство работы давления диссипации. Обе последние величины записаны
в безразмерной радиальной мере `r dr`, без множителя `2 pi`; это не ватты.
Вязкость положительна, средняя скорость и диссипация положительны.
Это баланс **средней** механической энергии: эффективная диссипация
с вихревой вязкостью включает моделируемый отток энергии в турбулентность.
Отдельное уравнение турбулентной энергии здесь не решается; положительность
этой величины не заменяет тепловой или энтропийный баланс всей установки.

Границы API `100<=Re_tau<=2000`, сетка 16–4096 — вычислительные ограничения
исследования. Они не означают физическую квалификацию всего этого диапазона.
Неконечные числа, неверные координаты, недопустимые сетки и расход вне
доступной скобки отклоняются. Исходный DNS проходит проверку хеша, столбцов,
монотонности координат, нормировки скорости и согласованности Re по диаметру.
Исходные погрешности DNS на стенке порядка 1e-13 сохраняются.

## Критерии и обнаруженное ограничение

До первого сравнения заданы: относительная ошибка трения <5%, взвешенная
по площади относительная L2-ошибка профиля <5%, максимальная ошибка профиля
относительно пика DNS <8%. Для численной проверки: порядок >1.8,
максимальная ошибка профиля <0.04 стеночной единицы, ошибка расхода <0.1%,
относительная невязка работы/диссипации <1e-9.
Первоначальная сетка 128/256/512 не разрешала пристеночную область старшего
Re_tau с устойчивым вторым порядком. Использованы более мелкие сетки;
критерии, данные и коэффициенты модели оставлены прежними.

При Re_b=5300 ошибка трения **6.4563%**: допуск 5% не выполнен.
При Re_b=11700, 19000 и 37700 ошибки соответственно **0.3652%, 0.4039%,
0.0740%**. Профили скорости проходят выбранные критерии во всех четырёх
точках; это не устраняет отказ по трению в младшей точке.
Три принятые дискретные точки не доказывают точность между ними,
при других свойствах среды или при нагреве.

В отчёте `passed` относится к завершённому воспроизводимому расчёту и
численной проверке. Полный DNS-критерий хранится отдельно:
`dns_momentum_comparison_passed=false`, `dns_refused_cases=[180]`.
Модель не становится DNS-решателем. Экспериментальная неопределённость
этим набором не квалифицирована.

## Воспроизведение без сети и CI

Все исходные профили включены в установленный пакет; сеть при расчёте не нужна.
Из корня проекта, для свежих выходных директорий:

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH="$PWD/src:$PWD" \
  .venv-layout/bin/python -m scripts.qualify_station_turbulence \
  --output artifacts/station-turbulence-local

OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH="$PWD/src:$PWD" \
  .venv-layout/bin/python -m scripts.verify_local_library \
  --output artifacts/local-station-turbulence-local

OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH="$PWD/src:$PWD" \
  .venv-layout/bin/python -m scripts.verify_station_turbulence_delivery \
  --output artifacts/installed-station-turbulence-local \
  --source-evidence artifacts/station-turbulence-local \
  --library-evidence artifacts/local-station-turbulence-local
```

Научные результаты: `protocol.json`, `spatial.json`, `dns.json`,
`friction.json`, `report.json`. Повтор из wheel выполняется свежим Python
с `-I` вне checkout, без сети; все пять JSON должны совпасть побайтно.
Профиль библиотеки дополнительно сверяет байты всех исходных ресурсов,
включая исходные DAT. Отдельный отпечаток компонента включает все его DAT/JSON.

## Что остаётся для станции

Сохранены исходники и отпечатки станционного backend v63, смешанной
конвекции v64 и переходной трубы v65. Текущие результаты не продолжают
станционный выбег после 1475 с и не закрывают NPP-11.03/04 или R1.
Счётчик основных задач остаётся **48/76, открыто 28**.

Следующий физический блок — совместимые данные восходящего нагрева с
тепловым условием и Pr фактической станции, закон турбулентного переноса
тепла и совместное действие плавучести на импульс. Требуются независимые
критерии ошибки, область применимости и только затем интеграция в станцию
с повтором длительных сценариев. Около низкорасходного состояния станции
Re_b близок к младшей DNS-точке, где уже выявлен отказ Cess по трению;
сам по себе новый профиль не обосновывает снятие ограничения Ri.

Для следующего теплового benchmark найден конкретный первичный источник:
[Chu, Marensi, Willis (2025), Mathematics 13(2), 293](https://doi.org/10.3390/math13020293).
В нём рассмотрены Re=5300, Pr=0,7, постоянная разность температур и
постоянный тепловой поток. Авторы указывают доступность кода через Openpipeflow;
страница статьи не предлагает отдельного табличного набора профилей.
Это кандидат на отдельный воспроизводимый тепловой replay, а не уже
выполненная квалификация или доказательство применимости к станции.
[Официальная страница нагреваемой трубы](https://www.openpipeflow.org/index.php?title=Download_-_Heated_pipe)
предупреждает об исправлении рисунка 3 в связанном PDF. Для дальнейшего
сравнения следует брать исправленную версию. Архив кода и исправленный PDF
сохранены для исследования; внешний код в этом этапе не собирался и не запускался.
