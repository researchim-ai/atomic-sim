# Совместные календарные, температурные и внешние переключения сети

Версия блока 1.64.0, 5 ноября 2026. Семейство `HybridThermalGraph` объединяет три вида событий над существующей сетью с фиксированными свойствами жидкости и reduced Radau. Это развитие AI-05.03/08; новая EOS-сеть, полная переменная плотность и двухфазность этим блоком не реализованы.

## Реализованные части

1. **Совместная диспетчеризация.** Календарь, повторные направленные температурные переходы и внешняя команда используют один физический clock и один транзакционный вызов. Интегрирование разрезается по известным календарным границам и времени включения защит. Событие на конечной границе вызова обрабатывается до возврата результата.
2. **Явные приоритеты.** Чем больше целое `priority`, тем выше приоритет. Календарные события одного точного времени и доступные на границе команды рассматриваются совместно. Одинаковый температурный предикат локализуется как один физический корень с несколькими конкурирующими действиями. Равенство двух наивысших приоритетов отклоняет всю операцию. Проигравшие записываются в `contenders`; календарные события при этом считаются потреблёнными.
3. **Задержка включения.** `arm_delay_s` отсчитывается от входа в режим. До включения соответствующая защита не наблюдает пересечения. На границе включения проверяется уровень: если условие уже выполнено, переход происходит тогда и помечается `guard_level`, без выдуманного времени пересечения. Это явная семантика inhibition/level-at-arm, а не запись подавленного корня и не прежняя минимальная длительность пребывания. После включения используются сертифицируемые направленные температурные корни старого event-backend.
4. **Согласованное переключение.** Новые давления и расходы проектируются совместимо с выбранными командами. Температурные приращения, температуры и интеграл внешней энергии сохраняются точно. Сбросы физического состояния, изменение запасов/топологии или теплоёмкостей через mode-команду запрещены. Сохранённые левые/правые состояния дают диагностику изменения алгебраики отдельно от физических запасов.
5. **Совместный rollback и restart.** Online `step` принимает ожидаемую revision и явный JSON `controller_state`. Управляющее состояние, физическое состояние, календарный cursor и журнал событий фиксируются вместе. Поздний отказ корня, проекции, источников, ресурсов или публикации возвращаемого checkpoint сохраняет исходный runtime. Восстановление заново исполняет все принятые вызовы и сравнивает весь checkpoint, включая native-состояние, историю и контроллер.

Режимы задают одинаковую полную маску управляемых полей; значения являются абсолютными по отношению к исходному вводу. Новый режим всегда переинициализируется в исходной дифференциальной рамке. Каждое переключение, включая переход в тот же режим, заново запускает время включения его защит.

## Интерфейс

```python
from scripts.hybrid_thermal_graph import HybridThermalGraph

model = HybridThermalGraph(request, max_macro_step_s=1.0)
result = model.advance(2.0)
result = model.step(
    "hold", 3.0,
    expected_revision=result["revision"],
    controller_state={"integral": 0.5, "tick": 1},
    priority=30,
)
checkpoint = model.checkpoint()
```

Чтение и операции одного экземпляра сериализованы. Каждая успешная операция, включая обычный advance, увеличивает revision. Устаревший revision отказывает до изменения состояния. Состояние контроллера фиксирует попытку команды, даже если её действие проиграло более приоритетному событию; результат выбора виден в журнале. Python-драйверы сохраняют ресурсный контекст существующего graph-backend: запускать из корня проекта либо установленного дистрибутива. CLI ниже обеспечивает отдельный процесс в нужном контексте, не меняя cwd вызывающего процесса.

Пример с сохранением на 17 s, продолжением до 40 s и сравнением с непрерывным прогоном:

```bash
python -m examples.hybrid_thermal_workflow --output artifacts/my-hybrid-workflow
```

Установленный CLI работает из произвольного каталога; относительные пути пользователя привязаны к его исходному cwd:

```bash
atomic-hybrid-graph run examples/hybrid_thermal_program.json --output result
atomic-hybrid-graph replay result
atomic-hybrid-graph continue result --program next-program.json --output continued
```

Вход CLI содержит `schema_version`, `model`, `max_macro_step_s`, `program`, `initial_checkpoint`. Программа — список `{duration_s, command}`; `command` равен null либо объекту `{mode, expected_revision, controller_state, priority}`. Готовый полный ввод сохранён в `examples/hybrid_thermal_program.json`; частичный ввод создаётся как `partial/input.json` в workflow выше. Сохранённый результат включает вход, наблюдения, конечный checkpoint и manifest. Replay заново считает весь сохранённый workflow; хеш-проверка сама по себе не заменяет численный replay. Три файла результата ограничены по составу, размеру и отсутствию симлинков. Произвольные функции и код из JSON не загружаются.

## Проверки

Восемь 40-секундных программ: аналитический idle-relay, календарь с повторными защитами, календарные приоритеты, отложенное включение, одинаковые предикаты с приоритетом, явное состояние online-контроллера, смена направления потока и разветвлённая сеть.

Каждая выполнена на трёх фактически различных максимальных шагах: 24 траектории, 120 наблюдений. Два отдельных эталона Radau/DOP853 дают 16 IVP. Reference самостоятельно диспетчеризует события через SciPy events и использует отдельные гидравлические и тепловые уравнения прежнего reference-семейства. Это независимый алгоритмический расчёт, но общая научная библиотека SciPy; экспериментальная независимость не заявляется.

Сравниваются температуры, давления, расходы, внешний интеграл энергии, последовательность и время событий. Сохраняется полный campaign, а audit повторяет вычисления. Для каждой сетки checkpoint на 17 s восстанавливается полным replay; дальнейшие результаты должны совпасть точно в том же окружении. Аналитический idle-контроль проверяет периоды и температуру без IVP-эталона.

Критерии до квалификации: 1e-6 K, 1e-5 Pa, 1e-7 kg/s, 0.1 J по внешнему интегралу, 1e-5 s по событиям и 1e-4 J по глобальному балансу. Они зафиксированы в `scripts/qualify_hybrid_graph.py`, а ограничения runtime — в `validation/ai05_hybrid_graph_budget_v1.json`.

```bash
python -m scripts.qualify_hybrid_graph run artifacts/my-hybrid-campaign
python -m scripts.qualify_hybrid_graph audit artifacts/my-hybrid-campaign
```

## Границы и оставшаяся работа

Разные предикаты с неразличимыми корневыми интервалами, корень, перекрывающий известную календарную/arming-границу, и неразрешимый endpoint contact отклоняются. Времена не сливаются по epsilon и не упорядочиваются произвольно. Произвольные guard-функции, физические state resets, потоковый неограниченный журнал и произвольная регистрация оборудования остаются открытыми.

До 16 режимов, 32 переходов, 128 календарных событий, 128 переключений за вызов и 4096 записей истории. Принятых вызовов не более 256; checkpoint до 8 MiB, JSON контроллера до 32 KiB. Цикл переходов нулевого времени заканчивается отказом с полным откатом. Replay ограничен журналом принятых вызовов; его стоимость растёт с историей. Файловая программа ограничена 32 новыми вызовами и объёмом отчёта; отдельное продолжение не обходит общий предел native-журнала.

Сеть остаётся однофазной, с алгебраическими расходами и фиксированными rho/cp. Здесь нет инерции потока, акустики, фазовых переходов, физических ударов клапана или естественной циркуляции ВВЭР. Учтённые события не делают её универсальной моделью установки. Статусы `validated=false`, `plant_referenced=false` сохраняются; AI-05.03/08 остаются частичными.
