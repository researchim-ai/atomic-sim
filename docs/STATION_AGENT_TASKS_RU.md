# Проверяемые задания для станционных агентов — v88

Пакет `atomic_model_station_tasks` добавляет исследовательские контракты задач
поверх существующих `StationEnv` и разделений v87. У каждой задачи есть явная
цель, конечный горизонт и отдельная проверка успеха. Завершённый расчёт может
не выполнить задачу; отказ агента или модели остаётся в общем знаменателе.

## Поддерживаемые задания

**Отслеживание мощности делений (`tracking`).** Агент получает объявленное
задание в ваттах. Оценщик считает интеграл нормированной абсолютной ошибки,
время вне относительной полосы и доступность измерений. Успех требует всего
заданного горизонта, пригодных измерений на каждом учитываемом интервале,
отсутствия trip и отсутствия выходов из полосы. Это пока не задача регулирования
электрической мощности, выдаваемой в сеть.

**Возврат в полосу после отклонения (`recovery`).** Помимо полного горизонта,
пригодных измерений и отсутствия trip необходимо сначала наблюдать отклонение,
а затем удержаться в полосе не менее объявленного dwell_s к концу эпизода.
Если отклонения не было, успех не засчитывается. Повторный выход из полосы или
пропуск измерения сбрасывает накопленное время устойчивости и прежнюю отметку
восстановления. Этот контракт оценивает измеренный возврат, но не доказывает,
что его вызвали действия агента, и не означает квалификации остаточного
теплоотвода после останова.

**Обнаружение неисправности измерений давления (`diagnosis`).** Агент выдаёт
булеву тревогу отдельно от команды станции. Истинные интервалы строятся
оценщиком из конфигурации неисправностей датчиков `pressure` и
`pressure_reference`; имена неисправностей и интервалы не передаются политике.
Попытка передать несовпадающие метки отклоняется. Измеряются длительности
ложных тревог и пропусков, а также задержка первого обнаружения каждого
интервала. Необнаруженный интервал имеет задержку `None`, а не ноль.
Строгий успех выбранного контракта требует полного горизонта без ложных
тревог и пропусков. Это не локализация произвольной неисправности оборудования.

Тревога относится к наблюдению **до** соответствующего шага. Временные границы
истинных интервалов должны совпадать с шагами принятия решений. Задержки
измерений не вычитаются скрыто из метрики обнаружения.

## Исходные политики

`observation_policy` не посылает управляющих команд и поднимает тревогу при
недоступности одного из двух каналов давления или превышении объявленного
порога их расхождения. Такое расхождение само по себе не определяет, какой
именно датчик неисправен. Общие согласованные ошибки двух каналов эта исходная
политика может не обнаружить; оценщик сохраняет пропуски.

`tracking_policy` дополнительно включает существующий автоматический контур
стержней и передаёт ему объявленное задание мощности. Она не назначает
фактическую мощность напрямую и не обходит ограничения или защиты модели.

Обе политики получают только копии операторского наблюдения, публичной схемы
действий и спецификации цели. Для каждого эпизода вызывается фабрика политики.
Истинная конфигурация неисправностей остаётся в привилегированном отчёте
оценщика. Как и в v87, Python callback не является изолированной песочницей.

## Пример исполнения

```python
from atomic_model_station_env import EnvConfig, StationEnv
from atomic_model_station_control.policy import valid_reading
from atomic_model_station_tasks import Task, run_task, tracking_policy

config = EnvConfig(max_steps=3, tick_s=0.01, automatic=False)
initial, _ = StationEnv(config).reset()
target = valid_reading(initial, "power", "fission_power_w")
if target is None:
    raise ValueError("Initial measured reference unavailable")
task = Task("tracking", horizon_s=0.03, target_w=target)
report = run_task(task, config, lambda: tracking_policy, policy_id="tracking/v1")
print(report["metrics"]["task_success"])
```

Здесь цель — удержать публично измеренный начальный уровень. Выбирать цель
следует до оценки политики. Значение `Task.target_w` по умолчанию 3,15 ГВт
не объявляется автоматически достигнутым номиналом текущей конфигурации.

`evaluate_tasks` принимает случаи `EvaluationCase`, назначение train/dev/test,
полную карту задач и фабрику политики. Она проверяет карту и горизонты всех
случаев до начала выбранной выборки. Итог разделяет число завершённых расчётов,
ошибок исполнения и успешных задач. Доля успешных задач делится на число всех
попыток, включая неуспешные. Прежний `atomic_model_station_evaluation` не изменён.

## Приёмка и сохранённые отрицательные результаты

Первый короткий прогон с фиксированной целью 3,15 ГВт не прошёл отслеживание
и восстановление: исходное измерение составляло около 3,023 ГВт. Ошибка около
4% превышала исходную полосу 2%. Этот результат сохранён; допуск не расширялся.

Отдельный проверочный набор использует удержание измеренного начального уровня
с той же полосой. В нём три коротких задания и три отрицательных контроля:
фиксированная цель 3,15 ГВт на том же коротком горизонте, постоянная тревога
и недопустимая команда приводу. Постоянная тревога завершает расчёт, но не
проходит задачу из-за ложного срабатывания до начала неисправности.

В проверке возврата временное искажение измерения мощности снимается
расписанием самой среды. Пассивная политика может пройти её; это проверка
контракта оценивания, а не доказательство способности агента ремонтировать
установку. Горизонты 0,03–0,05 с не являются промышленными испытаниями.

Метрики полосы и интегралы вычисляются по дискретным измерениям, с прямоугольной
квадратурой по правому концу интервала. Они не доказывают непрерывное пребывание
физического состояния в полосе между измерениями. Полный физический trace
внутри решателя не подменяется операторскими показаниями.

## Что ещё нужно для NPP-14.03/04

Экономичность намеренно не заменена штрафом за ошибку мощности. Для неё нужны
согласованные измерители электрической выработки, энергозатрат собственных
нужд и расхода тепла, а также проверенные балансы и единицы измерения.
Неподдерживаемый тип задачи `economy` отклоняется.

Остаются полноценные задания изменения электрической нагрузки, проверяемое
управляемое восстановление, расширенная диагностика и длительные сценарии,
принятые на станционном backend. Необходимы независимые семейства объектов
и параметров, содержательные исходные политики и достаточно длинные тестовые
горизонты. Текущий набор проверяет программный контракт; NPP-14.03/04 и полная
R1 остаются открытыми. Станционная приёмка — 48/76.
