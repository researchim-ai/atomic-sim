# Ускорение HLLC без изменения численного решения

Срез: 10 ноября 2026. Ускорено вычисление потоков `hllc` и `hllc-local`:
повторные расчёты скорости звука заменены точным кэшем на один этап RHS.
Формулы потока, IF97, шаг CFL, допуски и правила допуска состояний сохранены.

## Изменение

Восстановление primitive-состояний уже вычисляет верхнюю характеристическую
скорость для каждого жидкостного состояния. Раньше локальный поток повторял
эти вычисления при выборе границы волн и проверке входов HLLC. Теперь
приватный `_FluxEvaluation` использует эти только что проверенные значения.

Ключ — полный неизменяемый объект State. Значения не округляются и не
сближаются по допуску. Кэш создаётся заново при каждом RHS, не переносится
между шагами, моделями или restart и не сериализуется в checkpoint.
Числа из primitive-массива приводятся к обычному `float`, сохраняя прежний
тип скалярной арифметики. Объём кэша ограничен состояниями текущего этапа.

Публичные функции не принимают неподтверждённые скорости звука от вызывающего
кода. Прямой вызов `local_hllc` создаёт собственный короткоживущий кэш.
Обе звёздные области по-прежнему проходят обращение EOS и проверку звукового
веера. Повторное использование скорости не отключает проверки давления,
жидкостной фазы, положительности, глобальной или локальной границы волн.
Скрытого расширения границы и fallback нет.

В профиле конструктора и одного `advance(0.001)` на четырёх ячейках:

- вызовы `characteristic_speeds`: **20 342 → 8297**, примерно на 59% меньше;
- вызовы `rho_u`: **8342 → 8342** — обращения EOS не пропущены.

Время под cProfile использовалось для поиска затрат, а не для заявления
ускорения. Измерение времени выполнено отдельно, без включённого профайлера.

## Парное измерение

Сохранён полный исходный пакет до оптимизации. Перед импортом его SHA
проверяются по прежнему sealed-протоколу. Основание и зависимости должны
совпадать, исходники контактного пакета должны отличаться от текущих.
Это предотвращает случайное сравнение разных EOS или одного кода с самим собой.

На одном окружении выполнены прогрев и пять парных запусков со сменой порядка.
Учитываются конструктор, несколько `advance` до 1 мс и checkpoint.
Медианы процессорного времени:

- Неподвижный контакт, 4 ячейки, `hllc-local`:
  **0,15344 → 0,10028 с**, ускорение **1,53×**.
- Прямой перепад, 4 ячейки, `hllc-local`:
  **1,05307 → 0,93849 с**, **1,12×**.
- Широкий перепад, 2 ячейки, `hllc-local`:
  **0,80237 → 0,73069 с**, **1,10×**.
- Прямой перепад, 4 ячейки, фиксированный `hllc`:
  **0,96931 → 0,89722 с**, **1,08×**.

Опубликованы все пары, CPU/wall time и медианы. Время не является gate:
шумное оборудование не должно превращать корректную библиотеку в провал
физической приёмки. Это короткие профили одного окружения, не универсальное
преимущество по скорости, не сравнение с конкурентами и не выделенный стенд.

## Численная эквивалентность

Во всех пяти парах и прогреве каждого профиля наблюдения совпали **численно точно, без допуска**.
Содержимое checkpoint также совпало после исключения единственного поля
`source`; его изменение намеренное. Сериализованный digest checkpoint
при разных исходниках различается и не сравнивается как числовой результат.

Отдельно новой версией повторён широкий граф до 40 мс с restart в 20 мс.
Все наблюдения и числовой payload сохранённого checkpoint совпали с прежним
пакетом. Сам restart новой версии воспроизводит её конечный checkpoint точно.
Для сопоставления использованы два прежних независимых Radau/BDF-пути:
подпись основания и код независимой RH-сборки остались неизменными,
SHA наследуемых данных включены в новый протокол. Эти два эталона повторно
не интегрировались. Вся прежняя длинная матрица автоматически не переносится.

Повторены 15 физических face-случаев и неподвижные контакты на 2/4/8/16/32
ячейках; для контакта сохраняется предел 1e-9 К. Новый полный внешний стенд
на исходной MSL принял **48/48 сравнений** с 24 реальными внешними траекториями.
Это отдельная переквалификация новых исходников, а не замена поля `source`
в старом положительном отчёте. Дополнительные guard-программы проверяют
приём допустимого сжатия и ожидаемые отказы.

## Совместимость

Публичный выбор схемы не менялся. Новый кэш внутренний, дополнительных
runtime-зависимостей нет. `rusanov` продолжает использовать прежнюю ветку;
контрольное сравнение с сохранённой реализацией также дало точное совпадение.

Подпись контактного семейства изменилась. Старые checkpoint отклоняются
без изменения текущего состояния: подтверждённая численная эквивалентность
не является разрешением автоматически обходить проверку происхождения.
Прежние source-bound отчёты сохраняются исторически. Основание, EOS
и независимая reference-арифметика в этом блоке не изменены.

## Воспроизведение

```bash
python -m scripts.benchmark_hllc_speed \
  --baseline docs/benchmarks/baselines/hem_contact_v13 \
  --baseline-protocol docs/benchmarks/baselines/hem_contact_v13_source.json \
  --output artifacts/my-hllc-speed
python -m scripts.verify_hllc_speed \
  --previous-long artifacts/hllc-long-v4 --output artifacts/my-hllc-cache-check
python -m pytest -q tests/test_hllc_speed_cache.py
```

Нужны новые выходные директории. Исходный пакет до оптимизации включён
в репозиторий как read-only fixture в `docs/benchmarks/baselines/`; он не является
альтернативным поддерживаемым runtime. Численное окружение должно совпадать
с зафиксированной подписью основания. Для длинной проверки дополнительно
требуются сохранённые данные предыдущего этапа. Локальная исходная копия:
`artifacts/hllc-speed-v1/baseline_package/`. Старый пакет загружается отдельным
модулем, не подменяет production-класс и не патчит глобальную функцию потока.
Пять парных запусков уже завершены до широкой параллельной проверки.

Следующие этапы — профиль обращений EOS, более широкая волновая матрица
и отдельная квалификация новых физических замыканий. Ускорение кэшем не
добавляет теплообмен, трение, двухфазность или экспериментальную валидацию.
`validated=false`, `plant_referenced=false`.

## Поставка и итоговая переквалификация

**951 passed**, без отказов/пропусков; все восемь фаз локальной поставки
прошли. Wheel содержит 1449 файлов; проверены 788 ресурсов.
10 новых тестов проверяют точность ключей, область жизни кэша, сохранение
обоих обращений EOS, звёздные/глобальные отказы, изоляцию публичного API
и проверку baseline до загрузки кода. Итоговый wheel содержит оба новых CLI.

Из установленного wheel вне checkout с Python `-I` повторён широкий native
режим до 40 мс с поздним restart. Весь пакет, включая текущую source-подпись,
совпал с новым запуском из исходников. Это одна выборочная длинная
installed-траектория; performance и внешний Modelica-стенд из wheel повторно
целиком не запускались.
[Sealed JSON](benchmarks/hllc_speed_benchmark_v14.json) содержит все пары,
профиль счётчиков, фактическую матрицу переквалификации и SHA отчётов.
Артефакты: `artifacts/hllc-speed-v3/`, `artifacts/hllc-speed-qualification-v1/`,
`artifacts/modelica-hllc-speed-v1/`, `artifacts/modelica-hllc-speed-guards-v1/`,
`artifacts/local-hllc-speed-delivery-v2/`, `artifacts/installed-hllc-speed-v1/`.

Продолжение: [первая жидкостная EOS-ветвь](HLLC_LIQUID_EOS_FAST_PATH_RU.md)
ускорена отдельным изменением контактного пакета. Его новая подпись и новая
матрица переквалификации опубликованы отдельно; этот звуковой кэш сохранён.
