# Быстрый source fingerprint без кеширования содержимого

Оптимизирован только обход исходников в `sdk.experiment._source_fingerprint`.
Профиль EOS-эпизода показывал существенные накладные расходы Path.rglob,
relative_to и сортировки Path при повторных source checks. Уравнения, EOS,
интегратор, параметры точности, бюджеты и места вызова проверок не изменены.

Новая функция каждый раз заново выполняет `os.scandir`, отбирает тот же набор
`.py/.json/.yaml` из прежних десяти пакетов, сортирует **компоненты** путей в
прежнем Path-порядке и читает все байты файлов. Кеш списка файлов, stat/mtime
или содержимого не используется. Stream SHA-256 сохраняет прежние relative
имена, NUL-разделитель и содержимое. Строковая сортировка полного пути не
подходит: `a.py` и `a/child.py` могут изменить порядок относительно Path.

## Сохранённый контракт

На доступном для чтения неизменном дереве digest совпадает с независимым старым
алгоритмом. Проверены вложенные пути, Unicode, скрытые файлы, пустые файлы,
суффиксы, отсутствующие пакеты, переименование, добавление и удаление файлов.
Вложенные directory symlink не обходятся; file symlink хешируется по логическому
имени, как раньше. Политика ссылок не стала новым sandbox. Ошибки чтения
не должны заменяться устаревшим или частичным закешированным результатом.

В тесте файл заменяется байтами той же длины с восстановленным mtime: digest
меняется при следующем вызове. Source guard модельного checkpoint также
отклоняет смену источников. Контракт не обещает атомарный снимок всего дерева
при конкурентном редактировании: такого filesystem transaction не было и ранее.

**Сам SDK-файл изменился**, поэтому fingerprint новой версии закономерно иной.
Равенство алгоритмов на одном дереве не означает равенства версий исходников.
Старый SDK fingerprint:
`985bb203c41624768a50968109af0edb907c043046b53faf045cd410c7fdbe8a`.
Новый записан в отчёте поставки. Старые source-bound checkpoint не принимаются
автоматически; для их воспроизведения требуется прежний замороженный runtime.

До изменения сохранены восемь эпизодов. Свежие эпизоды после изменения дают
точно те же model coordinates, snapshot, observation, команды, clocks и counters.
В отдельном offline-сравнении нормализованы только source_sha256 и зависимая
checkpoint checksum. Это доказательство сохранения чисел, **не** миграция или
разрешение загрузки изменённого старого checkpoint. Остальные функции/классы
SDK-файла AST-идентичны сохранённому варианту; пять EOS qualification campaigns
повторены с новым source и прежними бюджетами.

## Контролируемое измерение

```bash
python -m scripts.qualify_source_scan run examples/eos_performance.json --output artifacts/source_scan_bench
```

В qualification-only worker выбирается старый либо новый обход **до** импорта
native drivers. Прежний алгоритм скопирован с AST-идентичным телом. На обоих
путях хешируется одно текущее дерево, поэтому source metadata и полные native
episodes также должны совпасть, без нормализации результатов измерения.
В production SDK нет переключателя на старый алгоритм или режима пропуска hash.

Оба worker используют одинаковый launcher и порядок импортов; startup, запись
выхода и admission включены в trial wall. Порядок legacy/optimized чередуется
между повторами. Общий CPU set для supervisor threads и workers, BLAS/OpenMP
настройки, восемь фиксированных cases, actions, horizon и max_step одинаковы.
Отдельно измеряются десять пар fresh-scan samples по пять вызовов на sample;
это microbenchmark, его speedup не выдаётся за ускорение всего моделера.

В конце — исходные trials, все отказы, p50/p95, RSS, native episode hashes,
source/driver identity и контрольные суммы. Для speedup допускаются только
полные trials с одинаковым численным результатом. 2x оценивается по всему
эпизодному workload при том же числе worker, отдельно от microbenchmark.

Тесты скорости не содержат зависящего от машины pytest-порога. Qualification
backend Linux, как исходный performance harness; кроссплатформенная битовая
воспроизводимость и hermetic dependencies не заявляются. Нет физической
валидации: `validated=false`, `plant_referenced=false`.

Измеренный local result: 128 полных парных эпизодов, все native hashes равны.
Fresh-scan microbenchmark ускорился в **3.711x**. Полный workload при одинаковом
числе worker: speedup 1.084x / 1.277x / 1.150x / 1.231x для 1/2/4/8 worker.
Порог 2x по полному эпизоду не достигнут; micro speedup его не заменяет.
Машинный summary: `validation/ai10_source_scan_summary_v1.json`.
