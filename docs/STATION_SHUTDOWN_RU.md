# Останов, выбег и остаточный теплоотвод

Актуальное продолжение: [снижение расхода и граница плавучести v63](STATION_LOW_FLOW_RU.md). Ниже сохранены программа и результаты v62 для прежней версии исходников.

Программа `atomic_model_station_shutdown` начинает работу из согласованного
горячего состояния всей станции. Два обязательных горизонта различаются:
600 с для SCRAM с продолжающим работать главным насосом и 1800 с для SCRAM
с отключением его двигателя. На обоих путях запрашивается DHR, внешняя
электрическая сеть доступна, а водяные запасы конечны. Это исследовательские
сценарии, а не модель подтверждённой безопасности реального блока.

## Что проверяется

Защита и останов турбины должны сохраняться на каждом такте. Ввод стержней
проверяется относительно конечной скорости привода, а не объявляется
мгновенным. После полного горизонта требуется снижение мощности деления
до 10⁻³ исходной с сохранением положительного остаточного тепловыделения.
Остановка цепной реакции не приравнивается к исчезновению тепла.

DHR переносит тепло из холодной ветви первого контура в существующий
конечный запас охлаждающей воды. Проверяются его активация, первый закон,
неотрицательное производство энтропии и накопленный перенос энергии.
Электропотребление DHR поступает из явно включённой сети; батарея не
расходуется. Это отличается от сценария потери сети с конечной батареей,
который должен приниматься отдельно.

При выбеге двигатель должен быть отключён, скорость — оставаться
положительной и невозрастающей. Контролируется баланс импульса контура.
Проверяются все физические состояния, непрерывность времени и глобальные
бюджеты: энергия 10⁻⁶, масса и бор 10⁻¹⁰. Подпитка и слив закрыты.
Реальные потоки между имеющимися баками продолжают учитываться.

## Исправление затухающего расхода

В старом расчёте обычного останова последний принятый такт закончился на
180 с. При следующем закрытии клапана интерполяция Radau дала отрицательные
значения расхода около −1,10·10⁻¹² кг/с ещё до найденного нулевого события.
Это не допустимый обратный поток: проверка строго отказала.

Для ненасыщенного регулятора напора имеющаяся формула даёт
`dq/dt = (demand - q) / tau`. При `demand=0` точное решение —
`q(t)=q(t0)*exp(-(t-t0)/tau)`, с tau=0,2 с для питания и 0,5 с для конденсата.
Такой положительный хвост не пересекает ноль за конечное математическое
время. Интегрировать его полиномом до ложного пересечения не требуется.

Добавлено аналитическое исключение этой координаты **после полного ввода
стержней при защёлкнутом останове**, если задание равно нулю и насосный
регулятор не насыщен. До этого начальный переход остаётся связанным.
Настоящие запасы массы и энергии продолжают интегрироваться с фактическим
экспоненциальным расходом. Они не обнуляются и не проецируются.

Условия ветви проверяются на стадиях интегратора и при проверке плотного
выхода. Насыщение или появление положительного задания внутри выбранного
интервала приводят к контролируемому отказу с rollback; автоматический
переход в другую ветвь внутри этого интервала пока не реализован. Следующая
команда на границе такта заново выбирает режим и может вернуть обычную ОДУ.
Для аналитического хвоста ложный охранный корень `q=0` отключён.
Строгий отказ для настоящего отрицательного расхода остаётся действующим.

## Почему длительный выбег ещё не принят

Исследовательский прогон прежней версии прошёл до 1045 с. Последняя принятая
точка имела Re≈10032 и Pr≈0,824. Следующий такт был отклонён корреляцией
Dittus–Boelter, используемой в текущей эквивалентной круглой трубе при
Re≥10000. Запрошенный горизонт 1800 с не был пройден.

Численное исправление расхода не расширяет область закона теплоотдачи.
Для продолжения нужны физически обоснованные модели низких Re, перехода
и, при существенной плавучести, смешанной конвекции. Ламинарную константу
или турбулентную формулу нельзя автоматически продолжить на весь выбег.
Документация [Modelica для прямой трубы](https://build.openmodelica.org/Documentation/Modelica.Fluid.Dissipation.Utilities.SharedDocumentation.HeatTransfer.StraightPipe.kc_turbulent.html)
ограничивает свою турбулентную модель по Re и геометрии; это не подтверждение
применимости к нашей установке. Требуются отдельные источники и проверки.

## Воспроизведение

```bash
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
export PYTHONPATH="$PWD/src"
python -m scripts.qualify_station_shutdown --output artifacts/shutdown-scram-new
python -m scripts.qualify_station_shutdown --output artifacts/shutdown-fine-new \
  --max-step-s .5 --rtol 2e-8 --restart
python -m scripts.qualify_station_shutdown --family coastdown \
  --output artifacts/shutdown-coastdown-new
```

Последняя команда сохраняет также неполный путь и причину отказа. Отказавший
такт не коммитится: отчёт содержит последний принятый момент и проверку
точного rollback. SolverError, DomainError и ошибки ввода различаются.
Строка `full_horizon` не становится истинной только из-за большого
запрошенного горизонта: требуются все запланированные переходы.

При `--restart` на середине пути native restore действительно повторяет
префикс и сравнивает checkpoint. Поле `native_whole_path_exact` означает
точное сравнение всего пути с отдельным эталоном только при наличии
`--reference` с теми же численными настройками. Отсутствующая проверка
не выдаётся за успешную.

```bash
python -m scripts.qualify_station_shutdown_short --output artifacts/shutdown-short-new
python -m scripts.verify_local_library --output artifacts/shutdown-library-new
python -m scripts.verify_station_shutdown_delivery \
  --output artifacts/shutdown-installed-new \
  --source-evidence artifacts/shutdown-short-new \
  --full-evidence artifacts/shutdown-scram-new \
  --library-evidence artifacts/shutdown-library-new
```

Установленная библиотека независимо исполняет полный исходный SCRAM 600 с
и короткий цикл с точным native replay, вне checkout и офлайн. Сравниваются
научные JSON. Короткие проверки на 0,04 с подтверждают жизненный цикл,
но не заменяют длинный выбег. NPP-11.03 и полная R1 остаются открытыми
до завершения всех соответствующих физических и численных испытаний.

## Результат v62

Новый SCRAM прошёл 600 с на исходной и уточнённой настройках.
Максимальное нормированное расхождение — 8.47381119e-05, времён четырёх
физических событий — 2.87120081e-06 с. Native restore
уточнения точно восстановил checkpoint 300 с, затем расчёт дошёл до 600 с.
Это проверка префикса с продолжением; отдельный эталон всего хвоста
при тех же настройках здесь не заявлен.

До прежнего отказа на 180 с все 36 физических векторов исходного пути
совпали с прежним расчётом точно. После этого новая аналитическая ветвь
работала 84 такта. Невязки бюджетов остались порядка 10⁻¹⁵.
К концу деление составляет 3,59·10⁻⁶ начального, реальное остаточное
тепловыделение модели — 34,87 МВт; DHR передал 60 ГДж.

Из установленного wheel независимо исполнены весь исходный SCRAM 600 с
и короткий цикл с точным native replay. Шесть JSON полного пути
и 20 JSON короткой программы совпали побайтно. Локальная поставка:
1932 теста и восемь фаз; новых целевых тестов — 27.

Текущий выбег повторно остановился на последней принятой точке 1045 с,
Re≈10032.006. Следующий такт отклонён,
всё состояние и журнал сохранены точно. NPP-11.03 остаётся открытым;
численное исправление не выдаётся за пригодность корреляции при низких Re.
Общий статус: 48/76, открыто 28. Данные:
[машинный отчёт v62](benchmarks/station_shutdown_v62.json).

Предыдущий установленный длинный запуск в одном процессе после коротких
сценариев замедлился после 520 с и был прерван; он не принят.
Причина замедления не установлена. Принятый длинный случай выполнен
в отдельном новом интерпретаторе, как исходный расчёт. Изоляция
сценариев зафиксирована в оркестраторе. Его исходная версия обновлена
после сборки wheel; физика и научные драйверы wheel не менялись,
обе версии оркестратора отмечены SHA в машинном отчёте.

Отдельный старый процесс диагностики с отложенным faulthandler завершился
SIGSEGV и исключён из принятых прогонов. Переход до 2 с с тактом 0,1 с
в текущей версии без этого таймера прошёл; это не объявляется объяснением
причины аварии диагностического процесса.

После изменения численного backend его отпечаток поменялся. Старые длинные
приёмки номинала и нагрузки относятся к сохранённым версиям кода. Новый
режим включается только после останова; полная повторная матрица для
общего релиза R1 ещё требуется, старые подписи не подменяются.
