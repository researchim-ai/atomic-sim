# Тепловое сопряжение инерционной сети

`ThermalInertialGraph` из `scripts/thermal_inertial_graph.py` объединяет
инерционные расходы, алгебраические давления, конечные тепловые ёмкости
узлов, перенос тепла при реверсе и обратную связь сопротивления с температурой.
Это отдельное семейство `thermal_inertial_pipe_graph_v1`. Ранее принятые
тепловой и механический backend и их бюджеты не изменяются.

```bash
python -m examples.thermal_inertial_graph
python -m pytest tests/test_thermal_inertial_graph.py -q
python -m scripts.qualify_thermal_inertial run artifacts/ai05_thermal_inertial_campaign_v2.json
python -m scripts.qualify_thermal_inertial audit artifacts/ai05_thermal_inertial_campaign_v2.json
```

## Ввод и физические приближения

Внешний формат `atomic-thermal-inertial-graph`, `schema_version: 1` содержит:

- `hydraulic` — явную инерционную сеть с положительной инерцией каждой трубы;
- `thermal` — постоянный cp, нуль отсчёта и область температур, полный словарь
  узлов с volume, начальной температурой, нагревом, UA, температурой среды и подачи;
- `edge_laws` — полный словарь законов сопротивления и долей тепла трения.

Гидравлические роли узлов фиксированы. В каждом узле задана постоянная масса
`rho * volume`; давление не получает сжимаемого запаса. Плотность и cp
постоянны, объёмное расширение и плавучесть отсутствуют. Узел с заданной
подачей массы учитывает её температуру и работу давления отдельно.
Полные входы приведены в `scripts/thermal_inertial_references.py`.

Инерционные уравнения и устранение массовых ограничений используют прежнее
семейство труб. Для ребра множитель сопротивления:

```text
mu = exp(beta * ((T_from + T_to)/2 - T_ref_law))
loss = mu * (R*q + K*q*abs(q))
```

Объявленные minimum/maximum multiplier проверяются без clipping. Параметры
R/K не меняются при вычислении RHS: прогретый коэффициент — отдельное
временное значение. Начальные давления решаются сразу с фактическими
начальными температурами. Нет холодного предварительного стационара.

## Тепловые потоки и три баланса

Внутренний поток вычисляется один раз по температуре узла-донора:
`q * cp * (T_upstream - T_reference)`. Он вычитается из одного узла и
добавляется в другой тем же числом. При реверсе меняется донор. Внешний
вход использует температуру подачи, внешний выход — температуру узла.
Давление `p/rho` не добавляется к этому тепловому потоку повторно: его
работа уже находится в механическом балансе.

Для каждой трубы `D = q*loss/rho >= 0`. Доля `alpha` в диапазоне [0,1]
переходит в тепло жидкости; эта часть поровну распределяется между двумя
концевыми узлами. Остаток отводится во внешнюю тепловую среду. Это явная
сосредоточенная модель распределения потерь, без температурного профиля трубы.
Нагрев и обмен со средой дают `Q = sum(heat - UA*(T-Tambient))`.

```text
DeltaK - W_pressure - W_gravity + F_fluid + B_export = 0
DeltaU - Q_external - H_external - F_fluid = 0
DeltaK + DeltaU - W_pressure - W_gravity - Q_external - H_external + B_export = 0
```

Здесь `DeltaU = sum(rho*cp*volume*temperature_increment)` вычисляется в исходной
системе приращений. `F_fluid` — внутренняя передача энергии из механики в тепло,
поэтому в последнем балансе она сокращается. Все шесть интегралов сохраняются
независимо. Нуль отсчёта энтальпии не должен менять физическую траекторию.

## API и восстановление

`advance(dt)` и `step(full_pressure_mask, dt, expected_revision=..., command_id=...)`
работают транзакционно. Меняются только уже объявленные границы давления.
Тепловые параметры, доли потерь, подачи и законы сопротивления в этом API
фиксированы вводом. Скачок давления сохраняет расходы, температуры, их
приращения, кинетическую энергию и все интегралы. Итог содержит
`boundary_transition` с левым и правым наблюдениями.

Чистая размерная `residual(state, rate)` принимает полные расходы, давления,
температуры и шесть интегралов. Строки имеют Pa для импульса/границ,
kg/s для массы и W для тепловых/энергетических уравнений. Пробные расходы
вне массового многообразия дают невязку массы, а не скрытую проекцию.
Интегратор использует редуцированные координаты и сохраняет ограничения.

Checkpoint `thermal-inertial-radau-v1` связывает полный тепловой/гидравлический
ввод, исходники, бюджеты, численные настройки и версии библиотек. Он хранит
исходные температурные и расходные приращения, шесть интегралов и журнал
давлений. Проверяется точное продолжение в том же окружении; история Radau
между публичными вызовами не переносится. Механический checkpoint без
температур и интегралов для этой модели не подходит.

Выход стадии из температурной, расходной, давленческой области или диапазона
mu отклоняет весь вызов, включая ранее рассчитанные шаги. Область проверяется
на вычисляемых стадиях и принятых наблюдениях, без строгого интервального
доказательства между всеми точками. Бюджеты работы и истории ограничены.
Хеш checkpoint не является подписью или полным физическим replay истории.

## Проверки и открытые границы

Девять программ по 40 s, 27 траекторий на трёх фактически различных сетках,
189 наблюдений, 18 независимых DOP853/Radau и три ожидаемых отказа.
Эталон интегрирует полные расходы и тепловые приращения, решает совместную
систему ускорений/давлений, самостоятельно собирает потоки и потери.
Он не использует production RHS, проекцию, residual или базис координат.
Сравниваются температуры, расходы, давления и все шесть интегралов.

Для эталонного Radau задан центральный численный якобиан с явно нулевыми
столбцами энергетических счётчиков: RHS от них не зависит. Размерные
абсолютные допуски различают расходы/температуры и энергетические интегралы;
допуски сравнения результатов при этом не ослабляются. Первая кампания с
автоматическим якобианом и предупреждениями SciPy сохранена отдельно.

Отдельные точные тесты проверяют преобразование кинетической энергии в тепло,
нулевую/полную/частичную рекуперацию, нагрев неподвижного объёма, консервативный
перенос в замкнутом контуре, подачу при обратном расходе, нуль энтальпии и
совместное восстановление. При отключённых feedback/рекуперации механическая
траектория совпадает с прежним backend в заданном численном допуске.

Плотность/EOS, совместно нагреваемая петля с плавучестью, двухфазность,
кавитация, тепловое расширение, конвективный перенос кинетической энергии,
волны давления и произвольная смешанная сборка оборудования остаются открытыми.
Нагретая гидростатическая колонна при постоянной плотности остаётся неподвижной;
это не модель естественной циркуляции ВВЭР и не объектная валидация.
