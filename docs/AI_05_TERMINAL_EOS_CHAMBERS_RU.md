# Конечные торцевые объёмы: масса, импульс и энергия

`TerminalEOSChambers` соединяет открытый Euler-канал с двумя конечными
торцевыми объёмами того же сечения. Противоположные торцы закрыты неподвижными
отражающими стенками. Внешних массовых источников больше нет. Давления и
температуры торцевых объёмов вычисляются из их текущих запасов через EOS.

```bash
python -m examples.terminal_eos_chambers
python -m pytest -q tests/test_terminal_eos_chambers.py tests/test_terminal_chamber_audit.py
python -m scripts.qualify_terminal_chambers run artifacts/ai05_terminal_chambers_campaign_v1.json
python -m scripts.qualify_terminal_chambers audit artifacts/ai05_terminal_chambers_campaign_v1.json
```

## Область модели

Это одномерная конечно-объёмная сборка с двумя более длинными/короткими
торцевыми ячейками: их длина равна V/A. У них есть собственные m, P, E,
скорость P/m и кинетическая энергия P²/(2m). Это не бак с принудительно
нулевым импульсом и не модель резкого расширения, входного сопла или
разветвлённого пленума. Сечение общее; каждый торцевой объём имеет постоянные
V и высоту, совпадающую с высотой соответствующей грани канала.
Профиль внутри торцевого объёма не разрешён дополнительной сеткой.

Вход `channel` задаёт геометрию, начальные состояния, EOS, нагрев и торможение
канала без внешних состояний. `chambers` содержит два набора V, p0, T0, u0,
высоты, постоянного нагрева, UA среды и её температуры. Начальные внешние
состояния канала выводятся из этих данных; независимого дублирующего
граничного источника нет. Для жидкости во всех объёмах используется одна
синтетическая stiffened-caloric EOS; целевой теплоноситель не калиброван.

## Общий интерфейс и стенка

На каждой стадии текущие rho/T/p/u торцевого объёма подставляются во внешний
Rusanov-интерфейс канала. Один полученный поток массы, импульса, физической
энергии и численной энтропии используется для обеих сторон соединения.
Торцевой объём получает противоположный поток. Базовый открытый канал и его
входы при этом не изменяются: используются временные представления состояния.

На закрытом торце нормальная скорость отражается, остальные примитивные
состояния совпадают. Принцип отражения описан в
[первичной документации Clawpack](https://www.clawpack.org/bc.html);
реализация потока Rusanov здесь собственная. Потоки массы, энергии и энтропии
через неподвижную стенку равны нулю. Численная сила стенки для левого/правого
торца — A*(rho*u²+p ∓ (|u|+c)*rho*u). Это численный импульсный поток, а не
отдельно восстановленное точное давление задачи Римана на стенке.

Статика стенки не выполняет работу, но её реакция изменяет общий импульс
жидкости. Поэтому журнал `endwall_impulse_kg_m_s` входит в общий импульсный
баланс. Нельзя требовать сохранения импульса жидкости в закрытом сосуде,
исключив эту внешнюю силу из уравнения.

```text
deltaMassTotal = 0
deltaMomentumTotal = gravityImpulse - dragImpulse + endwallImpulse
deltaEnergyTotal = externalHeatChannel + externalHeatChambers - exportedDragHeat
deltaEntropyTotal = externalEntropyTotal + generatedEntropyTotal
```

Внутренний обмен энергией и энтропией на гранях исключается из внешнего
журнала всей сборки. Для торцевых объёмов производство энтропии вычисляется
из производных Gibbs с учётом противоположного численного потока на интерфейсе.
В него входят диссипация интерфейса/отражения и теплообмен со средой.
Существенно отрицательное производство отклоняется; доказательство
энтропийной устойчивости для всех начальных данных не заявлено.

## Численная реализация

Все состояния интегрируются совместно SSPRK3. Ограничение шага использует
акустические размеры каждой ячейки канала и каждого V/A торцевого объёма,
а также UA/(m*cv). Стадии повторно проверяют область и ограничения.
Устойчивость не гарантирует временную точность; при отказе по балансу может
потребоваться меньший max_step_s. Нет implicit/IMEX или all-speed метода.
Рабочие приращения исключают постоянные p_inf*V и e_offset*m; физическая
энергия с e_offset*deltaMass восстанавливается при проверке.

`advance`, чистый `residual`, checkpoint/restore выполняются с проверкой
источников, бюджета, входа и шага. Ошибка не устанавливает промежуточные
состояния. JSON-restart точен в той же среде выполнения. SHA — контроль
случайного повреждения, а не подпись истории. Онлайн-команды нагревателя,
гибридные события и регулятор в эту совместную сборку пока не включены.
Короткие ключи наблюдения камер: m — kg, P — kg·m/s, rho — kg/m³,
u — m/s, T — K, p — Pa.

## Свидетельства

Восемь программ: покой, два направления перепада, отражение начального
движения, гидростатика, жёсткий p_inf с нагревом, нагрев/теплоотвод и разные
объёмы. Три ограничения шага, пять наблюдений до 0.2 s: 24 траектории,
120 наблюдений, 16 независимых программ DOP853/Radau с 80 solve_ivp-сегментами.
Независимая реализация использует абсолютные m/P/E, отдельно вычисляет
закрытые стенки и сопряжение с независимым Euler RHS. Такое сравнение
проверяет временное решение полудискретной модели, не объектную точность.

Отдельно проверяются точный равномерный нагрев всех запасов, гидростатический
покой при двух p_inf, попарный массовый обмен, реакция стенки, ориентационная
симметрия, температурный контакт и приближение к заданной внешней среде при
увеличении конечных объёмов. Прямое повреждение массового/энергетического/
энтропийного журнала или импульса стенки вызывает отказ с откатом.
Аудитор проверяет идентичность источников, матрицу, допуски, конечность метрик,
различие шагов и restart; полные масштабируемые балансы проверяет движок.
Аудит отчёта не повторяет интегрирование и не удостоверяет автора.

Переносимая проверка — `validation/ai05_terminal_chambers_portable_replay_v1.json`:
офлайн-wheel, архивный аудит, тесты и пример вне checkout с унаследованными
numpy/scipy/pytest. Это не герметичная среда и не повтор всей кампании.
Полный репозиторный прогон нового семейства не выполнен, прежний полный
software-baseline сохраняется.

До 32 внутренних ячеек, два конечных торцевых объёма, Mach≤0.2; остальные
ограничения — в `validation/ai05_terminal_chambers_budget_v1.json`.
Произвольные баки/пленумы, ветвление, разные сечения, смешанная сборка со
стенкой/управлением, фазовые границы, IAPWS и физическая/объектная валидация
остаются открытыми. AI-05.03/07/08 не получают полной приёмки;
validated=false, plant_referenced=false.
