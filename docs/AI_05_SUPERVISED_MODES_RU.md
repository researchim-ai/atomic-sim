# Единое управление режимами Radau: календарь, guards и онлайн-команды

Реализация: `scripts/supervised_radau.py`, пример:

```bash
python -m examples.supervised_radau
```

Слой объединяет температурный автомат, заранее объявленный календарь и
последовательные команды внешнего регулятора. Физика — прежний ограниченный
граф с фиксированными свойствами среды, температурным сопротивлением и
алгебраической гидравликой. Переключение сохраняет исходные температурные
приращения и интеграл внешней энергии, после чего заново решает гидравлику.

## Контракт

Внешний JSON имеет `format: atomic-supervised-mode-graph`, `schema_version: 1`,
`controller` в формате `atomic-hysteretic-graph`, `schedule` и `online_modes`.
Календарная запись: `{id, time_s, to}`; положительные времена строго возрастают.
`online_modes` — уникальный список режимов, разрешённых внешнему регулятору.
Режим может быть достижим через календарь или онлайн-команду без фиктивного
guard. Все объявленные режимы должны быть достижимы из таких входов или
начального режима, иметь общую полную маску исполнительных параметров.

`advance(duration_s, stop_at_transition=False)` исполняет температурные и
календарные события. `step(target_mode, duration_s, expected_revision=...,
command_id=...)` сначала подтверждает команду на текущем времени и затем
рассчитывает положительный интервал. Ревизия увеличивается один раз на успешный
вызов; устаревшие ревизии и повторные ID отклоняются. ID содержит 1–128 ASCII
букв/цифр или `-_.:`. Повтор не является идемпотентным HTTP-retry: для повторной
доставки уже принятой команды вызывающий код должен проверить журнал.

Повторный выбор текущего режима даёт запись-подтверждение, сохраняет время
входа и guards. Минимальный возраст применяется только к физической смене
режима и никогда не откладывает событие. Ранний переход отклоняет весь вызов.
История включает источник события, исходный/целевой режимы, ревизию,
календарный ID или ID онлайн-команды, хеши команд и входного состояния.

## Неопределённый порядок и атомарность

Численный интервал температурного корня в пределах `1e-7 s` от календарного
времени приводит к `ambiguous_event_order`. Это консервативный отказ, без
скрытого приоритета и объединения событий. Контакт с guard на календарной
границе также отклоняется. При ошибке последующей гидравлики, residence,
ресурсов, наблюдения или контрольных сумм откатываются вся команда, время,
ревизия, календарный курсор и история.

Ограничения работы RHS, локализации, попыток, событий, переключений и длины
истории общие на транзакцию. `stop_at_transition=True` останавливается на
реальной смене режима; подтверждение текущего режима не останавливает расчёт.
Календарное событие на конечной границе выполняется до возврата результата.

## Checkpoint и проверка

Используется только внешний `model: supervised-radau-v1`: он связывает полный
ввод, будущий календарь, онлайн-разрешения, численные настройки и исходники.
Внутренний native checkpoint требует исходной внешней системы отсчёта и
отдельно не переносится. Restore проверяет смешанную историю, корневые
сертификаты, календарный префикс, ревизии и ID, возраст режима и наблюдение.
Успешное продолжение проверяется в том же окружении; история с пересчитанным
хешем не является криптографически подписанным доказательством исполнения.

```bash
python -m pytest tests/test_supervised_radau.py -q
python -m scripts.qualify_supervised_radau run artifacts/ai05_supervision_campaign_v1.json
python -m scripts.qualify_supervised_radau audit artifacts/ai05_supervision_campaign_v1.json
```

Сравниваются последовательность и времена событий, конечные температуры,
давления, расходы и интеграл энергии; это не оценка ошибки на каждом
внутреннем шаге. Численный root-интервал не ограничивает физическую ошибку
ОДУ, а проверка сеток не заменяет экспериментальную валидацию.

Кампания охватывает 9 программ по 120 s, три ограничения макрошага, до 8 узлов,
смешанные события, паузу, повторные подтверждения, смену давления и режимы,
достижимые только извне. Отдельные DOP853 и Radau используют независимое
решение смешанной гидравлики и собственную диспетчеризацию. Для онлайн-случаев
принятые команды передаются как вход эталону: это проверка исполнения команд,
а не независимая проверка политики внешнего регулятора. Аудит пересчитывает
всю кампанию и сравнивает полный отчёт, а не только его хеш.

Нет произвольных reset/guards, приоритетов и параллельных владельцев состояния.
Состояние PID/ИИ/RNG внешнего регулятора не сохраняется. Это программная
проверка фиксированной модели, без экспериментальной валидации, сертификации
или подтверждения пригодности для управления реальной установкой.
