# Контактосохраняющий HLLC: новая опциональная модель жидкости

Обновлено: **10 ноября 2026**.

## Измеренное улучшение

В предыдущем сетевом benchmark схема Русанова размывала неподвижный
температурный контакт. Добавлен отдельный `ContactHEMNetwork` с потоком HLLC.
На тех же пяти сетках, при тех же начальных запасах и горизонте 0,001 с,
измеренная L1-ошибка температуры контакта составляет:

- Русанов, 2/4/8/16/32 ячейки: **0,6477/0,5740/0,4866/0,3830/0,2802 К**.
- HLLC: **0 К** во всех пяти случаях; предел приёмки **1e-9 К** не менялся.

Проверены баланс массы/энергии, отсутствие внешнего тепла, допустимость
энтропийного остатка и точный restart. Это сохранение конкретного
стационарного контакта в машинной арифметике, а не доказательство нулевой
ошибки произвольного переходного процесса.

Приняты также **30 аналитических лицевых контактов**: три давления,
пять скоростей от −20 до +20 м/с, два энергетических сдвига. В движущемся
контакте проверяется точный upwind-поток. Отдельные тесты проверяют обращение
ориентации грани, энергетическую инвариантность и ненулевой отклик на малый
перепад давления: приблизительно равные давления не приравниваются.

## Алгоритм и область

HLLC восстанавливает среднюю контактную волну между двумя внешними волнами.
Формулы потока и звёздных запасов основаны на
[Toro, Spruce, Speares, 1994](https://doi.org/10.1007/BF01414629) и
[авторском изложении Toro](https://www.prague-sum.com/download/2012/Toro_2-HLLC-RiemannSolver.pdf).
Используются ограниченные сигнальные скорости и реальные IF97-состояния,
без константы gamma идеального газа.

Новый выпуск **ограничен однофазной жидкостью** в квалифицированной области
EOS и старом Mach/wave-envelope. Система адиабатическая, без трения,
тепловых источников, кипения и фазового перехода. Для каждой вычисленной
звёздной плотности и энергии выполняется явный допуск через EOS. Неположительные
плотности/давления, выход за область или жидкую карту приводят к отказу шага.
Общая теорема положительности и устойчивости для произвольной EOS не заявлена.

Нет обрезания запасов, округления состояний до контакта и автоматического
перехода на Русанова. Равенство давления/скорости для точного контактного
потока проверяется **строго**, без физически ненулевого tolerance-порога.
Кэш потоков существует только внутри одного RHS-этапа, с полными точными
ключами неизменяемых состояний; в checkpoint скрытый кэш не переносится.

## Совместимость и API

Существующий `QualifiedHEMNetwork` и его схема по умолчанию не менялись.
Новая модель находится в отдельном пакете, имеет свою идентичность источников,
имя модели и привязку checkpoint к выбранной схеме. Контрольный режим
`scheme='rusanov'` воспроизвёл прежнюю динамику точно.

```python
from atomic_model_hem_contact import ContactHEMNetwork
from scripts.benchmark_modelica_network import request_for

# Опубликованный адиабатический жидкостный тест, а не конфигурация установки.
request = request_for("thermal_step", cells=4, cap=1e-5)
model = ContactHEMNetwork(request, scheme="hllc")
model.advance(0.0005)
checkpoint = model.checkpoint()

restored = ContactHEMNetwork(request, scheme="hllc")
restored.restore(checkpoint)
assert restored.checkpoint() == checkpoint
result = restored.advance(0.0005)
```

Формат request использует прежний квалифицированный граф. Новая модель
строже ограничивает физическую область; произвольный прежний двухфазный
request к ней не относится. Checkpoint другой схемы, изменённого источника
или подменённых координат отклоняется. После отказавшего restore/команды
текущее состояние сохраняется. Нулевые команды с controller state доступны
для воспроизводимых агентных сессий; ненулевое форсирование пока отклоняется.

## Нестационарная проверка

Для двух случаев с перепадом давления, сеток 2/4 и двух caps выполнены
**8 native траекторий** и **8 независимых временных ориентиров**:
самостоятельная HLLC/RH-сборка абсолютных запасов с DOP853 и Radau.
Она разделяет EOS, но не production face function, центрированную энергию
и SSP-RK stepper. Получены **16 сравнений**, все прошли при caps
**5e-6/2,5e-6 с** и прежних строгих бюджетах сетевой квалификации.
Максимальные ошибки: около **0,00117 Па**, **5,11e-7 Дж** энергии ячейки
и **1,60e-9 кг·м/с** импульса.

Первый прогон при cap1e-5 с не прошёл два импульсных сравнения сильного
перепада: **1,302e-8** против допуска **1e-8 кг·м/с**. Отрицательный отчёт
`artifacts/contact-hllc-qualification-v1/report.json` сохранён.
Допуск не ослаблялся. Окончательный отчёт:
`artifacts/contact-hllc-qualification-v2/report.json`.

Это проверка двух численных реализаций одного HLLC-потока и аналитического
контакта. Последующий [внешний Modelica-HLLC стенд](EXTERNAL_HLLC_BENCHMARK_RU.md)
прошёл 48/48 сравнений. Экспериментальная валидация и применение к связанной
установке этими блоками не выполнены.

## Производительность: явный компромисс

На четырёх ячейках, cap1e-5 с, выполнены по три парных запуска со сменой
порядка схем. Учитываются конструктор, четыре advance и checkpoint, CPU-время.
Медианы в текущем окружении:

- Стационарный `thermal_step`: Русанов **0,2858 с**, HLLC **0,1260 с** —
  примерно 2,27× быстрее. Сохранённый контакт позволяет повторно использовать
  совпадающие EOS-входы точного кэша.
- `pressure_thermal_step`: Русанов **0,3173 с**, HLLC **0,9570 с** —
  примерно 3,02× дороже. Проверка звёздных состояний требует дополнительных EOS.

Эти короткие CPU-профили не являются универсальной оценкой, выделенным
аппаратным стендом или gate производительности. Новая схема улучшает контакт,
но общего преимущества по скорости не даёт. Поэтому выбор остаётся явным;
прежняя быстрая схема доступна и воспроизводима.

## Запуск квалификации

```bash
python -m scripts.verify_contact_flux --output artifacts/my-contact-hllc
```

Нужна новая выходная директория. Сохраняются исходники/критерии, все варианты,
профили, native checkpoint, независимые решения и ошибки. Источник проверяется
на неизменность. Runtime-зависимости продукта не расширялись.

Независимый внешний HLLC-runner реализован в следующем блоке.
Следующие этапы: более широкий набор
акустических/ударных и разрежающих волн, затем отдельная квалификация
теплообмена и двухфазности. Весь продукт не переключён на экспериментальный
поток. `validated=false`, `plant_referenced=false`.
