# Фазовая граница: одинаковые координаты и независимый баланс стенки

Продолжение разбора: [коэффициенты MSL, контрольный эксперимент и корни событий](MSL_IF97_EVENT_AUDIT_RU.md).
Остаток энергии ниже теперь объяснён различными коэффициентами идеальной части
EOS. Сам по себе он не доказывает несогласованность внутренних переменных MSL.
Прежние измерения сохранены, интерпретация уточнена.

## Что проверено

Два отрицательных результата внешнего benchmark 38/40 сохранены. Для их
разбора добавлены три отдельные воспроизводимые проверки. Они отделяют
классификацию фазы, термодинамическую согласованность отсчёта и интегрирование
теплообмена. Ни одна из проверок не подменяет экспериментальную валидацию.

### Классификатор на одинаковых плотности и температуре

`scripts.benchmark_phase_boundary` компилирует настоящие функции неизменённой
MSL: `rhol_T`, `rhov_T`, `phase_dT`, `region_dT`. Интегрируемой динамики в этой
постановке нет. Вторая сторона вычисляет границы непосредственно из прямых
формул Гиббса IF97 при давлении насыщения для той же температуры; production
обращение `rho_u` в этой части не используется.

Матрица содержит **88 состояний**: четыре давления 0,5/1/8/15,5 МПа, жидкую
и паровую границы, 11 относительных возмущений плотности от −1e-4 до +1e-4,
включая ноль и ±1e-12. Дополнительно проверены пять native wall-отсчётов
и по пять отсчётов DASSL/IDA: всего **103 состояния**.

В трёх номинально точных граничных точках классификаторы различаются из-за
округления самих границ; расхождений дальше измеренного сдвига границ нет.
Этот сдвиг только измеряется и публикуется: он не становится новым допуском
для динамической приёмки. На всех 15 сохранённых wall-координатах классификация
при одинаковых `rho,T` совпала. Следовательно, два прежних динамических
расхождения нельзя объяснить разными классификаторами на одинаковом состоянии.

Важно различать соглашения: `phase_dT` обозначает точную границу как однофазную,
а `region_dT` включает её в регион 4. Atomic хранит отдельные состояния
`saturated_liquid`/`saturated_vapor`; их нельзя автоматически приравнивать
к внутренней точке смеси. Числа с плавающей точкой на самой границе могут
попасть по разные стороны строгого сравнения.

Отчёт: `artifacts/modelica-boundary-v4/report.json`. В протоколе сохранены
исходники, wrapper компилятора, полный manifest MSL и SHA входных трасс.

### Согласованность массы, энергии и температуры спорного отсчёта

При 0,005 с на паровом выходе обе внешние трассы дают однофазную метку.
Но обращение их же плотности и внутренней энергии через Atomic даёт смесь.
Восстановленная температура ниже сохранённой примерно на **3,8917e-5 К**.
Это больше расстояния данного состояния до температурной границы фаз.

Дополнительно проверена прямая EOS при сохранённых внешних `P,T`.
Atomic и **CoolProp 8.0.0 IF97** согласуются по внутренней энергии лучше
1e-9 Дж/кг, тогда как сохранённое внешнее `u` отличается от обоих примерно
на **0,0912401 Дж/кг**. Это проверка согласованности конкретного отсчёта,
а не отдельная динамическая валидация CoolProp.
Отчёт: `artifacts/modelica-boundary-v3/coolprop-forward-check.json`.

На этом этапе обнаружен остаток при проверке внешних величин другой
реализацией IF97. В последующем прямом аудите он локализован в коэффициентах
`Basic.g2`, а не в CSV-интерполяции. Совпадение на одинаковых rho/T не означает
совпадения при одинаковых rho/u, если энергетические EOS отличаются.
В этом первоначальном блоке корни времени перехода не сравнивались;
они добавлены в [следующем блоке](MSL_IF97_EVENT_AUDIT_RU.md).

### Независимое решение теплообмена с конечной стенкой

`scripts.verify_phase_wall` решает скалярное уравнение

```text
du/dt = (G/m) · (T_wall(u) − T_fluid(rho_fixed,u))
T_wall(u) = T_wall_initial − (u − u_initial)/(C/m)
```

Температура жидкости получается независимым решением прямых IF97-формул
при фиксированной плотности. В ориентире нет HEM-сети, production inverse EOS,
её интегратора и механизма restart. Энергия стенки исключена аналитически
через сохранение полной энергии. Выполнены **DOP853 и Radau** с rtol1e-11,
atol1e-10, максимальным шагом 2e-4 с.

Все **16 native траекторий** прошли сравнение с обоими решениями: четыре
входа/выхода фазы, сетки 2/4, caps 2e-5/1e-5 с. Проверяются все ячейки,
фазовый путь, энтропийные/энергетические балансы и точный restart.
Бюджеты объявлены до прогона: 0,1 Па, 1e-5 К жидкости, 2e-4 Дж/кг,
1e-7 К стенки. Это отдельные численные бюджеты этой постановки.

Обе сетки используют одну геометрию с диаметром 0,08 м. Прежний диаметр
0,05 м давал слишком малую паровую стенку на четырёх ячейках: ниже штатного
минимума 100 Дж/К. Ограничение модели не ослаблено. Начальная попытка с этой
геометрией сохранена в `artifacts/phase-wall-reference-v1/`; полная новая
кампания — `artifacts/phase-wall-reference-v3/report.json`.
Это проверка согласованности разбиения в равномерном нулепоточном пределе,
а не измерение порядка пространственной сходимости неоднородной сети.

## Проверка внешнего шага и допуска

`scripts.refine_modelica_wall` повторно запускает проверенные по SHA
нативные исполняемые модели. CSV вычисляются заново. Для каждого из четырёх
сценариев и двух интеграторов заданы caps 1e-4/2e-5/1e-5 с.
Начальные условия, уравнения и бюджеты исходного сравнения сохранены.

- При исходном tolerance1e-11 приняты **16/24**: шесть фазовых отказов
  парового выхода и два энергетических отказа DASSL на жидком входе.
- При tolerance1e-12 приняты **18/24**: энергетические отказы исчезли,
  все шесть фазовых расхождений парового выхода сохранились.

Отрицательные отчёты: `artifacts/modelica-wall-refinement-v4/report.json`
и `artifacts/modelica-wall-refinement-v3/report.json` соответственно.
Меньший cap сам по себе не гарантирует монотонного уменьшения каждой
сохранённой ошибки. Дублирующиеся по времени строки с разной фазой или
температурой стенки теперь отклоняются при чтении; NaN во времени и стенке
не может исчезнуть внутри операции вычисления максимальной ошибки.

## Воспроизведение

```bash
python -m scripts.verify_phase_wall --output artifacts/my-wall-reference

python -m scripts.benchmark_phase_boundary \
  --omc /path/to/omc --library /path/to/MSL \
  --output artifacts/my-boundary

python -m scripts.refine_modelica_wall \
  --campaign artifacts/modelica-cycles-wall-v1 \
  --tolerance 1e-12 --output artifacts/my-wall-refinement
```

Для диагностики сохранённых траекторий у `benchmark_phase_boundary` есть
`--wall-trace PATH/atomic.json --peer-traces PATH/dassl-comparison.json PATH/ida-comparison.json`.
Нужны полные локальные артефакты первоначального benchmark. Каждая выходная
директория новая. Отрицательный научный результат возвращает ненулевой код
у динамической приёмки; положительный запуск классификаторной диагностики
означает только успешное выполнение измерения, а не приёмку фазовой динамики.

Следующий блок выполнил атрибуцию коэффициентов и сопоставление корней событий.
Оставшиеся ограничения, включая более строгий временной gate и неоднородный
проточный канал, указаны в [актуальном разборе](MSL_IF97_EVENT_AUDIT_RU.md).
`validated=false`, `plant_referenced=false`.
