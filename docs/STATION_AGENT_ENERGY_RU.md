# Электрический энергетический бюджет агента — v89

`atomic_model_station_energy_eval` добавляет проверку отпуска энергии и
собственных нужд поверх существующего станционного backend. Новая физическая
модель не вводится: используются уже интегрируемые состояния энергетических
счётчиков. Это первый электрический контракт для экономических задач,
а не доказательство оптимальности или полной промышленной экономичности.

## Откуда берутся величины

Привилегированный оценщик читает пять счётчиков в джоулях:

- валовая электрическая генерация — `gross_generated_j`;
- собственные нужды — `own_needs_j`;
- нетто-генерация — `net_generated_j`;
- фактический подписанный отпуск через границу сети — `net_exported_j`;
- расход конечного резервного запаса — `backup_used_j`.

Это **идеальные расчётные счётчики модели**, а не показания физических приборов
с задержками, шумом и метрологическими неопределённостями. Политика агента их
не получает: ей передаются обычное операторское наблюдение, публичная схема
действий и объявленная цель. Счётчики сохраняются только в отчёте оценщика.
Доступ к Python callback не является защищённой песочницей.

Чтение выполняется на копии физической модели, поскольку её `snapshot()`
пересчитывает производные и рабочие кэши. Тест подтверждает неизменность
checkpoint живой среды до и после чтения.

## Балансы и единицы

Энергия за эпизод равна разности конечного и начального счётчиков. Она не
оценивается как последняя мощность, умноженная на длительность. Для каждой
контрольной точки проверяются соотношения:

E_net_generated = E_gross − E_own,

P_net_generated = P_gross − P_own.

При подключённой сети P_export = P_net_generated; при отключённой сети
P_export = 0. Для соседних подключённых контрольных точек сравниваются
приращения интегралов нетто-генерации и отпуска. Счётчики генерации,
потребления и расхода резерва не должны регрессировать сверх численного
допуска. Проверяется также существующая относительная невязка полного
энергетического баланса модели, с порогом 1e-6.

Допуск электрических тождеств — 1e-5 плюс 1e-10 от соответствующего масштаба
величин. Это численный допуск для выбранной расчётной модели, не класс
точности электрического счётчика.

Собственные нужды уже вычтены в нетто-отпуске. Повторно вычитать их из
`net_exported_j` нельзя. Отрицательное приращение означает нетто-импорт;
оно сохраняется без обрезки. Отдельные суммарные экспорт и импорт при смене
знака внутри интервала здесь не восстанавливаются из их разности.

Киловатт-часы вычисляются делением джоулей на 3 600 000. Отношение собственных
нужд к валовой генерации выдаётся только при положительной генерации; оно
может превышать единицу и не ограничивается искусственно. При нулевом
знаменателе результат `None`.

## Контракт задания

`ElectricalTask` задаёт горизонт, требуемую мощность делений и её относительную
полосу, минимальный подписанный отпуск энергии и максимальную энергию
собственных нужд. Для успеха одновременно нужны:

- полный согласованный горизонт без ошибки исполнения;
- пройденные проверки энергетического учёта;
- подключённая сеть во всех сохранённых точках;
- отсутствие trip;
- пригодные измерения мощности внутри объявленной полосы;
- выполнение обоих энергетических бюджетов.

Такой контракт не позволяет считать выгодным отключение реактора ради
снижения собственных нужд. Но он не подменяет остальные условия безопасного
управления: это исследовательская задача в ограниченной области модели.
Гарантия подключения сети и полосы является выборочной, на сохранённых
границах шагов.

`evaluate_electrical_tasks` соединяет задания с манифестами train/dev/test v87.
Карта задач и горизонты проверяются до запуска выбранной выборки. Ошибки
политики, недопустимые команды и отказы модели остаются в отчёте и общем
знаменателе. При неудаче сохраняются доступные префиксные показания, стоимость
и фаза отказа. Если отказал сам счётчик после шага модели, `total_metered_s`
описывает только подтверждённую счётчиками часть, а не обещает учесть
неизмеренный хвост.

## Пример

```python
from atomic_model_station_env import EnvConfig, StationEnv
from atomic_model_station_control.policy import valid_reading
from atomic_model_station_energy_eval import ElectricalTask, run_electrical_task

config = EnvConfig(max_steps=3, tick_s=0.01, automatic=False)
observation, _ = StationEnv(config).reset()
target = valid_reading(observation, "power", "fission_power_w")
if target is None:
    raise ValueError("Initial power measurement unavailable")
task = ElectricalTask(
    horizon_s=0.03,
    target_power_w=target,
    minimum_net_export_j=20_000_000.,
    maximum_own_needs_j=3_000_000.,
)
result = run_electrical_task(task, config, lambda: lambda obs, schema, goal: {},
                             policy_id="hold/v1")
print(result["task_success"], result["accounting"])
```

Пределы этого примера объявлены для короткой программной проверки. Их нельзя
переносить на другую установку или считать промышленной целевой функцией.

## Локальная приёмка

Протокол запускает три коротких опорных эпизода (0,03–0,05 с), отдельный
контроль дополнительного расхода DHR и четыре отрицательных контроля:
недостижимый отпуск, нулевой бюджет собственных нужд, недопустимое действие
и SCRAM. Во всех сохраняются собственные критерии успеха; завершение расчёта
не означает выполнение бюджета. При SCRAM проверяется сохранение
отрицательного нетто-отпуска, если потребление остаётся больше генерации.

Разделение примера относится только к временным горизонтам одной конфигурации,
а не к независимым объектам или физическим семействам. Это проверка проводки
оценщика, не статистический benchmark обученного агента.

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:. \
  .venv-layout/bin/python -m scripts.qualify_station_energy_eval \
```

## Что остаётся

Тепловой КПД не вычисляется: для него нужен согласованный интеграл подведённого
тепла с проверенным балансом, а не текущее значение мощности делений. Также
не добавлены тарифы, топливная экономика, ресурсные издержки и метрологическая
модель электрических измерений. Для закрытия NPP-14.03/04 нужны длительные
принятые станционные задачи, сопоставление исходных политик и независимые
семейства сценариев. Станционная приёмка остаётся 48/76.
