# AI-05: регулирующий клапан с конечной утечкой

Исторический блок регулирующего клапана. Продолжение: [газовые накопители и обратный клапан](AI_05_GAS_STORAGE_RU.md); прежние числа ниже сохранены для своей ревизии.

Дата: 31 октября 2026. Продолжение [насоса и вала](AI_05_DISPLACEMENT_PUMP_RU.md).
AI-05.05 переведён в работу, но не закрыт: этот блок реализует конечное
сопротивление и привод; обратный клапан, накопительные объёмы и компенсатор
остаются открытыми. AI-05 остаётся partial, **3/8 задач приняты**.

## Модель и энергетика

`valved-displacement-pump-circulation-loop` 1.0.0 добавляет одну регулирующую
арматуру в выбранный сегмент несжимаемого контура объёмного насоса.
Исходная геометрия и коэффициенты труб не изменяются при пробных вычислениях.
На каждый вызов RHS/Jacobian/observation создаётся отдельный вычислительный
вид контура с добавочным сопротивлением клапана.

```text
0 <= a <= 1
K_valve(a) = K_open + (K_closed-K_open)*(1-a)^2
R_valve = K_valve/(2*rho*A²)
Delta_p_valve = R_valve*m*abs(m)
P_valve = R_valve*abs(m)^3/rho >= 0
```

Объявлены конечные K_closed>=K_open>=0 и K_closed>0. Клапан работает при
обоих знаках расхода. Давление потерь меняет знак вместе с потоком,
а тепловыделение остаётся неотрицательным. Дополнительное сопротивление
входит и в импульс, и в локальный нагрев жидкости **один раз**. Сохраняются
парные интерфейсные потоки, работа насоса, энергия вала и общий баланс сборки.
Давление проверяется на всех гранях сегментов.

a=0 означает положение с конечной утечкой, а не герметичную изоляцию.
Не моделируются контакт обратного клапана, удар при посадке, изменение
топологии, гидроудар, кавитация, сжимаемость и работа вытесняемого объёма.
Для идеального запирания потребуется другая постановка ограничений сети.

## Привод и команды

Привод здесь является сигналом первого порядка, а не электромеханическим
агрегатом с собственным запасом энергии. Между командами его положение
вычисляется точно, без дополнительного численного состояния:

```text
a(t) = target + (a_epoch-target)*exp(-(t-t_epoch)/tau)
tau > 0
```

Новая команда меняет target, сохраняя текущее a. Положение, сопротивление,
расход и энергия в момент команды непрерывны. История интегратора
перезапускается. RHS явно зависит от физического времени; аналитический
якобиан берётся по состоянию при фиксированном времени. Непрерывный ход
клапана не аппроксимируется мгновенным скачком сопротивления.

В timeline разрешены отдельные команды `valve_opening` и `motor_torque_nm`
со строго возрастающими временами. Одна команда на отметку времени;
совместное атомарное переключение нескольких приводов пока не поддержано.
`valve_opening` вне [0,1], неверные коэффициенты и неизвестные сегменты
отклоняются до создания каталога расчёта. Ошибка команды сохраняет старые
цель/эпоху и интегратор; ошибка шага откатывает состояние, время и события.

## Checkpoint и проверки

Checkpoint schema 1 содержит паспорт клапанной сборки, полную исходную
конфигурацию, состояние насоса/вала и общую хронологию команд. Текущее
положение восстанавливается из начального открытия и цепочки команд.
Проверяются hash конфигурации, прежняя цель, положение в момент команды,
порядок событий, версии и энергетические инварианты. Снимок не является
подписанным доказательством подлинности физической истории.

Добавлены **27 тестов**: пассивность обоих направлений, точный привод,
аналитический якобиан нестационарной системы, отсутствие мутации геометрии,
restore посреди хода клапана, rollback, повреждённые снимки и смешанные команды.

До серии зафиксирован `validation/ai05_valve_budget_v1.json`.
`artifacts/ai05_valve_verification_v1` содержит девять семейств, 20 основных
пакетов: base/tight Radau и две дополнительные серии BDF. Переходы — 20 с,
стационары — 100 с; для каждого проверен restart на 1 с. Эталон DOP853
использует собственные уравнения в абсолютных температурах и независимое
восстановление положения/сопротивления; production RHS/Jacobian не вызываются.

Проверены закрытие и открытие обоих направлений, быстрый/медленный привод,
реверс момента, открытый стационар и два стационара закрытого протекающего
клапана. Максимальные ошибки: расход <2,97e-10 kg/s, скорость <2,24e-10 rad/s,
температура <1,43e-12 K, интегралы энергии <1,41e-9 J. Баланс, пересчитанный
по абсолютным температурам, <3,20e-9 J при бюджете 1e-5 J.
Это точность решения объявленных уравнений, не экспериментальная точность
реальной арматуры. Промышленная и объектная квалификация не заявляются.

## Запуск

```bash
python -m sdk.pump_experiment scenarios/ai05_valve_close_reopen.json \
  --output artifacts/NEW_VALVE_RUN
# После установки wheel:
atomic-valve-experiment scenarios/ai05_valve_close_reopen.json \
  --output artifacts/NEW_INSTALLED_VALVE_RUN

python -m scripts.verify_valve --output artifacts/NEW_VALVE_VERIFICATION
python -m scripts.audit_pump artifacts/NEW_VALVE_VERIFICATION \
  --output validation/NEW_VALVE_AUDIT.json
```

SDK сохраняет input, траекторию, checkpoint, report и manifest с паспортом
нового engine, source fingerprint, версиями и контрольными суммами.
Срезы до/после команды имеют одно время и разные phase. Ресурсный deadline
проверяется внутри RHS; при отказе сохраняется последний согласованный префикс.
Предыдущие принятые свидетельства остаются привязаны к своим frozen source.
