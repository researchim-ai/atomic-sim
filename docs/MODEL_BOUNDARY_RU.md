# Контролируемый останов на границе паспорта

Дата: 30 октября 2026. Продолжение [исправления EOS и рестарта](EOS_RESTART_RU.md).

Следующий реализованный этап: [отдельный изобарический канал кипения](ISOBARIC_CHANNEL_RU.md).
Он проверяет консервативный тепловой компонент; замкнутый кипящий ВВЭР ещё не реализован.

## Реализация

`ModelLimitError` отделяет распознанный предел паспорта от остальных DomainError,
включая несходимость EOS. Для ограничения объёмного кипения сохраняются имя
критерия, узел, наблюдаемое качество и предел. Если отказ возник в RHS,
записываются время **пробы** и фаза `rhs_probe`; эта точка не считается принятой.
Прежний предел качества 1e−4 не изменён.

Опциональный параметр сценария:

```yaml
domain_boundary_tolerance_s: 0.0001
```

Без него действует прежнее поведение отказа шага. С ним SDK, experiment CLI
и `run_scenario` используют `sdk.boundary.advance_until_limit`. При распознанном
ограничении неудачная попытка откатывается, затем проверяются меньшие интервалы.
Принятые участки сохраняются; неудачные состояния не принимаются. Уточнение
ограничено 64 попытками. Ошибки EOS, solver, программы и отмена не превращаются
в событие ограничения.

После нераспознанного отказа или отмены откатывается весь составной шаг:
состояние, диагностика и накопительный ledger. При возврате допустимого префикса
алгебраические свойства и потоки синхронизируются с последним принятым состоянием.
Команды, после которых не принято никакого продвижения, откатываются в runner.
Журнал содержит только команды и события принятых участков.

Энергетический отчёт составного шага суммирует delta/supplied/residual всех
его принятых подшагов. В horizon ledger они уже учтены по отдельности — повторного
observe нет. Поэтому сумма остатков CSV согласуется с накопительным отчётом.
`accepted_steps` в report продолжает считать интервалы вывода; `balance.steps`
считает внутренние принятые участки, а `accepted_prefix_steps` — участки
терминального составного шага. Эти числа не обязаны совпадать.

## Семантика результата

При контролируемом останове report содержит `status: model_limit`, действующий
checkpoint и `model_boundary`. CLI возвращает код 1: запрошенный горизонт
**не завершён** и `numerical_acceptance` остаётся false, даже если балансы пройдены.

Диагностика включает:

- `accepted_time_s`: время сохранённого допустимого состояния;
- `failed_endpoint_s`: запрошенный конец последней неудачной попытки;
- `failed_attempt_start_s`: начало именно этой попытки;
- `interval_width_s`: разность неудачного конца и последней принятой точки;
- `probe`: условие и время отклонённой пробы;
- `last_accepted_state`: значения условий в принятом состоянии.

Область результата — **integration_admissibility**. Это не доказанная скобка
корня физического события: неудачная попытка могла начинаться из более ранней
точки и отказать на внутренней стадии solver. Невязки ODE и EOS также влияют
на результат. Поэтому `physical_crossing_localized: false` задан явно.
Ширина интервала не выдаётся за физическую погрешность времени кипения.
Событие журнала `model_limit.t` обозначает принятую точку, не физический корень.

## Финальная серия выбега с АЗ

Запрошены 1800 с, двигатель отключён вместе с предписанной АЗ на 10 с.
Для всех трёх запусков Radau: rtol=1e−6, atol=1e−5, центральный якобиан 2e−6,
допуск численного уточнения 1e−4 с.

- Вывод через **5 с**: принято до **122.202606201 с**, ширина
  **7.6294e−5 с**, core quality около **9.99826e−5**.
- Вывод через **1 с**: принято до **122.202575684 с**, ширина
  **6.1035e−5 с**, качество около **9.99750e−5**.
- Вывод через **0.5 с**: принято до **122.202575684 с**, ширина
  **6.1035e−5 с**, качество около **9.99823e−5**.

Разброс принятого времени **3.05176e−5 с**, меньше численной цели 2e−4 с.
Эта цель выбрана после диагностических проб и до финальной серии; она не является
внешней физической нормой. Во всех запусках пройдены бюджеты энергии, массы и
бора, проверены хеши артефактов и соответствие исходников текущей реализации.
Все три checkpoint точно восстановлены; CSV заканчивается на их времени,
сумма energy_residual_j согласуется с накопительным ledger с допуском 1e−6 Дж.

Пакеты: `artifacts/boundary_5s_accounted`, `boundary_1s_accounted`,
`boundary_05s_accounted`. Время исполнения: примерно **14.26 / 17.77 / 23.68 с**
в общей среде с параллельными проверками, не hardware-controlled benchmark.
Машинная проверка: `validation/domain_boundary_refinement.json`;
численные цели: `validation/domain_boundary_budget.json`.

Предыдущие `coastdown_boundary_5s`, `boundary_*_release`, `boundary_*_verified`
сохранены как промежуточные исследования. Финальная приёмка с суммированием
энергии относится только к пакетам `boundary_*_accounted`.

## Воспроизведение

```bash
python -m sdk.experiment scenarios/vver_boundary_5s.yaml --output artifacts/boundary_new_5s --wall-limit-s 60
python -m sdk.experiment scenarios/vver_boundary_1s.yaml --output artifacts/boundary_new_1s --wall-limit-s 60
python -m sdk.experiment scenarios/vver_boundary_05s.yaml --output artifacts/boundary_new_05s --wall-limit-s 60
```

Выходные каталоги должны быть новыми. Ожидается контролируемый `model_limit`
и ненулевой код CLI, а не завершение 1800 с. Скрипт сравнения полных номинальных
траекторий не принимает такие остановленные запуски; доказательства уточнения
хранятся отдельно.

## Следующий физический этап

Уточнение допустимого участка не расширяет паспорт ВВЭР. Для расчёта после
достижения порога необходим отдельный паспорт кипения: консервативная фазовая
модель, режимы теплообмена, границы замыканий и независимые эталоны. Для
естественной циркуляции нужны явные высотные отметки и данные геометрии.
Простое повышение порога качества не является реализацией этих моделей.
Промышленная квалификация, физическая валидация и превосходство над другими
кодами не установлены; `validated` и `plant_referenced` остаются false.

## Проверки реализации

Финальный общий прогон: **314 passed, 1 deselected за 107.81 с**, без
предупреждений в этом запуске. Исключён только неизменённый внешний OpenMC/MPI
particle-run. 15 новых проверок покрывают аналитическую границу на трёх
допусках, баланс, журнал, отсутствие лишних шагов, откат после частичного
продвижения при solver/domain/program/KeyboardInterrupt, нулевой префикс,
валидацию параметра и согласованность CSV/checkpoint/manifest.

Ruff прошёл; покрытие не измерялось. Wheel установлен вне checkout и выполнил
прежние CLI-сценарии, опциональный обычный шаг с уточнением, синтетическую
границу SDK и загрузку нового YAML. Сводка: `validation/domain_boundary_delivery.json`.

Дополнительно `run_scenario` выполнил весь сценарий с выводом через 1 с до
того же останова; его конечный snapshot **точно совпал** с CLI checkpoint.
Сводка этой проверки: `validation/domain_boundary_scenario_api.json`.

Проверенный wheel и сводки сохранены в отдельном каталоге
`artifacts/model_boundary_delivery_v1/`. `verification.json` содержит SHA-256
файлов и результат проверки установки вне checkout.
