# Проверка покрытия интервалов неопределённости

Модуль `atomic_model_uncertainty` принимает наблюдения, прогнозы и явно заданную
совместную ковариацию пяти аддитивных вкладов ошибки: данные, параметры,
замыкания, сетка и интегратор. Недостающие ковариации не восстанавливаются
автоматически. Межкомпонентные корреляции учитываются при суммировании.

## Локальный воспроизводимый пример

После установки библиотеки (`python -m pip install -e .`) выполните из корня:

```bash
python -m atomic_model_uncertainty examples/research/uncertainty_family_imbalance.json --output artifacts/uq-pooled.json
python -m atomic_model_uncertainty examples/research/uncertainty_family_imbalance.json --output artifacts/uq-balanced.json --acceptance-metric family-balanced
```

Вторая команда намеренно завершается кодом **2**: порог не достигнут.
Оба отчёта сохраняются. Все значения примера искусственные: это проверка
диагностики, а не измерения или экспериментальная валидация.

В примере три успешные точки принадлежат одному физическому семейству,
а единственная точка второго семейства выходит за интервал. Общая доля
попаданий равна **0,75**, покрытие с равным весом семейств — **0,5**.
При целевом покрытии 0,75 первый критерий проходит, второй — нет.
Повторение точек успешного семейства не увеличивает его вес во втором критерии.

## Как читать результат

JSON содержит `payload` и `sha256`. Контрольная сумма обнаруживает изменение
содержимого, но не удостоверяет автора или независимость измерений.
В Python отчёт проверяется функцией
`atomic_model_multiphysics.provenance.unseal`.

- `heldout_coverage`: доля покрытых компонент всех validation-случаев.
- `family_balanced_coverage`: среднее покрытий validation-семейств с равным весом.
- `family_diagnostics`: случаи, количество точек и покрытие каждого семейства.
- `missed_components`: все промахи, их единицы, невязки и полуширины интервалов.
- `acceptance`: выбранный CLI-критерий, значение, порог и итог приёмки.
- `target_met`: прежний результат по общему покрытию; его смысл сохранён даже
  при выборе другого CLI-критерия. Для кода выхода смотрите `acceptance`.

Флаг `--acceptance-metric pooled` используется по умолчанию и сохраняет
прежнее поведение CLI. Код **0** означает достижение выбранного порога,
**2** — недостижение; ошибки входных данных не являются результатом покрытия.
Критерий и порог следует закреплять до анализа результатов, а не выбирать
после просмотра промахов.

## Ограничения интерпретации

Доли покрытия описательны. Независимость точек внутри эксперимента или между
семействами не предполагается; биномиальные доверительные границы не строятся.
Равный вес семейств также не доказывает их статистическую независимость.

Семейства и provenance задаёт поставщик данных. Код запрещает пересечение
одного имени семейства между calibration и validation, но не обнаруживает
переименованные дубликаты эксперимента. Такое разделение надо обосновать
происхождением данных. Calibration не входит в held-out показатели.

Гауссовы маргинальные ошибки — явное предположение входного формата.
Полное совместное покрытие многомерного состояния не заявляется.
Проверка положительной полуопределённости ковариации не доказывает её
физическую применимость. Даже метка `experimental` не повышает автоматически
`validated` или `plant_referenced`.

Для закрытия AI-09.06 нужны применимые экспериментальные held-out случаи
с обоснованной конфигурацией, неопределённостями и происхождением данных.
