# AI-09.05: чувствительность, идентифицируемость и отказ от необоснованной калибровки

Добавлен отдельный модуль `atomic_model_hem_identification`. Он оценивает, позволяют ли данные определить множители конвективной и нуклеационной частей Chen. **Производственные коэффициенты не обновляются:** эти множители используются только как диагностические гипотезы. Физическая приёмка модели этим блоком не повышается.

## Завершённый объём AI-09.05

Завершены аналитические чувствительности, определение допустимой области двух диагностических множителей, независимая проверка её границ и оценка необходимой точности измерений. Область приёмки ограничена условно-локальным Chen/CHF K1/K4, 15–16 МПа и закреплённым HIPER-набором. Это не универсальная идентификация всех параметров реактора, не физическая калибровка и не завершение AI-09.06.

Исходные движки, 268 прежних связанных тестов, source-bound checkpoints и отрицательный [HIPER benchmark](AI_06_STEADY_THROUGHFLOW_RU.md) сохраняются. В производственный расчёт не добавлен свободный коэффициент для компенсации расхождения.

## Метод без точечной подгонки

Диагностический закон записан как `q(Tw) = a*C(Tw) + b*N(Tw)`, где a,b≥0, а C и N — конвективный и нуклеационный тепловые потоки прежней реализации. Входные p/x/G/D остаются номинальными опубликованными величинами. Производственная граница CHF и диапазон температур сохраняются.

Для измеренных интервалов `[Tw_low,Tw_high]`, `[q_low,q_high]` монотонность закона даёт два линейных ограничения:

- `a*C(Tw_low) + b*N(Tw_low) ≤ q_high`;
- `a*C(Tw_high) + b*N(Tw_high) ≥ q_low`.

Интервал **наблюдения** пересекается с объявленным диапазоном закона. Это не изменение измерений и не проекция физического состояния. Исходный и пересечённый интервалы хранятся отдельно. Ветвь Tw=Tsat используется только как нулевой математический предел теплового потока; положительный q требует Tw>Tsat.

Допустимая область вычисляется линейным программированием, без искусственного верхнего ограничения множителей и без регуляризации. Границы в отчёте — **координатные проекции совместной области**, не независимый прямоугольник допустимых параметров и не доверительные интервалы. Например, допустимые минимумы обоих множителей по отдельности не означают, что пара (0,0) допустима.

Для конечных границ проверяются primal/dual условия и разрыв двойственности. Статус unbounded принимается только с проверяемым направлением неограниченного изменения. Отдельный алгоритм пересечения активных прямых проверяет результат без вызова оптимизатора. Для реальных строк также строится прямой допустимый пример и два направления из исходных ненормированных ограничений — без LP-решателя. Такой пример является **математическим свидетельством существования**, не предложением откалиброванных коэффициентов.

Реализация использует [официальный SciPy HiGHS API](https://docs.scipy.org/doc/scipy/reference/optimize.linprog-highs.html). Проверенная версия библиотек записывается в идентичность отчёта. Лимиты: 1–512 наблюдений на задачу, два неотрицательных множителя, ограниченное число итераций/время решателя. Ошибка сертификата или исчерпание бюджета не выдаются за идентифицированный результат.

## Физические серии вместо перемешивания строк

Первичный [HIPER README](https://mediatum.ub.tum.de/1839312), Table3.1, задаёт две серии при 15,4–15,5 МПа с разными входными температурами: опыты 215–223 и 258–269. Проверены хеш первичного README, привязка к workbooks и номинальные физические условия; повтор номера258 в другой строке README не интерпретируется автоматически как принадлежность к этой серии.

Из 150 ранее допущенных строк первая серия даёт **57 строк / 9 опытов**, вторая — **93 / 12**. Один опыт не попадает одновременно в обе группы. Данные второй группы не передаются в расчёт допустимой области первой.

Обе группы ранее просматривались, относятся к одной установке и связанным условиям. Поэтому это **ретроспективное разделение по рабочим сериям**, не новая независимая кампания и не prospective holdout. Прежняя проверка по чётным/нечётным опытам не переписывается и не выдаётся за скрытые данные. AI-09.03 остаётся открытым в части полноценной независимой валидации.

## Что установлено на данных

В обеих группах допустимые области обоих множителей не ограничены сверху. Проверены направления `(1,0)` и `(0,1)`: увеличение любого множителя остаётся совместимым с принятой моделью интервалов наблюдений.

При этом локальный Якобиан имеет ранг2, а его числа обусловленности около17–19. Следовательно, полный локальный ранг **не доказывает практическую идентифицируемость при данных границах измерений**. Уравнения могут различать параметры при достаточно точных данных, но текущая допустимая область не определяет их значения.

Причина: опубликованные интервалы температуры стенки допускают близость к насыщению. В таком интервале всё более высокий коэффициент теплоотдачи остаётся допустимым. Это вывод для **условной номинальной модели и консервативных наблюдательных boxes**. Ковариации и полный бюджет неопределённости неизвестны; результаты не объявляются доказательством о единственной истинной физической модели ошибок.

Калибровочный gate возвращает `calibration_status=rejected`, причины и `parameter_update=null`. Даже совпадение одной выбранной кривой с номинальными измерениями не разрешает обновление производственной модели. Прежний результат Chen — ошибка q88,35% при критерии20% — остаётся в отчёте неизменным; новая диагностика не отменяет его.

## Чувствительности и численная квалификация

Производные температуры по обоим множителям вычисляются из неявного уравнения теплового баланса. Все **300 производных на 150 состояниях** сопоставляются с разностями независимых обратных решений. Корень снабжён численной скобкой и невязкой q; неразрешимый большой множитель отклоняется, а не выдаёт ложную точность.

LP-часть проверяется на семи задачах с известными границами: ограниченные области, неограниченные направления, противоречивые наблюдения и вырожденные случаи. Эти задачи явно помечены как **синтетические численные эталоны**, не экспериментальные подтверждения модели.

## Точность измерений: условная диагностика

Отдельно вычисляется интервал `h=q/(Tw-Tsat(p))` по опубликованным p/Twall/q. Если нижний возможный перегрев не положителен, верхняя оценка h не ограничена.

Для каждой строки найдена максимальная общая доля λ исходных границ p и Tw, при которой относительная ширина этого HTC-box не превышает20%; границы q остаются прежними. Приведены допустимая и недопустимая стороны скобки λ. Если шум q уже исключает цель при идеальных p/Tw, результат прямо это сообщает.

Это **условный сценарий изменения границ измерений**, не рекомендация купить датчики указанного класса и не оценка действительной погрешности установки. Общие систематические ошибки и корреляции могут изменить интервал; их отсутствие не заменяется гауссовской независимостью. Численная скобка корня, измерительная неопределённость и неизвестная ошибка замыкания не объединяются в выдуманный95-процентный интервал.

## Воспроизведение

```bash
python -m atomic_model_hem_identification qualify --output artifacts/identification_qualification.json
python -m atomic_model_hem_identification audit-qualification artifacts/identification_qualification.json
python -m atomic_model_hem_identification analyse --output artifacts/identification.json --require-calibratable
python -m atomic_model_hem_identification audit artifacts/identification.json
pytest -q tests/test_hem_identification.py
```

`--require-calibratable` сохраняет отчёт об отказе и возвращает код3. Флаг `--require-identifiable` отдельно проверяет только условную разрешимость параметров. Аудит заново вычисляет весь результат, проверяет код, данные и runtime; изменение статуса с пересчётом одного внешнего hash не проходит проверку. Существующие результаты не перезаписываются.

Открытыми остаются физическая приёмка AI-06.06, полный UQ AI-09.06, новые независимые измерения и оценка точности замыканий. Этот блок закрывает метод диагностики чувствительности/идентифицируемости и предотвращение необоснованной подгонки, а не объявляет промышленную физическую достоверность всего симулятора.

Установленный wheel вне checkout повторил audit квалификации и оценки, воспроизвёл отказ в калибровке (код 3) и прошёл 46 тестов. Среда использует зависимости того же хоста; независимая матрица ОС/оборудования этим не подтверждается. Общая связанная регрессия: 314 тестов.
