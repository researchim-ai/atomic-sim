# Локальная проверка библиотеки

Atomic Sim — open-source исследовательская библиотека. Проверка выполняется на
компьютере пользователя. CI, GitHub Actions, GitHub-аккаунт, удалённый runner и
аттестация физической машины для неё не требуются.

Из корня исходников с установленными зависимостями разработки и `build`:

```bash
python -m scripts.verify_local_library
```

Каждый запуск создаёт новый каталог `artifacts/local-verification-<id>` и выводит
его путь. Предыдущие результаты сохраняются. Можно задать собственный **новый**
каталог через `--output`.

Команда последовательно:

1. Выполняет тесты библиотеки, runtime, пространственного решателя, UQ,
   переносимых проектов и локальной поставки; пишет фактический pytest receipt.
2. Создаёт sdist и собирает wheel из распакованного sdist в чистом каталоге.
   Сверяет состав и точные байты всех файлов `src/`, а также корневых пакетов
   `scripts`, `data`, `scenarios`, `validation`, включая вложенные ресурсы.
   Отклоняет пропущенные и устаревшие файлы, неизвестные верхнеуровневые модули,
   дубликаты ZIP-записей и скомпилированные Python-кэши. Генерируемый `.egg-info`
   в исходниках не считается библиотечным ресурсом. Сверка не нормализует
   окончания строк: закреплённые CSV должны сохранять исходные байты.
   В инвентаре отчёта приводятся отдельные счётчики для `src` и каждого
   корневого пакета. Проверки установки/replay выполняются дополнительно.
3. Создаёт временное venv, устанавливает wheel без сети и запускает его вне checkout.
4. Переносит проект через ZIP, воспроизводит три операторские программы,
   сравнивает состояния, единицы, команды, события и балансы.
5. Проверяет пакетные JSON/YAML ресурсы, пространственный restart и UQ.
   Отдельная фаза `installed-uncertainty-criteria` запускает оба критерия UQ
   новым процессом из установленного wheel вне checkout. На искусственном
   примере общий критерий должен вернуть 0, а равный вес семейств — 2.
   Проверяются полное совпадение Python/CLI, контрольные суммы отчётов,
   сохранение результата при недостигнутом пороге и неизменность входа.
   Ожидаемый отказ критерия считается успешной проверкой только после
   сверки содержимого отчёта; произвольный exit code 2 не принимается.
   Результат сохраняется в `uq-criteria.json` рядом с остальными отчётами.
6. Проверяет установленный Python/Gymnasium/JSONL интерфейс управляемого PWR,
   host restart и восстановление через новый процесс; сохраняет `agent.json`
   со сравнением provenance исходной и установленной реализации.
7. Сохраняет `report.json`, журналы этапов, wheel/sdist и отчёты replay.
   Ошибка любого обязательного этапа возвращает ненулевой exit code.

Установка wheel офлайн использует уже установленные научные зависимости через
system-site-packages; это изоляция пакета от исходников, не герметичный wheelhouse.
Проверенный process-runtime профиль — Linux x86_64, Python3.12.9, NumPy2.2.6,
SciPy1.15.2. Другие платформы/версии этой проверкой автоматически не сертифицируются.

## Полный набор локальных тестов

Для отдельной проверки выбранных физических свойств решателей:

```bash
python -m scripts.verify_physics
```

[Шесть групп, ограничения и аудит пробелов](PHYSICS_VERIFICATION_RU.md).
Этот профиль не собирает wheel и не заменяет проверку поставки выше.

Расширение седьмой группой пространственного уточнения при смене фаз:

```bash
python -m scripts.verify_physics --include-phase-mesh --phase-timeout-s 900
```

Полные длительные режимы reduced-PWR и replay запускаются отдельно:

```bash
python -m scripts.verify_pwr_horizons
```

[Восемь случаев, выбранные поднаборы и правила приёмки](PWR_FULL_HORIZONS_RU.md).
Это длительные расчёты на компьютере пользователя, без CI. Для полноценного
стандартного результата нужны одновременно `passed=true` и
`complete_default_matrix=true`.

Более широкий переносимый набор без специальных runtimes и длительных задач:

```bash
python -m scripts.verify_local_library --suite portable
```

Весь набор, включая длительные, OpenMC и hardware-specific тесты:

```bash
python -m scripts.verify_local_library --suite all
```

Для `all` соответствующие runtimes, данные и профиль оборудования должны быть
подготовлены локально. Наборы остаются явно разделёнными по pytest markers.
Можно также запускать pytest напрямую:

```bash
python -m pytest tests/ -q
```

## Область результата

В стандартный набор также включены unit/contract-проверки новых инструментов
`verify_pwr_refinement`, `verify_phase_release` и `audit_hem_closures`.
Включены контрактные и короткие actual-solver тесты
`verify_phase_branching`: сохранение исходных запасов, каноническое
отображение ориентации/порядка и реальный сброс в неравные ветви.
Его полная матрица из 20 траекторий запускается отдельно:
[разветвлённый flashing](PHASE_BRANCHING_RU.md).
Также включены тесты `verify_phase_cycles`: точный энергетический путь,
запрет использования обратной EOS в ориентире, реальные фазовые циклы
и restart. [Полная матрица тепловых циклов](PHASE_CYCLES_RU.md)
из 16 траекторий запускается отдельно; `--pressure-matrix` расширяет её
до 64 траекторий при 0,5/1/8/15,5 МПа. Стандартный набор также проверяет
предварительный отказ и точный rollback/recovery у границы EOS.
Включены также проверки `screen_chf_measurements`; первичный CHF-файл для
unit-тестов не требуется. Его отдельный реальный отсев описан в
[CHF_MEASUREMENT_SCREENING_RU.md](CHF_MEASUREMENT_SCREENING_RU.md).
Полные матрицы PWR, сеточные расчёты выпуска и восемь программ аудита
запускаются отдельно по соответствующим документам. Это сохраняет явное
различие проверки поставки и длительной численной квалификации.

Успех означает локально проверенную установку и численную воспроизводимость
объявленной исследовательской библиотеки. Экспериментальная точность, применимость
к конкретной станции и независимая техническая экспертиза имеют отдельные
свидетельства. Они не являются требованием CI или блокером запуска библиотеки.

Автоматические workflow удалены. Прежние отчёты и архивы сохранены как история
выполненных проверок; содержащиеся в них старые CI-требования больше не определяют
актуальный порядок локальной приёмки.


## Независимые внешние реализации

[Отдельный benchmark CoolProp/OpenMC](EXTERNAL_BENCHMARK_RU.md) выполняется
через `scripts.benchmark_external`. Контрактные тесты его проверки входят
в стандартный набор и не требуют установленных CoolProp/OpenMC/threadpoolctl:
внешние сбои проверяются явно обозначенными harness-фикстурами. Для реальных
сравнений устанавливаются отдельные зависимости `requirements/benchmark.txt`
и OpenMC. Отсутствующий внешний проект не считается прошедшим сравнение.


Новый производственный IF97 kernel проверяется 72 frozen raw-состояниями
и матрицами производных (`test_if97_optimization.py`). Контракты настоящего
Modelica runner и четыре native wall-сценария (`test_modelica_benchmark.py`)
включены в стандартную поставку без необходимости устанавливать компилятор.
На актуальном ядре прошли 755 тестов и все восемь фаз. Добавлены
`test_phase_boundary_benchmark.py`, `test_phase_wall_reference.py` и проверки
неоднозначных CSV-событий/нечисловых значений.
Прямой внешний coefficient-audit и корни события проверяются
`test_msl_coefficient_audit.py` и `test_phase_event.py`; выборка не требует
установленного компилятора. Фикстура содержит явно обозначенные настоящие
прямые MSL-измерения; она не имитирует динамическую внешнюю приёмку.
Производные насыщения и безопасный допуск сохранённых корней проверяют
`test_msl_saturation.py` и `test_phase_event_readmission.py`: 47 новых случаев,
включая замороженные реальные MSL-измерения и явно синтетические повреждённые
пакеты проверки admission. Синтетические пакеты не используются как физические
свидетельства. Отчёт: `artifacts/local-msl-tangent-delivery-v1/report.json`.
Положительная проверка
повторяемости внешнего benchmark не повышает его отрицательные научные gates.
