[Моделирование решений для агента](AGENT_DECISION_MODELING_RU.md): новый atomic_model_decision оценивает ветви из одного checkpoint, объясняет ограничения/отказы и применяет выбранную ветвь после полного replay и проверки актуальности. Физические исходники сохранены; уникальность относительно всех конкурентов и непрерывная гарантия ограничений не заявлены.

[Сравнительный стенд моделёров и агентов](MODELER_COMPARISON_RU.md): 6/6 независимых нагреваемых траекторий OpenModelica/MSL, 36 статических и 480 маршрутных EOS-проверок CoolProp; 240 test-эпизодов hold/PID/rule с пересчётом отчёта. В повторном EOS-замере CoolProp IF97 быстрее примерно в 2.35 раза. 34 новых теста; всего 1143 теста прошли. Общее превосходство и сравнение внешних сред обучения не установлены.

[Нагреваемый жидкостный HLLC](HEATED_HLLC_RU.md): отдельный HeatedHEMNetwork с предписанными мощностями, линейной стенкой и энтропийным учётом. 18 нативных путей, шесть временных эталонов DOP853 с общим RHS; 6/6 обязательных сравнений на шаге 5 мкс. 28 новых тестов; всего 1109 тестов прошли. Выбранный путь точно повторён из wheel. Прежний адиабатический пакет и его подпись сохранены.

[Транзакционность ИИ-команд и restart](HLLC_TRANSACTIONS_RU.md): шесть путей на двух сетках и трёх схемах, 18 точных восстановлений и 234 атомарных отказа. 24 новых теста; всего 1081 тест прошёл. Один полный путь с 39 отказами точно воспроизведён из установленного wheel вне checkout. Физическая область HLLC не расширялась.

Разветвлённая сеть: четыре узла, пять труб, два цикла; естественный разворот потока, балансы портовых реакций, смена ориентации и точный restart. Приняты семь нативных траекторий и шесть независимых временных решений; обязательные сравнения на меньшем шаге — 6/6. Добавлены 18 тестов; две выбранные траектории точно повторены из установленного wheel. [Протокол и границы применимости](HLLC_BRANCHING_RU.md).
Atomic Sim — open-source исследовательская библиотека. Проверка выполняется на
компьютере пользователя. CI, GitHub Actions, GitHub-аккаунт, удалённый runner и
аттестация физической машины для неё не требуются.

Из корня исходников с установленными зависимостями разработки и `build`:

```bash
python -m scripts.verify_local_library
```

Каждый запуск создаёт новый каталог `artifacts/local-verification-<id>` и выводит
его путь. Предыдущие результаты сохраняются. Можно задать собственный **новый**
каталог через `--output`.

Команда последовательно:

1. Выполняет тесты библиотеки, runtime, пространственного решателя, UQ,
   переносимых проектов и локальной поставки; пишет фактический pytest receipt.
2. Создаёт sdist и собирает wheel из распакованного sdist в чистом каталоге.
   Сверяет состав и точные байты всех файлов `src/`, а также корневых пакетов
   `scripts`, `data`, `scenarios`, `validation`, включая вложенные ресурсы.
   Отклоняет пропущенные и устаревшие файлы, неизвестные верхнеуровневые модули,
   дубликаты ZIP-записей и скомпилированные Python-кэши. Генерируемый `.egg-info`
   в исходниках не считается библиотечным ресурсом. Сверка не нормализует
   окончания строк: закреплённые CSV должны сохранять исходные байты.
   В инвентаре отчёта приводятся отдельные счётчики для `src` и каждого
   корневого пакета. Проверки установки/replay выполняются дополнительно.
3. Создаёт временное venv, устанавливает wheel без сети и запускает его вне checkout.
4. Переносит проект через ZIP, воспроизводит три операторские программы,
   сравнивает состояния, единицы, команды, события и балансы.
5. Проверяет пакетные JSON/YAML ресурсы, пространственный restart и UQ.
   Отдельная фаза `installed-uncertainty-criteria` запускает оба критерия UQ
   новым процессом из установленного wheel вне checkout. На искусственном
   примере общий критерий должен вернуть 0, а равный вес семейств — 2.
   Проверяются полное совпадение Python/CLI, контрольные суммы отчётов,
   сохранение результата при недостигнутом пороге и неизменность входа.
   Ожидаемый отказ критерия считается успешной проверкой только после
   сверки содержимого отчёта; произвольный exit code 2 не принимается.
   Результат сохраняется в `uq-criteria.json` рядом с остальными отчётами.
6. Проверяет установленный Python/Gymnasium/JSONL интерфейс управляемого PWR,
   host restart и восстановление через новый процесс; сохраняет `agent.json`
   со сравнением provenance исходной и установленной реализации.
7. Сохраняет `report.json`, журналы этапов, wheel/sdist и отчёты replay.
   Ошибка любого обязательного этапа возвращает ненулевой exit code.

Установка wheel офлайн использует уже установленные научные зависимости через
system-site-packages; это изоляция пакета от исходников, не герметичный wheelhouse.
Проверенный process-runtime профиль — Linux x86_64, Python3.12.9, NumPy2.2.6,
SciPy1.15.2. Другие платформы/версии этой проверкой автоматически не сертифицируются.

## Полный набор локальных тестов

Для отдельной проверки выбранных физических свойств решателей:

```bash
python -m scripts.verify_physics
```

[Шесть групп, ограничения и аудит пробелов](PHYSICS_VERIFICATION_RU.md).
Этот профиль не собирает wheel и не заменяет проверку поставки выше.

Расширение седьмой группой пространственного уточнения при смене фаз:

```bash
python -m scripts.verify_physics --include-phase-mesh --phase-timeout-s 900
```

Полные длительные режимы reduced-PWR и replay запускаются отдельно:

```bash
python -m scripts.verify_pwr_horizons
```

[Восемь случаев, выбранные поднаборы и правила приёмки](PWR_FULL_HORIZONS_RU.md).
Это длительные расчёты на компьютере пользователя, без CI. Для полноценного
стандартного результата нужны одновременно `passed=true` и
`complete_default_matrix=true`.

Более широкий переносимый набор без специальных runtimes и длительных задач:

```bash
python -m scripts.verify_local_library --suite portable
```

Весь набор, включая длительные, OpenMC и hardware-specific тесты:

```bash
python -m scripts.verify_local_library --suite all
```

Для `all` соответствующие runtimes, данные и профиль оборудования должны быть
подготовлены локально. Наборы остаются явно разделёнными по pytest markers.
Можно также запускать pytest напрямую:

```bash
python -m pytest tests/ -q
```

## Область результата

В стандартный набор также включены unit/contract-проверки новых инструментов
`verify_pwr_refinement`, `verify_phase_release` и `audit_hem_closures`.
Включены контрактные и короткие actual-solver тесты
`verify_phase_branching`: сохранение исходных запасов, каноническое
отображение ориентации/порядка и реальный сброс в неравные ветви.
Его полная матрица из 20 траекторий запускается отдельно:
[разветвлённый flashing](PHASE_BRANCHING_RU.md).
Также включены тесты `verify_phase_cycles`: точный энергетический путь,
запрет использования обратной EOS в ориентире, реальные фазовые циклы
и restart. [Полная матрица тепловых циклов](PHASE_CYCLES_RU.md)
из 16 траекторий запускается отдельно; `--pressure-matrix` расширяет её
до 64 траекторий при 0,5/1/8/15,5 МПа. Стандартный набор также проверяет
предварительный отказ и точный rollback/recovery у границы EOS.
Включены также проверки `screen_chf_measurements`; первичный CHF-файл для
unit-тестов не требуется. Его отдельный реальный отсев описан в
[CHF_MEASUREMENT_SCREENING_RU.md](CHF_MEASUREMENT_SCREENING_RU.md).
Полные матрицы PWR, сеточные расчёты выпуска и восемь программ аудита
запускаются отдельно по соответствующим документам. Это сохраняет явное
различие проверки поставки и длительной численной квалификации.

Успех означает локально проверенную установку и численную воспроизводимость
объявленной исследовательской библиотеки. Экспериментальная точность, применимость
к конкретной станции и независимая техническая экспертиза имеют отдельные
свидетельства. Они не являются требованием CI или блокером запуска библиотеки.

Автоматические workflow удалены. Прежние отчёты и архивы сохранены как история
выполненных проверок; содержащиеся в них старые CI-требования больше не определяют
актуальный порядок локальной приёмки.


## Независимые внешние реализации

[Отдельный benchmark CoolProp/OpenMC](EXTERNAL_BENCHMARK_RU.md) выполняется
через `scripts.benchmark_external`. Контрактные тесты его проверки входят
в стандартный набор и не требуют установленных CoolProp/OpenMC/threadpoolctl:
внешние сбои проверяются явно обозначенными harness-фикстурами. Для реальных
сравнений устанавливаются отдельные зависимости `requirements/benchmark.txt`
и OpenMC. Отсутствующий внешний проект не считается прошедшим сравнение.


Новый производственный IF97 kernel проверяется 72 frozen raw-состояниями
и матрицами производных (`test_if97_optimization.py`). Контракты настоящего
Modelica runner и четыре native wall-сценария (`test_modelica_benchmark.py`)
включены в стандартную поставку без необходимости устанавливать компилятор.
На актуальном ядре пройдено 1196 тестов и выполнены все восемь фаз. Добавлены
`test_phase_boundary_benchmark.py`, `test_phase_wall_reference.py` и проверки
неоднозначных CSV-событий/нечисловых значений.
Прямой внешний coefficient-audit и корни события проверяются
`test_msl_coefficient_audit.py` и `test_phase_event.py`; выборка не требует
установленного компилятора. Фикстура содержит явно обозначенные настоящие
прямые MSL-измерения; она не имитирует динамическую внешнюю приёмку.
Производные насыщения и безопасный допуск сохранённых корней проверяют
`test_msl_saturation.py` и `test_phase_event_readmission.py`: 47 новых случаев,
включая замороженные реальные MSL-измерения и явно синтетические повреждённые
пакеты проверки admission. Синтетические пакеты не используются как физические
свидетельства. Добавлены 29 контрактных и actual-native тестов неоднородной
сети (`test_modelica_network.py`), включая ориентацию ветвей, ненулевую опору,
строгий CSV/ledger admission и точный restart. Отчёт:
`artifacts/local-heterogeneous-network-delivery-v1/report.json` — исторический
сетевой срез. Текущий отчёт: `artifacts/local-contact-hllc-delivery-v1/report.json`.
Добавлены 48 тестов HLLC (`test_contact_flux.py`): аналитический upwind-контакт,
звёздные состояния, область, rollback/restart и несовместимые checkpoints.
Положительная проверка
повторяемости внешнего benchmark не повышает его отрицательные научные gates.

## Внешний локальный HLLC — 10 ноября 2026

[Независимая Modelica-сборка и критерии](EXTERNAL_LOCAL_HLLC_RU.md),
[машиночитаемые результаты](benchmarks/external_local_hllc_benchmark_v12.json).
Приняты 48/48 сравнений на 24 native и 24 внешних траекториях: шесть случаев,
2/4 ячейки, два native шага, DASSL/IDA. Использованы собственные уравнения
локального HLLC и неизменённая MSL, без вызова Python-потока. Максимальное
расхождение давления 0,614 Па, температуры 7,55e-8 К. Это согласование
реализаций одинаковой схемы; физическая пространственная точность обоснована
предыдущим отдельным эталоном, а не этим числом расхождения.

Три дополнительные скомпилированные программы приняли допустимое сжатие
и отклонили выход звёздных сигналов/локальной границы за пределы. Нужное
сообщение отказа обязательно; эти harness-пробы не прибавлены к числу
внешних физических траекторий. Manifest MSL совпал с прежним исходным стендом.

Локальная поставка: 914 тестов, восемь фаз; файлов в wheel — 1443,
788 ресурсов. Весь внешний стенд и guard-пробы повторены из установленного
wheel вне checkout. Совпали все 24 native-пакета с checkpoint и все внешние
вердикты. Физический код и подпись пространственной квалификации сохранены.

Следующие этапы — более широкая пространственно-временная матрица,
длительные волновые режимы и отдельная работа над теплообменом/двухфазностью.
Готовая Modelica.Fluid-сеть, экспериментальная валидация и вся установка
этими сравнениями не квалифицированы.

## HLLC до 40 мс и поздний restart — 10 ноября 2026

[Новая матрица и исправления стенда](HLLC_LONG_TRANSIENTS_RU.md),
[машиночитаемые результаты](benchmarks/long_hllc_benchmark_v13.json).
Приняты четыре конфигурации: прямой перепад на 2/4 ячейках, обратный и широкий
перепады на двух ячейках. 12 native-траекторий, 8 независимых Radau/BDF,
три native шага, 20 моментов времени. Поздний checkpoint в 20 мс воспроизводит
наблюдения и конечный checkpoint точно. Физические балансы и область сохранены.

Восемь сравнений самого мелкого шага прошли абсолютные бюджеты; крупные шаги
имеют отдельное назначение для проверки сходимости. Уменьшение ошибок давления
и импульса принято во всех четырёх конфигурациях с явными численными полами.
Предыдущие DOP853-прогоны с исчерпанием бюджета/отказом EOS сохранены как
отрицательные. Для длинного эталона выбраны Radau/BDF, явный начальный шаг
и оконный учёт работы; численные допуски не ослаблялись. Пограничное расхождение энергии широкого BDF
устранено ужесточением его допуска вдвое. 12 native и семь reference-путей
переиспользованы с проверкой исходников и данных; пересчитан один BDF. Это иной протокол,
а не положительная квалификация прежнего длинного DOP853.

Поставка: 941 тест, восемь фаз; файлов в wheel — 1447, ресурсов — 788.
Из установленного wheel вне checkout повторены выбранная широкая длинная
native-траектория и один ужесточённый BDF; пакеты совпали точно. Вся матрица
повторно из wheel не запускалась. Физический код и подпись прежних HLLC-стендов
сохранены. Следующий приоритет — обоснованное ускорение вычислений, более
широкая пространственно-временная матрица и отдельная работа над замыканиями.
40 мс не означают длительный эксплуатационный режим или валидацию установки.

## Точный кэш звуковых характеристик HLLC — 10 ноября 2026

[Изменение, измерения и границы](HLLC_SPEED_OPTIMIZATION_RU.md),
[публичные данные](benchmarks/hllc_speed_benchmark_v14.json).
Повторные звуковые производные заменены кэшем полного State на один RHS.
Число вызовов characteristic_speeds в контрольном профиле уменьшено
20342 → 8297, число обращений rho_u осталось 8342. Обе звёздные области
по-прежнему проверяются, правила допуска и CFL не изменены.

В пяти парных замерах CPU на одном окружении: 1,53× на контакте,
1,10–1,12× на волновых local-HLLC профилях и 1,08× на фиксированном HLLC.
Наблюдения и числовые checkpoint совпали побитно с архивным исходным пакетом;
временной выигрыш не является gate и не переносится на произвольную задачу.
Baseline из четырёх исходников включён в репозиторий как проверочный fixture.

Новый source-bound стенд принял 15 физических face-случаев, пять контактов
на сетках 2..32 и широкий режим до 40 мс с точным restart и сравнением
с двумя прежними эталонами неизменённой RH-сборки. Текущие исходники также
прошли заново 48 Modelica-сравнений и три нативные guard-пробы. Подпись
контактного семейства изменилась; старые checkpoint отклоняются. Вся старая
длинная матрица автоматически не объявлена квалифицированной для новой подписи.

Поставка: 951 тест, восемь фаз; файлов в wheel — 1449, ресурсов — 788.
Из установленного wheel вне checkout повторён один широкий 40-мс native-путь;
его полный пакет совпал с текущим запуском из исходников. Это выборочная
installed-проверка, не повтор всех performance/Modelica-матриц. Следующие
этапы — обоснованная оптимизация EOS и дальнейшая работа над замыканиями.

## Первая жидкостная Newton-ветвь EOS — 10 ноября 2026

[Реализация, сравнения и ограничения](HLLC_LIQUID_EOS_FAST_PATH_RU.md),
[публичные данные](benchmarks/hllc_liquid_eos_benchmark_v15.json).
В контактном HLLC-пакете одна raw Gibbs-оценка используется для residual
и якобиана первой жидкостной попытки. Критерии, seeds и арифметика Newton
сохранены. Иные ветви, насыщение и неудачные попытки передаются исходному
полному адаптеру с исходными seeds. Сам квалифицированный EOS не изменён.

На пяти парах наблюдения и числовые checkpoint совпали побитно. Измерен
дополнительный выигрыш 1,05–1,08× на двух local-HLLC волновых профилях,
1,12× на фиксированном HLLC; контакт практически без изменения. Число raw
Gibbs в контрольном профиле снизилось 97048 → 81628 при тех же 8342
обращениях EOS. Время не является gate, универсальный выигрыш не заявляется.

Новые исходники прошли 15 физических face-случаев, пять контактных сеток,
широкий путь до 40 мс, 48 Modelica-сравнений и три нативные guard-пробы.
Два неизменённых независимых reference-пути явно унаследованы по SHA;
вся старая длинная матрица на новую source-подпись не перенесена.

Поставка: 1027 тестов, восемь фаз; файлов в wheel — 1450, ресурсов — 788.
Один широкий 40-мс native-путь повторён из установленного wheel вне checkout:
полный пакет совпал с новым source-запуском. Старые checkpoint отклоняются.
Следующие этапы — дальнейшая оптимизация RHS и отдельное расширение
квалифицированных физических замыканий, а не ослабление точности.

## Прямой HLLC RHS без повторного транспорта — 10 ноября 2026

[Изменение и проверки](HLLC_DIRECT_RHS_RU.md),
[публичные данные](benchmarks/hllc_direct_rhs_benchmark_v16.json).
Для HLLC больше не строится неиспользуемый транспорт Русанова. Проверка
неподвижных узлов и все тепловые/энтропийные ledger-поля сохранены;
ветка Русанова и техническая инициализация продолжают использовать родителя.
В контрольном профиле вызовы graph RHS уменьшены 302 → 0, число обращений
к обоим inverse-путям не изменилось. Flux/EOS-код и основание не менялись.

Все биты RHS/aux совпали в регрессионных сравнениях. Пять парных замеров
с каноническим JSON-чеком дали 1,16× на контакте и 1,01–1,03× на волнах.
Проверка теперь отличает знак нуля; доступные последние пары двух прежних
кампаний также прошли дополнительный аудит, но все старые запуски не повторялись.

неизменённых RH-reference-пути явно унаследованы, полная прежняя длинная
матрица автоматически не перенесена. Source-подпись контактного пакета новая.

Поставка: 1039 тестов, восемь фаз; файлов в wheel — 1450, ресурсов — 788.
Из установленного wheel вне checkout повторён один широкий 40-мс native-путь;
полный пакет, включая source, совпал при каноническом сравнении. Это выборочная
installed-проверка, не повтор всей матрицы. Следующие этапы — более крупные
волновые сети и отдельное расширение квалифицированных физических замыканий.
