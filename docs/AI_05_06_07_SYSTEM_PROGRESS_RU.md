# AI-05/06/07: согласованная инициализация и проверка полных горизонтов

Дата: 6 ноября 2026. Эта поставка выполняет инженерную часть трёх открытых блоков и сохраняет их фактические ограничения. **Все три блока полностью не закрыты.** Новый код не меняет замороженные графовые/HEM-семейства и `plants/vver.py`, не расширяет порог кипения и не подавляет запрет обратного расхода через насос.

## Производственная инициализация нагреваемой сети

`atomic_model_initialization` решает стационар закрытой неоднородной сети Буссинеска напрямую. Ранее стационар для квалификации получали через независимый эталон. Теперь эталон остаётся проверкой, а продукт получает отдельный ограниченный решатель и сертификат.

Неизвестные — расходы рёбер, давления свободных узлов и температуры узлов. Одно давление явно задаёт gauge. Решаются массовые балансы свободных узлов, импульс всех рёбер с гидростатикой/плавучестью и тепловые балансы всех узлов. Массовый баланс gauge-узла отдельно проверяется, а не теряется из отчёта. Работа плавучести учитывается согласованно с прежним энергетическим замыканием.

Внутреннее масштабирование unknown/residual не меняет физические коэффициенты. Приёмка использует размерные пределы: **10⁻¹⁰ кг/с**, **10⁻⁵ Па**, **10⁻⁵ Вт**. Финальный Якобиан пересчитывается отдельно; требуется полный локальный ранг. Явно фиксируется, что это локальная единственность, а не исключение других стационарных ветвей. Замкнутая ненагреваемая сеть без ограничения средней температуры отклоняется как недоопределённая.

Результат содержит исходный и инициализированный запросы, единицы и невязки каждой строки, gauge, сингулярные числа, исходники/зависимости и хеш. В исходном запросе меняются только начальные расходы и температуры; тепло, сопротивления, геометрия и границы не подбираются. Время инициализации равно нулю, скрытых warm-up шагов нет. Audit проверяет свидетельство подстановкой в исходные физические уравнения, а также запрещает подмену модели, статусов или отчётных невязок даже при пересчитанном хеше.

```bash
python -m atomic_model_initialization initialize request.json --output artifacts/initialized.json
python -m atomic_model_initialization audit artifacts/initialized.json
python -m atomic_model_initialization qualify --output artifacts/initialization_qualification.json
python -m atomic_model_initialization audit-qualification artifacts/initialization_qualification.json
```

Для зеркальной ветви задаётся `--flow-guess -0.13`. Исходное приближение вне области отклоняется без clipping. Наличие оптимизаторного success без выполнения физических невязок не является приёмкой.

Квалифицированы четыре постановки: обычная и зеркальная нагреваемая петля, восемь узлов и ветвление. Есть независимый стационарный эталон, передача в динамику, выдержка 40 с на двух ограничениях шага, восемь полных restart и отказ с rollback. Невязки импульса в этих стационарах меньше 4·10⁻¹¹ Па. Это поддерживает принятие **AI-05.07 для ограниченной нагреваемой петли Буссинеска**, не естественной циркуляции ВВЭР.

AI-05.03 остаётся частичной для всего проекта: данный контракт не даёт общего согласованного старта произвольной сети воды/пара с компенсатором, клапанными активными ограничениями и сменой фаз. AI-05.05/08 требуют совместной приёмки такого оборудования и его переключений; отрицательная проверка одного вызова не закрывает весь блок.

## Полные запросы горизонтов ВВЭР

`scripts/qualify_system_horizons.py` воспроизводит кампанию из 11 запросов. Входы берутся из существующих версионированных сценариев, изменения duration/команд явные. Балансовые критерии прежних сценариев сохранены. Дополнительное сравнение на общих временах использует явные масштабы и порог 10⁻⁴; это численный протокол, не новый критерий экспериментальной точности.

```bash
python -m scripts.qualify_system_horizons run artifacts/system_campaign
python -m scripts.qualify_system_horizons audit artifacts/system_campaign
```

Команда `assess` предназначена для уже рассчитанной полной кампании. Для каждого случая сохраняются точный запрос, траектория, checkpoint, manifest, отчёт и контрольные суммы. Проверяется совпадение источников, длительностей, последнего времени CSV, бюджетов и статуса. Успешный префикс не выдаётся за полный горизонт. Audit пересчитывает анализ и проверяет сохранённые байты; это проверка пакета результатов, а не независимый повтор физического интегрирования.

Восемь запросов завершены:

- Номинал **3600 с** на двух точностях BDF и дополнительный Radau. Глобальная относительная невязка энергии меньше 7·10⁻¹⁵.
- SCRAM **60 с** при шагах вывода 1/0,5/0,25 с. Сравнения проходят численный порог; точный упор стержня совпадает около **13,75 с**. Глобальная относительная невязка энергии для первых двух точностей около 1,72·10⁻⁷ и 4,75·10⁻⁸.
- Возмущения питания и температуры стока до **120 с**, без изменения физических ограничений.

Три запроса не завершены:

- Защищённый выбег **1800 с**, обычная и уточнённая точности: последний принятый момент **122 с**, далее первичный core достигает запрещённого объёмного кипения. Времена RHS-проб — не точные времена события пересечения границы.
- Полный сброс нагрузки с запросом **600 с**: последний принятый момент **10 с**, дальнейший шаг требует неподдержанного обратного расхода через питательный насос.

Старый `HorizonLedger.full_horizon_accepted` намеренно остаётся false в исходных отчётах: общая приёмка горизонта в нём не выполняется. Кампания имеет отдельное поле `full_horizon_completed`, сохраняет исходный флаг и не переименовывает его в приёмку всего AI-07. Завершение номинала старого паспорта не означает, что новая сеть с фазами и естественной циркуляцией уже интегрирована.

## Экспериментальная часть AI-06

Проверен новый первичный источник: [Zenodo, DOI 10.5281/zenodo.14090025](https://zenodo.org/records/14090025), файл `4in_st.csv`. В нём видны двенадцать столбцов случаев и строки переменных; `runtime` не образует временной ряд. Есть строки с единицами и нулевой NCG, но нужны расшифровка каналов, давление относительно атмосферы/абсолютное, геометрия, границы и неопределённости. [Карточка кандидата](../validation/ai06_condensation_candidate_v1.json) отдельно фиксирует, что точные байты и лицензия перераспространения ещё не удостоверены; реконструированный CSV не выдаётся за первичный.

Данные этого источника не сравнивались с кипящим Chen как с моделью конденсации. AI-06.06 остаётся открытой: принятых независимых переходных экспериментов по всем четырём категориям нет. Прежняя неудачная HIPER-проверка также сохраняется.

## Что конкретно мешает закрыть три блока

Следующий необходимый инженерный шаг — совместная модель клапана/питательного насоса с квалифицированным переключением активного ограничения и корректным переносом массы/энергии. Удаление ошибки «обратный расход» без модели проверенного квадранта или невозвратного клапана не является исправлением.

Для полного выбега нужна действительно связанная поддерживаемая двухфазная первичная сеть: инерция, давление/запасы, теплопередача, насос и плавучесть, а затем повтор полного горизонта. Поднять `PRIMARY_QUALITY_LIMIT`, добавить фиктивный напор или заменить физическую задачу меньшим горизонтом нельзя.

Для AI-06 требуются пригодные первичные данные и соответствующие замыкания. Недостаток измерений нельзя закрыть синтетическим эталоном. До выполнения этих требований AI-05 (в целом), AI-06.06 и AI-07 остаются открыты; `validated=false`, `plant_referenced=false`.

Поставка проверена 255 связанными тестами (33 новых). Установленный wheel вне checkout повторил квалификацию и 33 теста. Для старого графового runtime явно подготовлены три budget JSON и сценарные YAML из установленного wheel; произвольная рабочая директория без этих входов не заявлена. Зависимости разделяются с тем же хостом; независимая матрица ОС/оборудования и полная регрессия проекта этой итерацией не подтверждены.
