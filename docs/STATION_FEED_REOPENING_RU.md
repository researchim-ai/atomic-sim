# Внутреннее открытие питательного клапана — v98

В существующий модуль `atomic_model_station_hybrid_heat.scenarios` добавлен `prepare_feed_reopening()`: воспроизводимый случай открытия питательного обратного клапана внутри физического интервала. Подготовка и переход выполняются штатным решателем, без ручного присваивания расходов, запасов или состояния клапана.

## Проверяемый механизм

Используется исследовательская конфигурация `FeedConfig(feed_gas_volume_m3=0.1)`, `rtol=10⁻¹⁰`, `max_step_s=0,01`. Малый газовый объём находится в разрешённом диапазоне модели, но не объявляется параметром конкретной станции или квалифицированным диапазоном оборудования.

Питательный насос отключается, сессия развивается до t=0,008 с, и обратный клапан штатно закрывается. После этого насос включается с ограничением напора на 10 кПа ниже текущего противодавления. На границе команды движущий перепад остаётся отрицательным, клапан закрыт, расход равен нулю.

По мере поступления воды в питательный бак газовая подушка сжимается и давление источника растёт. Противодавление снижается, и внутри окна t=0,008…0,028 с достигается штатный порог открытия. В проверенном случае корень находится около t=0,011086379 с; после него расход становится положительным.

Сценарий использует внутренние величины для подготовки проверочной команды. Он не является политикой для агента, моделью реальной установки или рекомендацией по эксплуатации. При стандартном газовом объёме проверенный короткий переход не воспроизводил требуемое открытие; результат относится именно к явно указанной конфигурации.

## Критерии проверки

На 8/16/32 подшагах проверяются время и тип корня, обе стороны события, энергетический баланс каждого участка, согласованность с конечными запасами и полным вектором обычного расчёта, а также сходимость интегралов. Допуски адаптера не изменены.

Отдельно проверяются точное совпадение инструментированного решателя с обычным, повторение после checkpoint и отсутствие изменения исходной сессии диагностикой. Контрольный расчёт с нулевой долей напора насоса проходит баланс без события открытия: подача команды сама по себе не считается открытием клапана.

Алгоритм гибридного адаптера и сборщик событий не изменены. Добавление рецепта меняет отпечаток модуля сценариев; новые отчёты содержат актуальные контрольные суммы, старые остаются историческими свидетельствами соответствующих ревизий.

## Результаты поставки

Прошли **32 целевых теста**, включая четыре новых. Повторены проверки конденсатного открытия, сборщика событий и атомарного адаптера. Установленный wheel вне репозитория повторил четыре новых теста и все шесть расчётных JSON. Полный набор тестов библиотеки в этом этапе не запускался.

## Использование

```python
from atomic_model_station_hybrid_heat.scenarios import prepare_feed_reopening
from atomic_model_station_hybrid_heat import record_hybrid_window

session, command, recipe = prepare_feed_reopening()
report = record_hybrid_window(
    session, recipe["duration_s"], command, subdivisions=16,
)
assert report["passed"]
```

Локальный протокол:

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:. .venv-layout/bin/python scripts/qualify_station_feed_reopening.py --output artifacts/feed-reopening-local
```

Выходная директория должна быть новой. CI не требуется.

## Оставшиеся ограничения

Теперь имеются отдельные короткие проверочные случаи внутреннего открытия обоих обратных клапанов — питательного и конденсатного. Это не квалификация произвольного режима станции. Открыты физический сценарий одновременных корней, предохранительные и байпасные события, длительные последовательности переключений, экспериментальная валидация и промышленная приёмка.
