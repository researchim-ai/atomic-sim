# AI-05: локализованные температурные события Radau

`StateEventGraph` исполняет одноразовые направленные температурные события
поверх [управляемого Radau](AI_05_CONTROLLED_RADAU_RU.md). Тип графа, физические
свойства, топология, объёмы и роли границ фиксированы. Событие меняет только
ранее разрешённый пакет команд; переустановки температуры или запасов нет.

## Контракт

```python
request = {
    "format": "atomic-state-event-graph", "schema_version": 1,
    "model_input": model_input,
    "guards": [{
        "id": "hot", "node": "a", "threshold_k": 310.125, "direction": 1,
        "changes": {"thermal_nodes": {"a": {"heat_power_w": 0.0}}},
    }],
}
model = StateEventGraph(request, max_macro_step_s=2.0)
report = model.advance(120.0)
```

`direction` — строго целое +1 для пересечения снизу вверх либо -1 сверху
вниз. Идентификаторы уникальны, порог внутри открытой области температуры.
Дублированный guard по одному узлу/порогу/направлению отклоняется: совместные
команды следует объединить в одном `changes`. Ограничение — 16 guards.
Пустой список разрешён как предельный случай без событий.

Guard может начинаться с любой стороны порога и ждать пересечения заданного
направления. Например, охлаждающий guard способен сработать после нагрева
и последующей смены режима. Начальный контакт с порогом в пределах 1e-8 К
отклоняется, а не объявляется неявным событием в нуле. После срабатывания
идентификатор потребляется навсегда; переармирование/периодический термостат
не реализованы.

## Допуск интервала и поиск корня

Перед пробным интервалом строится прежний консервативный физический бокс
температур, давлений, потоков и скоростей. Для каждого непотреблённого guard
пересечение должно быть исключено достижимыми границами либо монотонность
температуры должна следовать из границ скорости. В потенциальном пересечении
скорость обязана быть строго положительной или отрицательной с модулем
выше 1e-9 К/с. Радиус бокса уточняется до 20 раз; неразрешённая
трансверсальность приводит к отказу, не к молчаливому пропуску.

В допущенном интервале строится пробная траектория Radau с плотной
интерполяцией. Направленная смена знака ищется между её концами. Затем
бисекция локализует корень до ширины численного интервала не более 1e-8 с
и остатка guard не более 1e-8 К. Guard вычисляется в исходных температурных
приращениях. На границах интервала и при поиске используется одна и та же
плотная траектория; смешения разных округлений accepted/dense endpoint нет.

Выбирается правый конец локализованного интервала. Возвращаемый сертификат
содержит время, интервал, значения guard на обоих концах, остаток и границы
скорости. Это интервал корня численной интерполяции, а не строгий интервал
истинного физического события. Ошибка ODE проверяется отдельно независимыми
IVP. Боксы не реализуют directed-rounding interval arithmetic.

Пробная старая мода может вычисляться за найденным корнем, но только в
допущенной физической области. Принимается лишь её часть до локализованного
корня. Все пробные RHS-оценки учитываются в бюджете. Метрики шага отражают
пробные траектории, включая непринятую часть; отдельная временная сходимость
каждого корня одной лишь этой метрикой не заявляется.

## Переключение и неоднозначности

На найденном времени исполняется атомарный пакет команд с тёплой пересборкой.
Температурные приращения, интеграл энергии и время не меняются скачком;
температура не проецируется на порог. Алгебраические давления/расходы могут
измениться вследствие квазистационарного приближения. Результат правосторонний.

Корни упорядочиваются по найденным временам, не по позиции guard во входе.
Если интервалы корней перекрываются или неразличимы на поддержанной точности,
возвращается `ambiguous_roots`. Если на выбранном корне другой guard находится
в неразрешённом контакте, возвращается `zero_time_cascade`. Неявные приоритеты,
слияние по epsilon и мгновенные каскады не вводятся.

Направленная смена знака на конце вызова применяется до возврата. Но если
из-за округления остаётся только близкий контакт без смены знака, возвращается
`endpoint_contact` и весь вызов откатывается. Модель не пропускает такое
событие молча и не угадывает сторону. Можно запросить более длинный горизонт
с `stop_at_event=True`, чтобы остановиться на найденном событии.

## Остановка и checkpoint

```python
report = model.advance(120.0, stop_at_event=True)
checkpoint = model.checkpoint()
restored = StateEventGraph(request)
restored.restore(checkpoint)
```

При `stop_at_event=True` выполняется только ближайшее событие, уже с правой
модой. `time_s` может быть меньше `requested_time_s`; `stopped_at_event`
указывает причину остановки. Без события достигается запрошенное время.
Обычный вызов продолжает расчёт до конца горизонта с последующими событиями.

Checkpoint связывает все определения, включая ещё не сработавшие guards,
исходники/бюджеты, макрошаг, порядок потреблённых ID, сертификаты корней,
активные команды и внешнюю систему отсчёта вложенного Radau. Восстановление
проверяет их согласованность и состояние режима. Сработавшие события не
повторяются. При одинаковых следующих вызовах в том же окружении проверено
точное совпадение продолжения, в том числе из checkpoint прямо на корне.
Вложенный runtime checkpoint следует восстанавливать только этой оболочкой.

Вся операция `advance`/`restore` транзакционна. Отказ локализации, команды,
физической области, энергетики, ресурса или финального наблюдения сохраняет
исходный объект целиком. Лимиты попыток, RHS и вычислений guard общие для
всех пробных интервалов и переключений одного вызова. Ранее принятые вызовы
не откатываются. Сертификаты проверяют согласованность метаданных, но не
повторяют историческую физику при restore; хеши не удостоверяют автора.

## Квалификация и границы

Девять сценариев до 8 узлов по 120 с: нагрев, охлаждение, последовательная
смена режима, игнорирование неверного направления, реверс потока, совместная
команда подачи/температуры, восьмиузловая сеть, упорядоченные guards и отсутствие
пересечения. 27 основных траекторий сравниваются с 18 независимыми Radau/
DOP853 IVP с отдельными гидравлическими root и штатными SciPy terminal events.
Три ожидаемых отказа: совпадающие корни, недопустимая команда и выход из
области после события. Проверяются времена, состояния, энергия и root checkpoint.

Обычные ограничения макрошага — 2/1/0.5 с; для постоянного предельного случая
без пересечения — 1/0.5/0.25 с. Фактические максимальные пробные шаги соседних
уровней должны различаться минимум в 1.2 раза. Численные допуски не ослаблены.

python -m scripts.qualify_state_event_radau --output artifacts/state_event_qualification

восстанавливает его и завершает цепочку нагрев/охлаждение без повторного события.
Это инженерный companion; SDK runtime не изменён. Не поддержаны произвольные
функции guard, касания порога без направленного пересечения, переармирование, приоритеты
одновременных событий, сбросы состояния, совмещение календарных/онлайн-команд
с guards и изменение топологии. Инерция, переменная EOS, фазовые события,
смешанная сборка оборудования и экспериментальная/объектная валидация открыты.
