# Команды ИИ и восстановление сети при развороте потока

Срез: 10 ноября 2026. Продолжение [разветвлённого стенда](HLLC_BRANCHING_RU.md).
Этот блок квалифицирует транзакционность программного интерфейса на реальной
развивающейся сети, а не вводит новый физический режим.

## Что выполняет стенд

На прежней сети с четырьмя узлами и пятью трубами выполняются шесть путей:
схемы Русанова, HLLC и локальный HLLC, по две и четыре ячейки на трубу.
Ветвь j→b начинается с противотока −0,005 м/с. В моменты 0,1; 0,25; 0,5 мс
сохраняется и восстанавливается checkpoint. Эти точки охватывают смену
направления, наблюдавшуюся в предыдущем стенде.

Управление задаётся через `step`: нулевые мощности, последовательная ревизия
и JSON-состояние контроллера. Отдельная чистая модель выполняет те же команды.
После каждого восстановления следующий интервал должен точно совпасть с ней.
Сравниваются канонические конечные JSON, сохраняющие знак нуля; NaN запрещён.
Сравнение охватывает весь checkpoint, включая координаты, наблюдение,
историю команд, состояние контроллера и подпись исходников.

## Отказы

После каждого из трёх интервалов выполняются 13 отрицательных проб:

- ненулевой нагрев жидкости и стенки;
- устаревшая ревизия и логическое значение вместо целой ревизии;
- NaN в состоянии контроллера;
- нулевая и NaN-длительность;
- подмена координат, наблюдения и истории команд в checkpoint;
- другая схема и другая подпись исходников;
- искусственный отказ после вычисления первого этапа SSP-RK.

Для подменённых checkpoint пересчитывается внешний digest: проверяется
содержательная сверка с replay, а не только обнаружение неверного хеша.
Искусственный отказ вводится только в экземпляр модели стенда, снимается
в `finally` и не меняет производственные уравнения. Он проверяет отсутствие
частичного commit после начала интегрирования; физическую аварию не моделирует.

Успех означает ожидаемый `ValueError`, точное сохранение checkpoint и snapshot,
а также точное дальнейшее продолжение. Принятая ошибочная команда, другое
исключение или любое изменение состояния прерывают стенд с ошибкой.
Дополнительно контролируются масса, энергия, портовые реакции и осевой баланс.

## Воспроизведение

```bash
python -m pytest -q tests/test_hllc_transactions.py
python -m scripts.verify_hllc_transactions --output artifacts/my-transactions
python -m scripts.verify_local_library --suite library --output artifacts/my-delivery
```

24 теста включены в общую локальную проверку библиотеки. Полная матрица
содержит шесть путей, 18 восстановлений и 234 отклонённые команды/состояния.
[Публичный протокол и отчёт](benchmarks/hllc_transactions_benchmark_v18.json).
Локальные полные результаты: `artifacts/hllc-transactions-v1/`.

## Проверка поставки

Пройден 1081 тест, выполнены все восемь фаз локальной поставки.
Один полный путь локального HLLC на четырёх ячейках точно повторён
из свежего установленного wheel вне checkout: три restart и 39 отказов.
Вся матрица из wheel повторно не запускалась; независимые научные
зависимости переиспользованы из локального окружения без сети.

## Граница результата

Теплообмен и трение по-прежнему запрещены в этом HLLC-семействе. Они требуют
отдельной сборки источников, проверки энтропии и временной сходимости.
Новый стенд не повторяет независимые Radau/BDF и Modelica-сравнения, не даёт
экспериментальной валидации и не меняет историческую приёмку 106/109 задач.
Производственные исходники не менялись. Он проверяет договор ИИ-управления
и воспроизводимость при отказах на уже поддерживаемом физическом режиме.
