# AI-02: воспроизводимый benchmark контроллеров

Дата: 31 октября 2026. Benchmark pack **pwr-ai-research-v1**, protocol/schema **1**.

**AI-02 принят: 8 задач закрыты.** Следующий пакет — AI-03.

## Что реализовано

Исследовательский benchmark поверх принятого контракта AI-01: генератор
train/dev/test, baseline hold / PID с anti-windup / rule-based, настройка
только на train, проверка dev, независимый evaluator и отчёт из сырых данных.
Политика выполняется в отдельном процессе, физика и метрики — в родительском.
Поддержан пользовательский executable через argv без shell.

Формальная проверка завершена: **240/240 тестовых эпизодов**, по 80 для
каждого baseline; отдельно выполнены 96 train- и 16 dev-запусков PID.
**621 тест пройден, 1 внешний OpenMC/MPI исключён.** Машинные результаты: `validation/ai02_delivery_v1.json`. Установленный wheel
проверен вне checkout: реальный CLI генерации и реальный policy subprocess.

## Набор задач и разделение

Замороженный pack: `validation/ai02_benchmark_pack_v1.json`.
В нём train=32, dev=16, test=80, по 20 test-кейсов в каждом семействе:

- `hold`: удержание номинала при измерительном шуме;
- `tracking`: слежение за постоянной слегка пониженной целью мощности;
- `recovery`: ограниченный отклик на небольшой сброс открытия турбины;
- `diagnosis`: бинарная классификация исправного/неисправного канала мощности.

Каждый эпизод длится **2 с**, интервал решений **0.25 с**; событие recovery
на **0.875 с** требует разделения шага. Амплитуды небольшие и находятся в
окрестности номинала существующего редуцированного паспорта ВВЭР. Полный
возврат установки к стационару за этот горизонт не заявляется. Нейросеть
в этом пакете не обучалась: создана инфраструктура её подключения и оценки.

Разные split используют разные диапазоны tau датчика, заданий и амплитуд
возмущений, а также непересекающиеся seed. SHA256 group_id вычисляется из
физической/измерительной конфигурации **без seed**. Валидатор отклоняет
совпадающие группы между split, повторные ID/seed и несогласованные labels. Имена файлов ограничены схемой
split-family-index; изменённый manifest не может использовать case ID как
относительный путь за пределы каталога кампании.
Это проверка разделения заданного корпуса, не доказательство обобщения на
неизвестную установку или все комбинации параметров.

**Корпус публичный, blind_test=false.** Он пригоден для воспроизводимых
сравнений. Закрытый серверный test pack и запрет обучения стороннего агента
на опубликованных кейсах здесь не обеспечены. Поэтому публичный leaderboard
с заявлением о слепой оценке не выпускался.

## Baseline и калибровка

Hold выдаёт нулевую команду скорости стержня. Rule-based использует
фиксированные deadband 1e-4 и команду ±1e-5 с⁻¹. PID использует существующий
`control.regulation.PID`, условное интегрирование anti-windup и ограничение
0.0005 с⁻¹; D=0, то есть это PI-специализация PID.

Сетка kp={0.001, 0.003, 0.01}, ki=0.0001, kd=0 зафиксирована до test.
Все три кандидата прошли 32 train-кейса. Выбор: сначала полнота эпизодов,
затем минимальная средняя IAE. Выбран **kp=0.01**. Dev=16 проверен после
выбора, параметры не изменялись. SHA256 train/dev, результаты кандидатов,
выбранные параметры и source fingerprint записаны в
`artifacts/ai02_tuning_delivery_v1/tuning.json`. Test в настройке не запускался.

Это ограниченный grid search, не утверждение об оптимальности PID.
Неподходящие/невалидные измерения дают безопасное нулевое действие baseline.
В diagnosis PID/rule используют явный quality flag; результат не является
выявлением скрытого, ранее неизвестного физического отказа.

## Граница политики и evaluator

Политика получает JSON-lines сообщения только двух типов:

- reset: версия протокола, публичная цель и интервал решения;
- act: наблюдение и metadata измерений (качество, время, насыщение, единицы).

Не передаются полный state, config, seed среды, case ID, family, путь к
manifest, метка диагноза или evaluator metrics. Скрытая истина записывается
родительским evaluator в raw episode. Ответ содержит только action и
бинарный diagnosis. Неизвестные поля, запрос hidden_truth, NaN/Inf,
неверная форма и выход за диапазон приводят к `policy_error`.

На ответ задан deadline 20 с и ограничение 64 KiB. Ожидание учитывает
незавершённую строку: поступивший `{` не позволяет зависнуть в readline.
После ошибки worker уничтожается; следующий кейс получает новый процесс.
Состояние baseline сбрасывается перед каждым эпизодом. Ошибки программы
симулятора не маскируются ошибкой политики. Уже записанные кейсы сохраняются.

Это разделение процессов и протокола для **доверенного** Python executable,
а не OS sandbox. Рабочий каталог временный, окружение минимальное; файловая
система того же пользователя технически доступна. Запрос test-настроек
через протокол запрещён, чтение публичного pack через произвольный Python
код не предотвращается. Изоляция недоверенного кода остаётся AI-12.

## Независимые метрики и воспроизведение

Метрики пересчитываются отдельным модулем из raw truth/action/time:
IAE, RMSE, время превышения ошибки мощности, стоимость действия,
выборочные пики мощности/температуры/давления, число новых защёлок защиты,
точность бинарного diagnosis, reward и wall time. Reward не служит
источником физических метрик. Интегралы используют правые прямоугольники
по принятым границам решений; пики выборочные, не сертифицированные
экстремумы непрерывной траектории.

Полнота горизонта имеет приоритет над IAE/reward. Средняя IAE публикуется
только для завершённых эпизодов. Парные разности считают только общие
завершённые кейсы и явно показывают их количество. При потере случаев
такое условное сравнение нельзя выдавать за глобальное превосходство.

Сохранены результаты по каждому семейству. Diagnosis accuracy по
диагностическому семейству: hold 10/20, PID и rule 20/20. Это использование
quality flags на синтетическом наборе, не экспериментальная диагностика.
Средняя IAE по полному test pack, fraction·s:

- hold: 1.5730631e-4;
- PID: 1.5462815e-4;
- rule: 1.4876600e-4.

Каждая пара использует 80 одинаковых кейсов. Доверительные интервалы:
2000 парных bootstrap выборок, стратификация по семейству, фиксированный
seed 2026, percentile 95%. Интервалы описывают условную вариацию данного
корпуса, не неопределённость физической модели или всего процесса обучения.
При постоянной разности интервал может выродиться в точку.
На этом корпусе rule имеет меньшую IAE; превосходство над внешними
симуляторами или на промышленных переходах не заявляется.

Raw episodes содержат полный case config, команды, наблюдения/quality,
истину evaluator, reward, времена, причину завершения, checkpoint и журнал
предписанных событий. Метки имеют origin `synthetic scenario configuration`,
а не экспертную причинную аннотацию. Для пользовательской политики её
argv записывается в raw; исходники/веса/собственный seed нужно архивировать
с проектом. Произвольный stochastic executable не становится автоматически
детерминированным от seed физической среды.

## CLI и команды проверки

```bash
atomic-agent-benchmark generate --output /tmp/pack.json
atomic-agent-benchmark tune /tmp/pack.json --output /tmp/tuning
atomic-agent-benchmark run /tmp/pack.json /tmp/tuning/tuning.json --output /tmp/campaign
atomic-agent-benchmark report /tmp/campaign --output /tmp/recomputed.json
```

`run` по умолчанию выполняет все три baseline на test; --split выбирает
train/dev/test. `--policy-command-json` принимает argv для одной внешней
политики вместо baseline. Протокол реализован в `agent_envs/benchmark_policy.py`.
Пути вывода создаются исключительно, старые данные не перезаписываются.

`report` проверяет полный набор файлов и SHA256, привязку raw к case,
покрытие всех политик/кейсов и заново вычисляет метрики/интервалы.
Канонический порядок обеспечивает точное JSON-совпадение с исходным отчётом.
Формальный повтор выполнен:
`validation/ai02_recomputed_delivery_v1.json`.
Это пересчёт отчёта, не новый запуск физики или внешняя валидация.

## Критерии и ограничение приёмки

Критерии зафиксированы до test в
`validation/ai02_acceptance_budget_v1.json`: 80 кейсов, три baseline,
240 завершённых эпизодов, 112 train/dev запусков, неизменённый выбор PID,
точная пересборка отчёта. Превосходство конкретного контроллера не являлось
условием приёмки. Все критерии пройдены.

Дополнительно внешний некорректный worker с действием [2.0] получил
16/16 отказов на dev; ни один не засчитан успешным. Его нулевой накопленный
reward/нулевой интеграл на незапущенном горизонте не дают победы над
завершёнными эпизодами. Raw и исходник worker сохранены отдельно.

В исходной серии `ai02_test_campaign_v1` сохранено предупреждение SciPy BDF об invalid subtract.
Все принятые сериализованные состояния конечны, все горизонты завершены,
повтор отчёта пройден. Предупреждение не скрыто и не объявлено объяснённым;
это не новый результат квалификации интегратора или физики.

Результат закрывает **AI-02 в указанном исследовательском scope**.
Физические паспорта, пространственная квалификация, длинные переходы,
слепой закрытый test, OS sandbox и производственный performance остаются
соответствующими следующими пакетами. `validated=false`, `plant_referenced=false`.
