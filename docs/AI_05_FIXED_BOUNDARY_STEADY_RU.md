# Стационарная инициализация при фиксированных командах

`scripts/solve_fixed_primary_steam.py` находит согласованное начальное
состояние первичной/паровой сборки, сохраняя значения всех граничных команд.
Момент мотора, первичный и паровой нагрев, питание, паровой клапан,
генераторная нагрузка и охлаждение не оптимизируются.

Это дополняет `scripts/design_primary_steam.py`, который выбирает команды
под заданную рабочую точку. Здесь несовместимые команды приводят к
диагностическому отказу. Переходный разгон не используется: `warmup_steps=0`.

## Обязательные физические ограничения

В равновесной модели пар отбирается с энтальпией насыщенного пара, питание —
с энтальпией насыщенной жидкости. Поэтому стационарные потоки и мощности
не определяют массовое распределение двухфазных запасов. Пользователь
явно задаёт два ограничения:

- общую массу воды и пара в двух сосудах парового цикла,
  `total_steam_mass_kg` (масса жидкости первичной насосной петли сюда не входит);
- массовое качество смеси в парогенераторе, `steam_generator_quality`.

После нахождения давлений из этих условий вычисляются масса конденсатора
и его качество. Неположительная масса или качество вне паспортных границ
отклоняются; массы и качества не проецируются на допустимый интервал.
`inventory_anchors(spec)` помогает явно получить ограничения из исходных
запасов; сам решатель не выбирает их из начальных догадок.

## Алгоритм и диагностика

По фиксированному моменту мотора аналитически решаются первичный расход,
напор и скорость объёмного насоса. Формулы учитывают сопротивления,
утечку и трение вала; поддерживается обратный расход.

Для заданной температуры стенки парогенератора первичная тепловая система
линейна. Её масштабирование, ранг и обусловленность проверяются до решения.
Учитываются донор адвекции для каждого направления потока, жидкостное
трение, нагрев корпуса от утечки, нагрев стенок и потери в окружение.
Температуры и передаваемое тепло выражаются как аффинные функции температуры
стенки. Стенки паровой части и скорость турбины затем исключаются из
стационарных уравнений аналитически.

Массовый баланс фиксирует разность давлений через заданные питание и
открытие клапана. Давление конденсатора находится по его энергетическому
балансу скалярным brentq. Баланс парогенератора проверяется отдельно —
это дополнительное условие совместимости команд, а не свободный параметр
для подгонки. Например, увеличение первичного нагрева на 1000 Вт при
неизменных остальных командах может не иметь стационарного решения.

На 33 опорных давлениях проверяется монотонность выбранной ветви. Это
ограничение численной области решателя, не аналитическое доказательство
глобальной уникальности: `global_uniqueness_proven=false`. Немонотонная
ветвь требует другого механизма выбора и здесь отклоняется.

В конце заново создаётся рабочая модель и независимо вычисляются размерные
невязки: мощности всех запасов, первичный импульс, момент вала и массовые
производные. Их бюджеты сохранены в
`validation/ai05_fixed_boundary_steady_budget_v3.json`.

## Начальные догадки и команды

Поля начальных температур, расходов, скоростей и паровых запасов во входе
служат догадками этой процедуры, а не стартом переходного расчёта.
Геометрия, материалы, физические пределы и значения команд сохраняются.
Пустая временная шкала обязательна: иначе смысл будущих абсолютных команд
неоднозначен. Успешный результат — обычный явный вход SDK schema 1.

```bash
python -m scripts.solve_fixed_primary_steam fixed_commands.json \
  --total-steam-mass-kg 748.9919151407566 --steam-generator-quality 0.1 \
  --output artifacts/NEW_FIXED_POINT
atomic-primary-steam-experiment artifacts/NEW_FIXED_POINT/input.json \
  --output artifacts/NEW_FIXED_RUN
```

Пример численных ограничений соответствует исходной точке примера;
для другого проекта ограничения задаются по его физическим запасам.
Предпроцессор поставляется как инженерный скрипт, отдельный установленный
console entry point для него не заявлен.

При успехе сохраняются request/input/steady и manifest с source, бюджетом
и хешами инженерных зависимостей. При несовместимых ограничениях CLI
возвращает 2 и сохраняет request/diagnostics/manifest; `input.json` не создаётся.
Ошибка схемы — ошибка входа. Существующая выходная папка не перезаписывается.

## Сохранённый отказ на точной границе

Первая квалификация включала точку ровно на минимальном давлении конденсатора.
Рабочая модель удержала её 120 с, но независимый эталон завершился в t=0
на нулевой функции события. Этот случай не принят:
[сохранённая регрессия](../validation/ai05_fixed_boundary_endpoint_regression_v1.json).

Версия 2 требует минимум 0.001 Па численного запаса до каждой границы
давления. Это технический запас для конвенции событий, не проектный запас
безопасности установки. Найденное давление не сдвигается; случай на границе
становится обязательной отрицательной проверкой. Допуски точности и
паспортные интервалы не расширены. Общая семантика удержания/возврата на
точной границе остаётся отдельной задачей AI-05.08.

Версия 3 распространяет численный запас на все паспортные границы —
не менее одной объявленной root tolerance в соответствующих единицах.
Точки на границе сухости, скорости и первичного переохлаждения также
отклоняются, без сдвига состояния. Дополнительно исправлена проверочная
температура параметрической модели: она выбирается внутри заданного
интервала температуры/переохлаждения, а не фиксируется на 500 K.
Это позволяет решать допустимые проекты с нижней температурной границей
550 K. [Сохранённые регрессии](../validation/ai05_fixed_boundary_domain_regression_v1.json).

## Численная квалификация и перенос

Матрица содержит прямой/обратный и малый расход, частичное открытие,
теплопотери, разделение первичного/парового нагрева и перераспределение
запасов, а также повышенную нижнюю температурную границу первичной петли.
Каждый из 11 случаев проверяется 120 с методами Radau и BDF;
дополнительно проверяются 12 отказов. Сравниваются независимая абсолютная
траектория, постоянные физические состояния и линейные счётчики энергии.
Порядок сходимости стационарного численного шума не заявляется.

```bash
python -m scripts.qualify_fixed_primary_steam --output artifacts/NEW_FIXED_MATRIX
python -m scripts.qualify_fixed_primary_steam --audit artifacts/NEW_FIXED_MATRIX \
  --output artifacts/NEW_FIXED_AUDIT.json
```

`--reuse-from` разрешает повторное использование только целых raw-пакетов
с теми же входами, source и Python/numpy/scipy. Оценки вычисляются заново.
Аудитор проверяет также замороженные скрипты и исходники отрицательных
случаев. Пакет поставки поддерживает `--fixed`/`--fixed-audit`, переносимый
аудит — `--profile fixed`; см. [runbook поставки](AI_12_EVIDENCE_BUNDLE_RU.md).

Локальная программная регрессия этого блока: **1367 passed, 1 deselected**
(внешний OpenMC/MPI), включая 49 проверок решателя и его свидетельств.
Хеши и команда сохранены в
[baseline](../validation/ai05_fixed_boundary_baseline_v1.json).
Установленный source-matched SDK отдельно воспроизвёл по 120 с на BDF
разделённый нагрев, перераспределение запасов и повышенную температурную
границу: входы, траектории и checkpoint совпали с квалификацией.
См. [проверку установленной поставки](../validation/ai05_fixed_boundary_installed_v1.json).
Зависимости Python/numpy/scipy унаследованы из локального окружения;
удалённая CI и другие платформы здесь не проверялись.

Это решатель конкретной сборки с постоянными свойствами первичной жидкости,
равновесными паровыми запасами и эмпирическими машинами. Общая нелинейная
инициализация произвольного разветвлённого графа, переменная первичная EOS
и экспериментальная/объектная валидация не заявляются.
`validated=false`, `plant_referenced=false`.
