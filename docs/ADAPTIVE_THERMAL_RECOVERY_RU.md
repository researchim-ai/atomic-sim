# Резервная реакция с причинной оценкой температуры

Срез: 11 ноября 2026. Продолжение [подбора постоянной реакции](THERMAL_RECOVERY_TRAINING_RU.md).
Прежние 4% помогали при одном знаке смещения и ухудшали часть опытов с другим.
Теперь библиотека содержит `atomic_model_thermal_recovery`: отдельный
контроллер для публичного синтетического теплового стенда.

## Как устроена реакция

До тревоги контроллер возвращает действие исходной политики и корректирует
оценку температуры стенки по её измерению. При первой тревоге он прекращает
усваивать этот канал. Оценка дальше развивается по аффинной тепловой модели
с фиксированными предположениями о теплоёмкости, проводимости и потерях.
Используются предыдущая температура жидкости, измеренная окружающая
температура и фактически приложенная за прошедший интервал мощность.
Временной контракт совпадает с `ThermalEnv`.

Резервный запрос складывается из теплового feedforward и пропорциональной
поправки по разности цели и оценки. Он ограничен диапазоном [0, 1] и шагом
0,1 относительно предыдущего запроса. Это ограничивает скачок запроса,
но не делает переключение строго безударным. Отдельно среда сохраняет свою
очередь задержки и ограничение скорости фактического нагревателя.

Срабатывание фиксируется до конца эпизода: автоматического возврата на
подозрительный датчик нет. Под конец опыта внешний драйвер принудительно
задаёт ноль и опустошает очередь. Этот хвост имеет приоритет над ограничением
шага резервного запроса; его энергия входит в итоговую стоимость.

Контроллер получает только шесть каналов observation, булеву тревогу и
обычное действие. Истинной температуры, имени отказа и параметров объекта
в его входах нет. Метод возвращает действие, оценку температуры и состояние
тревоги. Checkpoint содержит историю входов; восстановление повторяет её
и сверяет восстановленное состояние. Снимки отделены от рабочего состояния,
невалидные входы не меняют его. Бюджет — 256 наблюдений.

## Что именно проверяет эксперимент

Четыре кандидата объявлены до запуска:

- `continue`: исходная замороженная политика без переключения;
- `four`: прежний запрос 4% после тревоги;
- `model_mid`: оценка с C=300 Дж/К, K=8000 Вт/К;
- `model_light`: оценка с C=150 Дж/К, K=4000 Вт/К.

У обоих модельных вариантов коэффициент пропорциональной поправки равен
40000 Вт/К, потери UA=20 Вт/К. Это два предположения из конечного набора,
а не идентификация параметров установки или непрерывная оптимизация.
Тревогу выдаёт прежний `ThermalMonitor`, который не изменялся.

Обучающая матрица: два прежних train-объекта, seed 810, здоровый датчик,
смещения −0,1 и +0,1 К с шага 2, зависание с шага 2, ошибочная гипотеза
наблюдателя. Итого 4 × 2 × 5 = 40 эпизодов. Выбор минимизирует худшее
среднее J по группе сценариев, затем общее среднее и id. Незавершённые
кандидаты исключаются; неполная матрица, NaN и подмешивание test отклоняются.

Замороженный выбор записывается до оценки. Test включает четыре прежних
оценочных объекта, seed 910/911, смещения ±0,25 К с шага 5, зависание с
шага 5, healthy и ошибочную гипотезу наблюдателя. Сравниваются `continue`,
`four` и выбранный вариант: 4 × 2 × 5 × 3 = 120 эпизодов.

Основное управление удлинено с 8 до 16 шагов по 0,25 мс: 4 мс плюс хвост.
Базовая imitation-политика не дообучалась. Изменение горизонта меняет её
вход нормированного времени: это также проверка переноса горизонта.
Сохраняются прежние J, IAE, энергия и порог ухудшения относительно своего
healthy-пути. Завершение расчётов отделено от качества управления.

Дизайн учитывает результаты предыдущих открытых опытов. Новые seed,
амплитуды и моменты отказа не делают его слепой независимой приёмкой.
Никакая настройка по результатам текущего test не выполняется.

## Ограничения

После тревоги модель работает без коррекции стенки и накапливает ошибку.
Остальные каналы считаются исправными. При тревоге с первого наблюдения
начальная оценка всё ещё берётся из первого измерения: неизвестное
начальное смещение этот метод не устраняет. Сам монитор может пропустить
отказ или сработать на неверную модель. Сигнал не доказывает, что сломан
именно датчик стенки.

4 мс — более длинный, но всё ещё короткий синтетический опыт. Здесь нет
доказательства ограниченности ошибки на длительном горизонте, подтверждения
на оборудовании или допуска к промышленному управлению. Физическое ядро
не менялось. Ни выигрыш одного кандидата, ни прохождение тестов не означают
превосходства над другими моделерами.

## Воспроизведение

```bash
python -m pytest -q tests/test_adaptive_thermal_recovery.py
python -m scripts.train_adaptive_thermal_recovery --training artifacts/thermal-energy-v1/training.json --output artifacts/my-adaptive-recovery
```

Сначала установите библиотеку с новым пакетом. При запуске из исходников
без обновления editable-установки можно задать `PYTHONPATH=src`.
Для базовой политики нужны её `training.json` и исходный `protocol.json`;
драйвер проверяет их происхождение до создания результатов.

## Использование библиотечного компонента

```python
from atomic_model_thermal_recovery import RecoveryConfig, ThermalRecovery

controller = ThermalRecovery(RecoveryConfig(max_command_step=0.1))
# Стенка, жидкость, цель, окружение: температуры минус 440 К.
# Далее: фактическая мощность / максимум и нормированное время.
observation = [0.0, 0.0, 0.3, -10.0, 0.0, 0.0]
decision = controller.act(observation, alarm=False, normal=0.2)
saved = controller.checkpoint()
restored = ThermalRecovery.restore(saved)
```

Передавайте одно наблюдение на каждый шаг `dt_s`. `normal` — запрос базовой
политики, а не фактическая мощность; последняя должна находиться в пятом
канале наблюдения. Повторный вызов `act` для того же физического шага
продвинет модель ещё на один шаг. Новый эпизод начинается новым экземпляром.

## Результаты зафиксированного запуска

Выбран `model_light`; все 40 train- и 120 test-эпизодов завершены.

По сравнению с `continue` выбранная реакция имеет меньший J в 20/40 путях, равный в 12/40 и больший в 8/40. Средние J: 0.530254 и 0.632116 соответственно.

По сравнению с `four` выбранная реакция имеет меньший J в 17/40 путях, равный в 12/40 и больший в 11/40. Средние J: 0.530254 и 0.534589 соответственно.

- `bias_high`: 0 / 0 / 0.
- `stuck`: 0 / 0 / 0.
