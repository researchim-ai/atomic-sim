# Версионированное исследование: модель, данные и сравнения

4 ноября 2026. Пакет `atomic_model_study`, CLI `atomic-model-study` и режим
`atomic-model-project-ui --study`. Область: принятые EOS-пресеты и две встроенные
детерминированные политики. Это программная воспроизводимость; реальные
экспериментальные данные и физическая валидация этим блоком не получены.

## Что реализовано

1. Единая ревизия нормализованной модели, сценариев, политик и привязок данных.
   SHA-256 цепочка, CAS, один writer, атомарный HEAD, 64 ревизии. История не
   переписывается; restore создаёт новую ревизию вместе с прежними привязками.
2. Content-addressed объекты эталонов: исходный CSV, оригинальная декларация,
   переносимая декларация, нормализованные значения и manifest. Копируются
   только объявленные файлы; посторонние файлы не попадают в снимок. Перед
   публикацией данные перечитываются и синхронизируются на диск.
3. Preview импорта работает во временном каталоге и не создаёт объектов в
   рабочем проекте. Ошибки SHA, schema, unit, path, policy, problem и role
   сохраняют прежний HEAD. Привязок не более 32.
4. Проверяется полное соответствие EOS problem (конфигурация и политика).
   `train/dev/test` соответствуют `calibration/validation/test`. Каталог
   блокирует пересечение физических случаев/CSV/нормализованных кривых между
   ролями. Это консервативный guard, а не проверка подлинности источника.
5. Изменение модели, несовместимое с данными, отклоняется. Требуется явно
   отсоединить эталон, изменить модель и заново объявить соответствующие данные.
   Произвольное автоматическое переназначение reference запрещено.
6. Переносимый data-only снимок: относительные ссылки, manifest всех
   объявленных файлов, проверка размеров/хешей/путей/симлинков и согласованности
   модели с данными до создания выходного хранилища. Новый журнал начинается
   с ревизии 0; история и выполненные оценки не входят в этот снимок.
7. Расчёт закрепляет полную study-ревизию и binding. Управляемый отдельный
   Linux-процесс, один CPU из доступной affinity, BLAS threads=1, wall deadline
   со старта процесса, наблюдаемый RSS, журнал попытки. Это trusted worker,
   не sandbox для чужого Python-кода и не cgroup quota. Монитор опрашивает
   процесс каждые ~25 ms, поэтому возможен кратковременный overshoot лимита.
8. Отмена/продолжение используют принятые native checkpoints. Незавершённая
   первая публикация без HEAD сохраняется отдельно как `incomplete-job` и
   не считается прогрессом. До 32 попыток, каждая со своим отчётом и логом.
9. Parent-death signal и постоянный порождающий поток защищают от осиротевшего
   вычисления. После аварии супервизора нужен явный `recover`: живой/повторно
   использованный PID консервативно отклоняется, неизвестные процессы не
   завершаются. Удаляется только lock с PID подтверждённо завершённого worker.
10. `completed` и `comparison_passed` различаются. Отрицательный эталон даёт
    законченный расчёт с `comparison_passed=false`; timeout/RSS/cancel не
    создают фиктивного отчёта. Новая study-ревизия помечает старый результат
    `stale=true`, но закреплённый отчёт остаётся доступным.
11. Отчёт перед выдачей проходит exact replay метрик и проверку reference/job
    identity. Доступны ошибки, события, причины останова, глобальные и локальные
    ledgers. Кривые содержат все сохранённые узлы решения и эталона в окне
    сравнения, с линейной интерполяцией на границах; внутренние solver substeps
    не подменяются решающими узлами и не выдаются как сохранённые измерения.
12. UI: JSON+CSV file picker, preview/attach/detach, запуск/poll/cancel/resume,
    загрузка сохранённого расчёта по ID, отчёт, SVG-кривые и экспорт study.
    Сохранились loopback Host/Origin/token/CSP guards. Upload передаёт байты,
    не пути файлов сервера: CSV до 8 MiB, декларация/request до 1 MiB,
    общий upload body до 12 MiB; прочие запросы по-прежнему до 1 MiB.

## Воспроизводимый запуск

```bash
python -m examples.eos_study_workflow --output artifacts/my-study
atomic-model-project-ui artifacts/my-study/study --study --port 8765
```

В примере нулевой энергетический residual проходит критерии, постоянная
температура стенки намеренно не проходит. Оба эталона синтетические. После
export/import повторно вычисленные channel/event метрики совпадают точно.
Не используйте одинаковый существующий output: все публикации отказываются
перезаписывать чужой каталог.

CLI: `create`, `inspect`, `preview`, `edit`, `attach-preview`, `attach`,
`detach`, `restore`, `export`, `import`, `evaluate`, `status`, `summary`,
`curve`, `recover`, `resume`. JSON request для attach использует schema_version,
expected_revision, expected_checkpoint_sha256, id, scenario_id, policy_id, note;
декларация добавляется из отдельного аргумента пути с проверенным CSV.
`evaluate` синхронно ждёт supervised worker. При провале критериев/расчёта exit=2.
`restore --expected-sha256` принимает **project_sha256**, остальные CAS-команды
с этим флагом — **checkpoint_sha256**; оба видны через inspect.

```bash
atomic-model-study inspect artifacts/my-study/study
atomic-model-study recover artifacts/my-study/study EVALUATION_ID
atomic-model-study resume artifacts/my-study/study EVALUATION_ID
```

Recover применим только после аварии с оставленным marker и подтверждённо
завершённым worker. После обычной отмены достаточно resume. Продолжение
устаревшей study-ревизии отклоняется; можно выполнить новый расчёт текущей.
Текущий source guard строгий: изменение кода требует старого runtime для старых
журналов либо переноса data-only snapshot в новый runtime, без автопереименования
старых результатов. Базовый model-only редактор запускается без `--study`.

## Проверки и границы приёмки

Пройдены 121 связанная unit/integration-проверка, 23 HTTP-проверки
и 89 регрессий public runtime/workspace (233 уникальные проверки);
окончательные количества и portable проверки записаны
в `validation/ai11_study_delivery_v1.json`. HTTP/Chromium требуют разрешённых
loopback sockets; внешняя сеть не используется. Сохранены реальные положительный
и отрицательный расчёты, exact replay и скриншоты desktop/mobile.

AI-11.01 развивается в ограниченном EOS schema-scope. Общий registry моделей,
произвольная топология, подключаемые агенты, статистический UQ, ensembles и
полное сравнение многих экспериментов не заявлены. AI-11.04 остаётся открытым
за пределами model/reference сравнения. Все флаги `validated` и
`plant_referenced` остаются false. Проход программных тестов не подтверждает
промышленную точность физики, применение к реальной установке или безопасность
управления ею.

Отдельный контроль более длинного запуска (0.3 s, action_dt=0.001 s)
сохранил штатный отказ native `numerical:numerical_contract`: study возвращает
`status=rejected`, без отчёта/metric pass и с отказом resume терминального
задания. Численные бюджеты/уравнения ради прохождения этого контроля не менялись.
Это ограничение native случая, а не доказательство пригодности длительных
траекторий; положительные примеры используют поддержанный короткий случай.
