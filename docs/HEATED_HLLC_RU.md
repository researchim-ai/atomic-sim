# Нагреваемая жидкостная сеть HLLC

Срез: 10 ноября 2026. Новый опциональный пакет `atomic_model_hem_heated`
добавляет предписанные мощности и линейный теплообмен к жидкостному HLLC.
Прежний `ContactHEMNetwork` остаётся адиабатическим, его исходники и подпись
не менялись. Запреты прежнего режима не снимаются.

## Физическая постановка

`HeatedHEMNetwork` использует конечные объёмы и EOS квалифицированного
семейства. Разрешена только жидкость Region 1, с прежними ограничениями
Маха, характеристических скоростей, температуры и положительности запасов.
Нагрев не разрешает пересечение насыщения: неподдержанный этап отклоняется
с откатом всего вызова. Трение, кипение и корреляционные коэффициенты
теплоотдачи отклоняются при создании модели.

Для стенки с постоянной теплоёмкостью C и проводимостью K:

- тепло в жидкость: Q = K(Tw − Tf);
- энергия стенки: C·dTw/dt = Pw + UA(Ta − Tw) − Q;
- внешний нагрев жидкости Pi добавляется к её полной энергии;
- обмен Q добавляется в энергию связанной ячейки с противоположным знаком
  относительно стенки.

Внешняя энтропия имеет скорость ΣPi/Ti + Σ[Pw/Tw + UA(Ta−Tw)/Ta].
Тепловое производство энтропии равно
Σ[K(Tw−Tf)²/(Tw·Tf) + UA(Ta−Tw)²/(Ta·Tw)] и неотрицательно.
Энтропийный остаток дискретного транспорта хранится отдельно.

Сборка источников, стенки и энтропийных ledger-полей наследуется от
`QualifiedHEMNetwork`. Для HLLC заменяются консервативные потоки граней,
запасы и реакции неподвижных узлов. Масса и энергия каждого внутреннего
потока добавляются в соседние объёмы с противоположными знаками.
В этой первой реализации родитель сначала вычисляет поток Русанова;
затем транспорт заменяется. Приоритет здесь — проверяемость источников,
ускорение такого RHS пока не заявлено.

## Интерфейс

```python
from atomic_model_hem_heated import HeatedHEMNetwork
from scripts.verify_heated_hllc import request_for, CAPS

request = request_for('branched_pulse', CAPS[-1])
model = HeatedHEMNetwork(request, scheme='hllc-local')
controls = model.snapshot()['controls']
controls['fluid']['a'] = 2000.0
result = model.step(controls, 0.0001,
                    expected_revision=0, controller_state={'tick': 1})
checkpoint = model.checkpoint()
restored = HeatedHEMNetwork(request, scheme='hllc-local')
restored.restore(checkpoint)
```

Поддерживаются `rusanov`, `hllc`, `hllc-local`. Восстановление воспроизводит
историю команд в новом экземпляре. Проверяется конечный канонический JSON
всего checkpoint, включая знак нуля. Модель, схема, запрос и подпись
должны совпасть; ошибочный replay не меняет живое состояние.

## Матрица численной проверки

Стенд использует прежнюю сеть: четыре узла, пять труб разного диаметра,
два цикла, две ячейки на трубу. Три сценария:

- равномерное изохорическое нагревание при одинаковых начальных p/T и
  мощности 100 кВт/м³ — проверяется точная скорость роста энергии;
- релаксация горячей стенки: Tw=460 К, C=100 Дж/К, K=10000 Вт/К,
  UA=20 Вт/К, Ta=430 К;
- тот же теплообмен с мощностью узла a 10 кВт и стенки 5 кВт;
  в 0,1 мс мощность узла переключается на −5 кВт, стенки — на ноль.

На двух схемах HLLC выполняются по три ограничения шага: 20, 10, 5 мкс.
Всего 18 нативных путей, шесть решений DOP853, времена наблюдения
0; 0,1; 0,25; 0,5 мс; checkpoint в 0,25 мс с точным продолжением.
DOP853 использует общий RHS/EOS: это независимый временной интегратор,
а не независимая реализация физических уравнений. Его параметры:
rtol=2·10⁻¹¹, atol=10⁻¹¹, максимальный шаг 2,5 мкс.

Обязательна точность шести путей на шаге 5 мкс. Грубые шаги служат
проверкой сходимости: ошибка давления должна уменьшаться как минимум
до 0,8 предыдущей с численным полом 0,001 Па. У исходных горячих сценариев
шаг 20 мкс не проходит допуск 0,1 Па; это ограничение сохранено в отчёте.
На шаге 10 мкс горячие сценарии также слегка превышают допуск импульса
10⁻⁸ кг·м/с. Из 12 грубых сравнений полностью проходят четыре
(равномерный нагрев); все шесть обязательных сравнений на 5 мкс проходят.
Допуски не увеличивались для принятия грубого шага.

Сравниваются давление, температура, масса, энергия и импульс жидкости;
температура стенки, переданное и внешнее тепло; внешняя энтропия и тепловое
производство. Проверяются балансы массы/энергии, положительность запасов,
область жидкой фазы, исходные аналитические тождества источников и restart.

## Тесты и воспроизведение

28 тестов проверяют источники, точное совпадение ветви Русанова с основной
моделью, изохорическую энергию, управляемый нагрев, restart, отказы на
неподдержанной физике и отказ по бюджету мощности. Дополнительная stage-проба подаёт
допустимую мощность 1 МВт при начальной температуре стенки 899,999 К:
выход этапа за предел 900 К отклоняется, checkpoint сохраняется точно,
дальнейшее продолжение совпадает с чистой моделью. Сравнение отклоняет NaN,
несогласованные времена и пропавшие данные стенки. Прежний адиабатический
класс продолжает отклонять нагреваемый запрос.

```bash
python -m pytest -q tests/test_heated_hllc.py
python -m scripts.verify_heated_hllc --output artifacts/my-heated-hllc
python -m scripts.verify_local_library --suite library --output artifacts/my-delivery
```

[Публичный протокол и результаты](benchmarks/heated_hllc_benchmark_v19.json).
Полные локальные данные: `artifacts/heated-hllc-v3/`.
На меньшем шаге максимальная ошибка давления относительно DOP853 —
0,00482 Па, температуры стенки — менее 1,9·10⁻¹¹ К. Эти ошибки относятся
к данной короткой матрице с общим RHS и не являются оценкой физической точности.

Поставка: 1109 тестов прошли; выполнены все восемь фаз локальной проверки.
Один нагреваемый путь с переключением мощности и restart точно повторён
из свежего wheel вне checkout, в изолированном Python. Полная матрица
и DOP853 из wheel повторно не запускались. Научные зависимости
переиспользованы из локального окружения без сети.

Этот блок не квалифицирует CHF, двухфазный HLLC, трение или экспериментальное
соответствие. Следующий шаг — отдельная проверка источника трения и его
энтропийного баланса, более длительные тепловые переходы и независимая
сборка нагреваемых уравнений.
