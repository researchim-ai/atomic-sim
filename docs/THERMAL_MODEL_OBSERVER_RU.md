# Тепловой наблюдатель согласованности модели и измерения

Срез: 11 ноября 2026. Продолжение [испытания датчиков](THERMAL_SENSOR_STRESS_RU.md).
Добавлен отдельный пакет `atomic_model_thermal_observer`; физическое ядро,
прежняя среда и её подписи не менялись.

## Задача и граница вывода

Монитор трёх одинаковых отсчётов обнаруживал заданное зависание, но пропускал
смещение. Новый монитор сопоставляет следующее измерение стенки с прогнозом
линейного теплового баланса, используя **фактически приложенную мощность**.
Запрос контроллера не подставляется вместо мощности после задержки и slew.

Монитор не получает истинное состояние, тип отказа или точные параметры
конкретной test-конфигурации. Доступны только прежние шесть наблюдений,
шаг времени и номинальная максимальная мощность нагревателя.

Обнаруженное расхождение не позволяет однозначно отличить неисправность
датчика от неверного физического приближения. Поэтому результат называется
`measurement_model_inconsistency`, а не «датчик сломан». Отдельный unit-тест
показывает тревогу при здоровом измерении и неправильно заданной теплоёмкости.

## Физическая гипотеза

Используется уравнение стенки:

`C*dTw/dt = P − K*(Tw−Tf) − UA*(Tw−Ta)`.

При постоянных Tf, Ta, P и коэффициентах точное обновление имеет вид:

`Tw_next = Tw + (T_equilibrium−Tw)*(1−exp(−(K+UA)*dt/C))`,

`T_equilibrium = (P + K*Tf + UA*Ta)/(K+UA)`.

Разность экспонент вычисляется через `expm1`. Для каждого интервала берутся
крайние значения гипотез C=100…500 Дж/К, K=1000…15000 Вт/К и UA=0…100 Вт/К.
Предыдущее измерение стенки расширяется на ±0,02 К; диапазон измерений жидкости
на концах шага — также на ±0,02 К. Минимум и максимум прогнозов дополнительно
расширяются на 0,003 К для инженерного модельного запаса.

Если полоса текущего измерения ±0,02 К не пересекается с прогнозной полосой,
сохраняются величина разрыва и сигнал несогласованности. Три точно одинаковых
отсчёта по-прежнему дают отдельную причину `repeated_reading`.
Первая тревога защёлкивается и сохраняет индекс, время и причины.

Это **оболочка выбранных угловых гипотез**, не доказанное интервальное
ограждение всех непрерывных значений параметров. Температура жидкости внутри
шага может отличаться от приближения по концам, а численные запасы не
калиброваны по измерениям оборудования. ±0,02 К не является заявленной
доверительной вероятностью: гауссовский шум математически не ограничен.

До тревоги прогноз каждого следующего шага опирается на предыдущее измерение.
Медленный дрейф может оставаться согласованным и не обнаруживаться. После
тревоги она остаётся защёлкнутой; отсюда не следует корректность диагноза
или достаточная точность дальнейшего прогноза.

## API и воспроизведение состояния

```python
from atomic_model_thermal_observer import ThermalMonitor

monitor = ThermalMonitor()
report = monitor.observe([0.0, 0.0, 0.3, -10.0, 0.0, 0.0])
saved = monitor.checkpoint()
restored = ThermalMonitor.restore(saved)
```

Вектор имеет прежний формат ThermalEnv: температуры относительно 440 К,
доля фактической мощности и доля прошедшего времени. `observe` возвращает
копию диагностики; изменение ответа или checkpoint не изменяет монитор.
Некорректные/NaN-входы отклоняются до изменения состояния.

Checkpoint содержит конфигурацию, до 256 наблюдений и подписи собственного
пакета. Восстановление повторяет наблюдения и сравнивает полный конечный JSON.
Хеши контролируют целостность и версию кода, не криптографическую подлинность.
Перенос между аппаратными/численными платформами отдельно не квалифицировался.

## Эксперимент с управлением

Коэффициенты обученной политики берутся из прежнего train-only подбора.
Пороги монитора заранее фиксированы; по новым test-результатам не выбираются.
На четырёх test-конфигурациях с новыми seed 510/511 выполняются три сценария
healthy/bias_low/stuck и три политики: исходная откалиброванная политика,
монитор повторов с резервной политикой и новый наблюдатель с той же резервной
политикой. Всего 72 эпизода. В active-части резервный запрос — 4% мощности;
в хвосте всегда ноль, чтобы опустошить очередь исполнительного устройства.

Сохраняются полные входы политики, прогнозные границы, остатки, первая тревога,
истинные состояния только для оценки, расход энергии и IAE. Сигнализация
может возникнуть и в хвосте: её время нужно отличать от своевременного
переключения во время управления. Общий факт тревоги не равен улучшению IAE.
Завершение solver и устойчивость управления остаются разными критериями.

Матрица использует прежние синтетические скачок −0,15 К и точное зависание
со второго наблюдения. Это не широкий корпус отказов или доказательство
распознавания произвольного смещения. Энергия и ошибка после завершения
управления учитываются, но полного установления теплового режима нет.

```bash
python -m pytest -q tests/test_thermal_observer.py
python -m scripts.benchmark_thermal_observer --training artifacts/thermal-energy-v1/training.json --output artifacts/my-thermal-observer
```

Локальные данные: `artifacts/thermal-observer-v1/`.
[Машинный протокол и результаты](benchmarks/thermal_model_observer_v25.json).

## Измеренный результат и непринятая реакция

Все 72 численных эпизода завершились без наблюдаемых нарушений, с хвостом
для опустошения очереди. На восьми healthy-путях observer_guard не дал тревог.
При скачке смещения он подал сигнал в 8/8 случаев, а repeat_guard — в 0/8.
При зависании оба дали сигнал в 8/8 случаев. Это результаты данной матрицы,
не вероятности обнаружения произвольных отказов.

**Обнаружение улучшилось, но резервная реакция при смещении ухудшилась.**
С observer_guard порог ухудшения IAE относительно собственного healthy
превышен в 4/8 случаев, против 2/8 у исходной политики и repeat_guard.
Средняя IAE при bias — около 0,000618 K·с против 0,000569 без переключения.
При stuck оба монитора дали 0/8 превышений против 4/8 без них.
Поэтому фиксированные 4% не принимаются как улучшенная универсальная реакция.
Пакет ThermalMonitor только сообщает диагностику и сам мощностью не управляет.

Диагностика наблюдателя сохраняется для всех политик; поле alarm_index
обозначает тревогу выбранного механизма политики. Отдельно в публичной
сводке посчитаны тревоги до конца активного управления.
Метрики всех трасс пересчитаны, checkpoint каждого монитора восстановлен точно.
Пройдено 1223 теста и восемь фаз локальной поставки; один bias-эпизод и replay
монитора точно повторены из wheel вне checkout. Полная матрица из wheel
не повторялась.

включающих ошибки датчика и модели, а новые амплитуды/времена отказов
оставлять для оценки. Подбор по уже увиденным test-результатам не считается
независимым подтверждением улучшения.

Установить измеренные границы шума и модельной ошибки, добавить квантование,
медленный дрейф и ошибки измерения мощности; проверить параметры вне выбранных
гипотез; оценить ложные тревоги на длительных здоровых режимах. Резервные 4%
также требуют собственной проверки для каждого объекта. Наблюдатель пока
не обосновывает безопасное управление промышленным оборудованием.
