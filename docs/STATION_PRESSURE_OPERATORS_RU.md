# Согласованность операторов давления v71

Дата: 17 ноября 2026.

В [v70](STATION_INITIALIZATION_RU.md) начальная скорость была явно
подготовлена с дивергенцией порядка 10⁻¹⁶, но последующая внешняя динамика
снова дала остаток около 0,00745. Новый блок отделяет одну проверяемую
причину: согласованность дискретного уравнения давления с теми операторами,
которыми измеряется непрерывность.

**На изготовленных задачах подтверждено, что отдельно собранный лапласиан
и композиция `div_h grad_h` различаются. Реализовано отдельное совместимое
решение скалярной задачи давления.** Это исследовательский компонент;
внешний интегратор и станционный backend не изменены. Полная динамика,
условия прилипания и регулярность у оси этим результатом не приняты.

## Почему малой невязки Пуассона недостаточно

Для одной Fourier-моды градиент и дивергенция имеют вид:

```text
G_h p = [D_scalar p, i*m*p/r, i*alpha*k*p]
D_h u = D_vector ur + ur/r + i*m*ut/r + i*alpha*k*uz
```

Скалярное и радиальное векторное поля имеют разную чётность при отражении
через ось: соответственно (-1)^m и (-1)^(m+1). Первая производная строится
по исходному девятиузловому шаблону, укороченному около стенки.

В исходном коде радиальный лапласиан собирается через отдельную вторую
производную. Полный оператор скалярной моды:

```text
L_fd = D2_scalar + (1/r) D_scalar - m²/r² - (alpha*k)²
L_compatible = D_h G_h
```

При конечном шаге `D2_scalar` не обязана совпадать с композицией двух
первых производных с их чётностями и укороченными шаблонами. Разница
операторов существует даже при очень точном решении линейной системы.

Если во внутренних строках решено `L_fd p = D_h u`, то после коррекции
`u_new = u - G_h p` остаётся:

```text
D_h u_new = (L_fd - D_h G_h) p
```

Это тождество относится к внутренним строкам. Строка у стенки заменяется
граничным условием и контролируется отдельно. Оно не утверждает, что всё
расхождение реального внешнего интегратора вызвано только этим эффектом:
там также есть вязкость, граничная коррекция и временная схема.

## Проверка исходного оператора

`scripts/replay_station_pressure_operators.py` заново извлекает проверенный
[официальный архив Openpipeflow-hp](https://www.openpipeflow.org/images/5/53/Openpipeflow-hp-1.21.tgz),
собирает только сеточную часть на N=32/64/96 и экспортирует коэффициенты
первых и вторых радиальных производных, включая отражённые узлы.
Не запускается временная эволюция. Меняются только размеры в параметрах;
исходный `meshs.f90` остаётся неизменённым. Самостоятельная Fortran-программа
лишь выводит уже построенные коэффициенты.

SHA-256 архива:
`4652325064ce4ecb2b351875d17bf1b3baa58f2f89529c365191bc9ad98bc269`.

Python независимо строит производные из условий точности полиномов.
Максимальная относительная разница с родными коэффициентами —
**2,97239·10⁻¹²** при объявленном допуске 10⁻⁹.
Экспортируются исходные радиальные операторы, а не готовая матрица
с заменённой граничной строкой давления; эти два уровня не смешиваются.

## Изготовленные решения

Использовано гладкое скалярное поле:

```text
p(r) = r^m F(r²), F(s) = (1-s)² exp(s)
dp/dr = r^(m-1) [m F + 2s F']
Lap(p) = r^m [4(m+1)F' + 4sF'' - (alpha*k)² F]
```

На каждой из трёх сеток проверены m=0/1/2/4; для средней моды k=0,
для остальных k=3, alpha=0,628319. Всего 12 задач.
Аналитический лапласиан позволяет отдельно оценить аппроксимацию
континуума; алгебраическая совместимость проверяется через RHS=`D_h G_h p`.
Это разные критерии: точный дискретный solve не обнуляет ошибку
аппроксимации дифференциального уравнения.

Для ненулевых мод явно задаётся производная давления на стенке, вычисленная
тем же дискретным оператором на изготовленном решении. Для k=m=0
используется отдельное условие калибровки давления. Одновременное задание
несовместимых граничных данных отклоняется.

Максимальная ошибка восстановления изготовленного давления совместимым
решателем — **9,65894·10⁻¹⁵**. Максимальная нормированная внутренняя невязка
`D_h G_h` — **6,69169·10⁻¹³** при допуске 10⁻⁹.

Например, для m=2, k=3:

- N=32: исходный FD-solve оставляет внутренний остаток 4,05167·10⁻⁴,
  совместимый — 7,10543·10⁻¹⁴.
- N=64: соответственно 7,73445·10⁻⁶ и 1,68754·10⁻¹³.
- N=96: соответственно 7,84496·10⁻⁷ и 3,18856·10⁻¹³.

Эти цифры относятся к скалярным изготовленным задачам, а не к новой
траектории турбулентного поля или АЭС.

## Граница и оставшийся отказ

Условие Неймана ограничивает радиальный градиент давления. Оно само по
себе не обнуляет осевой и азимутальный градиенты на стенке. Поэтому
коррекция скорости градиентом может нарушить касательное прилипание.
Отдельный отрицательный тест подтверждает этот случай даже при малой
внутренней невязке совместимого solve.

Библиотека возвращает невязку заменённой стеночной PDE-строки отдельно;
она не включается скрытно в успешно пройденный внутренний критерий.
Квитанции сохраняют:

```text
external_time_integrator_modified = false
no_slip_preservation_qualified = false
axis_regularity_qualified = false
time_integrator_qualified = false
dynamic_continuity_qualified = false
station_usable = false
```

Замена `L_fd` на `D_h G_h` в существующем внешнем интеграторе не выполнена:
для её принятия нужны согласованные граничная коррекция, начальное давление,
векторная регулярность у оси, вязкие операторы и проверка временного шага.
Прежние внешние исходники и отрицательные результаты v69/v70 сохранены.

## Воспроизведение

Компактный аудит использует упакованный экспорт коэффициентов и не требует
Fortran, сторонних checkpoints или сети. Директория вывода новая.

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH="$PWD/src:$PWD" \
  .venv-layout/bin/python -m scripts.qualify_station_pressure \
  --output artifacts/my-pressure-audit

OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv-layout/bin/python -m pytest -q tests/test_station_pressure.py \
  tests/test_station_initialization.py tests/test_station_spectral.py \
  tests/test_station_spectral_qualification.py tests/test_station_quadrature.py \
  tests/test_station_quadrature_qualification.py
```

Для нового экспорта из оригинального Fortran нужны проверенный архив,
компилятор и локальные зависимости, описанные в v69:

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH="$PWD/src:$PWD" \
  .venv-layout/bin/python -m scripts.replay_station_pressure_operators \
  --output artifacts/my-native-pressure-export \
  --archive artifacts/Openpipeflow-hp-1.21.tgz \
  --dependencies artifacts/heated-reference-deps
```

Сторонний исходник и двоичные файлы остаются в `artifacts/`; wheel содержит
собственный Python-код и компактные коэффициенты с происхождением.

[Машинная квитанция v71](benchmarks/station_pressure_v71.json) содержит
критерии, все 12 случаев и проверку поставки. Пройдено **137 целевых тестов,
включая 25 новых**. Полный прогон 2261 теста относится к историческому v69;
он не объявляется полным повторным прогоном v71.

Следующий шаг — совместная проверка градиентной коррекции с граничными
условиями скорости и регулярностью векторных мод, затем вязкая динамика
и уточнение по времени. Станционная приёмка остаётся **48/76**, открыто 28;
NPP-11.03/04 и R1 не закрыты.


Проверка поставки: свежий Python `-I` вне checkout, установка wheel без сети, побайтно одинаковый отчёт всех 12 задач. Проверены байты 816 Python-модулей/скриптов и упакованный экспорт коэффициентов. Сырые родные файлы и двоичные программы отдельно проверены по контрольным суммам.


Следующий этап — [регулярная линейная динамика Стокса v72](STATION_REGULAR_STOKES_RU.md). В отдельном вариационном компоненте регулярность, прилипание и несжимаемость удерживаются при вязкой эволюции с проверенным балансом энергии. Физическое давление, нелинейная и тепловая динамика остаются открытыми.
