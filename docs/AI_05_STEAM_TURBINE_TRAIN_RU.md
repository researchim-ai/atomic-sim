# AI-05.06: паровая турбина, вал и генератор

Дата: 1 ноября 2026. Engine `saturated-steam-turbine-generator`, версия 1.0.0.
Следующий компонент после [двух насосных петель с общей стенкой](AI_05_COUPLED_EXCHANGER_RU.md).
Паровой тракт здесь имеет заданные давления и расход; интеграция с расчётными
запасами парогенератора/конденсатора остаётся отдельным шагом AI-05.06.

## Термодинамика и область

Вход — сухой насыщенный пар при фиксированном давлении. Изоэнтропийная
опорная точка выхода должна лежать внутри купола насыщения при выходном
давлении. Свойства рассчитывает существующий backend IF97; основание —
[официальная формуляция IAPWS-IF97](https://iapws.org/technical-guidance/release/IF97-Rev).
В этой работе не расширяется область backend: насыщение выше его текущего
предела 623.15 К не подменяется экстраполяцией.

```text
x_is = (s_in - s_f,out) / (s_g,out - s_f,out)
h_is = h_f,out + x_is (h_g,out - h_f,out)
h_out = h_in - eta_is (h_in - h_is)
P_steam = mass_flow (h_in - h_out)
```

Эффективность задаётся явно и постоянна. Actual-выход проверяется по `(p,h)`;
он может быть влажным либо перегретым. Удельная энтальпия и энтропия не
обрезаются к границе насыщения. Проверяется положительная работа расширения
и неотрицательное производство энтропии с допуском округления.

Оба массовых порта имеют один и тот же неотрицательный расход; запасов
массы и энергии внутри проточной части нет. Разность входной и выходной
энтальпийных мощностей поступает на вал ровно один раз. Отдельное трение
турбины поверх заданной эффективности не добавляется.

Модель не задаёт карту лопаточного аппарата, расход сопла, choking, влажностные
поправки или характеристику изготовителя. Заданный расход не считается
решением паровой гидравлики. Эффективность — входной параметр, а не результат
идентификации конкретной машины.

## Вал, генератор и потери

Динамическое состояние — кинетическая энергия ротора `K=J omega²/2`.
Генератор создаёт противодействующий момент `G omega`; при размыкании
соединения этот момент точно нулевой. Подшипники дают момент `B omega`.

```text
dK/dt = P_steam - (G_connected + B) 2K/J
P_electric = eta_gen G_connected 2K/J
Q_generator = (1 - eta_gen) G_connected 2K/J
Q_bearing = B 2K/J
```

Электрическая энергия, потери генератора и подшипников интегрируются
раздельно. Их сумма с приращением K равна полученной от пара работе.
Изменение электрического КПД перераспределяет электричество и тепло,
не меняя механическую нагрузку `G omega`.

Нет напряжения, реактивной мощности, угла ротора относительно сети,
синхронизации нескольких генераторов или электрических коротких замыканий.
Подключение обозначает наличие объявленного диссипативного момента,
а не подтверждённую устойчивость электрической сети.

При постоянных управлениях уравнение K линейно. Шаг и интегралы его
мощностей вычисляются аналитически с `expm1` и устойчивым рядом для малого
коэффициента затухания. Проточная часть алгебраическая. Истории численного
решателя и разделения шагов механики/термодинамики нет.

## Рабочий диапазон и физический выход

В конфигурации обязателен диапазон `0 < omega_min < omega_max`.
Холодный пуск, остановленный ротор и обратное вращение не поддержаны.
Момент турбины `P_steam/omega` публикуется только внутри этого диапазона;
ограничение не заменяется искусственным знаменателем около нуля.

При сбросе нагрузки ротор может достичь верхней границы. При отключении
пара — нижней. `advance` отклоняет пересекающий границу интервал с
`ModelLimitError`, сохраняя принятое состояние; исключение содержит
аналитически найденное время пересечения.

`advance_until_limit` принимает согласованный префикс до самого корня
и возвращает отдельную запись `speed_limit`. Допускается только поправка
энергии в найденном корне не больше 10% энергетического бюджета;
её значение публикуется как `projection_j`. Это округление локализованного
корня, не обрезание конечной энергии по выходному шагу.

После граничного checkpoint можно задать возвращающее управление и
продолжить расчёт внутри области. Выход за паспорт не выдаётся за
автоматическую защиту, разрушение турбины или принятый полный эпизод.

## SDK, команды и восстановление

Полный атомарный вектор содержит расход пара, коэффициент нагрузки
генератора и строгий boolean подключения. Отрицательные/неконечные
параметры и неполный вектор отклоняются целиком. Команда не меняет
кинетическую энергию и уже накопленные интегралы.

Численный отказ или отказ проверки внутри интервала вывода откатывает
состояние, команды и промежуточные строки этого интервала. Физический
выход, напротив, сохраняет допустимый префикс до границы и прекращает job.
Статусы и коды CLI различаются:

- `completed`: полный горизонт, exit code 0;
- `domain_exit`: допустимый префикс до физической границы, exit code 2;
- `failed`: вычислительный/контрактный отказ, exit code 1.

У `domain_exit` поле `numerical_acceptance=false`: прохождение префикса
не означает выполнения всего запроса. `accepted_prefix=true` отделяет
этот случай от численного отказа. В report сохраняется причина и точное
время границы. Deadline — проверка между шагами, не жёсткая изоляция ОС.

Snapshot schema 1 содержит конфигурацию и SHA256, исходную скорость,
исходные/активные управления, пять энергетических состояний и историю
команд/границ. Восстановление проверяет схему, конечность, энергетические
остатки, скорость и цепочку управления. Подлинность траектории снимок
не доказывает. SDK дополнительно проверяет соответствие сценарию и
исполненному префиксу команд, включая ещё не исполненную команду ровно
в момент физической остановки.

## Численная проверка

Бюджет [ai05_turbine_budget_v1.json](../validation/ai05_turbine_budget_v1.json)
зафиксирован до формальной серии. Независимый reference интегрирует
`omega`, а не K, методом DOP853 вместе со своими интегралами мощностей;
границы он находит terminal events, а не production-формулой времени.
Работу расширения reference вычисляет отдельно по энтропии и насыщению.
Backend IF97 у них общий: это независимая проверка механического интегратора
и балансов, а не сравнение двух независимых уравнений состояния.

12 семейств, 24 основных пакета с двумя выходными шагами: номинал,
сброс нагрузки, верхняя граница, отключение пара и нижняя граница,
разгон без потерь, свободное вращение без потерь, идеальный генератор,
изоэнтропийный предел, другое противодавление, малый расход,
выход на верхней границе в начальный момент и перегретый actual-выход.
Граничные случаи принимаются как ожидаемый `domain_exit`, а не как
якобы выполненный полный горизонт.

Каждый checkpoint проверяется продолжением на секунду; после граничного
снимка задаётся возвращающее управление, и продолжение сравнивается с
независимым reference. Аудит пересчитывает метрики, точную матрицу,
входы, сетку, историю, классификацию завершения и независимые границы.

Серия не квалифицирует произвольные давления, характеристики машины,
отказы электрической сети или динамику полного парового контура.

```bash
python -m sdk.turbine_experiment scenarios/ai05_turbine_load_rejection.json \
  --output artifacts/NEW_TURBINE_RUN

# После установки wheel:
atomic-turbine-experiment scenarios/ai05_turbine_load_rejection.json \
  --output artifacts/NEW_INSTALLED_TURBINE_RUN

atomic-turbine-experiment extended.json \
  --resume artifacts/NEW_TURBINE_RUN/checkpoint.json \
  --output artifacts/NEW_RESUMED_TURBINE_RUN

  --output artifacts/NEW_TURBINE_AUDIT.json
```

checkpoint, report и manifest сохраняются вместе. CI включает отдельную
серию и аудит. Installed-wheel smoke проверяет CLI, restart и ненулевой
код ожидаемого физического выхода.

дала **1063 passed, 1 deselected**. Исключён внешний OpenMC/MPI. Ruff и
проверка форматирования прошли; Black локально не установлен. Это локальный
Linux/Python 3.12 результат, а не выполненная удалённая CI-матрица.
