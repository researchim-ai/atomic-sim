# Переносимые результаты и сравнение экспериментов

4 ноября 2026. План 1.59.0. Пакет `atomic_model_results`, CLI
`atomic-model-results`, расширение режима `atomic-model-project-ui --study`.
Область: поддержанные EOS-пресеты, локальные встроенные политики, синтетические
контроли. Промышленная физическая точность этим блоком не подтверждается.

## Реализованный блок

1. Выбор 1–32 сохранённых оценок study. Пакет содержит текущую конфигурацию
   исследования, отдельно закреплённую конфигурацию каждого расчёта, статусы,
   native checkpoints, эталоны и оригинальные отчёты с происхождением.
2. Экспорт завершённых и прерванных расчётов. У неполного запуска нет
   фиктивного metric pass. Сохраняется доступный принятый префикс; отсутствие
   начального checkpoint остаётся отсутствием, а не нулевой траекторией.
   Экспорт активного study worker отклоняется до создания output.
3. Траектории CSV в длинном формате: time_s, kind, channel, value, unit.
   Наблюдения, действия, глобальные и локальные балансы разделены. Начальная
   команда не выдумывается. Единицы K, W, J, J/K, kg, kg m/s объявлены явно.
   Это сохранённые decision samples, а не все внутренние solver substeps.
4. Проверка повторно интегрирует сохранённые команды от начального состояния,
   сверяет **каждую** строку наблюдений/балансов и конечный native checkpoint.
   Затем пересчитываются reference-метрики, события, качество политики и
   производные сводки. CSV генерируется повторно и сравнивается побайтово.
   Изменить промежуточное наблюдение и просто пересчитать manifest недостаточно.
5. SHA-256 inventory, строгая схема и источник кода, относительные пути,
   лимиты: 32 оценки, 64 reference-объекта, 2048 объявленных файлов,
   32 MiB на файл и 512 MiB суммарно вместе с manifest. Необъявленные файлы,
   симлинки, повреждения, неподдержанные схемы и несовместимые привязки
   отклоняются. Отказ не удаляет существующий чужой output.
6. Группы сопоставимости: одна модель, одинаковые config/seed/split/objective,
   reference-кривые/неопределённости/единицы/критерии/provenance, бюджеты и source.
   Политика исключена из ключа намеренно: сравниваются её варианты при прочих
   одинаковых условиях. Неодинаковый numerical step создаёт другую группу.
7. MAE ранжируется **отдельно по каналам и группам**, без суммы K с J.
   Равные машинные значения получают одинаковый competition rank. Полный
   расчёт с проваленными критериями остаётся видимым; незавершённый или
   не покрывающий reference-окно не ранжируется. Статистическая значимость
   повторов не заявляется.
8. Попарное сравнение допускает только общий протокол: согласованные узлы,
   две кривые, signed difference «left minus right», точные аналитические
   piecewise-linear метрики и единицы. Экстраполяция и скрытая децимация отсутствуют.
9. Wall/RSS — наблюдённые величины последней попытки, не общая цена всех
   попыток. Policy timings сохранены, но аппаратная идентичность исходных
   study inputs не записана. Поэтому `performance_comparable=false`: нет
   рейтинга скорости и заявлений о вычислительном преимуществе.
10. ZIP transport с фиксированными временем/порядком/правами файлов и
    побайтовым повторным rebuild в проверенном runtime. При импорте сначала
    проверяются заголовки/размеры/пути/дубликаты/тип файлов, затем bytes,
    native replay и метрики во временном каталоге; только после этого создаётся
    output. Из архива не выполняется пользовательский код. Компрессия между
    разными версиями zlib не объявляется побайтово одинаковой.
11. UI: выбор сохранённых оценок, раздельные группы и таблицы MAE с единицами,
    вывод исключённых запусков, экспорт результатов и траекторий. Индивидуальные
    отчёты study сохраняют события, причины останова и local/global ledgers.
    Защиты loopback Host/Origin/token/CSP и пределы JSON body сохранены.
12. Прежний study source и журналы не менялись: расширение находится в отдельном
    пакете. Новый CLI/UI маршрут работает поверх уже сохранённых оценок.
    В UI показываются первые 64 ID по лексикографическому порядку, не «последние
    по времени»; остальные можно выбрать явно через CLI.

## Воспроизведение

```bash
python -m examples.eos_results_workflow --output artifacts/my-results
atomic-model-project-ui artifacts/my-results/study --study --port 8765
atomic-model-results verify artifacts/my-results/results
atomic-model-results pack artifacts/my-results/results --output artifacts/my-results.zip
atomic-model-results unpack artifacts/my-results.zip --output artifacts/imported-results
atomic-model-results replay artifacts/imported-results --output artifacts/replayed-results
```

В примере четыре расчёта: две политики (нулевая команда и 500 W на стенке) и
два синтетических reference-контроля. Получаются две группы: энергетический
residual в J и температура в K. Температурный контроль намеренно отрицательный;
событие threshold=300.2 K демонстрирует диагностику отсутствующего события
эталона. Это не замена реальных измерений синтетическими.

Другие команды: `export STUDY ID [ID ...] --output DIR`,
`pair BUNDLE LEFT_ID RIGHT_ID CHANNEL`. Bundle здесь — каталог, содержащий
bundle.json и manifest.json. Output должен быть новым. Пакет результатов
не является изменяемым study-журналом: он предназначен для проверки, анализа
и переноса, а не для resume выполненных задач.

## Доказательства и оставшиеся границы

Окончательные результаты тестов, installed-wheel replay, Chromium и хеши
зафиксированы в `validation/ai11_results_delivery_v1.json` и
`validation/ai11_results_portable_replay_v1.json`. Хеши доказывают целостность,
а не подлинность автора; подпись издателя не заявляется. Повторная интеграция
доказывает воспроизводимость той же численной модели, не правильность физики.

AI-11.04 принимается только в этом EOS software scope после проверок. Общие
модельные графы, произвольные агенты, многопользовательский backend и физическая
валидация не входят в приёмку. AI-11.06 остаётся открытым: fresh-process/offline
wheel проверка вне checkout не выдается за испытание на независимой машине
или полной матрице ОС/численных библиотек. Следующие крупные направления —
контракт подключаемого агента (AI-11.05), общий открытый benchmark (AI-13.03/04),
и оставшиеся численные/сетевые пакеты AI-05 по их отдельным критериям.

В `job_metrics` сохранены прежние определения workspace: objective IAE —
трапецеидальное интегрирование **модулей значений на decision samples**.
При смене знака между узлами это не точный интеграл модуля линейной ошибки.
Эта legacy-величина не используется для нового рейтинга; reference MAE и
попарные метрики рассчитываются аналитически по piecewise-linear сегментам.

Код возврата 0 у `verify`/`replay` означает целостность и воспроизводимость.
Он не означает прохождения критериев каждого эксперимента: для этого служат
отдельные `comparison_passed`, статусы, channel checks и event checks.

В мобильной таблице MAE отображается компактно с обозначением «≈».
Полная точность сохранена в tooltip и экспортированных JSON/CSV; округление
отображения не участвует в ранжировании. Финальная проверка разделяет
полный прогон 269 тестов вычислительного кода и последующую UI-правку:
подтверждено побайтовое совпадение остального wheel payload, отдельно
выполнены Chromium и replay прежнего пакета результатов на финальном wheel.
