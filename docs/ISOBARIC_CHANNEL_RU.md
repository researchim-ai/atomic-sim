# Первый консервативный компонент кипения

Дата: 30 октября 2026. Модель `isobaric-heated-channel`, версия 0.1.0.
Продолжение [контролируемого останова ВВЭР](MODEL_BOUNDARY_RU.md).

## Реализованная модель

Добавлен открытый канал из смешиваемых контрольных объёмов с заданными
давлением, входной энтальпией, входным расходом и нагревом. Свойства воды
вычисляет локальная реализация [IAPWS-IF97 R7-97(2012)](https://iapws.org/technical-guidance/release/IF97-Rev).
Поддержаны жидкость, равновесная смесь и перегретый пар областей 1/4/2.
Давление ограничено областью реализованного насыщения до 16.529 МПа.

Давление одинаково во всех ячейках и постоянно. Акустика, импульс, потери
давления, скольжение фаз и естественная циркуляция исключены. Нагрев задан
непосредственно в жидкость/смесь; температура стенки, коэффициент кипящего
теплообмена, CHF и посткризисные режимы не рассчитываются. Выходной поток
однороден и несёт энтальпию ячейки; селективный отбор только пара отсутствует.

Это отдельный тепловой компонент с собственным CLI и паспортом, не новая
версия замкнутой установки ВВЭР. Статус паспорта остаётся `implemented`;
приведённые ниже проверки относятся к конкретным численным задачам.

## Консервативная постановка

Для фиксированного объёма ячейки при p=const:

```text
M = rho(p,h) V
U = M h - p V
dM/dt = F_in - F_out
dU/dt = F_in h_upstream - F_out h + Q

M dh/dt = F_in (h_upstream - h) + Q
F_out = F_in - (dM/dh) dh/dt
```

Выходной расход учитывает изменение запаса массы при тепловом расширении.
Принудительное равенство всех расходов при изменяющейся плотности нарушило бы
баланс массы. Межъячеечные потоки и их энтальпия используются обеими соседними
ячейками, поэтому внутренние переносы взаимно сокращаются.

В куполе насыщения используются x=(h−h_f)/(h_g−h_f), v=(1−x)v_f+x v_g и
`d rho/dh = -rho² (v_g-v_f)/(h_g-h_f)`. Массовое среднее cp фаз для этой
производной не используется. В однофазных областях производная получается из
`(dv/dT)_p / cp` того же потенциала IF97. Для области 2 добавлена аналитическая
производная dv/dT; обе однофазные ветви проверены разностями по h.

Потоки направлены вперёд; попытка обратного потока останавливает расчёт.
Энтальпия может быть отрицательной относительно принятого нуля IF97:
проверяется её термодинамическая допустимость, а не знак.

Одновременно с h интегрируются внешние массовый и энергетический потоки.
Глобальная невязка пересчитывается независимо из конечных M/U и накопленных
потоков. Бюджеты используют максимум абсолютной невязки в точках вывода,
нормированный на начальный запас, а не только остаток в конце.

## Аналитические проверки

Для одной двухфазной ячейки без входа с постоянным нагревом и однородным
выходом обозначим b=(v_g−v_f)/(h_g−h_f). Точное решение внутри купола:

```text
v(t) = v(0) exp(Q b t / V)
h(t) = h(0) + (v(t)-v(0))/b
M(t) = V/v(t)
```

Проверен случай p=7 МПа, V=0.01 м³, Q=200 кВт, x(0)=0.1, t=2 с.
При rtol 1e−3 / 1e−5 / 1e−7 ошибка h составила примерно
**0.379 / 0.00142 / 0.00000590 Дж/кг**; энергетический остаток —
**8.16 / 0.0310 / 0.000123 Дж**. Есть уменьшение ошибок, а не только
прохождение заранее выбранного единственного порога.

Для стационарного канала h(z)=h_in+Q z/(F L). После расчёта из однородного
начального состояния до 20 с проверены сетки 4/8/16 ячеек. Ошибки относительно
аналитических средних по ячейке: **18750 / 9375 / 4687.5 Дж/кг** — первый
пространственный порядок донорной схемы. Выходная энтальпия согласуется с
h_in+Q/F. Эта проверка показывает и существенную ошибку грубой сетки;
высокий пространственный порядок здесь не заявляется.

Результаты и исходные параметры: `validation/isobaric_benchmarks_delivery.json`.
Воспроизведение из рабочей копии:

```bash
python -m scripts.verify_isobaric --output validation/isobaric_benchmarks_new.json
```

## Сценарий снижения предписанного расхода: 1800 с

Проверочная геометрия: 4 ячейки, суммарный объём 0.004 м³, p=7 МПа;
входная энтальпия на 100 кДж/кг ниже насыщенной жидкости. Заданы
F_in(t)=1·exp(−t/600) кг/с и Q(t)=300000·exp(−t/1200) Вт.
Это синтетические граничные условия, не характеристика насоса или модель
остаточного тепловыделения конкретного блока.

- Базовый расчёт: rtol=1e−7, максимальный внутренний шаг 1 с, вывод 5 с.
- Строгий: rtol=1e−8, внутренний шаг 0.5 с, вывод 2.5 с.
- Оба завершили 1800/1800 с. Время исполнения около **7.77 / 9.98 с**,
  без изоляции аппаратной нагрузки.
- Базовые максимальные относительные невязки массы/энергии — примерно
  **5.89e−8 / 6.44e−8**; строгие — **4.65e−9 / 5.08e−9**.
  Максимальные абсолютные остатки энергии около **0.232 / 0.0183 Дж**.
- В 361 общей точке относительная разница выходной энтальпии ≤**6.78e−10**,
  абсолютная разница качества ≤**7.06e−10**, относительная разница запаса
  массы ≤**7.01e−10**. Численные пороги выполнены.
- Конечное выходное качество около **0.8211**. Оба checkpoint точно
  восстановлены и продолжены до 1800.5 с с сохранением временных законов.

Пакеты: `artifacts/isobaric_delivery_1800s/` и
`artifacts/isobaric_delivery_1800s_tight/`. Проверки сравнения и рестарта:
`validation/isobaric_delivery_comparison.json`, `validation/isobaric_restart_checks.json`.
Более ранние `isobaric_decay_1800s*` и `isobaric_release_1800s*` сохранены как
промежуточные исследования; финальная поставка относится к `isobaric_delivery_*`.

## Запуск и воспроизводимость

```bash
atomic-channel-experiment scenarios/isobaric_decay_1800s.yaml --output artifacts/channel_new --wall-limit-s 60
atomic-channel-experiment scenarios/isobaric_decay_1800s_tight.yaml --output artifacts/channel_ref_new --wall-limit-s 60
python -m scripts.compare_isobaric_runs artifacts/channel_new artifacts/channel_ref_new --output validation/channel_compare_new.json
```

Из исходников CLI запускается как `python -m sdk.channel_experiment`.
Каталоги/файлы результата должны быть новыми. Пакет содержит нормализованный
input, CSV, checkpoint, report JSON/Markdown и manifest с SHA-256, версиями
среды, исходниками и паспортом. Проверяются весь вход до запуска, восстановление
checkpoint, одинаковые граничные условия сравниваемых прогонов, полнота горизонта
и согласие CSV с объявленным балансом. Частичный, изменённый или чужой расчёт
не принимается как проверка точности solver.

Абсолютные допуски модели 0.1.0: 1e−4 Дж/кг для h, 1e−9 кг для интеграла массы,
0.001 Дж для интеграла энергии. Они фиксированы в реализации; rtol и maximum
step настраиваются. Профиль нагрева/расхода неизменен на протяжении сессии;
общие команды timeline не поддерживаются и отвергаются. Отмена, wall-limit,
численный отказ и ошибка программы имеют отдельные статусы; ошибка программы
после сохранения диагностики поднимается повторно.

## Исправление общей обёртки интегратора

Аналитический тест нового канала выявил сбой Radau на границе вывода:
ограничение max_step остатком до target могло оставить один ULP времени,
меньший допустимого шага solver. Теперь текущая точка вывода задаётся через
t_bound; завершённый на ней экземпляр возобновляется для следующей точки,
а глобальный горизонт хранится отдельно. Начальная граница также передаётся
при создании solver, чтобы его начальные пробы не уходили за текущий интервал.
Принятый вектор y и история не исправляются вручную.

Реализация опирается на описанные публичные поля
[BDF/Radau SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.integrate.Radau.html).
Поведение обёртки проверено на установленной SciPy 1.15.2: оба метода сохраняют
тот же экземпляр, точно достигают нескольких точек вывода и не вычисляют RHS
за заданной границей. Это проверка нашей обёртки, не обещание совместимости
любой будущей версии SciPy.

Регрессия ВВЭР: часовой номинал завершён за 9.71 с и прошёл прежнее сравнение
с reference (`validation/vver_hour_endpoint_fix_comparison.json`); защищённый
выбег сохраняет model_limit около 122.2026 с (`artifacts/vver_boundary_after_endpoint_fix`).

## Что остаётся до кипящего реакторного контура

У нового компонента нет прогнозируемого давления, импульса, вала насоса,
высотной геометрии, стенки, нейтроники и кризиса теплообмена. Для отдельного
паспорта кипящего контура нужны согласованные массы/энергии/импульс фаз,
механические энергетические члены, проверенные теплообменные замыкания и
независимые интегральные данные. Затем нужна связь с тепловой инерцией топлива
и обратными связями, проверка неопределённости и перенос сценариев выбега.

Полный выбег ВВЭР 1800 с **не принят**. Предел действующего паспорта сохранён.
Ни этот компонент, ни пройденные математические проверки не устанавливают
экспериментальную валидацию, промышленную квалификацию или превосходство над
другими кодами. `validated` и `plant_referenced` остаются false.
