# Пакет исследовательского эксперимента

В текущем релизе эксперимент выполняется тем же `VVERPlant`, что и SDK. Пакет содержит вход, траекторию, хеши исходников и ресурсов ядра, версии библиотек, события, невязки и последний принятый checkpoint. Завершение расчёта и прохождение численных бюджетов отделены от экспериментальной валидации.

## Запуск

После установки wheel:

```bash
atomic-experiment my_scenario.yaml --output results/run-001 --wall-limit-s 300
```

Из исходников:

```bash
python -m sdk.experiment scenarios/vver_load_rejection.yaml --output results/smoke
python -m sdk.experiment scenarios/vver_pilot_nominal.yaml --output results/nominal --wall-limit-s 600
```

Каталог результата должен быть новым: существующие результаты не перезаписываются. JSON/YAML вход проверяется целиком до создания каталога. Для отмены можно создать файл, переданный через `--cancel-file PATH`. Wall-time лимит и файл отмены проверяются между шагами и на каждом вызове RHS: длительное интегрирование прерывается без принятия шага. Блокирующий native-вызов без возврата в RHS требует отдельного worker/supervisor для жёсткого ограничения.

## Формат

```yaml
name: sink_step
schema_version: 1
engine: vver
model_id: vver-lumped-loop
duration_s: 2.0
step_s: 0.5
solver:
  rtol: 0.00001
  atol: 0.0001
budgets:
  mass_relative: 0.000001
  energy_relative: 0.00001
  boron_relative: 0.000001
timeline:
  - t: 0.37
    sink_temperature_k: 300.0
```

Событие в 0.37 с разрывает шаг вывода: состояние сначала интегрируется до 0.37, затем применяется команда, затем выполняется остаток шага. Все времена задаются относительно начала эксперимента. События допустимы на `[0, duration_s)`; при одинаковом времени порядок соответствует списку. Будущие неверные команды также отклоняются до запуска. Время симуляции, шаг, допуски и бюджеты должны быть конечными числами.

## Артефакты

- `input.json`: нормализованная спецификация, включая явно записанные допуски.
- `manifest.json`: SHA-256 входа, исходников/ресурсов ядра и файлов результата; версии runtime/библиотек, паспорт, время UTC. Генератор случайных воздействий в этом runner не используется; это отмечено в manifest.
- `trajectory.csv`: начальное состояние и все принятые интервалы, включая границы команд; поля наблюдения сохраняют единицы в названиях.
- `checkpoint.json`: последний успешно принятый физический шаг, команда и состояние защиты; восстановление через `sdk.api.restore_snapshot`.
- `report.json`: длительность, статус, экстремумы, события, накопительные баланс/дрейф, сравнение с численными бюджетами и контекст отказа.
- `report.md`: краткий переносимый итог с указателем на подробные данные.

Хеш кода идентифицирует поставленные файлы, но не является доказательством независимой валидации. Для полной воспроизводимости нужны совместимые платформа/зависимости и паспорт; битовое совпадение между разными solver/CPU не обещается.

## Статусы и коды возврата

`completed` — дошёл до заданного времени. `failed` — физическая область или solver не позволили принять шаг; сохраняются интервал и команды отказа, а checkpoint остаётся на предыдущем принятом состоянии. `cancelled` и `wall_limit` — останов с откатом непринятого шага. `program_error` — программное исключение: отчёт записывается, исключение повторно поднимается и не маскируется как физика.

CLI возвращает 0 при завершении без проваленных заданных бюджетов; 1 при физическом отказе, отмене, wall-limit или провале бюджета; 2 при ошибке входа/файлов. Неожиданная ошибка программы выходит с traceback. Без заданных бюджетов `numerical_acceptance` остаётся false, даже если CLI вернул 0 за успешное выполнение.

В отчёте `validated` и `plant_referenced` остаются false. Даже успешный короткий пакет не закрывает требования 3600 с номинала или независимой интегральной приёмки.

`energy_relative` нормируется на максимум из 1 Дж, начального запаса энергии и суммы абсолютных внешних интегралов. При стационарном источнике и стоке их разность близка к нулю и не служит устойчивым масштабом. Старое отношение к сумме модулей **нетто**-энергии шагов сохранено как `energy_net_relative`; абсолютная невязка `energy_global_j` не меняется. Масштаб и полный энергообмен записываются в отчёт. Это численный бюджет конкретного ledger, не оценка экспериментальной точности.

## Проверка поставки

```bash
python -m build --wheel --no-isolation
python scripts/verify_wheel.py dist/atomic_sim-2.0.0-py3-none-any.whl
```

Проверка создаёт временное окружение с доступом к уже установленным зависимостям, устанавливает именно wheel без сети, проверяет путь импортированного SDK и запускает установленный CLI вне checkout. Проверяются каталог/контрольная сумма данных, YAML-сценарий, выполнение физического шага и восстановление изменённого стока. Полностью пустая матрица OS/Python и квалификация внешних ядерных данных требуют отдельных проверок.
