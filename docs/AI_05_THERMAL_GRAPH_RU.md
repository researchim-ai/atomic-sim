# Стационарное смешение энтальпии в гидравлическом графе

`scripts/solve_thermal_graph.py` добавляет к стационарному графу сопротивлений
явные температуры подаваемой жидкости, смешение, нагрев/охлаждение,
теплоотдачу в окружение и переход диссипации в тепло жидкости.
Это следующий частичный блок AI-05.03/08. Общая динамическая сеть,
переменная плотность и естественная циркуляция этим блоком не реализованы.

## Постановка и область применения

Один явно названный medium, постоянные rho и cp > 0, идеальное смешение
в узлах нулевого объёма. Сначала решается прежняя нелинейная гидравлика,
затем — линейная система стационарных энергетических балансов.
Температура не меняет сопротивление или плотность; тепловая связь
односторонняя. Нет теплового разгона, произвольного назначения средней
температуры или корректировки команд ради совместимости.

Удельная энтальпия определена явно:

```text
h(T,p) = cp*(T-T_reference) + p/rho
```

Кинетическая энергия в этой сосредоточенной модели не учитывается.
Гравитационная работа учитывается отдельно, не повторяется в h.
Тепловые ограничения — объявленный пользователем открытый интервал T;
это не проверка фазы или паспорт IF97. Достоверность постоянных свойств
для конкретной жидкости/диапазона требует отдельного обоснования.

У границы давления массовая подача определяется гидравликой.
При положительной подаче обязательна `supply_temperature_k`.
При отборе уносится энтальпия смеси узла; резервуарная температура
не навязывается выходящему потоку. Ненулевая внешняя подача/отбор меньше
1e-8 кг/с отклоняется как численно неразрешённая: она не должна незаметно
закреплять температуру замкнутого контура. Поток не обнуляется и не обрезается.
Этот предел задан в бюджете, а не является физическим порогом течения.
Внутренние почти нулевые потоки сохраняются.

## Энергия каждого узла и ребра

Энергетический баланс узла использует фактического донора энтальпии
при каждом направлении расхода. Внешний нагрев может иметь любой знак.
Теплоотдача положительна из жидкости в окружение:

```text
sum(inward edge enthalpy powers) + external mass enthalpy
  + prescribed heat - UA*(T_node-T_ambient) = 0
```

Диссипация ребра D=(L*m²+R*abs(m)³)/rho >= 0 полностью переходит в тепло
жидкости на выходе ребра перед смешением. Это сосредоточенное приближение,
не пространственная модель распределённого нагрева стенки. При m=0
диссипация и перенос равны нулю; деления на нулевой расход нет.
Температура переносимой струи в отчёте при точном нулевом расходе равна
`null`: она не приписывается произвольно по выбранной ориентации ребра.
Проверяется также температура струи перед смешением: холодный узел
или большой UA не могут скрыть локально недопустимую выходную температуру.

В узловом балансе сохранён член p/rho, включая малую массовую невязку
гидравлического решения. Давление не теряется при переходе к температурной
матрице. Каждый конец ребра выдаёт одинаковое с узлом давление и две
строго противоположные записи массового/энергетического потока.
Конвенция положительного потока внутрь владельца и medium проверяются
существующим `core.network.PortSpec` с `specific_enthalpy_transport`.

Внутри ребра сумма входящих энтальпийных мощностей, заданной механической
мощности и гравитационной работы равна нулю. Поэтому глобальный баланс:

```text
external mass enthalpy + prescribed heat - ambient removal
  + prescribed hydraulic gain power + gravity power = 0
```

Диссипация не добавляется сюда второй раз: она уже связывает потерю
механической энергии с теплом потока. Работа заданного напора может
быть отрицательной при реверсе — источник тогда поглощает мощность.
Это не характеристика реального насоса/турбины и не модель вала.

## Однозначность, ограничения и ошибки

Температуры находятся после масштабирования строк и проверки обусловленности.
Замкнутый контур без температурного условия/теплоотвода не получает
скрытую температурную опору. Вырожденная или плохо обусловленная система
отклоняется как `thermal_rank`, в том числе при нулевом нагреве.
Неподвижный узел может получить температуру из своего ненулевого UA;
изолированный в тепловом смысле узел без такой связи отклоняется.

После решения заново суммируются физические потоки портов, а не только
невязка линейной матрицы. Бюджет
`validation/ai05_thermal_graph_budget_v1.json` требует <= 1e-5 Вт
для каждого узла, каждого ребра и глобального баланса.
Температуры не проецируются на допустимый интервал.

## Вход и запуск

Формат `atomic-thermal-hydraulic-steady`, schema 1, содержит:

- `hydraulic`: прежний явный граф `atomic-hydraulic-steady`;
- `thermal`: medium, cp, T_reference, минимальную/максимальную T и карту
  узлов с точным совпадением имён;
- у каждого теплового узла: heat_power_w, ambient_ua_w_k,
  ambient_temperature_k и при необходимости supply_temperature_k.

Неизвестные поля отклоняются. Пример с двумя источниками разной температуры:
`examples/thermal_graph_steady.json`.

```bash
python -m scripts.solve_thermal_graph examples/thermal_graph_steady.json \
  --output artifacts/NEW_THERMAL_POINT
python -m scripts.qualify_thermal_graph --output artifacts/NEW_THERMAL_MATRIX
python -m scripts.qualify_thermal_graph --audit artifacts/NEW_THERMAL_MATRIX \
  --output artifacts/NEW_THERMAL_AUDIT.json
```

При успехе CLI сохраняет request/solution/manifest с хешами входа,
результата, инженерных скриптов и бюджета. При отказе — diagnostics
вместо solution, exit code 2. Существующий каталог не перезаписывается.
Отчёт портов — статическая инженерная запись; автоматический перенос
в динамический backend `core/network.py` и регистрация новых компонентов
этим интерфейсом не заявлены.

## Численные свидетельства

21 случай: 18 manufactured графов до 128 узлов с ветвлениями, реверсом,
линейными/квадратичными потерями и почти нулевыми потоками; аналитические
замкнутый контур с заданным напором/теплоотводом, неподвижная жидкость
и смешение двух внешних источников. Проверяются точные температуры
и независимый эталон, который сначала решает полную гидравлическую систему,
затем находит корень непосредственно суммируемых потоков энтальпии.
Он не использует рабочий сборщик тепловой матрицы или обратный закон ребра.

Аудит требует полную матрицу, исходные входы/точные решения, хеши всех
замороженных скриптов и обоих бюджетов; пересчитывает каждую точку
и сравнивает результат с архивным. Подмена результата с пересчитанным
хешем не заменяет численную проверку.

`validated=false`, `plant_referenced=false`. Динамические запасы, обратная
связь температуры с гидравликой, переменная EOS, фазовые переходы и
экспериментальная валидация остаются открытыми задачами.
