# Явная дискретная подготовка начальной скорости v70

Дата: 17 ноября 2026.

[Пространственный аудит v69](STATION_SPATIAL_AUDIT_RU.md) выявил ненулевую
дивергенцию исходного состояния и чувствительность динамики к временному
шагу. Новый компонент `atomic_model_station_initialization` позволяет
**отдельно подготовить изменённое начальное поле** и проверить, устраняет
ли это причину последующих невязок.

Принята проверка дискретных ограничений нового начального состояния.
Динамическая непрерывность пока не принята: внешний расчёт снова накапливает
заметную дивергенцию. Исходные checkpoints и результаты v69 сохранены.

## Постановка

Для каждой хранимой Fourier-моды минимизируется взвешенная норма поправки:

```text
min sum_i w_i (|delta_ur_i|² + |delta_ut_i|² + |delta_uz_i|²)
при div_h(u_new) = 0
     ur_new(1) = ut_new(1) = uz_new(1) = 0
     2 sum_i w_i [1-r_i² + uz_new(0,0,r_i)] = target_bulk
```

Последнее ограничение относится только к средней моде. Производная и
отражённые узлы используют неизменённый проверенный оператор v69.
Стенные неизвестные исключаются до решения. Матрица ограничений
масштабируется на `sqrt(w)`; SVD даёт минимальную поправку без нормальных
уравнений. Зависимые строки средней моды обрабатываются через численный
ранг с относительным порогом 10⁻¹². Неразрешённые ограничения с невязкой
выше 10⁻⁹ отклоняются.

Проекция — **объявленное изменение входных данных**. Это не физический
импульс, не шаг интегратора и не разрешение скрытно корректировать рабочее
состояние. Температура и физические метаданные сохраняются. Энергия
исходного поля не объявляется сохранённой: квитанция содержит норму поправки,
остатки и контрольные суммы обоих состояний.

Бюджет изменения задаётся обязательно: RMS поправки делится на RMS полной
скорости, включая осевую базу `1-r²`. Поэтому нулевое возмущение Пуазейля
не создаёт деления на нулевую норму. Допускается бюджет из (0; 0,1];
превышение вызывает отказ. В выполненном опыте разрешён бюджет 0,01.
Функция возвращает новые массивы, исходные массивы не изменяет.

Область реализации ограничена положительной нормированной радиальной
квадратурой, не более 128 радиальных узлов и упаковкой мод v69.
Это алгебраическая согласованность с конечным дискретным оператором.
Аналитическая регулярность высоких мод у оси и совместимость начального
давления пока **не квалифицированы**. Поэтому результат не подключён
автоматически к станционному backend.

## Проверка на полном пространственном поле

Вход — сохранённое состояние `whole` v69 на t=0, N=64, K=80, M=76,
12 005 хранимых комплексных мод. Новая подготовка дала:

- L2-дивергенция: 0,00671481215 → **1,62421409·10⁻¹⁶**.
- Максимальная невязка линейных ограничений: 4,44956·10⁻¹⁶.
- Максимальная невязка стационарности минимума: 8,47033·10⁻²².
- RMS поправки: 8,22665·10⁻⁵; относительная поправка: **0,000156368**.
- Средний расход: 0,5 в пределах округления; скорости на стенке нулевые.

Тепловое поле и физические метаданные точно сохранены. Исходный файл
не перезаписан. Новый файл и квитанция имеют отдельные контрольные суммы.

## Внешнее продолжение и сохранённый отказ

Новый вход использован в свежей сборке того же численного варианта
Openpipeflow: исходные уравнения, явно исправленная квадратура v68,
dt=0,01 и 20 шагов до t=0,2 R/(2Ub). Источники, вход и эпохи проверены.
Три состояния дополнительно проверены родными `var_coll_norm` и
`var_coll_div` внешнего кода; расхождения с Python меньше 10⁻⁹.

Измеренная L2-дивергенция:

```text
t=0,0:  1,62421409e-16
t=0,1:  0,00730481127
t=0,2:  0,00744665142
```

Родные процедуры подтверждают и малую начальную, и большую последующую
невязку. Значит, дискретная очистка начальной скорости сама по себе
не закрывает проблему динамики. Допуск 10⁻⁷ не ослаблен.
По этому опыту нельзя объявить однозначной причиной конкретную процедуру
давления: отдельно нужны согласованность операторов, граничные условия,
регулярность у оси и временное уточнение.

В машинном отчёте разделены:

```text
initial_discrete_constraints_passed = true
dynamic_continuity_qualified = false
station_usable = false
validated = false
```

## Локальная проверка и воспроизведение

Добавлены 18 тестов. Целевой набор инициализации, пространственного аудита
и квадратуры содержит **112 тестов**. Проверяются линейные ограничения,
повторная проекция, независимый QR-решатель и ортогональность нулевому
пространству, нулевое возмущение, повреждённые входы, бюджет поправки,
неизменность исходного checkpoint, температуры и метаданных.
Новый тестовый файл включён в общий локальный профиль библиотеки.

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  .venv-layout/bin/python -m pytest -q \
  tests/test_station_initialization.py tests/test_station_spectral.py \
  tests/test_station_spectral_qualification.py tests/test_station_quadrature.py \
  tests/test_station_quadrature_qualification.py
```

Для подготовки отдельного файла из локально имеющегося полного checkpoint:

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH="$PWD/src:$PWD" \
  .venv-layout/bin/python -m scripts.prepare_station_spatial_state \
  --output artifacts/my-initial-state \
  --initial artifacts/station-spatial-v69-accepted/whole/state0000.cdf.dat \
  --weights artifacts/station-spatial-v69-accepted/whole/corrected_weights.dat \
  --maximum-relative-correction 0.01
```

Директория вывода должна быть новой. В ней создаются `state.cdf.in` и
`report.json`; входной файл не перезаписывается. Полные сторонние данные
не входят в wheel и должны быть получены по процедуре v69.

[Машинная квитанция v70](benchmarks/station_initialization_v70.json)
содержит исходный и конечный аудит, внешний отрицательный результат,
квитанцию целевых тестов и проверку установленной поставки.
Полная проверка **2261 теста и восемь этапов** относится к сохранённому
v69; она не переименовывается в полный прогон новой версии v70.

## Следующий этап

Исследовать согласованность дискретных операторов проекции давления,
дивергенции и граничной коррекции на изготовленных решениях и при
пространственно-временном уточнении. Отдельно проверить регулярность
векторных мод у оси. Затем повторить длинный тепловой прогрев и статистику.

Принятие начальной алгебраической задачи не закрывает станционные задачи:
**48/76 приняты, 28 открыты; NPP-11.03/04 и R1 остаются открытыми.**
