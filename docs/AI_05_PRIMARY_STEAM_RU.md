# Первичная насосная петля и паровой силовой цикл

Дата: 2 ноября 2026. Статус: исправленный runtime `985bb203…` принят
в объявленной редуцированной области: 53 переходных пакета / 17 семейств
и 14 стационарных / 7 семейств, с независимыми frozen-аудитами.

## Реализованная модель

`physics/power/primary_steam.py` решает одной системой ОДУ первичную
жидкостную петлю с импульсом потока, насосом, инерцией вала, температурой
жидкости и конечными стенками; парогенератор/конденсатор с запасами M/U/V;
горячую/холодную стенки, турбину, ротор, генератор и теплоотвод.
Источник первичного нагрева входит в выбранную стенку, поэтому изменение
его мощности не вызывает мгновенного скачка температуры жидкости.

Связь задаётся `Q=UA*(Tprimary-Tsgwall)`. Один поток и один независимо
интегрируемый счётчик энергии имеют противоположные знаки у двух сторон.
`SteamPowerCycle` принимает явные `hot_wall_port_w` и
`hot_wall_port_energy_j` для вычисления производных/наблюдения связанной
сборки. Этот обмен не записывается во внешний `heater` парового цикла.
Владельцем портового счётчика и checkpoint является связанная сборка;
standalone snapshot парового цикла сохраняет прежний нулевой контракт порта.

Проверяются баланс каждой подсистемы, сумма всех запасов, внешние энергии
и мгновенная мощность. Во внешнюю энергию входят мотор, заданный нагрев,
окружение, питание парового цикла; электричество и пассивные потери
вычитаются один раз. Внутренний теплообмен сокращается из общего баланса.

`core/bounded_step.py` локализует границы по состоянию и сохраняет
фактическую сетку/SciPy-счётчики. Текущие границы парового цикла дополнены
давлениями и температурой первичной жидкости и запасом до насыщения IF97.
При нарушении области EOS на пробном шаге возможен численный отказ с
откатом: метод не обещает локализовать любой произвольный большой шаг.
Конечные состояния не обрезаются до паспортных порогов.

## Область применения

Первичная жидкость имеет постоянные заданные rho/cp и фиксированную
опорную точку давления. IF97 используется для ограничения переохлаждения,
а не превращает первичную петлю в переменную EOS. Пример фиксирует rho/cp
по IF97 при 15.5 МПа и 587.784 K. Первичный насос — объёмная машина с
линейной утечкой, не центробежная карта ГЦН. Нет компенсатора давления,
акустики, пространственного кипения, нейтроники и обратных связей активной
зоны. Установка не получает объектный паспорт ВВЭР из факта этой сборки.

Начальные гидравлические условия примера стационарны. Тепловые условия
заданы явно и имеют ненулевые производные. Пример содержит нагрев и
отключение мотора, полный запрошенный горизонт — 5 с.
Отдельный [предпроцессор рабочей точки](AI_05_PRIMARY_STEAM_STEADY_RU.md)
согласует первичные температуры, стенки и граничные команды с заданным
паровым состоянием и знаковым первичным расходом без переходного разгона.
Это специальная задача данной сборки, а не общий решатель произвольной сети.

## Использование

```bash
python -m sdk.primary_steam_experiment scenarios/ai05_primary_steam.json \
  --output artifacts/NEW_PRIMARY_STEAM
atomic-primary-steam-experiment extended.json \
  --resume artifacts/NEW_PRIMARY_STEAM/checkpoint.json \
  --output artifacts/NEW_PRIMARY_STEAM_RESTART
```

Нагрев первичной стенки, момент мотора и полный вектор парового цикла
меняются по единой временной шкале. SDK откатывает весь неуспешный внешний
интервал: состояния, обе энергии обмена, команды и trace. Физический
выход сохраняет принятую часть и возвращает CLI-код 2; численный отказ — 1.
Строгий `advance` откатывает также физический выход; `advance_until_limit`
сохраняет его. Повторный вызов на исходящей границе удерживает состояние;
возврат допустим только при разрешимом направлении внутрь области.
