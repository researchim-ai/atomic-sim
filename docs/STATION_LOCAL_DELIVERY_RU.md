# Локальная проверка станционной поставки

[English](STATION_LOCAL_DELIVERY_EN.md). Протокол объединяет тесты исходников, чистую сборку sdist → wheel, сверку содержимого wheel, установку вне checkout и нативные станционные проверки. CI, облачный runner и новая физическая машина не требуются.

## Запуск

Из корня репозитория, в окружении с установленными научными и разработческими зависимостями:

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:. \
  .venv-layout/bin/python -m scripts.verify_local_library \
  --output artifacts/my-station-delivery \
  --suite library --phase-timeout-s 14400 \
  --station-nominal docs/benchmarks/station_nominal_requalification_v105.json
```

Каталог должен быть новым и не содержать символьных ссылок в пути. Лимит времени задаётся для каждой фазы, а не для физического интервала; timeout не засчитывается как успех. Команда может выполняться долго. Не меняйте код, поставляемые ресурсы, зависимости и правила сборки до завершения.

Если в проект добавлены новые верхнеуровневые Python-пакеты, обновите editable-установку через `python -m pip install --no-deps --no-build-isolation -e .`. Pytest умеет находить `src` через конфигурацию, но это не заменяет правильную установку для обычного нового Python-процесса.

## Возобновляемый полный библиотечный профиль

Для длинных проверок доступно выполнение по файлам с сохранением завершённых результатов:

```bash
python -m scripts.verify_local_tests --output artifacts/my-source-tests --suite library --batch-files 1
python -m scripts.verify_local_library --output artifacts/my-station-delivery \
  --suite library --phase-timeout-s 1100 \
  --test-receipts artifacts/my-source-tests \
  --station-nominal docs/benchmarks/station_nominal_requalification_v105.json
```

Первая команда создаёт план и выполняет все батчи; её повтор с тем же каталогом продолжает незавершённую работу. Отдельные независимые батчи можно запускать через `--prepare`, затем `--batch N`; один индекс одновременно выполняйте только одним процессом. `--accept` проверяет все квитанции и формирует сводку. Встроенного сетевого runner нет: каждый батч — обычный локальный pytest-процесс.

План сохраняет точный набор node ID и разделение по файлам. Перед каждым батчем и при приёмке сверяются исходники, тесты, входные квитанции, версии Python и установленных зависимостей. Число потоков BLAS/OMP фиксировано равным одному, `PYTHONHASHSEED=0`; скрытые фильтры из `PYTEST_ADDOPTS` и `PYTEST_PLUGINS` не наследуются. Квитанция привязана к плану и контрольным суммам лога, фактически собранных node ID и результата pytest. Пропуски в библиотечном профиле не допускаются; отсутствие, повторное покрытие и смена состава тестов проваливают приёмку.

Прерванная попытка сохраняется и может быть выполнена заново при неизменном окружении. Подтверждённую ошибку теста нельзя скрыть успешной повторной попыткой: приёмка отклоняет такую историю. Изменение кода или зависимостей требует нового плана. Сводка показывает число попыток и сумму времени завершённых pytest-процессов; при параллельном запуске это не время от начала до конца всей проверки.

Флаг `--test-receipts` повторно проверяет полный план и все результаты, а затем использует их вместо ещё одного дорогого монолитного pytest. Это явное повторное использование вычислений того же исходного и runtime-окружения, а не отключение тестов. Без флага сохраняется обычный монолитный режим.

[Квитанция батч-протокола v115](benchmarks/local_test_batches_v115.json) содержит состав всех 3367 тестов, 170 квитанций, отпечатки исходников и runtime. Итоговая библиотечная проверка принята без ошибок и пропусков; незавершённые монолитные попытки сохранены отдельно.

`portable` выбирает весь каталог `tests/`, исключая только явно помеченные `external_integration`, `long_running`, `hardware_specific`. `library` выбирает перечисленные библиотечные тесты, `all` не применяет исключение маркеров. Результат всегда содержит выбранный профиль и фактические числа выполненных, ошибочных и пропущенных тестов. Окончание процесса pytest без выполненных тестов не принимается. Профиль portable не означает испытание всех внешних интеграций и аппаратных ускорителей.

## Что делает протокол

1. Проверяет переданную приёмку номинала и фиксирует все поставляемые Python-исходники/ресурсы и правила сборки. Проверяет локальные тесты и сохраняет квитанцию pytest.
2. Выполняет короткую нативную станционную матрицу из восьми сценариев. Семь должны завершиться полностью; недопустимая команда должна дать именно `invalid_action`. Каждая попытка включает checkpoint и настоящее восстановление. Дополнительно проверяется восстановление после отключения питательного насоса с точным совпадением оставшихся переходов и конечного checkpoint, а также экспорт пяти физических кадров.
3. Собирает sdist, распаковывает его в новый временный каталог и уже из него строит wheel. Накопленный `build/lib` исходного checkout не участвует в этой сборке.
4. Сверяет каждый поставляемый модуль и ресурс wheel с текущими байтами `src`, `scripts`, `data`, `scenarios`, `validation`. Недостающие, устаревшие, дублирующиеся файлы и Python-кэши отвергаются.
5. Устанавливает wheel без сети и разрешения зависимостей в новый venv вне checkout. Научные зависимости переиспользуются через `system_site_packages`; это не новая независимая установка NumPy/SciPy.
6. В новых процессах проверяет исследовательский replay, ресурсы, критерии неопределённости, агентские интерфейсы и станционную матрицу. Станционный процесс запускается с `python -I` и требует импорта модуля, среды и экспортера из `site-packages`.
7. Сравнивает станционные научные результаты целиком, включая все checkpoint, наблюдения, события, причины ожидаемого отказа и кадры просмотра. Признак исходного/установленного запуска хранится отдельно. В конце повторно проверяет неизменность исходников и ресурсов.

JSON-квитанции из `docs/benchmarks` включены в sdist: явный вход часового номинала доступен и после распаковки исходного архива. Проверка фиксирует контрольные суммы существующих квитанций до запуска тестов и требует их неизменности. Добавление нового отчёта после приёмки не изменяет прежние входы.

Исторические тесты сравнивают все поля исходников, отдельно признавая одну подтверждённую миграцию: точный кэш водяного модуля v104. Разрешена только известная пара SHA256 этого файла, при наличии шести точных cached/uncached сравнений v104 и применимой полной приёмки номинала v105. Любое другое изменение, пропавшее доказательство или неуспешное сравнение отклоняется. Это устраняет устаревшее требование вечно сохранять хэш до v104; исторические квитанции остаются результатами своих версий и не объявляются заново выполненными.

Это проверка одинакового численного результата на одной машине, а не независимого физического решения. Станционная матрица использует прежний объявленный `fast_candidate` без изменения параметров физики и состоит из окон 0,10–0,15 с. Она дополняет длительные доказательства, но не заменяет их.

## Часовой номинал: что переиспользуется

Флаг `--station-nominal` задаёт явную запечатанную квитанцию полного номинала v105. До начала дорогих проверок протокол требует точного совпадения текущих исходников численного рецепта и драйвера с квитанцией. Требуются оба исходных расчёта по 3600 с, 601 проверенное окно каждого, 18 совпавших математических JSON, завершённый установленный уточнённый расчёт и точный нативный restart с полным продолжением. Неполные, повреждённые и устаревшие квитанции не допускаются.

Копия входа сохраняется в новой поставке. Отчёт явно указывает `reused_existing_execution=true` и `new_hour_executed=false`: новый час на только что построенном wheel не объявляется выполненным. Нынешний wheel проверяется заново короткими сценариями и точной сверкой поставляемых файлов. Если научный рецепт менялся, необходимо сначала выполнить полноценную [повторную приёмку номинала](STATION_NOMINAL_REQUALIFICATION_RU.md). Контрольная сумма обеспечивает целостность переданной квитанции, а не независимое удостоверение её автора.

Без `--station-nominal` остаётся прежняя проверка библиотеки; в её отчёте `station_delivery.accepted=false`. Она не закрывает станционный критерий NPP-16.03 автоматически. Никакой вариант этого протокола сам по себе не присваивает полную R1 или экспериментальную валидацию.

## Результаты и отказы

`progress.json` содержит исход каждой завершённой фазы и ссылки на логи; при ошибке последующие зависимые фазы не выполняются. `tests.json` содержит фактический результат pytest. Успешный `report.json` запечатан и включает полный манифест исходников, состав wheel и станционную приёмку. `station-source.json` и `station-installed.json` сохраняют результаты двух запусков; `station-nominal-input.json` — явный переиспользованный вход. Сборки и измерительные логи остаются в каталоге артефактов.

Станционная проверка сохраняет неожиданные отказы отдельных сценариев и исключения restart/экспорта. Они проваливают приёмку, даже если остальные расчёты завершились. Ожидаемый отказ недопустимой команды проверяется отдельно и не выдаётся за физическое прохождение эпизода.


## Приёмка v113

Прошли 3367 тестов библиотечного профиля в 170 привязанных к исходникам батчах. Установленные станционные результаты совпали целиком; все 20 условий прошли. Восемь коротких случаев включают семь завершений и ожидаемый отказ. Проверка из wheel дополнительно повторила 90 тестов HEM/поставки и три квалификационных JSON целиком. Один тест отказа импорта из checkout проверен в исходном окружении и исключён в установленном. Полный portable-прогон был остановлен после обнаружения двух исправленных ошибок и не принимается как завершённый. [Квитанция v113](benchmarks/station_local_delivery_v113.json). NPP-16.03 закрыт для указанного профиля; 56/76 задач, осталось 20.
