# Периодический HEM-канал: масса, импульс и полная энергия

Блок 1.66.0, 5 ноября 2026. `atomic_model_hem_flow` добавляет отдельное конечно-объёмное семейство над строгим равновесным IF97 из предыдущего блока. У ячеек теперь изменяются собственные масса, импульс и энергия вследствие переноса через грани. Это ограниченный периодический канал, а не законченная HEM-сеть установки.

## Постановка

Плоский одномерный периодический канал постоянного сечения. Равновесные жидкость и пар имеют одну скорость, температуру и давление; свойства восстанавливаются из текущих rho/u. Области IF97 1/2/4, T=300–900 K; давление строго внутри диапазона 0.1–10 MPa с запасом 100 Pa для численного термодинамического stencil. Новые коэффициенты IF97 не вводились.

Для плотностей массы, импульса и полной энергии:

```text
W = [rho, rho*v, rho*(u + v²/2)]
F = [rho*v, rho*v² + p, v*(rho*(u + v²/2) + p)]
d(V*W_i)/dt = A*(F_(i-1/2) - F_(i+1/2)) + [0, 0, Q_i]
```

В рабочей энергии вычитается постоянное `u_reference * mass`. Поэтому численный поток рабочей энергии также содержит соответствующее вычитание из массового потока. При проверке полного физического энергобаланса этот член восстанавливается, включая невязку массы. Нельзя проверять только изменённую рабочую координату, забыв перенос опорной энергии.

## Общий поток и шаг

Каждая грань вычисляется один раз и используется для обоих соседей с противоположными знаками. Использован поток типа Lax-Friedrichs/Rusanov:

```text
F_face = (F_left + F_right)/2 - a*(W_right - W_left)/2
```

Здесь `a` — заданная верхняя граница волновой скорости, фиксированная для всей задачи, а не автоматически подогнанная локальная диссипация. Метод и оценка скорости обсуждаются в [первичных учебных материалах автора CFD-решателей](https://www.ammar-hakim.org/sj/hancock-muscl.html). Наша реализация потока собственная; MUSCL-реконструкция и HLLC в это семейство не включены.

Время интегрируется совместным SSPRK3. На каждой стадии проверяются положительность массы, обратный EOS без проекции, область состояния и характеристические ограничения. Шаг не превышает `min(max_step_s, CFL*dx/a)`, CFL<=0.3. Непрошедшая стадия отклоняет весь вызов; скрытого переключения потока, clipping или автоматического подменивания EOS нет. Строгая математическая invariant-domain/entropy-stability гарантия для всех начальных данных не заявляется. На фазовых границах глобальный третий порядок времени не утверждается.

## Характеристики около насыщения

Для одной фазы берётся фундаментальная скорость звука IF97. Для смеси строится равновесный фазовый chart; производная по массовой доле берётся точно как разность насыщенных свойств, а производная по давлению — центральным stencil с проверкой половинного шага. Это позволяет отдельно оценить предел со стороны смеси на x=0/1 без выхода stencil паросодержания за [0,1].

Возле границы учитываются обе односторонние ветви. Для численного волнового ограничения используется большая скорость; для консервативного допуска скорости жидкости — меньшая. `abs(v)` не превышает 0.2 этой меньшей характеристики, а `abs(v)+c_bound` — заданного `a`. Это ограничение квалифицируемого слабого режима, не утверждение единственности двусторонней термодинамической производной на границе. Усреднённые однофазные скорости звука смеси не используются. Сама EOS и quality при этом не сглаживаются.

## Балансы и энтропия

Периодические внутренние потоки сокращаются. Проверяются отдельно:

```text
sum(deltaMass) = 0
sum(deltaMomentum) = 0
sum(deltaPhysicalTotalEnergy) = integratedExternalHeat
```

Нагрев задаётся как прямой объёмный энергетический источник. Это не корреляция кипящей теплоотдачи стенки. Журнал `external_heat_entropy_j_k` интегрирует сумму Q/T теми же RK-стадиями. Разность полного изменения энтропии и этого журнала публикуется как `numerical_entropy_production_j_k`.

Для адиабатического вызова контролируется неубывание полной энтропии относительно начала вызова и предыдущего принятого шага, с фиксированным численным допуском. Этот контроль не использует энтропийную ошибку прежней нагреваемой истории как основание для отказа текущего адиабатического участка.

Вызовы с нагревом/охлаждением сохраняют энтропийную диагностику, но полный второй закон для нагреваемой смеси этим блоком не принят. Отдельного доказательства знака производства на каждой грани нет. Числа энтропии не заменяют такую квалификацию.

## API и restart

```python
from atomic_model_hem_flow.model import PeriodicHEMChannel

model = PeriodicHEMChannel(request)
observation = model.advance(0.002)
checkpoint = model.checkpoint()
```

`step(full_heat_power_w, duration_s, expected_revision=..., controller_state=...)` атомарно меняет полную маску мощности и явное JSON-состояние контроллера. Принятые физические координаты, оба тепловых интеграла, мощность, clock и controller state фиксируются вместе. Поздний отказ, изменение исходников, устаревший revision или ресурсный отказ оставляют исходное состояние. Операции одного экземпляра сериализованы.

`residual(state, rate)` возвращает чистую размерную невязку: kg/s, kg*m/s², W и W/K для соответствующих блоков. Наблюдения отделены от внутренних массивов. Восстановление checkpoint повторяет все принятые вызовы и сравнивает весь результат; один переписанный SHA не разрешает подмену физической истории. Источники старого `atomic_model_hem` не изменены; его прежний vessel checkpoint по-прежнему воспроизводится.

Ограничения: 4–16 ячеек, 128 вызовов, 4096 шагов за вызов, длительность вызова до 0.1 s, checkpoint до 4 MiB, controller state до 32 KiB. Более мелкий заданный шаг может исчерпать общий бюджет раньше максимальной длительности. Ни эти пределы, ни короткая квалификация не доказывают пригодность длительного установочного сценария.

## Запуск

```bash
atomic-hem-flow demo --output artifacts/my-hem-flow
atomic-hem-flow replay artifacts/my-hem-flow
atomic-hem-flow qualify --output artifacts/my-hem-flow-qualification.json
```

Эквивалентный модуль: `python -m atomic_model_hem_flow ...`. Demo нагревает равномерную почти сухую смесь до однофазного пара, затем возвращает в смесь охлаждением. Это одновременно проверка фазового перехода в консервативных ячейках и совместного controller/plant checkpoint. Момент пересечения фазы не локализуется как точный event root: фаза выбирается по текущим запасам каждой RK-стадии.

`run input.json --output folder` принимает вход той же схемы, который создаёт demo. Результат содержит вход, наблюдения и native checkpoint; replay заново выполняет всю программу.

## Численные свидетельства

Шесть сценариев: покой смеси, равномерное движение жидкости и пара, слабая акустическая волна, изобарический контакт составов и равномерное испарение. Для каждого выполнены три временных ограничения: 18 траекторий. Два отдельных IVP-эталона, DOP853 и Radau, интегрируют абсолютные m/P/E и независимо собирают грани в цикле. Они не вызывают production RHS или его shifted-energy координаты, но используют общий строгий IF97 inverse. Это проверка временного интегрирования одной пространственной схемы; независимым EOS или пространственным эталоном она не является.

Критерии заданы до итогового прогона: 0.05 Pa, 1e-5 K, 1e-8 относительной ошибки rho, 0.001 J по внешнему тепловому интегралу, 1e-5 J/K по тепловому энтропийному интегралу. Для контакта составов грубый шаг не прошёл по rho; критерий сохранён, а шаги уточнены до 2e-5/1e-5/5e-6 s. Остальные сценарии используют 1e-4/5e-5/2.5e-5 s. Значения фактически принятых максимальных шагов сохранены.

Пространственная проверка отдельная: слабая линейная акустическая волна амплитудой 1 Pa, с правильными средними по ячейке на 4/8/16 узлах. Средняя абсолютная ошибка давления составляет примерно 0.462/0.363/0.245 Pa. Она уменьшается, но остаётся заметной относительно амплитуды. Это демонстрация грубой сходимости сильно диссипативной схемы первого порядка, не достижение высокой пространственной точности и не измеренный асимптотический порядок.

Проверены парный поток, ненулевой перенос массы, три баланса, отражательная симметрия, фазовый цикл, pure residual, точный JSON-restart, подмена rehashed checkpoint, поздние отказы потока/источников, адиабатическая энтропийная диагностика, CFL, ревизии и конкурентные команды. Установленный wheel выполняет demo/replay, всю qualification и новые тесты вне checkout с унаследованными научными зависимостями. Межмашинная/OS-матрица не заявлена.
