# Сжимаемые ёмкости: масса, внутренняя энергия, EOS и энтропия

`CompressibleStorageGraph` из `scripts/compressible_storage_graph.py` — отдельное
семейство с собственными массой и внутренней энергией каждого объёма.
Плотность равна m/V, давление и температура вычисляются из EOS. Расширение
задаётся законом движения поршня; работа давления входит в первый закон.
Это не подстановка gravity-density в постоянноплотностную сеть.

```bash
python -m examples.compressible_storage
python -m pytest tests/test_compressible_storage.py -q
python -m scripts.qualify_compressible_storage run artifacts/ai05_compressible_storage_campaign_v1.json
python -m scripts.qualify_compressible_storage audit artifacts/ai05_compressible_storage_campaign_v1.json
```

## Калорическая EOS и её область

Используется `stiffened_caloric_v1`, один набор параметров на всю сеть:

```text
R = (gamma-1)*cv; cp = gamma*cv
p + p_inf = R*rho*T
u = cv*T + p_inf/rho + e_offset
h = cp*T + e_offset
s = cv*ln(T/T_entropy_ref) - R*ln(rho/rho_entropy_ref)
c² = gamma*(p+p_inf)/rho
```

При gamma>1, cv>0, p_inf>=0 это согласованная механическая/калорическая EOS
со связанными энтропией и производными. Класс `StiffenedCaloricEOS` предоставляет
`rho_T`, `p_T`, `rho_u`. Проверяются прямое/обратное преобразования,
`du = T*ds - p*dv` и изоэнтропическая производная давления.

Форма stiffened-gas и связанные параметры описаны в первичных документациях
[LANL Singularity-EOS](https://lanl.github.io/singularity-eos/jhp/two_eos/src/models.html)
и [INL MOOSE](https://mooseframework.inl.gov/docs/site/source/fluidproperties/StiffenedGasFluidProperties.html).
Реализация формул и тестов здесь собственная. Примеры используют синтетические
параметры: это не калибровка воды, IAPWS, фазовое равновесие или валидация
реального теплоносителя. Численные границы p/T/rho не доказывают фазовую область.

## Состояния и консервативная постановка

Каждый узел `compressible_inventory_v1` имеет постоянный набор параметров:
V0, скорость поршня, минимальный/максимальный объём, начальные p/T, нагрев,
UA и температуру среды. `V(t)=V0+volume_rate*t`. До 8 узлов и 12 связей,
сеть связная; один изолированный узел допустим. Внешних массовых источников
и заданных границ давления нет. Все давления — динамические состояния EOS.

Связь `resistive_thermal_link_v1` задаёт монотонный закон
`p_from-p_to = linear*q + quadratic*q*abs(q)` и необязательную теплопроводность.
Массовый расход алгебраический, ориентирован от from к to; linear>0,
quadratic>=0. Коэффициенты фиксированы и задаются пользователем, без
автоматической плотностной коррекции, choking или расчёта геометрии клапана.

Уходящая масса переносит энтальпию донора. Тот же поток энтальпии с
противоположным знаком поступает получателю. Теплопроводный поток также
вычисляется один раз для обоих концов. Дополнительное тепло `q*deltaP/rho`
не добавляется: это повторно учло бы энергию дросселирования.

```text
dm_i/dt = sum(mass_flow_into_node)
dU_i/dt = Q_i - p_i*dV_i/dt + sum(enthalpy_flow_into_node)
Q_i = heat_i + UA_i*(Tambient_i-T_i)
```

Для точности при большом p_inf интегратор хранит приращения массы и
`A = U - p_inf*V - e_offset*m = m*cv*T` относительно исходного состояния.
Поэтому `dA/dt` содержит `-(p+p_inf)*dV/dt`. Изменение физической энергии
восстанавливается как `deltaA + p_inf*deltaV + e_offset*deltaM`.
Давление также вычисляется через относительные приращения без вычитания
двух больших почти равных чисел. Это смена координат, не изменение EOS.

## Энтропия и три проверки

Общая масса замкнутой сети постоянна. Для всей сети:

```text
DeltaM = 0
DeltaU - Q_external + W_piston = 0
DeltaS - S_external - S_generated = 0
```

`W_piston = integral(sum(p*dV/dt))`: положительный знак — работа жидкости
при расширении. Обратимое движение поршня само не создаёт энтропию.
Нагреватель передаёт энтропию `heat/T_node`; обмен с окружающей средой —
`UA*(Tamb-T)/Tamb`. Разность учитывается в неотрицательном производстве.

Для направленной связи от высокого давления к низкому вычисляется:

```text
sigma_mass = abs(q) * [cp*(x - ln(1+x)) + R*ln((p_up+p_inf)/(p_down+p_inf))]
x = (T_up-T_down)/T_down
sigma_conduction = conductance*(T_a-T_b)^2/(T_a*T_b)
sigma_ambient = UA*(Tamb-T)^2/(Tamb*T)
```

Все слагаемые неотрицательны в объявленной области. Для малых x используется
устойчивый ряд, а не разность почти равных чисел. Изменение полной энтропии
вычисляется через log1p исходных массовых/энергетических/объёмных приращений.
Контроль энтропии — отдельная проверка, а не только вывод диагностического числа.
Изменение нулей энергии или энтропии не должно менять физическую траекторию.

## Управление, невязка и checkpoint

`advance(dt)` рассчитывает положительный интервал.
`step(full_heat_power_w, dt, expected_revision=..., command_id=...)` меняет
полную маску нагревателей на текущем времени, затем интегрирует интервал.
Массы, энергии, объёмы и производные EOS величины при переключении не
сбрасываются. Прямой команды установки давления нет: для этого нужны
физические массовые/энергетические воздействия.

`residual(time, coordinates, rates)` — чистая размерная невязка в объявленных
приращениях: kg/s для массы, W для A и двух энергетических интегралов,
W/K для двух энтропийных интегралов. Выход стадии из положительных запасов,
объёмной или p/T/rho области отклоняет вызов полностью, без clipping.
Проверяются стадии и принятые наблюдения, не строгая интервальная гарантия.

`compressible-storage-radau-v1` связывает приращения с исходной рамкой m0/A0/V0
через хеш полного ввода; сохраняет абсолютное время, четыре интеграла и журнал
команд нагрева. Для restore нужен тот же исходный ввод, а не только текущее
наблюдение.
Checkpoint связывает EOS, начальные состояния, скорости поршней, геометрию,
законы связей, источники, исходники/бюджеты и версии библиотек. Проверяется
точное продолжение в том же окружении; заново вычислять V от нулевого времени
после restore нельзя. Хеш — не подпись и не полный физический replay истории.

## Проверка и оставшиеся расширения

9 программ по 20 s, 27 траекторий на трёх фактически различных временных
сетках, 189 наблюдений и 18 независимых DOP853/Radau. Эталон интегрирует
абсолютные m/U и использует отдельные формулы EOS и потоков; production
использует приращения m/A. Сравниваются массы, давления, температуры и четыре
интеграла энергии/энтропии. Проверены 9 точек EOS и изоэнтропические
производные; четыре некорректных программы должны отказать с откатом.

Отдельная проверка за 200 s сравнивает равновесие двух теплообменивающихся
ёмкостей с аналитическим результатом из общей массы, энергии и объёма.
Основной 20-секундный переходный прогон не объявляется достигшим равновесия.
Есть точные изохорный нагрев, изоэнтропические сжатие/расширение,
изобарное нагреваемое расширение и тесты намеренно сломанного первого/
второго закона. Последние должны отказать и сохранить исходное состояние.

Это отдельный однофазный backend хранения, не его автоматическая сборка
с прежней инерционной петлёй. Инерция потоков, гравитационная энергия при
переносе переменной массы, кинетический перенос, акустические волны,
механика поршня под нагрузкой, смешанные среды, двухфазность, IAPWS-сеть и
объектная валидация остаются открытыми. Свойство EOS c² не означает, что
пространственные волны давления разрешаются этим сосредоточенным решателем.
