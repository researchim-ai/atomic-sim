# AI-05: идеальный обратный клапан в инерционной сборке

Дата: 1 ноября 2026. Продолжение [насоса, вала и накопителей](AI_05_PUMP_STORAGE_RU.md).
Модель `check-valve-pump-storage` 1.0.0 добавляет гибридное ограничение
одностороннего расхода. Поддержаны посадка при нулевой скорости потока,
удержание закрытого состояния и повторное открытие. AI-05 остаётся partial,
**3/8 задач приняты**; паровой компенсатор и общая сеть ещё открыты.

## Фазы и область модели

```text
g = p_left-p_right+H-p_crack
open:   m>=0, I*mdot=g-R*m²
closed: m=0, mdot=0
```

При открытом клапане работа порогового перепада `p_crack*m/rho` нагревает
правый накопитель. Поток при принятом состоянии только слева направо.
При закрытом клапане газовые энергии, теплообмен, утечка насоса и вал
продолжают развиваться; остановлен только перенос жидкости. Поэтому насос
может работать на закрытую ветвь, превращая механическую работу в тепло
утечки и потери подшипников. Давления не заменяются внешним boundary condition.

Реакция закрытой связи равна `max(-g,0)`. Она не совершает работы при m=0.
Открытие разрешается при положительном разрешённом g=1e-6 Pa. Это объявленное
численное разрешение события, не материальный гистерезис клапана. До него
допускается невязка закрытой связи <=1,01e-6 Pa; она выводится отдельно как
`check_constraint_residual_pa`. Проверяется невязка корня открытия <=1e-5 Pa.

Посадка определяется корнем m=0 при убывающем расходе. Не задаётся момент
закрытия «по сетке» и не отбрасывается конечная кинетическая энергия.
После локализации допускается только остаток |m|<=1e-10 kg/s и перевод его
в точный нуль с кинетической поправкой <=1e-12 J. Остаток и поправка записываются
в `check_closed`, а общий ledger по-прежнему должен пройти свой бюджет.

Это идеальное седло при нулевом расходе. Масса/угол створки, её привод,
контактная упругость, удар, шум, гидроудар и акустика не моделируются.
Нет командного мгновенного запирания при ненулевом m. Характеристика
порогового перепада не заменяет экспериментальную карту реальной арматуры.

## Численный метод и энергия

Radau/BDF интегрируют отдельные гладкие участки с terminal events. При
событии принимается состояние именно в найденном корне, меняется фаза,
перезапускается решатель и продолжается остаток того же внешнего интервала.
Выходной шаг не определяет момент посадки. Максимум 128 переходов на внешний
интервал защищает от незавершающейся последовательности; превышение означает
отказ с rollback, а не молчаливое пропускание события.

Событие в начальной точке может менять фазу без продвижения времени;
после него решатель продолжает тот же интервал. Это проверено отдельно
для открытия на пороге и посадки с расходом ниже точности корня.
Склейка публичного dense-output результата не требуется; для локализации
событий решатель использует свой локальный полином.

В закрытой фазе RHS вычисляется на подпространстве m=0; соответствующие
строка и столбец якобиана нулевые. m остаётся постоянным точно. Гладкое
продолжение открытой фазы на отрицательный пробный m используется только
для локализации корня; отрицательные принятые состояния отклоняются.
Принятый расход не обрезается по завершении большого шага.

В открытой фазе к выходной энтальпийной мощности правого накопителя добавляется
тепло порогового сопротивления. Разность портовых потоков с механической
мощностью насоса и отводом тепла утечки остаётся равной dK_flow/dt.
Глобальная энергия, газовая работа, баланс вала и отдельные тепловые/механические
порты сохраняются из предыдущей сборки. Реакция связи не является скрытым
источником тепла или работы. Посадка не обнуляет энергетические интегралы.

Каждый внешний вызов начинает сегментный решатель заново: история между
выходными интервалами не сохраняется. Это не DAE backend и не оптимизация
пропускной способности. Разрешённые горизонты/политики проверяются отдельно.

## Управление и восстановление

Сохраняются атомарные векторы момента двигателя и конечного сопротивления.
Они не являются командой физического запирания клапана. Ошибка любого
сегмента, наблюдения после посадки или команды возвращает полностью последнее
принятое состояние, время, фазу и историю событий. Нет частично принятого
внешнего интервала, даже если внутри него уже нашёлся корень.

Checkpoint schema 1 содержит исходную и текущую фазы, активные управления,
полный энергетический базис, hash конфигурации и хронологию посадок/открытий.
Проверяются чередование фаз, цепочка команд, остатки корней, положительность
запасов и энергетические балансы. Закрытый snapshot требует m=0 точно.
Снимок подтверждает согласованность записи, не подлинность физической истории.

## Независимая проверка

Добавлены **22 теста**: аналитическое открытие, закрытие без обратного
потока, точный покой без дребезга, якобианы обеих фаз, работа связи, затухание
вала при заблокированной линии, повторное открытие, restart и полный rollback
при ошибке после посадки.

Бюджет задан до серии: `validation/ai05_check_storage_budget_v1.json`.
13 семейств, 28 основных пакетов: base/tight Radau и две серии BDF.
Переходы — 20 с; два стационара — 100 с; каждый пакет дополнен restart на 1 с.
Независимый DOP853 интегрирует абсолютные температуры. В его закрытой фазе
расход удалён из вектора неизвестных — 13 состояний вместо 14; production
RHS/Jacobian и его проекция состояния не используются.

Первое открытие дополнительно сравнивается с аналитическим решением
закрытого вала: `omega=omega_eq+(omega0-omega_eq)*exp(-a*t)`, где
`a=(D²/C+B)/J`. При неподвижной жидкости и отсутствии газового теплообмена
давления до открытия постоянны, поэтому время получается логарифмом.
Отдельно проверяются точные интегралы утечки/подшипников при закрытом
затухающем вале. Аудит заново вычисляет метрики, временное уточнение,
энергию по абсолютным температурам и отсутствие обратного расхода.

## Запуск

```bash
python -m sdk.check_storage_experiment scenarios/ai05_check_valve_restart.json \
  --output artifacts/NEW_CHECK_STORAGE_RUN
# После установки wheel:
atomic-check-storage-experiment scenarios/ai05_check_valve_restart.json \
  --output artifacts/NEW_INSTALLED_CHECK_STORAGE_RUN

python -m scripts.verify_check_storage --output artifacts/NEW_CHECK_STORAGE_VERIFICATION
python -m scripts.audit_check_storage artifacts/NEW_CHECK_STORAGE_VERIFICATION \
  --output validation/NEW_CHECK_STORAGE_AUDIT.json
```

Input, initialization, trajectory, checkpoint, report и manifest включают
паспорт, source fingerprint, версии и SHA256. При отказе сохраняется согласованный
префикс; deadline проверяется в RHS и не является изоляцией ОС. Численная
приёмка ограничена объявленными случаями. Промышленная, экспериментальная
и объектная квалификация не заявляются.
