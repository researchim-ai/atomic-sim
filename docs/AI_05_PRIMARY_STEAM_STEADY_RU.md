# Совместная стационарная инициализация первичной петли и парового цикла

Расчёт рабочей точки реализован в `scripts/design_primary_steam.py`.
Он выбирает согласованные начальные состояния и граничные команды по
заданным давлениям/качествам паровых запасов, скорости турбины, открытию
парового клапана и знаковому расходу первичной жидкости.

Результат — обычный явный вход SDK schema 1. Предпроцессор поставляется
с исходниками и замороженными инженерными скриптами; отдельный installed
console entry point для него не заявлен.

## Уравнения и выбранные параметры

Сначала определяется стационарный паровой цикл: питание, нагрузка генератора,
теплоотвод и температуры стенок. Необходимое тепло парогенератора подаётся
через внутренний тепловой порт; внешний heater парового цикла равен нулю.

Для заданного первичного расхода вычисляются напор сопротивлений, скорость
объёмного насоса и момент мотора. Далее решается система из `2N+1` уравнений
для температур жидкости, первичных стенок и мощности выбранного нагревателя.
Учитываются адвекция с правильным донором для каждого направления потока,
трение, утечка насоса, уже заданный нагрев, обмен с окружением и теплообмен
с парогенератором. Тепло насоса сокращает требуемый внешний нагрев.

Температуры решаются как приращения к опорной температуре. Строки и столбцы
масштабируются; проверяется обусловленность и размерные невязки. После
линейного решения полная связанная модель заново проверяет давление,
переохлаждение, балансы и производные всех физических запасов.
`warmup_steps=0`: время интегрирования для построения начального состояния
не используется. Энергетические счётчики при последующем стационарном
расчёте продолжают накапливаться.

Пример при расходе 100 кг/с выбирает первичный нагрев около 256.732 кВт
при передаче в парогенератор 260.316 кВт. Разность обеспечивается
гидравлической диссипацией и утечкой насоса. Обратный расход рассчитывается
с собственными знаками напора/вала и направлением адвекции.

## Контракт использования

Вход — полная конфигурация `primary-loop-steam-power-cycle` с пустым
`timeline`. Непустая временная шкала отклоняется, поскольку подобранные
команды изменили бы смысл её абсолютных значений. Начальные первичные
температурные догадки заменяются; параметры материалов и геометрия сохраняются.

```bash
python -m scripts.design_primary_steam operating_point.json \
  --primary-flow-kg-s 100 --output artifacts/NEW_STEADY_POINT
atomic-primary-steam-experiment artifacts/NEW_STEADY_POINT/input.json \
  --output artifacts/NEW_STEADY_RUN
```

В папке точки сохраняются исходный запрос, явный `input.json`, отчёт о
выбранных командах/невязках и manifest с SHA256. Неподдерживаемый режим
отклоняется до создания выходной папки: например, недоопределённая
нулевая циркуляция, требование отрицательного нагревателя или потеря
заданного переохлаждения при недостаточном расходе.

Это проектирование граничных условий для объявленной рабочей точки.
Решение произвольного набора фиксированных команд, нейтронное равновесие
реактора и переменная EOS первичного контура в эту процедуру не входят.

## Проверка

19 тестов проверяют прямой/обратный расход, частичное паровое открытие,
потери в окружение, замену начальных догадок, независимые размерные
невязки, недопустимые режимы, manifest и отсутствие переходного разгона.

`scripts/qualify_primary_steam_design.py` проверяет семь семейств двумя
методами, включая сохранение прямой/обратной стационарной точки 120 с.
Сравниваются независимая система абсолютных состояний и решение с
постоянными физическими состояниями/линейными счётчиками. Режим решателя
для стационарной задачи объявлен отдельно от строгой переходной матрицы;
физические бюджеты точности общие. Для стационарного сигнала порядок
сходимости не выводится из численного шума.

Квалификация и аудит выполняются отдельно:

Текущий статус: исправленная реализация прошла **14/14** стационарных
прогонов и [независимый аудит](../validation/ai05_primary_steam_design_audit_v1.json),
повторённый из frozen-sdist с идентичным отчётом. Установленный wheel
воспроизвёл прямую и обратную рабочую точку по 120 с на BDF;
траектории/checkpoint совпали с checkout. См.
[installed-проверку](../validation/ai05_primary_steam_installed_v2.json).
Полная переходная квалификация исправленных исходников также принята:
[53 пакета / 17 семейств с холодным frozen-аудитом](../validation/ai05_primary_steam_audit_v2.json).
В первом прогоне Radau сохранил рабочую точку 120 с, но потребовал
118956 шагов; BDF выявил деградацию шага. Отдельный диагностический
прогон BDF с `rtol=1e-4` завершился ошибкой
`Required step size is less than spacing between numbers` около 18 с.
Следовательно, ослабление допуска не является исправлением.
Причина связана с округлением при восстановлении больших абсолютных
энергий и температур из малых приращений. Поправка только паровой части
не устранила срыв; нужна согласованная обработка всей связанной системы.
Диагностические результаты сохранены отдельно:
[14 прогонов / 7 семейств](../validation/ai05_primary_steam_roundoff_diagnostic_v1.json).
Они не заменяют квалификацию новой реализации.

### Численное продолжение малых приращений

В `PrimarySteamCycle.derivatives` реализовано локальное продолжение
производных около фиксированного начального состояния. Радиус определяется
максимальным относительным приращением физических переменных, с масштабами
`1e-12` от начальных запасов/температур/расхода/скорости; для паровых стенок
используется температурный масштаб 300 К, для нулевого первичного расхода
и скорости — нижний масштаб 1 в соответствующих единицах.
Энергетические счётчики не входят в радиус и не влияют на производные.

При радиусе до половины окна используется `f(y0)+J(y0)*(y-y0)`;
между половиной и полной шириной — смесь с исходными нелинейными
уравнениями с весом `q³*(10-15q+6q²)`. За пределами окна возвращаются
исходные нелинейные производные. Якобиан продолжения вычисляется
конечными разностями исходных уравнений, с прежними физическими масштабами.
Кэш зависит от конфигурации и текущих команд; история траектории и
прошлые вызовы решателя не задают опорную точку. При восстановлении
checkpoint опорная точка восстанавливается из исходной конфигурации.

Это явно объявленная численная аппроксимация на масштабе малых приращений.
Состояния не обрезаются и не проецируются на равновесие; IF97-инверсия,
наблюдаемые запасы и физические границы вычисляются по прежним формулам.
Формат checkpoint не изменён. В стационарной матрице возвращены исходные
строгие настройки `rtol=1e-10`, `atol_scale=0.01`; физические бюджеты
не ослаблены. Новые переходная и стационарная квалификации должны быть
привязаны к исправленным исходникам; старые результаты этого не доказывают.

```bash
python -m scripts.qualify_primary_steam_design --output artifacts/NEW_DESIGN_CHECK
python -m scripts.qualify_primary_steam_design --audit artifacts/NEW_DESIGN_CHECK \
  --output artifacts/NEW_DESIGN_AUDIT.json
```

Область модели сохраняется: постоянные rho/cp, объёмный насос, равновесные
паровые запасы и эмпирический паровой расход. Объектная и экспериментальная
валидация отсутствует: `validated=false`, `plant_referenced=false`.
