# Проверка управляемого восстановления — v108

[English](STATION_CONTROLLED_RECOVERY_EN.md)

В `atomic_model_station_tasks` добавлен `compare_recovery`: оценка восстановления расхода по двум ветвям, начатым из одного checkpoint. Агент действует в первой ветви; во второй по умолчанию сохраняются команды, действовавшие в точке разветвления. Исходная среда не продвигается.

Обычный `Task(kind="recovery")` по-прежнему оценивает наблюдаемое возвращение в полосу. Новый API отвечает на более узкий вопрос: обеспечили ли действия агента восстановление в объявленном окне, когда опорная ветвь его не обеспечила? Старые метрики и исторические протоколы не переопределяются.

## Условия успеха

Начальное допустимое измерение должно находиться вне заданной полосы. Ветвь агента должна закончить весь контракт, вернуть измеряемый расход в полосу и удержать его в конце не меньше `dwell_s`. Отсутствующие или недопустимые показания прерывают удержание и запрещают успешное сравнение. Защитный останов не засчитывается как восстановление.

Обе ветви должны пройти весь горизонт без ошибок исполнения и с допустимыми энергетическими балансами. Ошибка опорной политики или решателя не делает действия агента успешными. Неудачные команды и фаза отказа сохраняются, а исходное состояние остаётся неизменным.

Для несопоставимых ветвей `relative_iae_gain` равен `null`. Ошибка исполнения или неполный префикс не публикуют ложный положительный выигрыш как награду.

Контракт также требует, чтобы опорная ветвь не восстановилась, команды различались, а уменьшение интеграла нормированной абсолютной ошибки было не меньше объявленного порога. Контракт намеренно консервативен: ускорение восстановления, которое успевают завершить обе политики, здесь не засчитывается. Для него нужна другая постановка задачи.

Ошибка вычисляется по правым концам обычных тактов измерения:

`IAE = Σ abs(measured_flow − target) / target × Δt`.

Относительный выигрыш — `(IAE_baseline − IAE_agent) / max(IAE_baseline, 10⁻¹² с)`. Величины не обрезаются для получения положительного результата; не представимая конечными числами арифметика отклоняется. Это метрика дискретных измерений, а не доказательство непрерывного пребывания истинного расхода в полосе.

## Изоляция ветвей и видимость данных

Ветви получают копии одного физического состояния, регуляторов, измерительных фильтров, очередей и состояния RNG. Каждая политика создаётся новой фабрикой и получает только измерительное наблюдение, публичную схему действий и контракт цели. Ни checkpoint, ни физический вектор, ни расписание неисправностей ей не передаются.

Отчёт сравнения содержит привилегированные данные оценщика, включая контрольные суммы и конечные checkpoint. Он не добавляется в транспорт наблюдений агента. Проверка измерительных ограничений интерфейса не является изоляцией произвольного Python-кода от процесса хоста. Внешняя политика также должна самостоятельно фиксировать свои веса, код и случайность; строка `policy_id` не сериализует их.

## Пример: восстановление питательного расхода

```python
from atomic_model_station_env import StationEnv, EnvConfig
from atomic_model_station_control.policy import valid_reading
from atomic_model_station_tasks import (
    RecoveryContract, compare_recovery, restart_flow_policy,
)

env = StationEnv(EnvConfig(max_steps=25, tick_s=.05,
                          automatic=False, rtol=1e-10))
observation, _ = env.reset()
target = valid_reading(observation, "feed_flow", "feed_flow_kg_s")
for _ in range(4):
    env.step({"operator": {"feed_pump_on": False}})

contract = RecoveryContract("feed_flow", target,
                            steps=20, dwell_s=.2)
result = compare_recovery(env, contract,
                          lambda: restart_flow_policy,
                          policy_id="restart-flow/v1")
print(result["task_success"], result["relative_iae_gain"])
```

Состояние получено обычными командами и интегрированием, без ручного исправления запасов или расхода. Политика видит измерение с обычной динамикой датчика. `restart_flow_policy` запрашивает включение соответствующего насоса, если наблюдаемый расход ниже нижней границы полосы. Это простая исходная политика; подбор оптимального управления она не выполняет.

Поддержаны измерительные каналы `feed_flow` и `condensate_flow`. Точка сравнения должна иметь запас объявленных шагов. Полный контракт означает все запрошенные шаги от этой точки, а не автоматически весь эпизод среды.

## Локальная приёмка

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:. .venv-layout/bin/python -m scripts.qualify_station_controlled_recovery --output artifacts/my-controlled-recovery
```

Протокол проверяет пять сравнений: включение насоса, бездействие, естественное восстановление при уже включённом насосе, недопустимое действие агента и недопустимое действие опорной политики. Все попытки сохраняются. Последнее сравнение не считается успехом даже при восстановившемся агенте.

Отдельно исходный checkpoint восстанавливается штатным API, и положительное сравнение повторяется целиком. Приёмка требует точного совпадения всего результата, а не только итогового признака успеха.

## Границы результата

Это сравнение действий в одной детерминированной исследовательской модели при совпадающем начальном состоянии. Оно не является оценкой причинного эффекта на реальной установке или статистикой генеральной совокупности. Четыре намеренных отрицательных контроля не включаются в рейтинг качества агента как случайная выборка задач.

Горизонт выбранного примера — одна секунда после разветвления. Длительные задания, разнообразие оборудования, train/dev/test по независимым объектам и промышленная полезность требуют отдельной приёмки. NPP-14.03/04 этим блоком не закрываются; общий статус остаётся 50/76.

## Результаты поставки

Положительный сценарий прошёл все условия. Интеграл нормированной ошибки уменьшился на 69.70% относительно удержания выключенного насоса. Восстановление измеряемого расхода с требуемым удержанием подтверждено к 0,90 с после разветвления; конечное удержание составило 0,30 с. Опорная ветвь не восстановилась. Эти числа относятся к объявленной дискретной исследовательской постановке.

Все четыре отрицательных контроля отклонены по ожидаемым причинам. При естественном восстановлении обе ветви выполнили цель, но успех управления не засчитан; при ошибках политик выигрыш равен null. Восстановление исходного checkpoint и весь повтор положительного сравнения совпали точно.

Прошли 103 целевых теста, включая 29 новых. Установленный вне репозитория wheel повторил 29 новых тестов и все восемь JSON протокола целиком, без исключения полей. Полный набор тестов библиотеки и длительная матрица R1 не запускались. Научный backend станции не менялся; новая версия относится к оцениванию задач.
