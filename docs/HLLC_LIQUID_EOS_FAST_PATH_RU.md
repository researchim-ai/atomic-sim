# Быстрый жидкостный путь обращения EOS для HLLC

Срез: 10 ноября 2026. После
[кэша звуковых характеристик](HLLC_SPEED_OPTIMIZATION_RU.md) основную долю
времени занимало восстановление состояния по плотности и внутренней энергии.
Ускорено это обращение для звёздных состояний HLLC, без изменения основания
`atomic_model_hem_qualified.eos` и его остальных потребителей.

## Область изменения

В `atomic_model_hem_contact.inverse.liquid_first_rho_u` воспроизводится только
первая жидкостная попытка исходного Newton-адаптера. Она используется, когда
тот же объёмный критерий относительно насыщения выбирает жидкость первой.

На каждой итерации исходный адаптер вычислял Gibbs-функцию отдельно для
остатка и якобиана. Новый путь использует один raw-результат для обоих.
Формулы и порядок операций жидкостного якобиана сохранены. Не менялись:

- исходные pressure/temperature seeds и порядок выбора первой ветви;
- 32 Newton-итерации, 18 попыток уменьшения шага;
- ограничения приращений давления и температуры;
- критерии сходимости по объёму и энергии;
- проверка исходной физической области, классификация региона и forward-residual.

Кандидат возвращается только при тех условиях, при которых исходная первая
жидкостная попытка возвращает тот же State. Вблизи насыщения, на endpoints,
при другом порядке ветвей или неудаче попытки вызывается **неизменённый полный
адаптер** с исходными seeds. Последняя Newton-точка не используется как новый
seed. Это не принудительное превращение состояния в жидкость: полный адаптер
может вернуть другую фазу, а HLLC затем отклонит её по прежнему правилу.

Нет новых коэффициентов IF97, проекции запасов, ослабления residual,
скрытого Русанова или обхода проверки обеих звёздных областей. При промахе
быстрого пути часть работы может повториться; ускорение таких случаев не
заявляется. Изменён только контактный пакет. Прямые обращения исходного EOS,
другие модели установки и независимая RH-сборка не переключены на новый путь.

## Проверка равенства

Сравнивается весь State, включая давление, температуру, плотность, энергию,
энтальпию, энтропию, фазу и регион. В тестах используются 54 сочетания шести
давлений, трёх расстояний от насыщения и трёх вариантов seed; отдельно
проверяются двухфазность, оба endpoints, близкая жидкость и неудачная попытка.
Неподдерживаемые входные данные не проецируются в допустимую область.

Все проверенные жидкостные состояния совпали с полным адаптером **точно**.
76 новых тестов дополнены прежними проверками потока и звёздного допуска.
Тест счётчика EOS обновлён на новый вход адаптера: проверяется наличие обоих
обращений, а не обязательный вызов имени прежней функции.

Пять парных запусков каждого графового профиля со сменой порядка дали
численно точно, без допускае совпадение наблюдений и числового checkpoint. Поле `source` и внешний
digest checkpoint намеренно отличаются: исходники контактного семейства
изменились, прежние checkpoint автоматически не принимаются.

## Измеренные затраты

В контрольном профиле конструктора и одного `advance(0.001)` на четырёх ячейках:

- raw Gibbs: **97 048 → 81 628**, примерно на **15,9%** меньше;
- до изменения: 8342 вызова исходного `rho_u`;
- после: 2358 исходных вызовов и 5984 обращения быстрого пути;
- суммарно — те же **8342** обращения. Для этого профиля промахов быстрого пути нет.

Это счётчики работы, не замер времени под профайлером. Парные CPU-измерения
выполнены отдельно, до параллельных широких проверок, с одним прогревом и
пятью парами. Учитываются конструктор, несколько advance до 1 мс и checkpoint.

- Прямой перепад, четыре ячейки, `hllc-local`:
  **0,94997 → 0,87966 с**, **1,08×**.
- Широкий перепад, две ячейки, `hllc-local`:
  **0,74875 → 0,70996 с**, **1,05×**.
- Прямой перепад, четыре ячейки, фиксированный `hllc`:
  **0,94259 → 0,84380 с**, **1,12×**.
- Неподвижный контакт: **0,10345 → 0,10305 с** — практически без изменения;
  на нём звёздные состояния не требуют этого обращения EOS.

Это дополнительный выигрыш относительно уже ускоренной версии со звуковым
кэшем. Данные двух отдельных кампаний не перемножаются для заявления общего
ускорения. Нет gate производительности, выделенного аппаратного стенда или
доказательства преимущества над другими моделерами.

## Научная область и воспроизводимость

Новый source-bound стенд повторяет физические face-случаи, неподвижные контакты
на сетках 2/4/8/16/32 и широкий режим до 40 мс с restart в 20 мс. Для длинного
случая сопоставляются прежний числовой пакет и два сохранённых независимых
reference-пути. Основание и код RH-эталона должны совпасть по SHA.
Траектории эталонов не интегрируются заново; вся прежняя длинная матрица
автоматически не объявляется квалифицированной для новой source-подписи.

Отдельно повторяются нативные внешние Modelica-сравнения на исходной MSL и
программы проверки отказов. Это проверка реализации той же схемы, а не
экспериментальная валидация жидкости, трубы или всей установки.

```bash
python -m scripts.benchmark_hllc_speed \
  --baseline docs/benchmarks/baselines/hem_contact_v14 \
  --baseline-protocol docs/benchmarks/baselines/hem_contact_v14_source.json \
  --output artifacts/my-liquid-eos-speed
python -m scripts.verify_hllc_speed \
  --previous-long artifacts/hllc-long-v4 --output artifacts/my-liquid-eos-check
python -m pytest -q tests/test_hllc_liquid_inverse.py
```

Нужны новые выходные директории. Архивный baseline предназначен только для
проверочного импорта, не для использования как второго runtime. Его SHA
проверяются до загрузки кода. Численное окружение должно соответствовать
зафиксированному основанию; смена EOS или его внутренних производных требует
новой квалификации быстрого пути.

Новые физические замыкания, теплообмен, трение, фазовые переходы в HLLC и
валидация установки этим ускорением не добавлены.
`validated=false`, `plant_referenced=false`.

прошли. Добавлены 76 EOS-тестов; прежние проверки потоков и кэша сохранены.
