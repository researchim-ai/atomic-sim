# Повторная приёмка часового номинала после изменения EOS — v105

Добавлена команда `scripts.requalify_station_nominal`, объединяющая полный исходный расчёт и повтор из установленного wheel. Она предназначена для проверки текущей версии после изменения вычислительной реализации, включая точный кэш EOS v104.

## Что выполняется

Исходный протокол выполняет непрерывные 3600 с на двух настройках интегратора: `max_step_s=1`, `rtol=1e-7` и `max_step_s=0.5`, `rtol=2e-8`. Начальное состояние определяется существующим согласованным решателем при t=0. Работают шесть автоматических контуров с прежними параметрами оборудования и нейтральной полосой уровней 0,2 мм.

Проверяются весь час, все 601 скользящее окно по 600 с, целевые наблюдаемые величины, отсутствие защитного останова, локальные и глобальные балансы и численное уточнение физического вектора. Накопительные счётчики проверяются через бюджеты, а не как стационарные координаты.

Затем команда офлайн собирает wheel без разрешения новых зависимостей и устанавливает его в свежее окружение вне репозитория. Доступные научные зависимости повторно используются через `system_site_packages`. Изоляция `python -I` и проверки путей импорта подтверждают запуск установленной библиотеки. Это проверка локальной поставки; чистая установка всех зависимостей из интернета не выполняется.

Установленная библиотека независимо повторяет уточнённый час и штатный replay основного расчёта: восстановление полного префикса 1800 с, продолжение 1800 с, сравнение всех записей хвоста и окончательного checkpoint. Математические JSON сравниваются целиком по содержимым файлов. Исходные coarse-файлы явно передаются как эталонные входы; они не считаются новым установленным исполнением.

## Сохранность доказательств

Проверяются версия исходников, полная длительность, 601 окно и наличие всех 721 записей каждой исходной траектории. Перед установленным запуском фиксируются хеши математических JSON. После выполнения они проверяются повторно; также проверяется неизменность wheel и исходников.

Выходная директория должна быть новой. Символические ссылки во входном математическом дереве отклоняются. Логи исполнения хранятся отдельно от математического сравнения: их время и сообщения не являются физическим результатом.

Ошибка сборки, установки или расчёта сохраняется в итоговом `report.json`, если выполнение дошло до контролируемой фазы. Частичные исходные данные и логи остаются для диагностики. Уже пройденный исходный час сам по себе не даёт положительного итогового статуса при отказе установленного повтора. Завершение процесса извне может оставить только файлы завершённых фаз; отсутствие итогового успешного отчёта не трактуется как приёмка.

## Локальный запуск

Полная последовательность:

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:. .venv-layout/bin/python -m scripts.requalify_station_nominal --output artifacts/my-nominal-requalification
```

Для уже завершённого исходного часа **текущей версии**:

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:. .venv-layout/bin/python -m scripts.requalify_station_nominal --output artifacts/my-nominal-installed --source artifacts/my-source-hour
```

Источник остаётся неизменяемым входом, его файлы не переписываются. Команда не запускает CI и не требует внешней машины.

Если основной исходный час уже полностью принят, а исходное уточнение ещё выполняется, можно добавить `--allow-running-source`. В этом режиме до старта фиксируются протокол и весь основной путь. Установленный уточнённый час и native replay выполняются параллельно исходному уточнению. Положительный итог всё равно требует завершённого и принятого полного исходного протокола, точной сверки всех 18 математических JSON и неизменности заранее зафиксированных входов. Если источник не завершился к финальной сверке, проверка завершается отказом с сохранением результатов. Новые файлы исходного уточнения не выдаются за заранее неизменяемые входы; их полный манифест записывается отдельно после приёмки источника.

## Граница приёмки

Протокол относится к заданному исследовательскому часовому номиналу. Он не включает изменение нагрузки, выбег, потерю питания или полную матрицу R1. Полный набор тестов библиотеки также остаётся отдельной проверкой. Положительный результат подтверждает повторную численную и локальную проверку номинала конкретной версии; он не создаёт экспериментальную валидацию. Промышленный счётчик остаётся 48/76, новых закрытых задач этим этапом не добавляется.

## Результаты поставки

Оба исходных часа приняты, по 601 контрольному окну в каждом. Максимальные нормированные размахи окон: 1.26262e-09 и 9.92357e-10; различие физических координат при уточнении — 8.47805e-10. Все исходные критерии номинала и балансов выполнены.

Установленный wheel исполнил уточнённые 3600 с, восстановил основной префикс 1800 с и точно повторил хвост до 3600 с и конечный checkpoint. Все 18 математических JSON совпали целиком. Исходные coarse-файлы являются объявленными входами для сравнения, а не дополнительным установленным прогоном.

Прошли 52 различных целевых теста, включая 16 новых; из установленного wheel отдельно повторены 16 новых тестов. Полный набор тестов библиотеки не запускался.

[Машинный протокол](benchmarks/station_nominal_requalification_v105.json). Длительные изменения нагрузки, останов/выбег и полная матрица R1 остаются отдельными открытыми проверками текущей версии.
