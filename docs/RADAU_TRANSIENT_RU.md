# Переход изменения нагрузки: явный выбор Radau

Дата: 30 октября 2026.

## Выполнено

`solver.method` в experiment/scenario принимает `BDF` и `Radau`. Для обоих
поддержаны продолжение между точками вывода, центральный якобиан, локализация
защиты и откат непринятого состояния. `ImplicitContinuation` использует публичный
интерфейс SciPy; прежнее имя `BDFContinuation` сохранено как совместимый alias.
Смена метода сбрасывает историю. Метод записывается в manifest. По умолчанию
остаётся BDF; автоматического выбора или переключения нет.

Для сохранённого состояния на 25 с исследованы четыре шага центрального
якобиана от 1e−4 до 1e−7: ни один не завершил участок до 30 с в лимите 8 с.
В другой пробе с первым шагом 0.1 с BDF завершил этот участок за 9.19 с,
Radau — за 3.53 с. Это локальная диагностика, не hardware-controlled benchmark.
Единственная причина замедления BDF этими пробами не установлена. Физические
константы, управляющие законы и допуски области модели не менялись.

Профиль одного шага теперь принимает `--method`, `--jacobian-relative-step`
и `--first-step-s`, сохраняет эти настройки вместе с исходным checkpoint hash.

## Полные переходы

Начальное состояние номинальное. На 10-й секунде throttle меняется с 1 до 0.98,
горизонт — 120 с. Это конкретное малое изменение нагрузки, не полный сброс.

- `artifacts/radau_throttle_120s`: 120/120 с за **5.41 с**, вывод 5 с,
  rtol=1e−5, atol=1e−4, шаг якобиана 1e−5.
- `artifacts/radau_throttle_120s_tight`: 120/120 с за **7.44 с**, вывод 2.5 с,
  rtol=3e−6, atol=3e−5, шаг якобиана 5e−6.
- `artifacts/radau_throttle_120s_resolved_base`: 120/120 с за **9.98 с**,
  вывод 1 с, rtol=1e−5, atol=1e−4, шаг якобиана 1e−5.
- `artifacts/radau_throttle_120s_resolved`: 120/120 с за **18.17 с**,
  вывод 0.5 с, rtol=1e−6, atol=1e−5, шаг якобиана 2e−6.

Во всех четырёх выполнены бюджеты энергии, массы и бора. У первой пары
относительные глобальные остатки энергии около 1.91e−10 и 5.30e−10.
Остаток не обязан монотонно уменьшаться при изменении solver и квадратуры:
отдельное исследование сходимости энергобаланса остаётся в тестах ledger.

Сравнение первой пары в 25 общих точках прошло. Для лучшего разрешения перехода
дополнительно рассчитана пара с выводом 1/0.5 с. Во всех **121 общей точке**:

- относительная разница тепловой мощности ≤ **5.06e−8**;
- температура топлива ≤ **6.73e−6 K**;
- давление первого контура ≤ **0.105 Па**, ПГ ≤ **0.0442 Па**;
- расход ≤ **4.04e−5 кг/с**.

Пороги `validation/throttle_120s_budget.json` перенесены без ослабления из ранее
принятых численных порогов номинала. Это предварительные цели согласия двух
решений; они не задают физическую погрешность. Все пороги выполнены. Проверка
выполнена по выбранным точкам вывода и не ограничивает ошибку между ними.

Скрипт сравнения требует `--allow-commands` и одинаковые временные команды;
проверяет хеши input/report/trajectory, завершение горизонта и конечность данных.
Номинальный часовой флаг для перехода остаётся false; используется отдельный
`numerical_comparison_accepted`.

## Воспроизведение

```bash
python -m sdk.experiment scenarios/vver_radau_throttle_120s_resolved_base.yaml --output artifacts/transient_base_new --wall-limit-s 60
python -m sdk.experiment scenarios/vver_radau_throttle_120s_resolved.yaml --output artifacts/transient_ref_new --wall-limit-s 60
python -m scripts.compare_hour_nominal artifacts/transient_base_new artifacts/transient_ref_new --budgets validation/throttle_120s_budget.json --allow-commands --output validation/transient_new.json
```

Каталоги и выходной файл должны быть новыми. Машинные результаты:
`validation/radau_throttle_120s_result.json` и
`validation/radau_throttle_120s_resolved_result.json`.

## Что остаётся

Теперь численно подтверждены часовой номинал и указанный 120-секундный переход.
Следующие отдельные проверки: останов насоса, быстрый ввод отрицательной
реактивности/АЗ, более сильный сброс нагрузки, чувствительность к параметрам
и независимые физические эталоны. Нельзя переносить успех одного перехода
на все режимы. `validated` и `plant_referenced` остаются false;
промышленная квалификация и realtime/HIL-пригодность не установлены.
