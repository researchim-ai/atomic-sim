# Полная численная квалификация цикла нагрузки

Эта проверка продолжает [программу изменения нагрузки](STATION_LOAD_CYCLE_RU.md).
Её цель — отделить успешный одиночный расчёт от подтверждённого результата
для конкретного исследовательского режима.

## Один физический сценарий, три численные настройки

На всех настройках станция начинает из одной согласованной номинальной
точки с точечной кинетикой. Геометрия, коэффициенты, PI, измерения,
ограничения, конечные баки и нейтральная полоса 0,2 мм одинаковы.
Меняются только максимальный шаг интегратора и относительный допуск:

- основной расчёт: 1 с и 10⁻⁷;
- уточнение: 0,5 с и 2·10⁻⁸;
- дополнительное уточнение: 0,25 с и 5·10⁻⁹.

Каждый путь длится **1800 с** с управляющим тактом 5 с. Площадки:
100% до 450 с, 98% до 900 с, 102% до 1350 с, затем 100% до конца.
Прежний исходный расчёт v60 повторно используется как неизменяемый
вход с проверкой версии кода и SHA всех файлов. Это явно объявленное
использование прежнего результата, а не ещё один выполненный прогон.

## Что проверяется на всём пути

Вновь вычисляются критерии всех площадок из измерений; старого поля
`passed` недостаточно. Проверяются все 360 переходов, правильный график,
качество датчиков, шесть автоматических контуров, отсутствие trip и
невязки энергии, массы и бора. Положения стержня, впуска и байпаса
должны быть конечными и находиться в [0,1]. Валовая генерация должна
покрывать собственные нужды на каждом такте, включая переходы.

Учётные счётчики исключаются из сравнения стационарных координат,
но физические запасы воды и энергии не исключаются. Разрешён ровно
штатный список семи накопительных координат для этой топологии.
Полный вектор имеет 78 координат; изменение схемы требует новой проверки.

Сравниваются **все совпадающие по времени состояния** двух менее точных
расчётов с наиболее точным. Нормировка — `max(abs(reference), 1 SI unit)`,
порог — 10⁻³. Отчёт показывает наихудшие координату и такт: совпадение
финала не скрывает отличия внутри перехода.

Времена физических переключений сверяются отдельно, с допуском 0,05 с
и совпадением последовательности типов событий. Операторские команды
и точные кинематические прибытия приводов исключены из этого списка;
положения приводов остаются в сравнении физических координат. Переключения
физических портов и защитных блокировок не исключаются.

Полезная электрическая энергия получается из разности штатных интегральных
счётчиков между t=0 и концом. Отдельно показываются валовая генерация,
собственные нужды, полезная отдача, расход батареи и переданное DHR тепло.
Эти величины не оцениваются квадратурой редких измерений мощности.
Согласованность электрических счётчиков и их уточнение проверяются отдельно
от исключённых накопительных координат.

## Restart перед повышением нагрузки

Native restore использует checkpoint **900 с**, перед применением команды
повышения нагрузки. Восстановление заново исполняет префикс 0–900 с,
включая снижение нагрузки на 450 с, и сравнивает весь checkpoint.
Затем исполняются 900–1800 с с повышением и возвратом нагрузки.
Каждая запись хвоста и конечный checkpoint должны точно совпасть.

Сохранённые префиксные строки не выдаются за независимое исполнение:
их отдельно не копируют в native-результат. Доказательства native-ветви —
восстановленный checkpoint, записи исполняемого хвоста и конечное состояние.

## Проверка установленной библиотеки

Из локального wheel в свежем окружении вне checkout независимо исполняются
полный уточнённый цикл 1800 с и полный native replay основного расчёта.
Импорты проверяются на принадлежность `site-packages`; установка офлайн,
с повторным использованием уже установленных научных зависимостей.

Все шесть JSON уточнённого пути сравниваются побайтно с исходным исполнением.
Основной расчёт остаётся объявленным входом для native-сравнения, а третья
сетка не выдаётся за дополнительный установленный прогон. Научные данные,
доказательства restore и квитанции поставки хранятся раздельно.

```bash
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
export PYTHONPATH="$PWD/src"
python -m scripts.qualify_station_load_envelope \
  --output artifacts/load-envelope-new --coarse artifacts/load-coarse-new
python -m scripts.verify_local_library --output artifacts/load-envelope-library-new
python -m scripts.verify_station_load_envelope_delivery \
  --output artifacts/load-envelope-installed-new \
  --source-evidence artifacts/load-envelope-new \
  --library-evidence artifacts/load-envelope-library-new
```

При совместном запуске вычислений установленный повтор может стартовать
после готовности coarse и локальной поставки, пока исходные уточнения ещё
считаются. Финальная сверка требует завершённого полного научного отчёта.
Если исполнение установленных ветвей уже завершилось, повторная сверка
доступна через `--finalize-only` и не повторяет физические расчёты.

## Границы вывода

Даже успешная совокупность проверок относится к указанному небольшому
ступенчатому циклу исследовательской модели. Она не квалифицирует все
допустимые задания 95–105%, произвольные диспетчерские графики, глубокую
разгрузку, отключение генератора или останов станции. Полная матрица R1,
пространственная зона и экспериментальная валидация имеют собственные задачи.

## Принятый результат v61

Три полных исходных пути по 1800 с прошли все критерии. Максимальное
расхождение физических координат — 5.06609229e-05, времён событий —
3.90055058e-05 с. Полезная отдача наиболее точного пути — 435.488473 МВт·ч.
Все шесть JSON установленного уточнения совпали побайтно. Native replay
восстановил checkpoint на 900 с и точно повторил хвост до 1800 с.
Локальная поставка: 1905 тестов и восемь фаз.

Закрыт NPP-11.02 для указанного исследовательского цикла: **48/76**,
открыто **28**. Полная R1 и NPP-11.03/04 ещё открыты.
Данные: [машинный отчёт v61](benchmarks/station_load_envelope_v61.json).
