# Атомарный тепловой аудит клапанного события в среде агента — v95

`atomic_model_station_hybrid_heat.step_hybrid_heat` подключает двусторонний аудит физических событий к `StationEnv`. Первое квалифицированное клапанное событие — закрытие обратного питательного клапана после отключения питательного насоса. Сохранена поддержка диагностического окна исчерпания резерва DHR.

## Что получает агент

Адаптер сначала выполняет обычный шаг на копии среды. Регуляторы, защиты и измерительная система работают один раз, в прежнем такте. Проверочные физические расчёты используют команды из квитанции этого шага. Если все проверки проходят, принимается именно состояние обычного шага, а не состояние повторного расчёта. Наблюдение, вознаграждение, признаки завершения и checkpoint совпадают с обычным переходом.

При неуспехе теплового аудита, несовпадении событий или конечного состояния, ошибке вычисления или смене исходников исходная среда не изменяется. Для отказа по критериям аудита `HeatEventError.receipt` содержит повторные расчёты и причины. Неподдержанные события вызывают явную ошибку; успешный баланс не скрывает неизвестное переключение.

```python
from atomic_model_station_hybrid_heat import step_hybrid_heat

transition, proof = step_hybrid_heat(
    env,
    {"operator": {"feed_pump_on": False}},
    subdivisions=(4, 8, 16),
)
```

Полные диагностические данные `proof` предназначены для оценщика. Агенту можно передавать обычное наблюдение из `transition`.

## Как записывается закрытие клапана

Диагностическая копия перехватывает существующий корень расхода. Для обратных клапанов воспроизведено штатное преобразование из `feed._resume_stop`: проверка остатка расхода, обнуление в пределах допуска и перенос соответствующей остаточной кинетической энергии в бак. Код научного backend не изменён; его контрольная сумма входит в происхождение отчёта. Тест с реальным закрытием питательного клапана проверяет **точное совпадение** полного снимка и вектора состояния инструментированного и обычного расчётов без подшагов.

Перед обработкой корня расход иногда имеет крошечное отрицательное значение. Полный публичный снимок проверяет допустимость уже принятого состояния и может отклонить такой предсобытийный остаток. Поэтому предсобытийный считыватель вычисляет потоки и запасы непосредственно из фактического состояния на копии, без проекции. Остаток закрывающегося клапана предварительно ограничивается штатным допуском 10⁻⁶ кг/с. После преобразования используется обычный снимок. На допустимом состоянии оба способа считывания дают одинаковые значения.

Предсобытийный и послесобытийный отсчёты имеют одинаковое время и относятся к разным участкам интегрирования. Проверяются непрерывность запасов и счётчиков, каждый участок отдельно и сумма абсолютных невязок. Допуски v94 не ослаблены.

## Критерии принятия шага

Используются три независимо начатых расчёта с удвоением числа подшагов. На каждом уровне нужны успешный сегментный баланс и баланс с конечными запасами обычного шага. Порядок, типы и времена корней сверяются с обычным расчётом; допуск времени — 10⁻⁹ с. Покомпонентное относительное расхождение конечного состояния ограничено 10⁻⁶ при масштабе `max(abs(native_state), 1)` в исходных единицах.

Последняя разница интегралов должна быть не больше 2·10⁻⁶. Проверяется невозрастание разницы при уточнении с порогом численного шума 10⁻⁸. Для результирующего потока около нуля в масштаб входит интеграл ядерного тепловыделения. Эти критерии дают численную согласованность; они не являются строгой верхней границей ошибки или экспериментальной валидацией установки.

`record_hybrid_window` предоставляет отдельный интерфейс только для чтения физической сессии. Он поддерживает точные типы `PWRPowerSession` и `PWRFaultSession` без заданных неисправностей. Фиксированный такт адаптера неисправностей обходится исключительно на диагностической копии без неисправностей; такт исходной среды не меняется.

## Область проверки

Протокол использует такт 0,02 с, `rtol=10⁻¹⁰` и уровни 4/8/16. Он проверяет отключение питательного насоса с закрытием клапана внутри шага, повторное включение насоса на границе следующего шага и шаг без новой команды. Восстановление checkpoint проверяется перед повторным включением. Открытие на границе команды не выдаётся за квалификацию самостоятельного внутреннего корня открытия.

Отдельно повторяется окно исчерпания резерва DHR t=0,08…0,12 с на физической сессии. Это регрессионная проверка; полный переход потери внешнего питания этим протоколом не принимается.

Диагностический обработчик содержит штатные преобразования открытия/закрытия питательного и конденсатного обратных клапанов, но в этом протоколе квалифицирован **внутренний корень закрытия питательного клапана**. Отключение конденсатного насоса проверено на точное совпадение решателей без события закрытия в выбранном коротком окне; это не квалификация конденсатного корня.

Предохранительные и байпасные клапаны, одновременные корни без положительного интервала между ними, нерешённое событие на конечной границе и запланированные неисправности остаются неподдержанными. Открыты длительные режимы, физическая валидация и промышленная приёмка. Станционный статус **48/76**, новых закрытых станционных пунктов нет.
