# Атомарная последовательность и полный короткий цикл давления — v100

Добавлен `advance_hybrid_schedule`: физическая сессия принимает последовательность окон только после успешного аудита каждого окна и суммарного баланса. Реализована запись достижений заданных позиций байпасного и паровых приводов. На этой основе проверяется полный заданный цикл: открытие по верхнему порогу давления, закрытие по нижнему и возврат байпасного привода к нулевому положению.

## Атомарное выполнение

API принимает от одного до шестнадцати окон с явными `duration_s` и `patch`. Каждая длительность ограничена одной секундой; три уровня уточнения должны удваиваться. Это расписание физических расчётов и команд, а не изменение такта агента.

Вся последовательность сначала выполняется на копии. Для каждого окна проверяются допущенные состояния после команды, три повторных расчёта, энергетические балансы, времена и типы корней, конечный вектор относительно обычного решателя и сходимость интегралов. Между окнами команды не должны менять накопленные счётчики или запасы энергии мгновенно.

Для всей последовательности суммируются абсолютные невязки участков, привязанных к конечным запасам обычных шагов. Ошибки разных окон не могут взаимно компенсироваться. Только после всех проверок и подтверждения неизменности исходников принимается обычная физическая траектория.

Ошибка поздней команды или аудита откатывает **всю** последовательность. Диагностический префикс сохраняется в `HeatEventError.receipt`, но не записывается в исходную сессию. Отдельно проверен отказ суммарного баланса, даже если локальный флаг успешности повреждён.

## Достижение позиции привода

События `bypass_position_arrival` и `steam_valve_arrival` передаются штатным обработчикам. Сохранены аналитические проверки времени и остатка позиции. Приводы движутся с конечной скоростью.

Один штатный корень парового привода может породить несколько записей журнала. Адаптер сохраняет их все, включая индексы и цели, и сверяет полный порядок с обычным расчётом. Для такого совместного штатного преобразования записывается один двусторонний снимок; промежуточные состояния внутри функции не записываются. Проверка сохранения нескольких записей — отдельный модульный тест, не квалификация станционного сценария одновременных физических корней.

## Заданный цикл

Используются исследовательские параметры `area_m2=0.03`, `stroke_time_s=0.1`, пороги 6 368 300 / 6 368 290 Па, `rtol=10⁻¹⁰`, `max_step_s=0,01`. Они не обозначают уставки или характеристики реального оборудования.

В t=0 команда паровому клапану меняется с 1 на 0,99. Давление пересекает верхний порог, реле открывается. В t=0,01 с команда возвращается к 1; давление пересекает нижний порог, реле закрывается, байпасный привод возвращается в ноль. Проверяется вся последовательность до t=0,022 с, включая оба достижения позиции парового клапана и окончание возвратного хода байпасного привода.

Расчёт разделён на окна длительностью 0,002 / 0,001 / 0,007 / 0,001 / 0,001 / 0,010 с. Новые команды присутствуют только в первом и четвёртом окнах. Такое численное разбиение сохраняет моменты подачи команд и позволяет пройти неизменный допуск сверки времени корней 10⁻⁹ с. На каждом окне используются 8/16/32 подшага.

Грубая последовательность из двух окон с теми же командами не проходит аудит; её отказ и отсутствие частичного изменения сессии сохраняются. Поэтому результат относится к явно объявленному расписанию и точности. Уточнение одновременно меняет квадратуру и перезапуски решателя; строгой верхней границей полной ошибки оно не является.

Checkpoint восстанавливается после третьего окна, когда давление уже прошло открытие. Оставшаяся часть повторяется с точным совпадением проверочных траекторий и окончательного checkpoint.

## Результаты поставки

Прошли **50 целевых тестов**, включая 12 новых. Установленный wheel вне репозитория повторил 12 новых тестов и все шесть JSON протокола, включая полный цикл, продолжение из checkpoint, отказ грубой сетки и окончательный checkpoint. Сравнивались целые документы без исключения полей. Полный набор тестов библиотеки в этом этапе не запускался.

Нормированная сумма абсолютных энергетических невязок принятого цикла составила около 5,07·10⁻¹¹ при допуске 10⁻⁶. Это наблюдаемая невязка баланса, а не оценка физической точности модели.

## Использование

```python
from atomic_model_station_hybrid_heat import advance_hybrid_schedule
from atomic_model_station_hybrid_heat.scenarios import prepare_relief_cycle

session, schedule, recipe = prepare_relief_cycle()
report = advance_hybrid_schedule(session, schedule)
assert report["passed"]
```

В отличие от диагностического `record_hybrid_window`, успешный `advance_hybrid_schedule` изменяет переданную сессию. При отказе она остаётся прежней.

Локальный протокол:

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 PYTHONPATH=src:. .venv-layout/bin/python scripts/qualify_station_relief_cycle.py --output artifacts/relief-cycle-local
```

Директория должна быть новой. CI не требуется.

## Границы результата

Полный цикл относится к этому короткому исследовательскому сценарию физической сессии. Байпасный клапан не проходит полный ход до положения 1: проверены срабатывание гистерезиса и возврат в ноль. Не квалифицированы произвольные циклы давления, пропускная способность реального оборудования, цикл в `StationEnv`, одновременные физические корни и длительные режимы. Экспериментальная валидация остаётся отдельной работой.

Научный backend не изменён; расширен адаптер аудита. Станционная приёмка **48/76**, новых закрытых станционных пунктов нет.
