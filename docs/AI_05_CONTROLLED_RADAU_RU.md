# AI-05: команды и расписания на редуцированном Radau

`ScheduledReducedGraph` и `OnlineReducedGraph` добавляют управление к
[зарегистрированному Radau-backend](AI_05_REDUCED_RESIDUAL_ENGINE_RU.md).
Оба сохраняют фиксированные топологию, роли границ, положительные объёмы,
плотность/теплоёмкость и пользовательские законы L(T). Это инженерные
companion-классы; установленный SDK runtime не изменён.

## Расписание

```python
model = ScheduledReducedGraph(scheduled_request(model_input, timeline),
                               max_macro_step_s=2.0)
result = model.advance(120.0)
```

Формат запроса совпадает с [контрактом расписаний](AI_05_SCHEDULED_GRAPH_RU.md):
`atomic-scheduled-thermal-graph`, schema1, `model_input`, `timeline`.
Допустимы мощности нагрева/охлаждения, температура окружения/подачи,
давление существующей границы, расход существующей инжекции и заданный
напор ребра. Единицы — Вт, К, Па, кг/с. Менять объёмы, свойства, законы,
роли границ или оборудование командами нельзя.

Начальная модель должна быть допустимой самостоятельно. Метки времени
конечны, неотрицательны и строго возрастают. Одновременные изменения
задаются одним пакетом `changes`. Команда в нуле применяется при создании;
команда на конце вызова применяется до формирования результата. Состояние
правостороннее. Интегратор останавливается перед каждой командой и не
пересекает её разрыв. Близкие представимые отметки не объединяются;
коррекция календарного округления не более одной ULP записывается в отчёт.

## Пересборка на текущем состоянии

Конструктор активной физической системы проверяет фактические текущие
температуры. Исходные холодные температуры не используются как догадка
для нового режима. После проверки сохраняются глобальные температурные
приращения, исходная система отсчёта и масштабированный интеграл энергии.
Векторы масс, масштабы и порядок узлов обязаны совпадать.

Таким образом, сотни частичных удержаний не преобразуются в последовательность
вычитаний округлённых абсолютных температур. Команда не создаёт импульс
температурного запаса или интеграла энергии. Давления/расходы пересчитываются
и могут измениться скачком: гидравлика квазистационарна, без инерции/гидроудара.
Сохраняется прежняя политика Radau: новая коллокационная история на каждом
макроинтервале. История предыдущего решателя не переносится через команду.

Инициализация нового режима использует проверенный конструктор и его
гидравлическое решение на текущих температурах. Между командами расчёт
исполняется новым residual/Newton/Radau-backend. Прежний DP-интегратор
не используется ни для продолжения, ни для исполнения команд.

## Онлайн-регулятор

```python
model = OnlineReducedGraph(model_input)
observation = model.observation()
report = model.step(changes, duration_s=10.0,
                    expected_revision=observation["revision"])
```

Один пакет применяется на текущей отметке и удерживается положительный
интервал. Версия увеличивается только после успешного шага; устаревшие,
повторные и нецелые версии отклоняются. История добавляется только после
успеха. Отклонённую команду можно исправить и повторить с прежней версией.
Лимиты: 128 команд и 10000 с эпизода, плюс бюджеты базового backend.

Наблюдение между вызовами относится к окончанию прошлого удержания,
до следующей команды. В `command_switch` отчёта есть левое и правое
состояния. Независимые IVP правосторонние; при сравнении давления/расхода
на границе удержания используется правое состояние новой команды.

Внешний PID/ИИ вызывается владельцем, за пределами транзакции физической
модели. Его память, RNG, интегральная ошибка, внешние действия и сообщения
не входят в checkpoint модели. Их согласованное сохранение остаётся
обязанностью владельца. Один экземпляр рассчитан на последовательные вызовы;
проверка версии не является блокировкой для многопоточного доступа.

## Полный откат и ресурсы

Расписание и онлайн-шаг исполняются на отделённом кандидате. Любой отказ
пересборки, интервала, Newton, Radau, энергетики, ресурса или финального
наблюдения откатывает весь вызов вместе с уже пройденными интервалами и
применёнными внутри него командами. Ранее успешно принятые вызовы сохраняются.

Ограничения RHS-оценок и попыток интегрирования общие для всего вызова,
не обновляются на каждой команде. Также ограничиваются число событий и
сегментов между ними. Проверки области и минимум шага наследуются от
backend. Консервативный отказ интервала не объявляется точным временем
физического события. Автоматические события по пересечению state-guard,
фазовые переходы и изменение топологии не реализованы.

## Checkpoint и система отсчёта

Checkpoint расписания связывает исходники/бюджеты, полный исходный вход
вместе с будущими командами, макрошаг, курсор, квитанции, активную модель,
температуры входа в текущий режим и вложенный native checkpoint. При
восстановлении заново проверяются активный префикс, время, параметры
входа, исходная глобальная система отсчёта, физическое состояние и энергия.
Глобальные приращения не сбрасываются после восстановления.

Вложенный native checkpoint относится к частному конструктору на тёплой
точке входа; его система отсчёта задаётся внешним checkpoint. Он не является
самостоятельным checkpoint для обычного `ReducedResidualEngine`. Использовать
нужно только `ScheduledReducedGraph.restore` либо `OnlineReducedGraph.restore`.
Самостоятельный handoff событийной модели в legacy solver не предоставлен.

Онлайн-checkpoint дополнительно связывает исходную модель, принятую историю
и версию. Будущие, неудержанные и пропущенные начальные команды отклоняются.
Изменить будущее расписание при restore нельзя. Квитанции проверяют
согласованность метаданных, а не повторяют физическое исполнение всей истории;
хеши не удостоверяют автора checkpoint.

## Квалификация

Семь сценариев расписаний и два онлайн-сценария по 120 с до восьми узлов:
нагрев, реверс, смена подачи, совместные границы, endpoint/checkpoint,
пустое расписание, тёплая пересборка и внешняя тепловая обратная связь.
Итого 27 основных траекторий, 26 независимых Radau/DOP853 IVP и три
ожидаемых отказа с полным откатом. Каждый онлайн-IVP получает свою реально
принятую историю команд; это проверка физического исполнения действий,
не независимая сертификация регулятора.

Три ограничения макрошага обычно 2/1/0.5 с. В случае узкого диапазона
давления используются 0.5/0.25/0.125 с, потому что физический допуск
ограничивает более крупные шаги одной и той же сеткой. Измеренные максимальные
внутренние шаги соседних уровней обязаны различаться минимум в 1.2 раза;
разница в один ULP не считается уточнением. Ошибки физики не ослаблялись.
Проверяются restart в 37.5 с и точное продолжение при одинаковых следующих
вызовах в том же окружении, без межплатформенной гарантии.

```bash
python -m scripts.qualify_controlled_radau --output artifacts/controlled_qualification
python -m scripts.qualify_controlled_radau --audit artifacts/controlled_qualification --output artifacts/controlled_audit.json
python -m examples.controlled_radau
```

[Пример](../examples/controlled_radau.py) выполняет расписание с restart до
120 с и онлайн-реверс с restart до 10 с. Открыты произвольная регистрация
оборудования и смешанная сборка, сопряжение памяти регулятора, инерция,
сжимаемость, переменная EOS и экспериментальная/объектная валидация.
