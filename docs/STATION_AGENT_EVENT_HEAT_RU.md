# Тепловой учёт на границе команды — v91

Пакет `atomic_model_station_event_heat` добавляет атомарный `step_heat` поверх `StationEnv`. Он использует команды из квитанции регуляторов и защит: запрошенное оператором действие может отличаться от действительно допущенного. На копии состояния восстанавливаются потоки сразу после команды. Запасы энергии и накопленные счётчики в этот момент должны остаться неизменными.

Интеграл за следующий шаг рассчитывается между состояниями после команды и в конце шага. Потоки до переключения сохраняются отдельно: соединять их трапецией с концом шага нельзя. Это даёт диагностический отрицательный контроль, который не влияет на принятие корректного расчёта.

## Атомарность и воспроизводимость

Физический шаг выполняется на копии среды. Исходная среда получает новое состояние только после успешного энергетического аудита и проверки неизменности исходного кода. При отказе `HeatEventError.receipt` содержит причину; при нарушении баланса также сохраняются кандидат, оба конца интервала и невязки. Ошибки действий, внутренние события без разрешённой временной границы и изменение исходников не оставляют частично выполненного шага.

`run_event_window(config, commands)` принимает словарь команд по номерам тактов. При ошибке сохраняет принятый префикс и диагностику; ошибки инициализации также возвращаются как неуспешное окно. Суммарные дефекты учитываются по абсолютным значениям, чтобы ошибки соседних шагов не компенсировали друг друга.

## Проверенный объём

Локальный протокол `scripts/qualify_station_event_heat.py` проверяет два окна по 0,04 с с шагом 0,01 с: переключения коэффициента нагрузки 1 → 0,95 → 1 и 1 → 1,05 → 1. Оба окна проходят энергетический аудит; ошибочная квадратура через скачок отклоняется на обоих переключениях каждого окна. Тесты отдельно проверяют точное совпадение перехода и checkpoint с обычным `StationEnv.step`, а также продолжение после восстановления checkpoint.

Включение аварийного теплоотвода DHR **не квалифицировано**. При шаге 0,01 с относительная невязка тепловой квадратуры около 1,28·10⁻⁵ превышает неизменный допуск 10⁻⁶. Отказ сохраняется как отрицательный результат, исходное состояние остаётся прежним. Это ограничение текущего интегрирования тепла; само по себе оно не доказывает ошибку физической модели DHR. Для принятия нужны более точное интегрирование и независимое временное уточнение.

Запланированные неисправности пока не поддерживаются этим адаптером. События после левой границы, в том числе на правой границе без известного предсобытийного потока, отклоняются до реализации явного разделения интервала. Стационарный КПД, длительные переходы и промышленная применимость не заявляются. Станционная приёмка остаётся **48/76**; новых закрытых станционных задач нет.

Проверка поставки: **117 целевых тестов прошли**, включая 11 новых. Установленный wheel вне репозитория повторил 11 новых тестов и пять расчётных JSON без поля времени выполнения `wall_s`. Полный набор тестов библиотеки в этом этапе не запускался; исходники научного ядра v90 не изменены.
