# Конечный HEM-канал, торцевые объёмы и тепловые стенки

Блок 1.67.0, 5 ноября 2026. Отдельный движок `atomic_model_hem_system` объединяет перенос массы, импульса и полной энергии с конечной теплоёмкостью стенок. Это численно проверенное ограниченное семейство моделей; `validated=false`, `plant_referenced=false`.

## Что моделируется

Одномерный канал постоянного сечения содержит 4–12 внутренних ячеек и две торцевые ячейки заданного объёма. Канал обменивается с ними массой, импульсом и энергией через общие грани. Торцевые объёмы — такие же одномерные Euler-ячейки с конечными запасами и кинетической энергией, а не неподвижные перемешанные резервуары или модели сопел. Внешние торцы отражающие: вся сборка замкнута по массе.

HEM предполагает общие скорость, температуру и давление равновесных фаз. Используется прежний строгий IF97 inverse из rho/u без проекции состояния: области 1/2/4, 300–900 K, 0.1–10 MPa с дополнительным запасом давления 100 Pa. Критическая область, метастабильность, slip и неравновесие фаз не поддержаны.

Одна или несколько стенок подключаются к выбранной жидкостной ячейке. Для каждой заданы теплоёмкость C, проводимость K, мощность Q и опциональный теплообмен UA со средой:

```text
q_wall_to_fluid = K * (Twall - Tfluid)
C * dTwall/dt = Qwall + UA*(Tamb - Twall) - q_wall_to_fluid
dEfluid/dt = A*(Fenergy_left - Fenergy_right) + Qfluid + sum(q_wall_to_fluid)
```

Это линейное консервативное тепловое соединение. Корреляция кипящей теплоотдачи, CHF и post-CHF здесь не заявлены.

## Общие потоки и контроль балансов

Каждая грань вычисляется один раз: соседние ячейки получают противоположные потоки. Использован прежний фиксированный LF/Rusanov-поток и SSPRK3. Журналы граней, нагрева и теплового обмена интегрируются теми же стадиями, что и запасы. Рабочая энергия содержит вычитание постоянной опорной энергии на единицу массы; во всех физических энергобалансах этот член восстанавливается.

На внешних границах отражается скорость. Массовый и энергетический потоки точно нулевые, импульсный поток учитывает реакцию неподвижной стенки. Полный импульс жидкости меняется на накопленный импульс внешних стенок. Отражение нормального импульса соответствует общему принципу [граничных условий Clawpack](https://www.clawpack.org/bc.html); код реализации собственный.

Проверяются локальные балансы каждой жидкостной ячейки, каждой стенки и всей сборки. Ненулевой накопленный перенос массы/энергии через внешнюю стенку отклоняется даже при взаимной компенсации двух торцов. Контролируется физическая полная энергия, включая кинетическую, а не только внутренняя энергия жидкости.

Для стенок учитывается C*log(Twall/Twall0), для среды — переданная теплота/Tamb. Производство энтропии теплопроводностью имеет неотрицательную алгебраическую форму. На участке без внешних источников и обмена со средой контролируется неубывание общей энтропии жидкости и стенок. Остаток энтропийного баланса при внешнем нагреве остаётся диагностикой: полного доказательства entropy stability нет.

## Допуск и транзакции

Шаг ограничивают CFL по минимальной фактической длине V/A, тепловые времена стенок и жидкости, изменение температуры стенок и удельной внутренней энергии. Для смеси изохорная теплоёмкость вычисляется из фазового chart; около насыщения учитывается ограничивающая односторонняя ветвь. Каждая RK-стадия проходит строгую проверку EOS, положительности запасов, температур и допустимых характеристических скоростей. Это проверяемый допуск стадий, не математическая гарантия invariant domain для любых данных.

API: `advance`, `step`, `snapshot`, `control`, `contract`, `residual`, `checkpoint`, `restore`. `contract` публикует координаты и единицы, `control` — полные маски мощностей ячеек и стенок. Есть optimistic revision, сохраняемое JSON-состояние контроллера, блокировка конкурентного доступа и проверка исходников. Ошибка любой стадии откатывает весь вызов. Restore воспроизводит всю принятую историю и сравнивает полный checkpoint: повторный расчёт контрольной суммы повреждённого файла не делает его допустимым.

## Запуск

Из установленного wheel или рабочего checkout:

```bash
atomic-hem-system demo --output artifacts/my-finite-system
atomic-hem-system replay artifacts/my-finite-system
atomic-hem-system run examples/finite_hem_system.json --output artifacts/my-finite-request
atomic-hem-system qualify --output artifacts/my-finite-qualification.json
atomic-hem-system audit artifacts/my-finite-qualification.json
```

Каталог результата не перезаписывается. Demo нагревает почти насыщенную смесь горячими стенками и проходит появление перегретого пара; суммарная энергия замкнутой сборки сохраняется.

## Управление из Python

```python
import json
from pathlib import Path
from atomic_model_hem_system.model import FiniteHEMSystem

request = json.loads(Path("examples/finite_hem_system.json").read_text())
model = FiniteHEMSystem(request["model"])
controls = model.control()  # Полные маски, мощности в W.
controls["walls"]["w0"] = 4000.0
observation = model.step(
    controls, 0.001, expected_revision=0, controller_state={"tick": 1}
)
checkpoint = json.loads(json.dumps(model.checkpoint()))
restored = FiniteHEMSystem(request["model"])
restored.restore(checkpoint)
assert restored.snapshot() == model.snapshot()
```

Ревизия равна количеству принятых вызовов; устаревшая команда отклоняется. Координаты `residual` включают приращения запасов и интегральные журналы: используйте полный вектор `payload.coordinates` checkpoint этой же версии исходников.

## Численные свидетельства

`artifacts/ai06_finite_system_qualification_v1.json`: 10 программ, 30 временных траекторий и 20 отдельных IVP DOP853/Radau. В матрице покой, прямой/обратный перенос, отражение импульса, разные торцевые объёмы, испарение от стенки, среда, внешнее тепло и online-команды. Три фактических шага различаются; обычно ограничения 100/50/25 мкс, для отражения и испарения — 25/12.5/6.25 мкс. Восстановление JSON checkpoint в 0.009 s продолжает расчёт до 0.018 s с точным совпадением.

Эталонный RHS отдельно реализует абсолютные m/P/E и температуры стенок, собственные граничные потоки и глобальные интегралы. Он разделяет IF97 EOS с рабочим движком: это независимая проверка интегрирования и сборки уравнений, не независимая термодинамика или эксперимент.

Максимальные расхождения с IVP: давление 0.004959 Pa, температура 2.155e-7 K, относительная плотность 4.703e-9, температура стенки 2.480e-10 K, импульс 7.223e-8 kg*m/s. Заранее фиксированные допуски: 0.1 Pa, 1e-5 K, 1e-8, 1e-6 K и 1e-6 kg*m/s соответственно. Максимальная глобальная энергетическая невязка 1.456e-11 J. Это ошибки сравнения одной полудискретной постановки, не точность физического прогноза и не пространственная сходимость.

AI-06.03 принят для ограниченной численной реализации общих потоков и нагрева стенок. Общий пакет AI-06 остаётся в работе.

46 новых тестов проверяют балансы, изменение фаз, rollback, повреждение журналов и checkpoint, онлайн-управление, CLI и файловые артефакты. Прежняя portable-регрессия: 3452 passed; вместе с новыми тестами — 3498 уникальных passed, 40 external/long/hardware исключены. Установленный вне checkout wheel повторил всю численную матрицу, 46 тестов и прежние checkpoint. Установочный протокол и архив поставки фиксируются отдельно в `validation/ai06_finite_system_*_v1.json`; результаты не заменяются ожидаемыми числами.
