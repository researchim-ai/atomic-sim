# AI-06: стационарный проточный канал и прямой HIPER benchmark

В отдельном `atomic_model_hem_throughflow` реализован стационарный открытый канал. Прежние source-bound движки и экспериментальные отчёты сохраняются; импорт нового семейства их не подменяет.

## Закрытый численный блок: проточная постановка

Граничные данные — входные статические p/h и массовый поток G. Выходное давление **предсказывается**, а не задаётся одновременно со входным. Решатель учитывает ускорение, Darcy/Churchill-трение с явным выбором McAdams/Cicchitti и signed gravity. Плотность и энтальпия могут проходить через насыщение; энергия включает кинетическую и потенциальную части.

Уравнения при постоянной площади, v=1/rho:

- `(p + G²v)' = -F - rho*g`, где F — положительная потеря давления на единицу длины;
- `(h + G²v²/2 + g*z)' = 4*q/(G*D)`;
- массовый расход постоянен по постановке задачи.

Это steady IVP, не временная динамика, не задача с двумя заданными давлениями и не модель choking. Равновесная вода IF97 1/2/4: 0,1–16 МПа, 300–900 К, с прежним запасом давления 100 Па и ограничением Mach≤0,2. Геометрия: D=5–50 мм, L=0,1–10 м; профиль q задаётся явно по 1–256 равным участкам. Для корреляции трения требуются явные предположения о гомогенном no-slip развитом потоке.

Границы участков q проходятся отдельно, без усреднения через скачок. Корни появления/исчезновения фаз локализуются по энтальпии. Для поиска корня допускается алгебраическое продолжение текущей ветви, но принятое состояние повторно проверяется физической p/h-EOS. Запасы не обрезаются; точная координата корня не достигается присвоением `h=hsat`. Односторонний Якобиан на границе выбирается по направлению потока состояния при разрешении EOS, без изменения h.

RK4 имеет строгую проверку каждой принятой/пробной физической стадии. Ошибка на поздней стадии откатывает весь вызов. Checkpoint восстанавливается полным повторением истории пространственных целей; изменённые координаты/события нельзя легализовать пересчётом внешнего hash.

Независимая проверка использует **полную энтальпию** вместо производственной статической h, отдельную сборку уравнений, отдельную p/h-инверсию, разностные производные EOS, собственный расчёт трения и DOP853/Radau. Общая IF97 явно остаётся общей. Проверены три ограничения пространственного шага, точные x=0/1, испарение, конденсация, выход в жидкость/пар и неоднородный тепловой профиль. Отдельная гладкая задача показывает четвёртый порядок пространственного интегрирования steady ODE; это не выдаётся за новую квалификацию сетки transient PDE.

## Энтропия: отделение численной ошибки от свойства EOS

В отчёте отдельно сохранены исходная энтропийная невязка, интеграл несогласованности смеси IF97 с точным Gibbs identity и исправленная **численная** невязка. Аналитически дифференцируется фактическая энтропия IF97, а не подставляется предположение об идеально согласованных фазовых аппроксимациях. Ненулевой термодинамический дефект не скрыт и не объявлен экспериментальной ошибкой.

Для пробного нагрева до двухфазной области исходная невязка около −0,00444 Дж/(кг·К), а численная после явного учёта дефекта — порядка 1e-8. Тепловой член Q/T относится к жидкости; тепловая стенка и внешний резервуар энтропии в этом bulk-решателе не моделируются. Полной теоремы энтропийной устойчивости не заявляется.

## Закрытый блок реализации замыкания: 15–16 МПа, трубные поправки CHF

Добавлена отдельная версия `chen-inl-hfg025-iaea1995-k1k4/v1` с 30 проверенными углами CHF 1995: p=15–16 МПа, G=300–2000 кг/(м²·с), x=0–0,1. Она не интерполирует за пределы этого прямоугольника.

Источник — [IAEA-TECDOC-1203](https://www-pub.iaea.org/MTCD/Publications/PDF/te_1203_prn.pdf), Table II.I и Table3.3. Кусочно-трилинейная таблица дополнена явно выбранными трубными поправками диаметра K1 и длины нагрева K4. Их область ограничена D=5–25 мм, нагретым расстоянием 0,2–10 м и L/D≥5. Остальные коэффициенты равны единице только при заявленных равномерном нагреве, вертикальном восходящем потоке, круглой трубе без spacers/bundle. Протокол чтения и хеш первичного PDF сохранены отдельно; вся книга в пакет не включается.

Теплоотдача следует конкретному документированному [варианту Chen INL](https://mooseframework.inl.gov/bison/source/materials/CoolantChannelMaterial.html), hfg^0,25. Его формула численно совпадает с прежним вариантом в общей допустимой точке; это не исходная Chen hfg^0,24 и не универсальная корреляция. Температура стенки предсказывается обратным решением по заданному q. Поддержан только перегрев 0–10 К и q<0,8 CHF; за пределами — отказ, без post-CHF fallback. Значение 0,8 является вычислительной границей, не калиброванным запасом безопасности. Погрешность поправок/корреляции не назначена выдуманным доверительным интервалом.

Bulk-канал с внешне заданным q и локальное стеночное замыкание — разные постановки. Возможность интегрировать энергию жидкости не означает поддержку теплоотдачи dryout/post-CHF или расчёта стенки на всей HIPER-петле.

## Закрытый блок экспериментального сравнения: отрицательный результат сохранён

Сохранён полный аудит всех 12 320 строк первичного [HIPER/TUM набора](https://mediatum.ub.tum.de/1839312). Критерии и разбиение заданы в `benchmark.PROTOCOL`, до вычисления ошибок. Разделение выполнено **по опытам**, не по строкам одной кривой: чётные номера — описательная development-когорта без подгонки, нечётные — отложенная когорта. Ни одного настраиваемого коэффициента по HIPER не подбиралось. Когорты используют одну установку и связанные серии условий; разделение номеров опытов не выдаётся за независимую кампанию/установку.

Сравнение условно-локальное: опубликованные p/x/G/D/q используются как входы; выход — температура внутренней стенки и согласованность q при измеренной температуре. Это не независимое предсказание всей петли. Нагретое расстояние берётся буквально из опубликованного l/di и di. Для равномерного upstream q проверяется непустое пересечение опубликованных интервалов q всех предшествующих сегментов. Это согласованность с границами измерения, не доказательство идеальной равномерности. Остальные причины исключения и ошибки предсказания сохраняются для всех строк.

Допустимы **150 строк из 21 опыта**: development 71/10, holdout 79/11. Порог средней абсолютной относительной ошибки теплового потока был заранее задан **20%**. На holdout получилось **88,35% — критерий НЕ пройден**. Средняя абсолютная ошибка температуры стенки — около **4,11 К**. Номинальные предсказания попадают в широкие опубликованные интервалы Tw, но это не повышает статус до validated.

Анализ идентифицируемости объясняет ограничение данных: во всех 150 строках консервативный интервал перегрева, полученный из опубликованных p/Twall, содержит ноль. Верхняя граница выводимого коэффициента `q/(Twall-Tsat)` поэтому не ограничена. Доверительный уровень и ковариации неизвестны; по такому интервалу нельзя честно доказать точность HTC 20% или откалибровать коэффициент. Условное попадание температуры в интервал не заменяет эту проверку.

Честный итог: **реализация и численная квалификация протока завершены; прямое экспериментальное сравнение выполнено и не прошло заданный критерий.** Общая физическая приёмка AI-06.06 остаётся открытой. Для неё нужны отдельные достаточные измерения/протоколы кипения, конденсации, flashing/blowdown, полный UQ и независимый предметный разбор. Увеличение тестового счётчика этого не заменяет.

## API и повторение

```bash
python -m atomic_model_hem_throughflow demo --output artifacts/throughflow_demo.json
python -m atomic_model_hem_throughflow replay artifacts/throughflow_demo.json
python -m atomic_model_hem_throughflow qualify --output artifacts/throughflow_qualification.json
python -m atomic_model_hem_throughflow audit-qualification artifacts/throughflow_qualification.json
python -m atomic_model_hem_throughflow benchmark --output artifacts/throughflow_hiper.json --require-pass
python -m atomic_model_hem_throughflow audit-benchmark artifacts/throughflow_hiper.json
```

`benchmark --require-pass` сохраняет отрицательный отчёт и завершает процесс кодом **3**. Аудит проверяет воспроизводимость результата, не превращает отрицательный результат в физическую приёмку. Выходной файл публикуется атомарно без перезаписи уже существующего результата.

Python API `SteadyChannel.advance_to(z)`, `checkpoint()` и `restore(cp)` работают с пространственной координатой, не временем. CLI `run` принимает `request`, `targets_m`, `checkpoint` (null или сохранённый payload с digest). Пример входа находится в `examples/steady_throughflow.json`.


## Поставка и проверенный объём

Пройдены 268 связанных тестов, из них 76 новых; полная регрессия проекта в этой
итерации не повторялась. Установленный wheel вне checkout повторил численную
квалификацию, 76 тестов, restart/replay и отрицательный экспериментальный gate
с ожидаемым кодом3. Проверка на одной машине с общими зависимостями не является
независимой OS/hardware-матрицей.

Ограничения API: G=10–2000 кг/(м²·с), шаг 0,0001–0,5 м, не более16384 шагов
за вызов, 128 целей в истории, 512 фазовых событий и 4МиБ на checkpoint.
Сочетание минимального шага и максимальной длины может потребовать нескольких
вызовов; превышение бюджета откатывает текущий вызов. История результатов и
границы подтверждённого объёма сохранены в `validation/ai06_throughflow_summary_v1.json`.
