# AI-04: уточнение сетки разрывного фронта

**AI-04 принят в объявленном компонентном численном scope, 7/7 задач.**
Итог: 44 расчёта, 10 принятых и 4 непринятых проверки; 9 допущенных физических fixtures.
Регрессии: **680 passed, 1 deselected**; внешний OpenMC/MPI не запускался.
Источники, wheel и сырые результаты зафиксированы; промышленная и объектная валидация не заявляются.
Машинный итог: `validation/ai04_delivery_v2.json`. Далее — AI-05.

Дата: 31 октября 2026. Продолжение [первой квалификации HLLC](AI_04_HLLC_QUALIFICATION_RU.md).

## Причина расширения

На 16/32/64 ячейках подвижный разрыв не прошёл зафиксированный критерий
порядка 0,35: первый переход дал 0,182. Четвёртая сетка 128 не позволила
принять диапазон 32/64/128: последний порядок оказался 0,335557.
Эти результаты остаются непринятыми. Отказы не удаляются и не превращаются
в принятые после появления более тонких сеток.

`scripts/diagnose_contact_orders.py` независимо решает линейный
полудискретный донорный перенос через FFT и точную экспоненту его спектра,
без временного интегратора. Запасы нормированы на один опорный объём;
линейный перенос коммутирует с этим масштабированием. Температура численного
и точного консервативного среднего восстанавливается через IF97.

Диагностические порядки для 16→32→64→128→256→512:
0,181914; 0,533399; 0,335561; 0,488466; 0,457475.
Почти точное воспроизведение провала на 128 ячейках указывает на влияние
положения фронта относительно ячеек при вычислении ошибки средних.
Это диагноз линейного оператора, не квалификация полного Euler-решателя.

## Протокол полного расчёта

Верхний технический предел HLLC расширен до 512 ячеек. Rusanov сохраняет
прежний предел 64, model_id и schema. Разреженный якобиан, инварианты
консервативной сборки, реальный шаг и восстановление проверяются также
на 128 и 512 ячейках. Разрешение конфигурации конструктором само по себе
не означает допуска к генерации квалифицированных задач.

Критерии и дополнительные диапазоны зафиксированы до запуска в
`validation/ai04_qualification_budget_v3.json`; все численные пороги из v1
сохранены, включая 180 с на один расчёт. Добавлен диапазон 128/256/512
для отдельного допуска. Обе более грубые последовательности сохраняются
в той же матрице со своим отказом. Для 512 ячеек отдельно уточняются
rtol и max_step. Все прежние контактные и связанные переходные задачи
повторяются после заморозки новой версии исходников.

```bash
python -m scripts.qualify_hllc \
  --budget validation/ai04_qualification_budget_v3.json \
  --output artifacts/NEW_QUALIFICATION_DIRECTORY
python -m scripts.audit_hllc_qualification artifacts/NEW_QUALIFICATION_DIRECTORY \
  --output validation/NEW_INVENTORY_AUDIT.json
python -m scripts.audit_hllc_refinement artifacts/NEW_QUALIFICATION_DIRECTORY \
  --output validation/NEW_REFINEMENT_AUDIT.json
```

Первый аудит пересчитывает балансы, положительность сохранённых запасов,
допустимость EOS и работу gate. Второй заново вычисляет контактные нормы,
порядки и временную ошибку из raw trajectories и сверяет решение о допуске.
Само наличие совпадающей SHA256 не заменяет эту численную перепроверку.

На 512 ячейках исходная пара настроек дала временную разность около
1,67e-6 K при неизменном допуске 1e-6 K. Поэтому этот вариант остаётся
непринятым даже при достаточном пространственном порядке. Протокол v4
назначает базовую политику Radau/rtol=1e-11/max_step=0,01 с и контрольную
Radau/rtol=1e-12/max_step=0,005 с. Вектор абсолютных допусков интегратора
остаётся прежним; принимается именно проверенная комбинация параметров.

```bash
python -m scripts.resolve_hllc_time artifacts/ai04_qualification_v4 \
  --budget validation/ai04_qualification_budget_v4.json \
  --output artifacts/NEW_TIME_QUALIFICATION
```

Повторная серия использует неизменные runtime sources. Родительские файлы
проверяются по SHA256 и копируются; уже выполненные базовые расчёты с
rtol=1e-11 используются повторно, что отражено в provenance. Добавляются
два новых контрольных интегрирования. Отдельно учитываются число уникальных
расчётов и число сохранённых траекторий с учётом копий базовых задач.

Эта дополнительная серия тоже не прошла порог: разность около
1,076e-6 K. Фиксированный вектор абсолютных допусков содержит 1e-4 Дж на
энергию каждой ячейки; один и тот же допуск запаса при меньшей массе
разрешает большую ошибку интенсивных величин. Поэтому добавлен явный
`solver.atol_scale` в Euler API/SDK. Диапазон 1e-6…1, значение по умолчанию
1 сохраняет прежнее поведение. Масштаб умножает весь размерный вектор
абсолютных допусков, включая стенку и балансовые интегралы. Изменение
масштаба сбрасывает историю продолжения; недопустимое значение отклоняется
до изменения состояния. Сам вектор остаётся объявленным в исходниках.

Протокол `validation/ai04_qualification_budget_v5.json` задаёт базовый
масштаб 0,1 и контрольный 0,01. Соответствующие абсолютные допуски энергии
ячейки — 1e-5 и 1e-6 Дж, массы — 1e-11 и 1e-12 кг. Это внутренние
параметры интегратора; размерные **критерии приёмки** из v1 не ослаблены.
После изменения API вся серия повторяется с новым source fingerprint:

```bash
python -m scripts.qualify_hllc \
  --budget validation/ai04_qualification_budget_v5.json \
  --output artifacts/NEW_ABSOLUTE_TOLERANCE_QUALIFICATION
```

## Запуск допущенной задачи

```bash
python -m scripts.run_qualified_euler \
  --qualification artifacts/ai04_qualification_v6 \
  --case step_positive_asymptotic --cells 512 \
  --output artifacts/NEW_QUALIFIED_EXPERIMENT
```

Команда допускает только точный fixture, принятый для текущего runtime
fingerprint. Конфигурация, горизонт и solver policy передаются публичному
SDK. `admission.json` связывает эксперимент с матрицей и исходным input,
его SHA256 добавляется в manifest эксперимента. Отсутствие допуска,
подмена input или смена исходников отклоняются до запуска расчёта.
Уменьшение сетки не разрешается автоматически, даже если input конструктивно
поддержан. CLI квалификации и запуска из `scripts` используется из checkout;
устанавливаемый `atomic-euler-experiment` сохраняет собственный обычный режим.

## Область результата

Приёмка относится к перечисленным компонентным задачам с малыми амплитудами
и заданными горизонтами. Она не подтверждает физическую точность акустики,
точные статические pressure ports, произвольные ударные волны, глобальную
положительность или TVD неявной схемы. `validated=false`,
`plant_referenced=false`; компонент не подключён к новой системной модели ВВЭР.

## Итоговые измерения

Фронты ±1 м/с на 128/256/512 ячейках: порядки 0,48846 и 0,45745;
на 512 ячейках L1(T)=0,00042958 K. Максимальная временная разность
по общим срезам — менее 3,181e-7 K при допуске 1e-6 K. Грубые диапазоны
16/32/64 и 32/64/128 остаются непринятыми. Положительное направление
повторено через публичный SDK с checksum-проверкой полного результата.

Самый долгий расчёт серии занял 141,154 с при бюджете 180 с; стоимость
относится к интегрированию и restart на текущем окружении. Нагретое
равновесие, импульс стенки, запуск и реверс прошли повторную приёмку.
Аудиты заново вычисляют запасы, нормы и решения о допуске из raw states.

Wheel дополнен ранее отсутствовавшими JSON-сценариями. Проверка установки
сверяет байты всех файлов runtime fingerprint и сам fingerprint вне checkout;
дополнительный режим проверяет работу установленного gate со всей матрицей:

```bash
python scripts/verify_wheel.py dist/atomic_sim-2.0.0-py3-none-any.whl \
  --qualification artifacts/ai04_qualification_v6
```

Результат относится к текущему Linux/Python 3.12 и версиям зависимостей
из baseline. Другие платформы и зависимости требуют самостоятельной
квалификации. Временные/пространственные допуски не означают промышленной
достоверности установки, реальных pressure ports или универсальной точности HLLC.
