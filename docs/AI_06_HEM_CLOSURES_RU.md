Пакет `atomic_model_hem_closures`, идентификатор `hem-closures/1.2.0`.

Текущий статус версии 1.2.0: `partial_1995_tiny_cube_only`. Доступна отдельная

## API для интегратора сети

```python
from atomic_model_hem_closures import darcy_factor
f_D = darcy_factor(reynolds, relative_roughness=0.0)
```

Это коэффициент **Darcy**, в четыре раза больше Fanning. Числовой интерфейс
не распознаёт фазу: интегратор обязан на каждой стадии RK проверить однофазность,
круглую прямую трубу, установившийся профиль, ньютоновскую среду, постоянные
локальные свойства и пренебрежимо малые эффекты сжимаемости/плавучести.
Re положителен, вычисляется через модуль скорости: `rho*abs(u)*D/mu`.
Относительная эквивалентная песочная шероховатость `epsilon/D` в `[0, 0.05]`.
Для `0 < Re < 2300` используется `64/Re`; для `4000 <= Re <= 1e8` решается
Colebrook. Остальные Re, включая нулевой расход, NaN и infinity, отвергаются.
При нулевом расходе сеть должна иметь собственное явное правило нулевого
сопротивления; пакет не вводит скрытую регуляризацию и не сглаживает переход.

Локальное падение давления в направлении положительной координаты:
`dp = f_D*(L/D)*rho*u*abs(u)/2`. При отрицательной скорости знак меняется.
Знак источника импульса — противоположный сопротивлению. Пакет не меняет
полную энергию сети и не добавляет повторно «потерянную» механическую энергию.
Гравитационный и ускорительный члены не входят в этот результат.
Сеть самостоятельно проверяет положительные L, D, площадь и свойства на каждой
стадии. Для source identity хешировать файлы исходного пакета `*.py`,
сохранять также CLOSURE_VERSION; не включать меняющиеся файлы `__pycache__`.

Более строгие интерфейсы принимают `physics.materials.iapws.ThermoState`:

```python
from atomic_model_hem_closures import (
    TubeScope, friction_factor, friction_pressure_drop_pa, heat_transfer,
    single_phase_transfer,
)
scope = TubeScope(
    circular_straight=True, fully_developed=True, constant_properties=True,
    forced_convection=True, negligible_compressibility=True,
)
f = friction_factor(state, mass_flux_kg_m2_s, diameter_m,
                    scope=scope, roughness_m=roughness_m)
dp = friction_pressure_drop_pa(state, mass_flux_kg_m2_s, diameter_m, length_m,
                              scope=scope, roughness_m=roughness_m)
ht = heat_transfer(state, mass_flux_kg_m2_s, diameter_m, wall_temperature_k,
                   scope=scope, constant_wall_temperature=True,
                   thermally_developed=True, correlation="auto", length_m=length_m)
h = ht.coefficient_w_m2_k
```

Флаги — утверждения вызывающего кода о физической постановке; значение True
не является доказательством установившегося профиля. Для теплообмена дополнительно
предполагаются пренебрежимо малые вязкая диссипация и осевая теплопроводность.
Безразмерный интерфейс и интерфейс по состоянию используют один решатель Darcy.
`FrictionResult` содержит Re, шероховатость, невязку Colebrook и provenance.
`HeatTransferResult` содержит Nu, h, q'', Re, Pr и provenance.
`q'' = h*(Tw-Tbulk)`, положителен от стенки к жидкости; сеть может использовать
`h*area` как тепловую проводимость при выполнении всех условий.
Адаптер `single_phase_transfer(state, velocity_m_s, diameter_m, length_m,
roughness_m, wall_temperature_k, *, scope, constant_wall_temperature,
thermally_developed, correlation="auto")` возвращает тот же HeatTransferResult;
он требует конечную положительную длину, переводит скорость в `G=rho*u` и
вызывает те же проверки заново. Условий физического scope автоматически не предполагает.
У `heat_transfer` длина опциональна (None), но при передаче проверяется.
Параметр `correlation` допускает `auto`, `laminar`, `gnielinski`. Auto выбирает
ветвь по Re; явный выбор отвергает несовместимый режим. Неизвестные имена отвергаются.
Длина не служит доказательством развития профиля; проверка входного участка остаётся
за интегратором. Данный API не вычисляет усреднённый по входному участку h.

## Область и отказы

Интерфейсы по состоянию намеренно ограничены IF97 regions 1/2,
`273.15 <= T <= 623.15 K`, `611.212677 <= p <= 16529164.2526 Pa`,
статусом IN_DOMAIN и строго ненасыщенным bulk. Regions 3/4/5 не поддержаны.
Границы выбраны консервативно по доступной в backend линии насыщения, это
ограничение реализации, а не универсальные границы применимости Colebrook.
Положительность и конечность rho, mu, k, cp проверяются. Объект состояния должен
быть получен из backend: пакет не пересчитывает EOS для проверки всех его полей.

Теплообмен: только гладкая круглая труба, постоянная температура стенки,
полностью развитые гидродинамический и тепловой профили. В ламинарном режиме Nu=3.66;
в турбулентном используется ограниченный Gnielinski, описанный ниже.
Стена и bulk строго по одну сторону насыщения: достижение насыщения стенкой
отвергается, без попытки предсказать ONB или конденсацию. Постоянный тепловой
поток и входной участок этим интерфейсом не поддерживаются.

Gnielinski реализован в версии 1.1 как fully-developed constant-property предел,
без поправок на входной участок, переменные свойства и шероховатость:
`Nu = (f/8)*(Re-1000)*Pr / (1+12.7*sqrt(f/8)*(Pr**(2/3)-1))`,
`f = (1.82*log10(Re)-1.64)**(-2)`. Здесь f для теплообмена соответствует
первичному программному источнику INL MOOSE; он намеренно отличается от
численного Colebrook для импульса. Результат маркирован `gnielinski-smooth-inl-1.82`.
Это не утверждение, что 1.82 — единственная авторская версия коэффициента.

Область `4000 <= Re <= 5e6`, `0.5 <= Pr <= 2000`, строго нулевая шероховатость.
INL допускает более низкую границу Re=2300, но здесь переход `[2300,4000)`
по-прежнему отвергается. Авторская статья 2013 обсуждает отдельную интерполяцию
перехода; пакет её не выполняет. Дополнительный envelope состояния backend
и проверки стенки действуют и для Gnielinski. Constant-properties scope означает
отсутствие влияния переменных свойств: множитель K=1 не подменяет поправки для
большого перепада температур. Не назначены проценты экспериментальной точности.

`TubeScope.heat_transfer_regime` допускает только `single_phase`; запросы
`two_phase`, `boiling`, `CHF`, `postCHF` и любые неизвестные режимы отвергаются.
Двухфазное трение не оценивается через смешанную вязкость region 4.
`DomainError` использует существующий тип `core.status`; неподдержанные физические
режимы имеют `Applicability.UNSUPPORTED`, нарушения числовой области — OUT_OF_DOMAIN.

## CHF: только насыщенный неподвижный бассейн

```python
from atomic_model_hem_closures import PoolScope, zuber_pool_chf_screening
screen = zuber_pool_chf_screening(
    pressure_pa, surface_tension_n_m,
    surface_tension_source="источник sigma при данном давлении насыщения",
    scope=PoolScope(saturated_quiescent=True,
                    large_horizontal_upward_wetted=True, pure_water=True),
)
q_pool_screen = screen.heat_flux_w_m2
```

Формула `q = (pi/24)*h_fg*sqrt(rho_v)*(sigma*g*(rho_l-rho_v))**0.25`;
`g=9.80665 m/s²`. h_fg и плотности берутся из насыщения backend при одном p.
Диапазон p тот же, что выше, вдали от критической точки. sigma должна относиться
к тому же насыщению; её согласованность с p подтверждает вызывающий код.
Backend функции sigma не предоставляет, поэтому её нельзя выдумывать или
молча заменять константой. API требует непустой источник sigma.

Физическая постановка: чистая вода, насыщенный неподвижный бассейн, большая
горизонтальная смоченная поверхность нагрева вверх, нормальная гравитация.
Размер «большая» и смачиваемость заявляются вызывающим кодом; API не квалифицирует
конечный нагреватель. Результат содержит `qualifies_forced_flow=False`.
`PoolScope.application` допускает только `pool_screening`; forced-flow, CHF канала,
DNBR, postCHF, переохлаждённый бассейн и иная ориентация отвергаются.
Пакет не рассчитывает теплоотдачу при/после CHF и не разрешает продолжить её
по однофазному h. Масштаб Zuber нельзя использовать как аварийный предел канала.

## Источники и фактически просмотренные свидетельства

Проверка веб-источников выполнена 2026-11-05. Формулы не калибровались по эксперименту.

1. [NPTEL, Applications of Viscous Flows Through Pipes, recap](https://archive.nptel.ac.in/content/storage2/courses/112104118/recap/11-recapa.htm).
   Оригинальный учебный материал NPTEL: Darcy/Fanning и вывод ламинарного 64/Re
   из Navier–Stokes. Это первичное учебное изложение, не историческая статья Пуазейля.
2. [Colebrook, 1939, pp. 133–156, DOI](https://doi.org/10.1680/ijoti.1939.13150).
   DOI через браузер не открылся; просмотрена
   [репродукция оригинальной статьи](https://pdfcoffee.com/colebrook-white-1939-pdf-free.html),
   уравнение (12), с OCR-ограничениями. Решается именно неявное уравнение:
   `x + 2*log10(rr/3.7 + 2.51*x/Re)=0`, `f=1/x²`.
   Бисекция x на [1,100], максимум 100 шагов, абсолютная невязка <=1e-12.
   Это явная численная процедура решения, не явная аппроксимация формулы.
   Диапазоны Re/rr в пакете — заявленный инженерный envelope реализации;
   они не выданы за экспериментальную аттестацию каждой точки.
3. [S. Chakraborty, NPTEL IIT Kharagpur, Lecture 29](https://archive.nptel.ac.in/content/storage2/courses/103105052/AdvHeatMass_L_29.pdf),
   стр. 2 и 6–7: допущения, постоянная Tw, асимптота 3.658, округлённое 3.66.
   Там различаются постоянный тепловой поток и постоянная температура.
4. [Zuber, 1959, AECU-4439, оригинальная диссертация в UNT](https://digital.library.unt.edu/ark:/67531/metadc872491/).

   Реализация помечена screening; полнотекстовый аудит нужен до расширения статуса.
5. [Gnielinski, On heat transfer in tubes, 2013, DOI](https://doi.org/10.1016/j.ijheatmasstransfer.2013.04.015):
   теперь просмотрена [репродукция авторского текста](https://studylib.net/doc/28037627/on-heat-transfer-in-tubes---gnielinski),
   стр. 135: Eq. (2), поправка свойств K и различие версий f; переход рассматривается отдельно.

6. [INL MOOSE, первичный исходный код разработчиков](https://mooseframework.inl.gov/docs/doxygen/modules/ADWallHeatTransferCoefficientGnielinskiMaterial_8C_source.html),
   computeQpProperties, строки C++ 63–77: f с коэффициентом 1.82, формула Nu,
   ограничения Pr=0.5..2000 и Re=2300..5e6. В отличие от предупреждения исходного
   приложения, пакет жёстко отвергает выход из своей области. Математические
   формулы реализованы самостоятельно; код MOOSE в пакет не копировался.

Локально просмотрен `physics/materials/iapws.py`: ThermoState предоставляет
`viscosity_pa_s`, `conductivity_w_m_k`, `cp_j_kg_k`, rho, p, T, region и applicability.
Вязкость IAPWS 2008 и теплопроводность IAPWS 2011 реализованы **без критических
добавок**. Это явно записано в `transport_provenance`. Неопределённости свойств
не распространяются в результат. Не назначены вероятностные интервалы, коэффициенты
запаса или универсальная процентная точность. Малая невязка Colebrook — свойство
численного решения уравнения, а не физическая погрешность корреляции.

## Проверки

`tests/test_hem_closures.py` проверяет независимые контрольные значения Darcy,
невязку Colebrook, монотонность по шероховатости, совпадение потери давления
с аналитическим законом Пуазейля и смену знака при реверсе. Для тепла проверяются
Nu, h, q'', Pr, паровая однофазная ветвь и отказ при пересечении насыщения.
Для Zuber проверяется атмосферный масштаб около 1.108 MW/m² при заданной
тестовой sigma=0.0589 N/m, а не экспериментальная точность. Отдельно проверяются
нечисловые/нефизичные входы, геометрия, двухфазность и недопустимые режимы.
Команды: `python -m pytest tests/test_hem_closures.py -q` и
`python -m ruff check atomic_model_hem_closures tests/test_hem_closures.py`.
Эти проверки устанавливают соответствие реализации формулам и отказам;
экспериментальная валидация не выполнена.


## Исследование forced-flow CHF: явная блокировка в версии 1.1

`FORCED_FLOW_CHF_AVAILABILITY.status = "blocked_primary_raster_lut_not_audited"`.
`forced_flow_chf(pressure_pa, mass_flux_kg_m2_s, quality, *, diameter_m, length_m)`
для любых аргументов выдаёт DomainError с UNSUPPORTED и причиной. Никакого
числового forced-flow CHF, DNBR и перехода к postCHF в этом выпуске нет.

Фактическая доступность исследована, а не объявлена отсутствующей вообще:

- [Groeneveld et al., 2007, The 2006 CHF look-up table](https://doi.org/10.1016/j.nucengdes.2007.02.014):
  первичная аннотация описывает нормализованную вертикальную трубу 8 mm и
  сетку 24 давления × 20 массовых скоростей × 23 качества. Полный publisher PDF
  в этой сессии не получен. Это не универсальная корреляция для любого канала.
- [NRC NUREG/KM-0011](https://www.nrc.gov/regulations-legislation/nureg-series-publications/publications-prepared-by-nrc-staff-for-knowledge-management/km0011):
  открытая запись сообщает о более 25 тысячах экспериментальных точек,
  использованных для построения LUT. Сами измерения не являются готовой LUT;
  интерполяция произвольных экспериментальных точек вместо неё не реализована.
- [ANL/GTRI/TM-14/1, E. Feldman, 2014](https://publications.anl.gov/anlpubs/2014/10/78422.pdf):
  открытый первичный PDF действительно описывает Excel с листом G2006CHF_table,
  трилинейную интерполяцию восьми углов и отказ вне диапазонов P/G/X.
  Числовой диапазон там: 100..21000 kPa, G=0..8000 kg/(m² s), x=−0.5..1.
  Однако полноценный XLS payload не извлечён из этого PDF; описание листа
  упоминает 15 давлений и 21 строку G, что требует сверки версии с сеткой статьи.
  Четыре примера не заменяют все табличные узлы.
- [NEA/WKP(2023)1, January 2024](https://oecd-nea.org/upload/docs/application/pdf/2024-01/nea_wkp_2023_1_2024-01-18_16-23-40_237.pdf),
  Appendix B/C: файл results/LUT/LUT2006.xls существует, но GitLab доступен
  зарегистрированным участникам benchmark. Здесь такой доступ не использовался.
- [IAEA-TECDOC-1203](https://www-pub.iaea.org/MTCD/Publications/PDF/te_1203_prn.pdf),
  Appendix II: опубликована **1995** LUT; это не автоматически таблица 2006 года.
  В индексируемом тексте указано, что затенённые значения имеют менее надёжную
  основу или являются экстраполяцией. Последующая загрузка через
  `exec_command(require_escalated)` выполнена успешно; прежний DNS-блокер снят.
  Проверка полного первичного PDF описана ниже. Маска надёжности и первичные
  числовые ячейки пока не импортированы в интерполятор.
- Обнаружена доступная сторонняя транскрипция `2006LUTdata.txt` (репозиторий
  greenwoodms06/2006_Groeneveld_CriticalHeatFlux_LUT). Она не объявлена
  авторским выпуском IAEA/AECL. Нет выполненной в этой сессии сверки каждого
  узла, порядка осей, вариантов сетки и применимости ячеек с первичным payload.
  Поэтому таблица не включена в пакет и по ней не возвращается CHF.

Для разблокировки нужны первичный числовой payload конкретного выпуска,
аудит осей/единиц/значений и применимости интерполяционных ячеек, контрольная
сумма, независимые контрольные точки и ограничение геометрии/потока. Тогда
допустима только ограниченная интерполяция внутри аудированной области,
без экстраполяции, произвольных поправок на диаметр или подмены Zuber.

Дополнительные тесты версии 1.1 проверяют контрольные Nu Gnielinski, границы
Re/Pr, явный выбор ветви, двусторонние границы насыщения стенки (±1e−6 K),
адаптер скорости, реверс, изменение условий между стадиями и явный отказ forcedCHF.

`FORCED_FLOW_CHF_AVAILABILITY` (хеш, размер, номера PDF-страниц).

`pdftotext -layout` успешно извлёк основной текст документа. Однако приложение II
не является машиночитаемой числовой таблицей: PDF-страницы 184–190 содержат
по одному растровому TIFF; текстовый слой каждой состоит только из номера
печатной страницы (176–182). Страница PDF 183 / печатная 175 поясняет, что
затенённые числа основаны на менее надёжных данных или экстраполяции.
Первый лист таблицы отрендерен Poppler и просмотрен, исходный растр также
извлечён и просмотрен. Заголовок непосредственно подтверждает **1995** LUT
для труб 8 mm, единицы kW/m², давление kPa, массовую скорость kg/(m² s) и
термогидравлическое качество. Непустые и затенённые области различаются;
пустые ячейки нельзя заполнять или превращать в нулевые значения.

Итак, первичный payload достижим; блокером больше не являются DNS или права
доступа к IAEA. Точный терминальный статус: **первичная растровая таблица
доступна, но полная транскрипция значений и маски применимости не аудирована**.
Парсинг чисел через pdftotext невозможен для этих страниц. OCR-инструмент
Tesseract в окружении отсутствует; даже его вывод потребовал бы проверки
каждой включённой ячейки и изображения затенения. Не выполнена подмена
1995 LUT на 2006 LUT, не добавлена интерполяция по непроверенным числам и
не заявлена физическая валидация. Статус forcedCHF остаётся UNSUPPORTED,
с обновлённой машинно-читаемой причиной. API Darcy/heat_transfer и их
области не изменились. Для квалификации версия пакета теперь 1.1.1;
исходники следует перехешировать после этого изменения.


## Финальное поступление ограниченного куба: версия 1.2.0

Только `chf_1995_cube(p, G, x, *, diameter_m, scope=CHF1995CubeScope(...))`.
Результат `CHF1995CubeResult.heat_flux_w_m2`; provenance явно содержит 1995,
страницу первичного PDF и его SHA-256. Этот API не вызывается автоматически
вместо общего `forced_flow_chf` и не разрешает postCHF теплоотдачу.

Жёсткая область: p=300000..500000 Pa, G=1000..1500 kg/(m² s), x=0..0.05,
D **строго** 0.008 m. Положительный G означает восходящий поток; реверс запрещён.
Все границы включены. x — локальное термогидравлическое равновесное качество,
x=0 — насыщенный жидкий край. Никакой нормировки качества, проекции или
экстраполяции за границы нет. Восемь углов интерполируются трилинейно;
исходные kW/m² умножаются на 1000 для результата в W/m².

`CHF1995CubeScope` требует явных True для `pure_water`,
`circular_tube_internal_flow`, `steady_vertical_upflow`, `uniform_heating`,
`equilibrium_quality`. `application` допускает только `nominal_local_chf_table`.
Это номинальный локальный табличный результат, без поправок на конечную длину,
поверхность, сетки, неравномерный нагрев или иную геометрию. Положительная
длина сама по себе не квалифицирует канал; параметр длины поэтому не принимается
ограниченным табличным API. `qualifies_channel_chf=False`, экспериментальная
валидация не заявлена, численная неопределённость/запас не назначены.

Первичный источник: IAEA-TECDOC-1203, Table II.I, печатная p.176 / PDF p.184.
Название таблицы указывает 1995 LUT, трубы 8 mm и kW/m²; заголовки осей:
давление kPa, массовая скорость kg/(m² s), quality. Предшествующая PDF p.183 /
печатная p.175 объясняет, что затенённые числа менее надёжны или основаны
на экстраполяции; вертикальная ориентация на этой странице **не указана**.
Для постановки steady vertical upflow с внутренним охлаждением равномерно
нагреваемой трубы использован явный текст §3.4.1, печатная p.24.
Это не квалификация нестационарных стадий сети как steady CHF эксперимента.

Восемь независимо прочитанных и незатенённых значений, порядок пары x=[0,0.05],
в kW/m²:

- p=300 kPa, G=1000: [4189, 3285].
- p=300 kPa, G=1500: [4209, 3339].
- p=500 kPa, G=1000: [4873, 4075].
- p=500 kPa, G=1500: [4909, 4093].

Источник воспроизводимого визуального аудита: растр PDF p.184 размером
3758×5638; SHA-256 извлечённого TIFF
`a9d78b1962e621f71b4e456eb84af30bfad90b3b2da002c23409608899a246f4`.
Заголовки y=0..420; строки p=300/G=1000,1500 y=2320..2550;
